= API 카탈로그
:toc: macro
:toclevels: 2

사내에서 운영하는 API 를 한곳에 등록하고, 문서를 보고, 직접 호출해 보고, 변경 이력과 품질을 관리하는 메뉴입니다.
데이터셋·모델과 마찬가지로 **API 도 하나의 거버넌스 대상**으로 다룹니다.

이 문서는 처음 사용하는 분을 기준으로 화면(메뉴) 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **찾기** — "주문 API 가 어디 있지?" 같은 질문에 이름·설명·태그·소유자로 검색해 답을 찾습니다.
* **등록** — OpenAPI(Swagger) 스펙을 붙여넣거나 파일·URL 로 올리면 엔드포인트가 자동으로 정리됩니다. 스펙이 없는 API 도 수동으로 등록할 수 있습니다.
* **문서 보기와 호출해 보기(Try-it)** — 엔드포인트별 파라미터·요청·응답 구조를 보고, 화면에서 바로 호출해 결과를 확인합니다.
* **변경 관리** — 스펙의 새 버전을 올리면 이전 버전과 비교해 하위 호환을 깨는 변경(Breaking)을 알려 줍니다.
* **품질 점검(린팅)** — 스펙이 작성 규칙을 잘 지켰는지 점수로 보여 줍니다.
* **관계(리니지)와 사용량(관측)** — 이 API 가 어떤 시스템·데이터셋·모델과 연결되는지, 얼마나 호출되는지 봅니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| API
| 다른 시스템이 호출해서 쓰는 기능의 묶음입니다. 예: "주문 API", "결제 API".

| 엔드포인트
| API 안의 개별 호출 주소입니다. `GET /orders/{id}` 처럼 **메서드 + 경로**로 구분합니다.

| 스펙(Spec)
| API 를 기계가 읽을 수 있게 적은 설명서입니다. 이 카탈로그는 **OpenAPI 2.0(Swagger)·3.x** 형식(JSON/YAML)을 읽습니다.

| 스펙 API / 수동 API
| 스펙을 올려 엔드포인트가 자동으로 만들어진 API 가 **스펙 API**, 스펙 없이 화면에서 직접 적어 넣은 API 가 **수동 API** 입니다.

| 계약 문서
| 수동 API 에 붙여 두는 원문 문서입니다(GraphQL 스키마, WSDL, .proto, AsyncAPI 등).

| Base URL
| 실제 호출이 나가는 서버 주소입니다. 예: `https://api.example.com/v1`.

| 자격증명
| 호출할 때 필요한 API Key·토큰·아이디/비밀번호입니다. 암호화되어 저장됩니다.

| Breaking 변경
| 기존 사용자가 그대로 쓰면 오류가 나는 변경입니다(엔드포인트 삭제, 필수 파라미터 추가 등).

| 리니지
| 이 API 가 무엇을 제공하고, 무엇을 소비하며, 무엇에 의존하는지를 나타내는 관계입니다.
|===

=== 메뉴 위치

왼쪽 사이드바의 **API 카탈로그** 아래에 두 메뉴가 있습니다.

[cols="1,2,3",options="header"]
|===
| 메뉴 | 주소 | 용도

| API | `/dashboard/apis` | 목록·검색, 등록, 상세(개요·엔드포인트·인증·리니지·관측·린팅·원본·이력)
| 즐겨찾기 | `/dashboard/apis/favorites` | 별표(★)한 엔드포인트만 모아 보고 바로 호출
|===

=== 누가 무엇을 할 수 있나요

[cols="3,1,1,1",options="header"]
|===
| 작업 | 일반 사용자 | API 소유자 | 관리자

| 목록·상세 보기, 문서 보기, 즐겨찾기 | ✓ | ✓ | ✓
| Try-it 호출(자격증명 없이) | ✓ | ✓ | ✓
| API 등록(스펙 가져오기 포함) | 기능 권한 `apis.register` 에 따름 | 〃 | ✓
| 개요 편집·상태 변경·새 스펙 버전 등록·엔드포인트 편집·Breaking 확인 | – | ✓ | ✓
| 저장된 자격증명 조회·사용 | 기능 권한 `apis.credentials` 에 따름 | 〃 | ✓
| 자격증명 추가·삭제, 리니지 추가·삭제, API 삭제 | – | – | ✓
|===

등록한 사람이 기본 소유자가 되며, 소유자는 개요 탭에서 바꿀 수 있습니다.
권한이 없는 버튼은 화면에 아예 나타나지 않습니다.

image::governance-api-catalog/user-readonly.png[일반 사용자가 남의 API 를 볼 때 — 편집 버튼이 보이지 않음, 800]

[TIP]
.고급 사용자
====
`apis.register`(API 등록) · `apis.credentials`(저장된 자격증명 사용)는 **권한 관리** 메뉴의 기능(FEATURE) 권한입니다. 아무 역할에도 지정하지 않으면 모든 로그인 사용자에게 열려 있고,
특정 역할(예: `argus-superuser`)에 지정하면 그 역할(과 관리자)만 API 를 등록하거나 저장된 자격증명을 보고 쓸 수 있습니다.
`apis.register` 가 없으면 목록의 등록 버튼이 보이지 않습니다.
====

=== 검색·필터·정렬

* **검색창** — 이름, 표시명, 설명, 카테고리, 태그, 소유자에서 찾습니다. 입력을 멈추면 잠시 뒤 자동으로 검색되고, Enter 를 누르면 바로 검색됩니다.
* **필터** — 상태(초안/게시/사용 중단/폐기), 카테고리, 프로토콜, 인증 상태.
* **정렬** — 최근 수정순(기본) / 최근 등록순 / 이름순.
* **보기 방식** — 표 보기와 카드 보기를 오른쪽 위 버튼으로 바꿉니다. 한 페이지에 10~50개까지 보이게 할 수 있습니다.

image::governance-api-catalog/list-card-view.png[카드 보기, 800]

=== 행 메뉴(⋮)

각 행 끝의 ⋮ 를 누르면 **새 탭에서 열기 / 링크 복사 / URN 복사** 를 할 수 있습니다.
메신저로 동료에게 API 를 알려 줄 때는 "링크 복사"를 쓰면 됩니다.

image::governance-api-catalog/list-row-menu.png[행 메뉴, 800]

[TIP]
.고급 사용자 — 주소(URL)에 조건이 남습니다
====
검색어·필터·정렬·페이지가 모두 주소창에 저장되므로, 주소를 그대로 북마크하거나 공유하면 같은 화면이 열립니다.

[source]
----
/dashboard/apis?q=order&status=published&protocol=REST&cert=certified&sort=name&size=50&view=card
/dashboard/apis?owner=unowned        # 소유자 미지정
/dashboard/apis?alert=1              # 미확인 Breaking 변경
/dashboard/apis?api=it-pet-api&tab=endpoints   # 특정 API 의 특정 탭
----

이름순 정렬은 영문(대소문자 구분 없음) 다음에 한글 순서로 나옵니다.
====

== API 등록

목록 오른쪽 위의 **API 등록** 버튼을 누르면 등록 창이 열립니다. 탭이 두 개 있습니다.

* **스펙(Swagger/OpenAPI)** — OpenAPI 스펙이 있을 때(권장). 엔드포인트가 자동으로 만들어집니다.
* **수동 등록** — 스펙이 없거나 REST 가 아닌 API(GraphQL, gRPC, SOAP, Webhook 등)일 때.

=== 스펙(Swagger/OpenAPI) 탭으로 등록

. 스펙을 넣는 방법을 하나 고릅니다.
** **스펙 붙여넣기** — 편집기에 JSON 이나 YAML 을 붙여넣습니다.
** **파일 불러오기** — 같은 "스펙 붙여넣기" 화면에서 `.json`, `.yaml`, `.yml` 파일(최대 5MB)을 불러옵니다. 200KB 가 넘는 파일은 내용이 접힌 상태로 보이며 "내용 펼치기"로 열 수 있습니다.
** **URL** — URL 탭에서 스펙 주소를 넣고 **불러와서 확인** 을 누릅니다.
. 스펙을 읽으면 아래에 **미리보기**가 자동으로 나옵니다. 제목·버전·엔드포인트 수·서버·인증 방식을 확인하세요. 이 단계에서는 아직 저장되지 않습니다.
. **식별자**는 스펙 제목으로 자동 제안됩니다. 영문, 숫자, `.`, `-`, `_` 만 쓸 수 있고, 이미 있는 식별자면 "이미 존재합니다"라고 표시되며 등록 버튼이 잠깁니다.
. **등록**을 누르면 끝입니다. 등록한 사람이 소유자가 됩니다.

image::governance-api-catalog/register-spec.png[YAML 파일로 등록할 때의 미리보기, 800]

==== Base URL 을 물어볼 때

스펙에 서버 주소가 없거나 `/v1` 처럼 상대 경로만 있으면, 실제로 어디로 호출할지 알 수 없어 **Base URL 입력란**이 나타납니다.
`https://api.example.com` 처럼 `http://` 또는 `https://` 로 시작하는 전체 주소를 넣으세요.

image::governance-api-catalog/register-base-url.png[상대 경로 서버 경고와 Base URL 입력, 800]

NOTE: 직접 넣은 Base URL 은 나중에 새 스펙 버전을 올려도 유지됩니다.

==== AsyncAPI 문서는 수동 등록으로

AsyncAPI(메시지·이벤트 API) 문서는 엔드포인트를 자동으로 뽑을 수 없어 스펙 탭에서는 등록할 수 없습니다.
안내에 따라 **수동 등록** 탭에서 프로토콜(Webhook 등)을 고르고, AsyncAPI 문서를 **계약 문서**로 붙여 등록하세요.

image::governance-api-catalog/register-asyncapi-rejected.png[AsyncAPI 스펙을 넣었을 때의 안내, 800]

=== 수동 등록

* **프로토콜** — REST, GraphQL, gRPC, SOAP, Webhook, 기타 중에서 고릅니다.
* **식별자·표시명·버전·Base URL·설명** 을 적습니다.
* REST 가 아니면 **계약 문서**를 URL 이나 원문(붙여넣기·파일)으로 붙일 수 있습니다. 파일은 `.graphql`, `.gql`, `.wsdl`, `.xml`, `.proto`, `.json`, `.yaml`, `.yml`, `.txt` 를 받습니다.

image::governance-api-catalog/register-manual.png[수동 등록 탭, 800]

수동 API 의 엔드포인트는 등록 후 상세 화면의 **엔드포인트** 탭에서 하나씩 추가합니다(<<_엔드포인트_탭>> 참고).

[TIP]
.고급 사용자 — 저장하지 않고 스펙만 검사하기
====
`POST /api/v1/apis/preview` 에 `{"spec_text": "..."}` 또는 `{"spec_url": "..."}` 를 보내면 저장하지 않고 미리보기 결과(버전, 엔드포인트 수, 제안 식별자 `name`/`name_auto`)만 돌려줍니다.
CI 에서 스펙이 카탈로그에 등록 가능한지 미리 확인할 때 쓸 수 있습니다.
====

== API 상세

목록에서 API 이름을 누르면 상세 화면이 열립니다. 위쪽 머리글과 여덟 개 탭으로 구성됩니다.

[cols="1,4",options="header"]
|===
| 탭 | 내용
| 개요 | 기본 정보(설명, 소유자, 등급, 태그 등) 보기·편집
| 엔드포인트 | 엔드포인트 문서와 Try-it 호출
| 인증 | 호출에 쓸 자격증명 관리
| 리니지 | 다른 시스템·데이터셋·모델·API 와의 관계
| 관측 | Try-it 호출 통계
| 린팅 | 스펙 품질 점수
| 원본 | 스펙 원문(또는 계약 문서)과 새 버전 등록
| 이력 | 상태 변경·버전 등록 기록과 버전 비교
|===

=== 머리글 — 상태와 Breaking 알림

머리글의 **상태** 드롭다운으로 API 의 생애주기를 바꿉니다(소유자·관리자).

[cols="1,3",options="header"]
|===
| 상태 | 의미
| 초안 | 아직 준비 중. 다른 사람에게 권하지 않는 상태
| 게시 | 정식으로 쓰도록 공개된 상태
| 사용 중단 | 새로 쓰지 말라는 예고. 기존 사용자는 옮겨 가야 함
| 폐기 | 더 이상 운영하지 않음
|===

**사용 중단**이나 **폐기**로 바꿀 때는 사유를 적는 창이 뜹니다. 적은 사유는 **이력** 탭에 남으니, 대체 API 이름 등을 적어 두면 사용자에게 도움이 됩니다.

image::governance-api-catalog/status-dialog.png[사용 중단 사유 입력 창, 800]

새 스펙 버전에 Breaking 변경이 있으면 머리글 아래에 **경고 배너**가 나옵니다.
**자세히**를 누르면 무엇이 바뀌었는지 보이고, 소유자·관리자가 **확인**을 누르면 배너가 사라집니다(목록의 "미확인 Breaking 변경" 수에서도 빠집니다).

image::governance-api-catalog/breaking-banner.png[Breaking 변경 경고 배너, 800]

API 삭제는 관리자만 할 수 있으며, 머리글의 **삭제** 버튼을 씁니다. 엔드포인트·자격증명·이력이 함께 지워지니 신중히 사용하세요.

=== 개요 탭

API 의 "명함"에 해당하는 정보입니다. 소유자·관리자는 **편집**을 눌러 바꿀 수 있습니다.

* **표시명·설명** — 사람이 읽기 좋은 이름과 소개.
* **Base URL** — 호출 서버 주소(`http(s)://` 로 시작하는 전체 주소만 허용).
* **카테고리·태그** — 검색과 분류에 쓰입니다.
* **소유자·부서** — 사용자 검색으로 소유자를 고르면 부서가 자동으로 채워집니다.
* **인증 상태** — 없음 / 인증됨 / 검토 중 / 지원 중단. "이 API 는 검증을 거쳤다"는 표시입니다.
* **등급** — 골드 / 실버 / 브론즈. 중요도나 서비스 수준을 나타냅니다.
* **비고** — 자유 메모.
* 수동 API 는 **버전**과 **계약 문서 URL**도 여기서 고칩니다.

image::governance-api-catalog/overview-edit.png[개요 탭 편집 화면, 800]

NOTE: 편집 중에 **취소**를 누르거나 다른 화면으로 이동하면, 저장하지 않은 내용을 버릴지 확인합니다.

=== 엔드포인트 탭

이 카탈로그에서 가장 많이 쓰는 화면입니다. 엔드포인트가 스펙의 **태그**별로 묶여 나오고, 태그가 없는 것은 "기타"에 모입니다.

image::governance-api-catalog/endpoints.png[엔드포인트 탭 — 태그별 그룹, 800]

* 그룹 머리를 눌러 접고 펼치며, **모두 접기**로 한 번에 정리할 수 있습니다.
* 자주 쓰는 엔드포인트는 ★ 를 눌러 즐겨찾기에 넣습니다. **즐겨찾기만 보기**로 별표한 것만 볼 수 있습니다.
* 위쪽의 **서버**와 **자격증명** 선택은 이 탭의 모든 호출에 공통으로 쓰입니다.

엔드포인트 행을 펼치면 **문서**와 **호출** 두 탭이 있습니다.

==== 문서 보기

파라미터(경로·쿼리·헤더), 요청 본문 구조, 응답 코드별 구조가 표로 나옵니다. 필수 항목에는 표시가 붙습니다.

==== 호출해 보기(Try-it)

. 위쪽에서 **서버**를 고릅니다. 인증이 필요한 API 면 **자격증명**도 고릅니다.
. **호출** 탭에서 파라미터 값을 채웁니다. 필수 값이 비어 있으면 빨갛게 표시되고 호출이 막힙니다.
. 요청 본문이 있는 엔드포인트는 스펙의 예시로 미리 채워져 있으니 필요한 부분만 고치면 됩니다.
. **호출** 버튼(GraphQL·SOAP 은 **실행**)을 누르면 응답 코드, 걸린 시간, 응답 헤더와 본문이 나옵니다.

image::governance-api-catalog/try-it.png[Try-it 호출 결과, 800]

image::governance-api-catalog/try-it-required.png[필수 경로 파라미터를 비웠을 때, 800]

응답 본문은 형식(JSON, XML, HTML, YAML, 텍스트)에 맞춰 보기 좋게 표시됩니다.

image::governance-api-catalog/response-xml.png[XML 응답 표시, 800]

그 밖에 알아 두면 좋은 기능입니다.

* **코드 스니펫** — 지금 입력한 요청을 cURL, Python, JavaScript, wget 코드로 보여 줍니다. 비밀값(토큰 등)은 빠진 채로 나오니 복사 후 직접 넣으세요.
* **최근 호출** — 내가 했던 호출이 남아 있어 **불러오기**로 같은 입력을 다시 채울 수 있습니다. 비밀값은 가려져 저장됩니다.

NOTE: 서버가 하나도 없는 API(Base URL 미입력 등)는 **호출**/**실행** 버튼이 비활성화됩니다. 개요 탭에서 Base URL 을 넣으면 호출할 수 있습니다.

==== GraphQL API

프로토콜이 GraphQL 이면 호출 탭이 **GraphQL 콘솔**로 바뀝니다. 쿼리와 변수(variables)를 입력해 실행합니다.
구독(subscription) 작업은 실시간 연결이 필요해 콘솔에서 실행할 수 없습니다.

image::governance-api-catalog/graphql.png[GraphQL 콘솔, 800]

==== 수동 API 의 엔드포인트 추가·편집

수동 API 는 소유자·관리자에게 **엔드포인트 추가** 버튼과 행별 편집·삭제 버튼이 보입니다.
메서드, 경로, 요약, 설명, 태그, 파라미터, 요청 본문, 응답을 입력합니다. 요청 본문과 응답은 **필드 표**로 입력하거나 **JSON** 으로 직접 적을 수 있습니다.

image::governance-api-catalog/endpoint-edit.png[엔드포인트 편집 — 요청 본문 필드, 800]

* 경로에 `{id}` 같은 경로 파라미터를 썼다면 파라미터 목록에도 반드시 선언해야 합니다.
* 같은 메서드 + 경로 조합은 중복 등록할 수 없습니다.

[TIP]
.고급 사용자 — 호출은 서버를 거쳐 나갑니다
====
Try-it 호출은 브라우저가 아니라 **카탈로그 서버가 대신** 보냅니다(CORS 문제 없음). 그래서 보안 정책이 적용됩니다.

* 루프백(127.0.0.1 등), 클라우드 메타데이터 주소, 카탈로그 자체 인프라로의 호출은 항상 차단되며 "보안 정책으로 차단된 호출입니다"라고 나옵니다.
* 리다이렉트가 일어나면 바뀐 주소도 다시 검사합니다.
* 운영자는 `config.yml` 의 `api_outbound` 항목으로 정책을 조정합니다.

[source,yaml]
----
api_outbound:
  block_private: false        # true 면 사설망(10.x, 192.168.x 등)도 차단
  allowed_hosts: "api.partner.com,10.20.0.0/16"   # 다른 차단 규칙보다 우선 허용
  denied_hosts: "legacy.internal"                 # 추가 차단
----
====

=== 인증 탭

인증이 필요한 API 를 호출하려면 자격증명을 미리 저장해 둡니다. 스펙에 정의된 인증 방식(보안 스킴)도 함께 표시됩니다.

image::governance-api-catalog/auth.png[인증 탭 — 저장된 자격증명, 800]

[cols="1,3",options="header"]
|===
| 종류 | 입력하는 것
| API Key | 키 값. 보안 스킴을 연결하면 스펙 정의대로 헤더·쿼리·쿠키에 넣고, 연결하지 않으면 `X-API-Key` 헤더로 보냅니다
| Bearer 토큰 | 토큰 → `Authorization: Bearer <토큰>`
| Basic 인증 | 사용자명, 비밀번호 → `Authorization: Basic …`
| OAuth2 토큰 | 미리 발급받은 액세스 토큰 → `Authorization: Bearer <토큰>`
|===

각 자격증명에는 알아보기 쉬운 **이름**(예: 운영 키)을 붙이고, 필요하면 **보안 스킴**(스펙에 정의된 인증 방식)과 연결합니다.

* 저장한 비밀값은 **암호화**되며 화면에는 가려서 나옵니다. 눈 모양 버튼으로 잠시 볼 수 있습니다(권한이 있을 때).
* 자격증명은 **이 API 의 서버/Base URL 로 보낼 때만** 쓰입니다. 다른 주소로 새어 나가지 않습니다.
* 추가·삭제는 관리자만 할 수 있습니다. 엔드포인트 탭이나 즐겨찾기에서 고르기만 하면 호출에 자동으로 붙습니다.

[TIP]
.고급 사용자 — 운영 암호화 키
====
자격증명은 환경변수 `ARGUS_SECRET_KEY` 로 암호화됩니다. 운영 배포에서는 `ARGUS_REQUIRE_SECRETS=true` 를 켜 두면
키가 없거나 개발용 기본값이거나 16자 미만일 때 서버가 기동하지 않아 실수를 막아 줍니다(`openssl rand -base64 36` 등으로 생성).

키를 바꾸면 기존에 저장한 자격증명을 풀 수 없게 되고, 호출 시 "저장된 자격증명 '…' 을(를) 복호화하지 못했습니다" 오류가 납니다(이때는 인증 없이 호출하지 않습니다).
이때는 인증 탭에서 해당 자격증명을 삭제한 뒤 다시 저장하세요.
====

=== 리니지 탭

이 API 가 다른 대상과 어떻게 이어지는지 기록합니다.

* **관계** — 제공(이 API 가 데이터를 내어 줌), 소비(이 API 가 가져다 씀), 의존(동작에 필요함).
* **대상** — 시스템(자유 입력), 데이터셋, 모델, AI 에이전트, 다른 API(검색해서 선택).
* **표/그래프** 보기를 바꿀 수 있고, 다른 API 가 이 API 를 가리키는 관계는 **들어오는 관계**에 따로 나옵니다.

image::governance-api-catalog/lineage-graph.png[리니지 그래프 보기, 800]

관계 추가·삭제는 관리자만 할 수 있으며, 똑같은 관계를 두 번 넣을 수는 없습니다.

TIP: API 를 사용 중단하기 전에 리니지 탭과 **들어오는 관계**를 보면 영향을 받는 곳을 빠르게 파악할 수 있습니다.

=== 관측 탭

카탈로그의 **Try-it 으로 호출한 기록**을 모아 보여 줍니다. 운영 트래픽 전체가 아니라는 점에 유의하세요.

image::governance-api-catalog/usage.png[관측 탭, 800]

* **기간** — 최근 7 / 30 / 90일.
* **엔드포인트 필터**, **내 호출만** 보기(소유자가 아니면 항상 내 호출만 보입니다).
* **지표** — 총 호출, 성공률, 오류 수, 평균 응답 시간, p95 응답 시간.
* 일별 호출 차트, 상태 코드 분포, 많이 호출된 엔드포인트(누르면 엔드포인트 탭으로 이동), 호출자 목록.

[TIP]
.고급 사용자
====
기간은 주소의 `&days=30` 으로 유지되어 공유할 수 있습니다. 호출 기록 보관 기간은 `config.yml` 의
`api_observability.retention_days`(기본 180일, 0 이하면 지우지 않음)로 정합니다.
====

=== 린팅 탭

스펙이 작성 규칙을 얼마나 잘 지켰는지 **100점 만점**으로 보여 줍니다. 점수가 낮다고 API 가 동작하지 않는 것은 아니지만,
설명·예시가 부족해 다른 사람이 쓰기 어렵다는 신호입니다.

image::governance-api-catalog/lint.png[린팅 결과, 800]

* 문제는 **오류 / 경고 / 정보** 세 단계로 나뉘며, 각 항목에 위치와 고치는 방법이 적혀 있습니다.
* 스펙 버전이 여러 개면 **버전 선택**으로 예전 버전도 검사할 수 있고, **다시 검사**로 새로 돌립니다.
* 수동 API 는 스펙이 없어 린팅 대상이 아니라는 안내가 나옵니다.

[TIP]
.고급 사용자 — 점수 계산과 규칙
====
점수 = 100 − (오류 × 5 + 경고 × 2 + 정보 × 1), 최저 0점.

[cols="1,3",options="header"]
|===
| 단계 | 규칙 ID
| 오류 | `info-required`, `info-title`, `paths-required`, `operation-responses`, `path-params-declared`, `path-params-required`, `security-defined`, `spec-parse`
| 경고 | `info-version`, `info-description`, `oas2-host`, `oas3-api-servers`, `server-trailing-slash`, `operation-description`, `operation-success-response`
| 정보 | `info-contact`, `info-license`, `operation-tags`, `operation-tag-defined`, `parameter-description`, `tag-description`, `tag-unused`, `security-recommended`
|===

API 로는 `GET /api/v1/apis/{name}/lint?spec_id=<버전 ID>` 로 조회합니다. 없는 버전 ID 를 주면 404 입니다.
====

매번 API 를 찾아 들어가지 않고 여기서 바로 문서를 보고 호출할 수 있습니다.

* ★ 를 다시 누르면 즐겨찾기에서 빠지는데, 잠시 나타나는 **되돌리기**로 실수를 취소할 수 있습니다.

== 자주 묻는 질문·문제 해결

[qanda]
AsyncAPI 문서를 올렸더니 거절됩니다.::
  AsyncAPI 는 엔드포인트를 자동으로 뽑을 수 없어 스펙 등록을 지원하지 않습니다. **수동 등록**에서 프로토콜(Webhook 등)을 고르고 계약 문서로 붙이세요(<<_asyncapi_문서는_수동_등록으로>>).

"이미 존재하는 식별자입니다"라고 나옵니다.::
  식별자는 카탈로그 전체에서 하나뿐이어야 합니다. 뒤에 `-v2`, 팀 이름 등을 붙여 바꾸세요.

새 버전을 올릴 수 없습니다(같은 버전).::
  스펙의 `info.version` 이 현재 버전과 같습니다. 버전 번호를 올려서 다시 등록하세요.

호출(실행) 버튼이 회색입니다.::
  호출할 서버가 없습니다. 개요 탭에서 Base URL 을 넣거나 스펙에 서버 주소를 넣어 새 버전을 올리세요. 필수 파라미터가 비어 있어도 호출이 막힙니다.

"보안 정책으로 차단된 호출입니다"가 나옵니다.::
  호출 주소가 루프백·메타데이터·카탈로그 내부 주소이거나 운영자가 차단한 호스트입니다. 정상적인 사내 API 라면 관리자에게 `api_outbound.allowed_hosts` 등록을 요청하세요.

자격증명을 골랐는데 "복호화하지 못했습니다" 오류가 납니다.::
  서버의 암호화 키(`ARGUS_SECRET_KEY`)가 바뀐 경우입니다. 관리자가 인증 탭에서 해당 자격증명을 삭제하고 다시 저장하면 됩니다.

저장된 자격증명이 보이지 않습니다.::
  `apis.credentials` 기능 권한이 특정 역할로 제한되어 있을 수 있습니다. 관리자에게 문의하세요. 자격증명 없이도 공개 엔드포인트는 호출할 수 있습니다.

관측 탭의 숫자가 실제 트래픽보다 훨씬 적습니다.::
  관측 탭은 카탈로그 Try-it 호출만 집계합니다. 운영 트래픽 모니터링 도구를 대신하지 않습니다.

편집 버튼이 없습니다.::
  그 API 의 소유자나 관리자가 아니면 편집할 수 없습니다. 개요 탭에 적힌 소유자에게 요청하세요.

== 부록 — REST API 로 쓰기

화면에서 하는 모든 작업은 REST API 로도 할 수 있습니다. 기본 경로는 `/api/v1/apis` 이며, 로그인 토큰을 `Authorization: Bearer <토큰>` 헤더로 보냅니다.

[source,bash]
----
# 게시된 API 를 이름순으로 조회
curl -H "Authorization: Bearer $TOKEN" "$CATALOG/api/v1/apis?status=published&sort=name"
----

[cols="2,3",options="header"]
|===
| 엔드포인트 | 설명

| `GET /apis` | 목록·검색(`q`, `status`, `category`, `protocol`, `cert`, `owner`, `alert`, `sort`, `page`, `size`)
| `GET /apis/stats` | 상단 통계 카드 값
| `GET /apis/name-available?name=` | 식별자 사용 가능 여부
| `POST /apis/preview` | 스펙 미리보기(저장 안 함)
| `POST /apis` | API 등록(스펙 또는 수동)
| `GET·PATCH·DELETE /apis/{name}` | 상세 조회 / 개요·상태 수정 / 삭제(관리자)
| `POST /apis/{name}/specs` | 새 스펙 버전 등록
| `POST /apis/{name}/endpoints`, `PATCH·DELETE …/endpoints/{ep_id}` | 수동 API 엔드포인트 관리
| `POST /apis/invoke` | Try-it 호출(서버 경유)
| `GET /apis/{name}/diff?from=&to=` | 스펙 버전 비교
| `GET /apis/{name}/lint?spec_id=` | 린팅
| `GET /apis/{name}/alerts`, `POST …/alerts/{id}/ack` | Breaking 알림 조회·확인
| `GET /apis/{name}/usage?days=`, `GET …/invocations` | 관측 통계·호출 기록
| `GET·POST /apis/{name}/lineage`, `GET …/lineage/incoming`, `DELETE …/lineage/{edge_id}` | 리니지
| `GET·POST /apis/{name}/credentials`, `DELETE …/credentials/{id}` | 자격증명
| `GET·POST·DELETE /apis/{name}/favorites`, `GET /apis/favorites` | 즐겨찾기
| `GET /apis/{name}/status-history` | 상태 변경 이력
|===
