= AI Agent 카탈로그
:toc: macro
:toclevels: 2

사내에서 운영하는 AI 에이전트(LLM 기반 자동화 · 어시스턴트 등)를 한곳에 등록해 관리하는 화면입니다.
누가 책임지는지, 어떤 도구와 MCP 서버를 쓰는지, 어떤 데이터에 의존하는지, 실제로 얼마나 호출되는지를 한눈에 볼 수 있습니다.
에이전트가 쓰는 MCP 서버 자체의 승인 정책과 감사는 xref:governance/mcp-server-catalog.adoc[MCP Server 카탈로그] 에서 다룹니다.

이 문서는 처음 사용하는 분을 기준으로 화면(메뉴) 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **에이전트 등록** — 화면에서 하나씩, 또는 정의 파일 · CSV · A2A 소개 정보로 한꺼번에 등록합니다.
* **책임자와 정보 품질 관리** — 소유자가 없거나 정보가 부족한 에이전트를 찾아 채웁니다.
* **도구 · MCP 연결 관리** — 에이전트가 쓰는 도구와 위험도, 연결한 MCP 서버를 기록합니다.
* **통제 정책 정하기** — PII 처리 · 사람 승인(HITL) · 예산 같은 정책을 적으면 실행 환경이 받아 가서 집행합니다.
* **사용 현황 보기** — 실행 환경이 보낸 호출 수 · 오류율 · 비용을 봅니다.
* **그림자 에이전트 찾기** — 실행 기록에는 있지만 카탈로그에 없는 에이전트를 찾아 등록합니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| 실행 환경
| 에이전트를 실제로 돌리는 런타임이나 게이트웨이입니다. 카탈로그에서 정책을 받아 가고, 호출 기록을 보내 줍니다.

| 정책 번들
| 도구 · MCP 연결 · 거버넌스 값을 묶어 실행 환경에 내려 주는 정책 묶음입니다.

| 사람 승인(HITL)
| 중요한 작업을 하기 전에 사람이 승인해야 하도록 하는 설정입니다.

| 정의 파일
| 에이전트 정보를 적은 YAML 파일(`agent.yaml`)입니다. 정의 파일로 반영한 에이전트는 파일 내용이 기준이 됩니다.

| A2A 에이전트 카드
| 에이전트끼리 서로를 소개할 때 쓰는 표준 정보(Agent-to-Agent)입니다.

| 미등록 에이전트
| 실행 기록에는 나왔지만 카탈로그에 없는 에이전트입니다.
|===

=== 메뉴 위치

[cols="1,2,3",options="header"]
|===
| 메뉴 | 주소 | 용도

| AI 카탈로그 → AI Agent | `/dashboard/ai-agents` | 에이전트 목록 · 등록 · 미등록 에이전트
| 에이전트 상세 | `/dashboard/ai-agents?agent=<이름>` | 상세 화면. 주소로 바로 열 수 있어 링크로 공유하기 좋습니다.
|===

=== 누가 무엇을 할 수 있나요

화면을 쓰려면 로그인해야 하고, 권한 관리에서 이 메뉴가 열려 있어야 합니다.

[cols="1,3",options="header"]
|===
| 작업 | 할 수 있는 사람

| 조회
| 로그인한 사용자 누구나
| 에이전트 등록, 정의 파일 적용, 에이전트 카드 가져오기, 미등록(발견) 항목 등록
| 기능 권한 **AI Agent 등록**(`agents.register`)이 있는 사용자(권한 관리에서 설정하지 않았으면 로그인한 사용자 누구나). 권한이 없으면 등록 버튼이 보이지 않습니다.
| 수정 · 삭제, 도구 · MCP · 리니지 · 버전 · 평가 추가/삭제
| 관리자, 그 에이전트를 등록한 사람, **소유자 이메일** 에 적힌 사람(대소문자 무시)
| 상태를 **차단** 으로 바꾸거나 차단 해제
| 관리자만
| 미등록 에이전트 **무시** · **되돌리기**
| 관리자만
|===

권한이 없는 사용자에게는 편집 · 삭제 버튼이 보이지 않고 상태도 배지로만 표시됩니다.

=== 지표 카드

목록 위 지표 카드는 지금 손봐야 할 곳을 알려 줍니다. 카드를 누르면 그 조건으로 목록이 걸러집니다.

[cols="1,3",options="header"]
|===
| 카드 | 의미

| 에이전트
| 등록된 에이전트 수입니다.
| 호출 (24시간) · 오류율 (24시간)
| 실행 환경이 보고한 최근 24시간 호출 수와 실패 비율입니다.
| 사람 승인(HITL) 필요
| 중요 액션에 사람 승인이 필요한 에이전트 수입니다.
| 승인 없는 고위험 도구
| 위험도가 높은데 **승인 필요** 가 꺼진 도구 수입니다.
| 미등록 MCP 연결
| MCP Server 카탈로그에 없는, 주소만 직접 입력한 연결 수입니다. 아래 <<_mcp_서버_연결>> 에서 카탈로그 배포로 승격합니다.
| 미등록 에이전트
| 실행 기록에는 나왔지만 카탈로그에 없는 에이전트 수입니다. <<_미등록_에이전트>> 를 참고하세요.
| 책임자 확인 필요
| 소유자가 없거나, 사용자 목록에 없거나, 비활성 계정인 에이전트 수입니다.
| 정보 부족
| 정보 완성도가 낮은 에이전트 수입니다.
|===

=== 검색 · 필터 · 정렬

[cols="1,3",options="header"]
|===
| 도구 | 설명

| **AI Agent 검색...**
| 이름 · 표시명 · 설명으로 찾습니다. 입력 후 Enter 를 칩니다.
| **전체 상태**
| 초안 · 스테이징 · 활성 · 차단 · 사용 중단 · 폐기 중 하나로 좁힙니다.
| **위험도 전체**
| 에이전트가 가진 도구의 최고 위험도 기준으로 좁힙니다(예: 매우 높음 이상).
| **책임자 전체**
| 소유자 없음 · 사용자 목록에 없음 · 비활성 계정 · 확인 필요(전부)로 좁힙니다.
| **관리 방식 전체**
| **화면** 에서 등록, **정의 파일** 로 관리, 실행 기록에서 **발견** 되어 등록된 것을 구분합니다.
| 소유자 이메일 · 부서 · 태그
| 부서는 쉼표로 여러 개, 태그는 쉼표로 적은 것을 모두 가진 에이전트만 남깁니다. **내 것** 은 본인이 소유한 에이전트만 보여 줍니다.
| 정렬
| 최근 갱신 · 이름 · 완성도 낮은/높은 · 위험도 높은 · 호출 많은 · 최근 호출 순으로 바꿉니다.
| **조건 초기화**
| 검색어와 필터를 모두 지웁니다.
|===

소유자 칸 아래에는 책임자 상태(**소유자 없음** · **사용자 목록에 없음** · **비활성 계정**)가 표시됩니다.
**완성도** 막대와 **최고 위험도** 로 정보가 부족하거나 위험한 에이전트를 바로 알아볼 수 있습니다.

오른쪽 위 **카드 보기** / **테이블 보기** 로 보는 방식을 바꿉니다.

image::governance-ai-agent-catalog/card-view.png[카드 보기, 900]

=== 저장된 보기

자주 쓰는 필터 · 정렬 · 검색어 조합을 저장해 두고 다시 불러옵니다.

. 원하는 조건을 맞춘 뒤 **현재 조건 저장** 을 누르고 이름을 붙입니다.
. 다른 사람과 같이 쓰려면 **모두에게 공유** 를 켭니다.
. 다음부터는 **보기 선택**(공유된 것은 **공유 보기**)에서 고릅니다.

공유 보기를 고치거나 지우는 것은 만든 사람과 관리자만 할 수 있습니다.

image::governance-ai-agent-catalog/save-view.png[현재 조건을 보기로 저장, 500]

=== 부서별 정보 품질

**부서별 정보 품질** 을 펼치면 부서마다 에이전트 수 · 평균 완성도 · 누락 수 · 책임자 확인 필요 수를 보여 줍니다.
부서 행을 누르면 그 부서 에이전트로 목록이 걸러집니다.

image::governance-ai-agent-catalog/department-quality.png[부서별 정보 품질, 900]

=== 일괄 변경

여러 에이전트의 상태 · 소유자 이메일 · 부서 · 분류 · 태그(추가 · 빼기)를 한꺼번에 바꿉니다.

. 행 왼쪽 선택 칸으로 에이전트를 고릅니다.
. **선택 N개 일괄 변경** 을 누르고 바꿀 값을 적습니다.
. **미리 보기** 로 에이전트별 결과를 확인합니다. 미리 보기를 해야 **반영** 버튼이 켜집니다.
. **반영** 을 누릅니다.

image::governance-ai-agent-catalog/bulk-preview.png[일괄 변경 미리 보기, 900]

NOTE: 권한이 없는 에이전트가 섞여 있으면 그 에이전트만 실패로 표시됩니다. 정의 파일로 관리되는 에이전트는
"다음 반영 때 되돌아갑니다" 안내가 붙습니다. 원본 정의 파일을 고쳐야 값이 유지됩니다.

== 에이전트 등록

에이전트를 카탈로그에 올리는 방법은 네 가지입니다. 처음이라면 **화면에서 등록** 부터 해 보세요.

[cols="1,3",options="header"]
|===
| 방법 | 언제 쓰나

| 화면에서 **에이전트 등록**
| 한두 개를 직접 등록할 때
| **가져오기** — 정의 파일(YAML) · 표 형식 파일(CSV)
| 여러 에이전트를 한 번에 만들고 고칠 때. 이후 파일 기준으로 관리됩니다.
| **가져오기** — A2A 소개 정보 불러오기
| 에이전트가 `/.well-known/agent-card.json` 을 내놓고 있을 때
| 명령줄 도구(`argus-catalog agent-apply`)
| 정의 파일을 Git 저장소에 두고 CI 에서 반영할 때(아래 고급 상자 참고)
|===

=== 화면에서 등록

. 목록 오른쪽 위 **에이전트 등록** 을 누릅니다.
. 아래 항목을 채웁니다.
. 저장합니다. 처음에는 상태를 **초안** 으로 두고, 검토 후 **활성** 으로 바꾸는 것을 권합니다.

image::governance-ai-agent-catalog/add-dialog.png[AI Agent 등록, 500]

[cols="1,3",options="header"]
|===
| 항목 | 설명

| 이름 (고유 식별자)
| 카탈로그 안에서 유일한 이름입니다. 만든 뒤에는 바꿀 수 없습니다. 정의 파일로 관리하려면 영문 소문자 · 숫자 · `.` `-` `_` 만 씁니다(예: `cs.refund-helper`).
| 표시명 · 설명
| 목록과 검색 결과에 보이는 이름과 설명입니다.
| 소유자 이메일 (필수)
| 이 에이전트를 책임지는 사람입니다. 로그인한 사용자의 이메일이 미리 채워집니다.
| 부서 (필수) · 분류 (필수)
| 부서는 로그인 사용자의 소속 부서가 미리 채워집니다. 분류는 `assistant`, `customer-service` 처럼 용도를 적습니다.
| 상태
| 처음에는 보통 **초안** 으로 두고, 검토 후 **활성** 으로 바꿉니다.
|===

=== 정의 파일 · 표 형식 파일 가져오기

. 목록 오른쪽 위 **가져오기** 를 누르면 **정의 파일 가져오기** 대화상자가 열립니다.
. 정의 파일(`agent.yaml`, 여러 개 가능)이나 표 형식 파일(`.csv`)을 고르거나, 내용을 직접 붙여 넣습니다. CSV 양식은 **표 형식 양식 내려받기** 로 받을 수 있습니다.
. **미리 보기** 를 눌러 결과(생성 · 갱신 · 변경 없음 · 실패)를 확인합니다. 미리 보기를 해야 **반영** 이 켜집니다.
. **반영** 을 누릅니다.

image::governance-ai-agent-catalog/import-dialog.png[정의 파일 가져오기, 700]

처음 보는 항목이나 빠진 필수 항목이 있는 문서는 **실패** 와 사유가 표시되고, 나머지 문서만 반영됩니다.

image::governance-ai-agent-catalog/import-preview.png[미리 보기 — 변경 없음과 실패, 700]

[IMPORTANT]
====
정의 파일로 반영된 에이전트는 목록의 **관리 방식** 이 **정의 파일** 로 표시되고, 상세 화면 위에 파란 안내
("정의 파일로 관리됩니다 … 마지막 반영 …")가 나옵니다. 화면에서 고친 값은 다음 반영 때 파일 내용으로 되돌아가므로
**원본 파일을 고치는 것이 원칙입니다.**
====

image::governance-ai-agent-catalog/managed-notice.png[정의 파일로 관리되는 에이전트 상세, 900]

상세 화면 오른쪽 위 **정의 파일 보기** 는 현재 내용을 정의 파일 형식으로 보여 주며, **복사** · **내려받기** 할 수 있습니다.
기존 에이전트를 파일 관리로 옮기거나 다른 환경에 옮길 때 씁니다.

image::governance-ai-agent-catalog/manifest-view.png[정의 파일 보기, 600]

  tags: [환불, 결제]
spec:
  description: 환불 문의 처리
  version: 1.0.0
  status: active
  model:
    name: gpt-4o
  runtime:
    framework: langgraph
  interface:
    endpoint: https://agents.corp.example/refund
  tools: []
  mcpServers: []
  lineage: []
----

=== A2A 소개 정보 불러오기

에이전트가 A2A 에이전트 카드를 내놓고 있으면 그 정보를 읽어 등록 내용을 자동으로 채울 수 있습니다.

. **가져오기** 대화상자의 주소 칸에 에이전트 주소(예: `https://agents.corp.example/refund`)를 넣습니다.
. **소개 정보 불러오기** 를 누릅니다. A2A 에이전트 카드(`/.well-known/agent-card.json` 또는 `agent.json`)를 읽어 정의 내용을 채워 줍니다.
. 카드에 없는 필수 항목(소유자 · 분류 등)은 노란 안내로 알려 줍니다. 채운 뒤 **미리 보기** → **반영** 합니다.

image::governance-ai-agent-catalog/card-loaded.png[소개 정보 불러오기, 700]

NOTE: 루프백 주소(`127.0.0.1` 등)나 클라우드 메타데이터 주소(`169.254.169.254`)는 보안 정책으로 차단됩니다.

[TIP]
.고급 사용자 — 명령줄 도구로 반영하기
====
SDK 의 `argus-catalog` 명령으로 디렉터리의 정의 파일을 한 번에 반영합니다. 실행 전에 `ARGUS_SERVER`,
`ARGUS_USERNAME`, `ARGUS_PASSWORD` 환경변수로 접속 정보를 줍니다.

[source,bash]
----
argus-catalog agent-apply -f agents/ --source my-repo --dry-run   # 미리 보기 (저장 안 함)
argus-catalog agent-apply -f agents/ --source my-repo             # 반영
argus-catalog agent-apply -f agents/ --source my-repo --prune     # 파일에서 빠진 에이전트는 '사용 중단'
argus-catalog agent-export cs.refund-helper -o exported/          # 정의 파일로 내보내기
----

* `--source` 는 정의 파일의 출처 이름으로, 상세 화면에 `my-repo#agents/a.yaml` 처럼 파일 위치가 표시됩니다.
* `spec.release.systemPromptFile` 로 지시문 파일을 지정하면 버전 기록에 그 내용이 함께 남습니다.
* 파일 하나라도 깨져 있으면 `--prune` 정리는 건너뛰고 종료 코드 1 로 끝납니다.
====

== 미등록 에이전트

실행 환경이 호출 기록이나 훅 이벤트를 보냈는데 카탈로그에 없는 이름이면 **미등록 에이전트** 탭에 쌓입니다.
몰래 쓰이는 "그림자 에이전트"를 찾아 책임자를 정하는 곳입니다.

image::governance-ai-agent-catalog/discoveries.png[미등록 에이전트 탭, 900]

행마다 상태(처리 전 · 등록됨 · 무시), 기록 수, 처음 · 마지막 발견 시각, 보낸 계정 · 호출자가 표시됩니다.

* **등록** — 대화상자에서 소유자 이메일 · 부서 · 분류를 채워 **초안** 으로 등록합니다. 등록된 에이전트의 **관리 방식** 은
  **발견** 이고, 상세 위에 "실행 기록에서 발견되어 등록된 에이전트입니다." 안내가 붙습니다.
* **무시** · **되돌리기** — 관리자만 할 수 있습니다. 무시한 항목은 상태 선택에서 **무시** 를 골라야 보입니다.

[[_실행_환경_연동]]
== 부록: 실행 환경 연동 API

에이전트 런타임이나 게이트웨이는 아래 API 로 카탈로그와 연동합니다. 기본 경로는 `/api/v1/ai-agents` 이며,
**모든 호출에 로그인 토큰(`Authorization: Bearer <토큰>`)이 필요합니다**. 토큰이 없으면 401 입니다.
실행 환경용 계정을 만들어 그 계정으로 로그인한 토큰을 쓰세요.

[cols="2,3",options="header"]
|===
| 엔드포인트 | 설명

| `GET /ai-agents/{name}/policy`
| 정책 번들을 받습니다. 응답의 `ETag` 를 다음 요청의 `If-None-Match` 로 보내면 바뀐 것이 없을 때 304 를 받습니다(`Cache-Control: no-cache`).
| `POST /ai-agents/{name}/invocations`
| 호출 기록(`status`=success/error · 소비자 · 지연 · 토큰 · 비용)을 보냅니다. **관측·비용** 탭과 목록의 호출 지표에 반영됩니다.
| `POST /ai-agents/{name}/hook-events`
| 집행 결과(허용 · 거부 · 마스킹 등)를 보냅니다. **집행(연동)** 탭에 표시됩니다.
| `GET /ai-agents/{name}/card`
| A2A 에이전트 카드를 받습니다.
|===

카탈로그에 없는 이름으로 호출 기록이나 훅 이벤트를 보내면 <<_미등록_에이전트>> 로 쌓입니다.

[source,bash]
----
# 정책 번들 — 바뀌었을 때만 다시 받기
curl -s -D h.txt -H "Authorization: Bearer $TOKEN" $CATALOG/api/v1/ai-agents/cs.refund-helper/policy > policy.json
ETAG=$(grep -i '^etag:' h.txt | cut -d' ' -f2 | tr -d '\r')
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" -H "If-None-Match: $ETAG" \
  $CATALOG/api/v1/ai-agents/cs.refund-helper/policy          # 304

# 호출 기록 보내기
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  $CATALOG/api/v1/ai-agents/cs.refund-helper/invocations \
  -d '{"status":"success","consumer":"svc-a","latency_ms":120,"input_tokens":300,"output_tokens":120,"cost":0.002}'
