= 데이터 표준
:toc: macro
:toclevels: 2

"고객 전화번호"를 누구는 `cust_tel`, 누구는 `customer_phone_no` 로 적는다면 데이터는 금세 제멋대로가 됩니다.
**데이터 표준** 메뉴는 조직의 명명 규칙을 **표준 사전**으로 정리해 두고, 실제 데이터셋 컬럼이 그 규칙을 얼마나 잘 지키는지(**준수율**)를 자동으로 재 줍니다.

이 문서는 처음 사용하는 분을 기준으로 화면(메뉴) 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **사전 만들기** — 본사·자회사·프로젝트처럼 쓰임새별로 표준 사전을 여러 개 둘 수 있습니다.
* **단어·도메인 정리** — "고객", "번호" 같은 단어와 "번호는 `VARCHAR(20)`" 같은 데이터 타입 규칙을 등록합니다.
* **용어 자동 생성** — "고객번호"라고만 입력하면 단어로 쪼개 영문명·약어·물리명(`cust_no`)과 도메인을 자동으로 추천합니다.
* **코드 관리** — 성별(M/F)처럼 정해진 값만 써야 하는 항목의 허용 값을 관리합니다.
* **데이터셋 매핑과 준수율** — 데이터셋 컬럼을 표준 용어와 연결하고, 표준과 일치하는 비율을 봅니다.
* **변경 이력** — 누가 언제 무엇을 바꿨는지 사전 단위로 확인합니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| 표준 사전
| 단어·도메인·용어·코드를 담는 상자입니다. 화면 맨 위 **사전** 선택에서 고른 사전 안에서 모든 작업이 이뤄집니다.

| 단어
| 용어를 이루는 가장 작은 단위입니다. 예: 고객(`CUST`), 전화(`TEL`), 번호(`NO`).
유형은 **일반 / 접미사 / 접두사** 세 가지이며, "번호·명·코드·일자"처럼 끝에 붙어 데이터 성격을 정하는 단어를 **접미사**로 둡니다.

| 도메인
| 데이터 타입 규칙입니다. 예: 도메인 "번호" = `VARCHAR(20)`.

| 용어
| 단어를 조합한 표준 이름입니다. 예: "고객번호" → 약어 `CUST_NO`, 물리명 `cust_no`, 도메인 "번호".

| 코드 그룹 / 코드 값
| 정해진 값의 목록입니다. 예: 코드 그룹 "성별" → `M` 남성, `F` 여성.

| 매핑
| 데이터셋 컬럼과 표준 용어의 연결입니다. 상태는 **일치(매칭) / 유사 / 위반 / 미연결(미매핑)** 으로 나뉩니다.

| 준수율
| 매핑 대상 컬럼 중 표준과 **일치**하는 컬럼의 비율입니다.
|===

`standards.edit` 는 **권한 관리** 메뉴의 기능(FEATURE) 권한입니다. 아무 역할에도 지정하지 않으면 **관리자만** 편집할 수 있고,

== 표준 사전

**거버넌스 → 데이터 표준** 을 누르면 화면 맨 위에 **사전** 선택 상자가 있습니다. 사전을 고르면 오른쪽 위에 그 사전의 단어·도메인·용어·코드 개수가 나오고,
아래 여섯 개 탭에서 작업합니다.

image::governance-standards/dictionary.png[사전 선택과 편집·삭제·새 사전 버튼, 800]

[cols="1,4",options="header"]
|===
| 탭 | 내용
| 단어 | 표준 단어 목록·편집
| 도메인 | 데이터 타입 규칙 목록·편집
| 용어 | 표준 용어 목록·검색, 형태소 분석으로 용어 추가
| 코드 | 코드 그룹과 코드 값
| 준수율 | 이 사전을 적용한 데이터셋의 표준 준수율
| 변경 이력 | 사전 안에서 일어난 추가·수정·삭제 기록
|===

=== 사전 만들기·고치기

. **새 사전** 을 누릅니다.
. **이름**, **버전**(예: `1.0`), **설명** 을 적고 **생성** 을 누릅니다. 이름은 카탈로그 전체에서 하나만 쓸 수 있습니다.
. 사전 선택 상자에서 새 사전을 고릅니다.

이름·버전·설명을 고칠 때는 사전을 고른 상태에서 **편집** 을 누릅니다.

=== 사전 삭제

**삭제** 를 누르면 지워질 단어·도메인·용어·코드 그룹 개수를 보여 주는 확인 창이 뜹니다. 사전을 지우면 그 안의 모든 항목과 데이터셋 매핑이 함께 지워지니 신중히 사용하세요.

image::governance-standards/dictionary-delete.png[사전 삭제 확인 — 함께 지워질 항목 수, 800]

== 단어 탭

용어를 만들기 전에 먼저 단어를 등록합니다. 표의 칸을 더블클릭하면 바로 고칠 수 있고, Enter 를 누르면 저장됩니다.

image::governance-standards/words.png[단어 탭 — 고객·번호(접미사)·전화, 800]

[cols="1,3",options="header"]
|===
| 칸 | 설명
| 이름 (한글) | 예: 고객. 같은 사전 안에서 하나만 쓸 수 있습니다
| 영문 / 약어 | 예: Customer / `CUST`. 약어가 물리명을 만드는 재료가 됩니다
| 유형 | 일반 / 접미사 / 접두사. **접미사 단어는 도메인 추천의 기준**이 됩니다(<<_형태소_분석으로_용어_추가>>)
| 금칙어 | "예" 로 두면 쓰지 말아야 할 단어로 표시됩니다(빨간 글씨)
| 동의어 그룹 | 같은 번호를 준 단어끼리 같은 뜻으로 묶습니다. 금칙어가 쓰이면 같은 그룹의 표준 단어를 대신 쓰도록 안내합니다
| 설명 | 자유 메모
| 용어 | 이 단어를 쓰는 용어 수(읽기 전용)
| 상태 | 활성 / 비활성. 비활성 단어는 형태소 분석에 쓰이지 않습니다
|===

=== 행 추가와 고치기

오른쪽 위 **추가** 를 누르면 `(new)` 라는 임시 이름의 행이 생깁니다. 이 행의 칸을 고쳐 실제 단어로 바꾸면 됩니다.
연달아 누르면 `(new 2)`, `(new 3)` … 으로 계속 추가되므로 여러 단어를 한꺼번에 준비할 수 있습니다. 도메인·코드 그룹 탭의 **추가** 도 똑같이 동작합니다.

image::governance-standards/add-new-rows.png[추가를 두 번 누른 모습 — (new), (new 2), 800]

이미 있는 이름으로 바꾸는 등 저장할 수 없는 값을 넣으면 경고가 뜨고 칸이 **원래 값으로 되돌아갑니다**. 화면에 남은 값은 언제나 서버에 저장된 값과 같습니다.

image::governance-standards/cell-dup-revert.png[중복 이름으로 바꾸면 경고 후 원래 값으로 복원, 800]

행 끝의 휴지통 버튼으로 삭제합니다. 단어를 지우면 그 단어로 만든 용어의 **구성 단어 연결만** 끊기고 용어 자체는 남습니다.

== 도메인 탭

도메인은 "이 성격의 데이터는 이런 타입으로 저장한다"는 규칙입니다. **도메인 이름, 그룹, 데이터 타입, 길이, 정밀도, 스케일, 코드 그룹, 설명** 을 적습니다.

image::governance-standards/domains.png[도메인 탭 — 번호 VARCHAR(20), 800]

TIP: 도메인 이름을 **접미사 단어와 같은 이름**으로 지어 두세요. 예를 들어 접미사 단어 "번호"와 도메인 "번호"를 함께 만들어 두면, "고객번호"·"주문번호" 같은 용어를 만들 때 도메인 "번호"가 자동으로 추천됩니다.

코드형 도메인(예: 성별 코드)은 **코드 그룹** 칸에서 허용 값 목록을 연결합니다. 도메인을 지우면 그 도메인을 쓰던 용어는 남고 도메인 연결만 비워집니다.

== 용어 탭

용어 탭에는 표준 용어가 **용어 이름, 영문, 약어, 물리명, 도메인, 타입, 구성 단어, 매핑 수, 상태** 와 함께 나옵니다.
위쪽 검색창에서 용어명·물리명·영문명으로 찾을 수 있습니다.

image::governance-standards/terms.png[용어 탭 — '고객' 검색 결과 2건, 800]

=== 형태소 분석으로 용어 추가

. 용어 탭에서 **추가** 를 누르면 **용어 추가 (형태소 분석)** 창이 열립니다.
. **용어 이름(한글)** 에 `고객번호` 처럼 붙여 쓴 이름을 넣고 **분석** 을 누릅니다.
. 사전의 단어로 쪼갠 결과와 함께 **영문, 약어, 물리명, 추천 도메인**이 채워집니다. 물리명과 도메인은 필요하면 직접 고칠 수 있습니다.
. **용어 저장** 을 누르면 용어 목록에 추가됩니다.

image::governance-standards/term-analyze.png[고객번호 분석 — 고객(CUST)+번호(NO), CUST_NO / cust_no, 도메인 번호 · VARCHAR(20), 800]

사전에 없는 글자가 있으면 **사전에 없는 부분**으로 강조해 보여 줍니다. 이때는 단어 탭에 빠진 단어를 먼저 추가하고 다시 분석하세요.

image::governance-standards/term-analyze-unmatched.png[고객명 분석 — 사전에 없는 부분 '명' 강조, 800]

[TIP]
.고급 사용자 — 분석 규칙
====
* 사전의 **활성** 단어를 **가장 긴 이름부터** 용어 앞에서부터 맞춰 잘라 냅니다(greedy longest-match). 맞지 않은 글자는 한 글자씩 "사전에 없는 부분"이 됩니다.
* 영문 = 단어 영문명을 공백으로 연결(`Customer Number`), 약어 = 단어 약어를 `_` 로 연결(`CUST_NO`), 물리명 = 약어를 소문자로(`cust_no`).
* 추천 도메인 = 분해 결과 중 **마지막 접미사 단어와 이름이 같은** 활성 도메인입니다. 없으면 추천하지 않습니다.
* API: `GET /api/v1/standards/terms/analyze?dictionary_id=<사전 ID>&term_name=고객번호` — 저장하지 않고 분석 결과만 돌려줍니다.
====

=== 용어 고치기·삭제

다른 탭과 마찬가지로 셀을 더블클릭해 고치고, 행 끝의 휴지통으로 삭제합니다. 용어를 지우면 그 용어로 연결된 **데이터셋 컬럼 매핑도 함께 지워집니다**.

== 코드 탭

왼쪽에서 **코드 그룹**을 고르면 오른쪽에 그 그룹의 **코드 값**이 나옵니다.

. 코드 그룹 목록의 **추가** 로 그룹을 만들고 이름을 고칩니다(예: `성별`).
. 그룹을 고른 뒤 **값 추가** 로 값을 넣고 **코드**, **코드명**, **순서** 를 고칩니다. 연달아 누르면 `NEW1`, `NEW2` … 자리표시 값이 생깁니다.

image::governance-standards/code-values.png[값 추가를 두 번 누른 모습 — NEW1, NEW2, 800]

같은 그룹 안에서 이미 있는 코드로 바꾸려 하면 "코드 'M' 이(가) 이미 이 그룹에 있습니다." 경고가 뜨고 원래 값으로 돌아갑니다. 필수 칸(코드·코드명·순서)을 비워도 "값을 입력하세요." 안내 후 되돌아갑니다.

image::governance-standards/code-value-dup.png[같은 그룹의 기존 코드로 바꾸면 경고 후 복원, 800]

== 데이터셋에 표준 적용하기

데이터셋 상세의 **표준 용어** 탭에서 컬럼을 표준 용어와 연결합니다. 자기 데이터셋(생성자)이거나 관리자일 때 매핑 버튼이 보입니다.

image::governance-standards/dataset-automap.png[데이터셋 표준 용어 탭 — 자동 매핑 결과와 준수도, 800]

=== 자동 매핑

. **사전** 에서 적용할 사전을 고릅니다. 고른 사전은 이 데이터셋의 **기본 사전**으로 저장되어, 다른 화면에 다녀와도 그대로 유지됩니다.
. **자동 매핑** 을 누릅니다. 결과 요약(신규·갱신·일치·위반·미매핑 건수)이 버튼 옆에 나옵니다.
. 컬럼마다 상태 배지가 붙고, 위쪽 **준수도** 막대에 비율이 나옵니다. 위반 컬럼은 아래 **표준 위반** 상자에 이유(실제 타입 → 표준 타입)가 적힙니다.

[cols="1,3",options="header"]
|===
| 상태 | 의미
| 일치 | 컬럼 이름이 용어 물리명과 같고, 타입도 표준 도메인과 맞음
| 위반 | 컬럼 이름은 용어 물리명과 같지만 타입이 표준 도메인과 다름(예: 표준 `VARCHAR(20)` 인데 실제 `INT`)
| 유사 | 사람이 직접 연결한 매핑(<<_수동_매핑>>)
| 미연결 | 맞는 용어가 없음
|===

자동 매핑은 여러 번 눌러도 결과가 같습니다(이미 맞는 매핑은 그대로 두고, 더 이상 맞지 않는 자동 매핑만 정리합니다).

[TIP]
.고급 사용자 — 자동 매핑 규칙
====
* 컬럼 이름과 용어 물리명이 (대소문자 무시) **완전히 같을 때만** 연결합니다. 비슷한 이름은 자동으로 연결하지 않습니다.
* 타입 비교는 계열 단위입니다: 문자(`VARCHAR·CHAR·TEXT·STRING…`), 정수(`INT·BIGINT·NUMBER…`), 실수(`DECIMAL·NUMERIC·FLOAT…`), 날짜(`DATE·TIMESTAMP…`).
* 수동 매핑(유사)과 다른 사전의 매핑은 자동 매핑이 건드리지 않습니다.
* API: `POST /api/v1/standards/mappings/auto-map?dictionary_id=<사전 ID>&dataset_id=<데이터셋 ID>`
====

=== 수동 매핑

이름이 달라 자동으로 연결되지 않는 컬럼은 **미연결** 행의 **용어 매핑** 을 눌러 용어를 직접 고릅니다. 이렇게 연결한 매핑은 **유사** 로 표시됩니다.

image::governance-standards/dataset-manual-mapping.png[memo 컬럼을 용어에 수동 연결 — 유사, 800]

매핑을 하나 지우려면 행의 × 를, 이 데이터셋의 매핑을 모두 지우려면 **매핑 초기화** 를 누릅니다.

NOTE: 준수율에는 **일치**만 들어갑니다. 수동으로 연결한 **유사** 매핑은 "표준과 같은 뜻이지만 이름이 다르다"는 기록이므로 준수율을 올려 주지는 않습니다.

== 준수율 탭

사전 화면의 **준수율** 탭은 **이 사전을 적용한 데이터셋**(이 사전 용어와 매핑된 컬럼이 있거나, 이 사전을 기본 사전으로 고른 데이터셋)의 전체 컬럼을 기준으로 계산합니다.

image::governance-standards/compliance.png[준수율 탭 — 전체 3, 매칭 1, 유사 0, 위반 1, 미매핑 1, 33.3%, 800]

----
준수율 = 일치(매칭) 컬럼 수 ÷ 대상 컬럼 수 × 100
----

숫자 아래 안내 문구("이 사전을 적용한 데이터셋 N개의 컬럼 M개 중…")로 계산 기준을 확인할 수 있습니다. 준수율이 낮다면 위반·미매핑 컬럼이 많은 데이터셋부터 표준 용어 탭을 열어 보세요.

== 변경 이력 탭

사전 안의 사전·단어·도메인·용어·코드 그룹·코드 값에 대한 **추가 / 수정 / 삭제** 가 최신순으로 쌓입니다. 바뀐 항목, 바뀐 필드, 이전 값과 새 값, **변경자**와 시각을 볼 수 있습니다.

image::governance-standards/history.png[변경 이력 탭 — 변경자 admin, 800]

== 자주 묻는 질문·문제 해결

[qanda]
"단어 '고객' 이(가) 이미 이 사전에 있습니다."라고 나옵니다.::
  같은 사전 안에서 단어·도메인·용어 이름은 하나만 쓸 수 있습니다. 다른 이름을 쓰거나, 기존 항목을 고치세요. 다른 사전에는 같은 이름을 둘 수 있습니다.

형태소 분석에서 도메인이 추천되지 않습니다.::
  용어의 마지막 단어가 **접미사** 유형인지, 그 단어와 **같은 이름의 도메인**이 있는지 확인하세요. 비활성 단어·도메인은 분석에 쓰이지 않습니다.

"사전에 없는 부분"이 표시됩니다.::
  그 글자를 담은 단어가 사전에 없습니다. 단어 탭에서 단어를 추가하고 다시 **분석** 하세요.

자동 매핑을 눌렀는데 아무 컬럼도 연결되지 않습니다.::
  컬럼 이름이 용어 물리명과 정확히 같아야 연결됩니다. 이름이 다르면 **용어 매핑** 으로 직접 연결하세요(유사).

자동 매핑·매핑 초기화 버튼이 없습니다.::
  데이터셋 매핑은 그 데이터셋을 만든 사람이나 관리자만 할 수 있습니다.

추가·편집 버튼이 보이지 않습니다.::
  사전 편집 권한(`standards.edit`)이 없는 경우입니다. 관리자에게 권한을 요청하세요.

셀을 고쳤는데 원래 값으로 돌아갑니다.::
  중복이거나 비어 있는 등 저장할 수 없는 값입니다. 함께 뜬 경고 문구를 확인하세요.

== 부록 — REST API 로 쓰기

화면에서 하는 작업은 REST API 로도 할 수 있습니다. 기본 경로는 `/api/v1/standards` 이며, 조회 · 변경 모두 로그인 토큰(`Authorization: Bearer <토큰>`)이 필요합니다.

[source,bash]
----
# 사전 목록
curl -H "Authorization: Bearer $TOKEN" "$CATALOG/api/v1/standards/dictionaries"
# 용어 분석(저장 안 함)
curl -H "Authorization: Bearer $TOKEN" "$CATALOG/api/v1/standards/terms/analyze?dictionary_id=1&term_name=고객번호"
----

[cols="2,3",options="header"]
|===
| 엔드포인트 | 설명

| `GET·POST /standards/dictionaries`, `GET·PUT·DELETE …/{id}` | 사전
| `GET·POST /standards/words`, `GET·PUT·DELETE …/{id}` | 단어(`dictionary_id`, `word_type` 필터)
| `GET /standards/{words·domains·terms·code-groups}/{id}/usage` | 삭제 전 영향(사용처) 확인
| `GET·POST /standards/domains`, `GET·PUT·DELETE …/{id}` | 도메인
| `GET·POST /standards/terms`, `GET·PUT·DELETE …/{id}` | 용어(`search` 검색)
| `GET /standards/terms/analyze` | 형태소 분석
| `GET·POST /standards/code-groups`, `GET·PUT·DELETE …/{id}`, `POST …/{id}/values`, `PUT·DELETE /standards/code-values/{id}` | 코드 그룹·코드 값
| `POST /standards/mappings/auto-map`, `POST /standards/mappings`, `DELETE …/{id}` | 자동·수동 매핑
| `GET /standards/mappings/dataset?dictionary_id=&dataset_id=` | 데이터셋 컬럼별 매핑 현황과 준수도
| `DELETE /standards/datasets/{id}/mappings?dictionary_id=` | 매핑 초기화
| `GET·PUT /standards/datasets/{id}/dictionary` | 데이터셋 기본 사전
| `GET /standards/compliance?dictionary_id=&dataset_id=` | 준수율
| `GET /standards/change-logs` | 변경 이력(`{items, total}`)
|===
