= MCP Server 카탈로그 — 감사와 정책 집행
:toc: macro
:toclevels: 2

이 페이지는 xref:governance/mcp-server-catalog.adoc[MCP Server 카탈로그] 의 심화 내용입니다.
MCP 서버가 카탈로그로 감사 로그를 보내게 하거나, 강제(enforce) 모드로 서버가 카탈로그 정책을 받아 직접 호출을 거부하게 하려는 운영자 · 개발자를 위한 내용입니다.
서버 등록, 승인 정책, finding 같은 기본 사용법은 본문 페이지를 먼저 보세요.

toc::[]

== 감사 이벤트

MCP 서버의 도구 호출 감사 로그를 받아 승인 정책으로 판정합니다. 배포 상세의 **감사 이벤트** 탭에서 다룹니다.

=== 감사 로그 보내기

. **감사 이벤트** 탭의 **서비스 토큰** 카드에서 **발급** 을 누릅니다. 토큰(`mcpi_…`)은 발급 직후 한 번만 보이므로 바로 복사합니다.
  다시 발급하면 기존 토큰은 즉시 무효가 됩니다.
. 서버(또는 로그 전송기)가 이 토큰을 `X-Argus-Ingest-Token` 헤더에 넣어 `POST /api/v1/mcp-deployments/{배포}/audit-events` 로
  감사 로그를 보냅니다. 카드에 예시 명령이 표시됩니다.
. 손으로 올릴 때는 **JSONL 업로드** 로 한 줄에 이벤트 하나인 파일을 올립니다. 결과에 받음 · 저장 · 중복 · 무효 · 위반 건수가 나옵니다.

image::governance-mcp-server-catalog/audit-upload.png[감사 로그(JSONL) 업로드, 600]

=== 감사 이벤트 읽기

목록은 판정(전체 · 위반만 · 서버가 거부 등)으로 거를 수 있습니다. 인자 중 비밀번호 같은 민감한 값은 `***` 로 가려 저장합니다.
위반 호출은 **승인 정책 위반 호출** finding 으로도 남습니다.

image::governance-mcp-server-catalog/audit-events.png[감사 이벤트 탭, 900]

[cols="1,3",options="header"]
|===
| 판정 | 의미

| 허용
| 승인 정책 안의 호출입니다.
| 범위 밖
| 승인 리소스 범위를 벗어난 호출입니다.
| 차단 도구
| 차단한 도구를 호출했습니다.
| 판정 불가
| 리소스를 알 수 없어 판정하지 못했습니다.
| 서버 거부
| 강제 모드에서 서버가 카탈로그 정책으로 호출을 거부했습니다. 어떤 에이전트의 호출이었는지도 표시됩니다.
|===

image::governance-mcp-server-catalog/server-denied.png[서버 거부 감사 이벤트, 900]

[[_서비스_토큰_폐기]]
=== 서비스 토큰 폐기

서비스 토큰을 더는 쓰지 않으면 **감사 이벤트** 탭의 **서비스 토큰** 카드에서 **폐기** 합니다. 폐기한 토큰으로는 감사 로그를 보내거나
정책 번들을 받을 수 없습니다.

[[_정책_집행_강제_모드]]
== 정책 집행 (강제 모드)

**승인 정책** 탭의 **정책 집행** 카드에서 서버가 정책을 받아 가는지 확인합니다.

* **번들 미리보기** — 서버가 받아 갈 정책 번들(그룹 on/off · 차단 도구 · 범위 · 제한값 · 에이전트별 허용 범위)을 미리 봅니다.
  미리보기는 pull 기록을 남기지 않습니다.
* **서버 설정** — Argus Forge MCP 서버 `config.yaml` 에 넣을 `catalog_policy` 설정 예시입니다. 서비스 토큰은 `ARGUS_CATALOG_TOKEN`
  환경변수로 줍니다. `fail_mode` 를 `closed` 로 두면 번들을 못 받을 때 변경 도구 호출을 거부합니다.

image::governance-mcp-server-catalog/bundle-preview.png[정책 번들 미리보기, 600]

image::governance-mcp-server-catalog/server-snippet.png[서버 설정 — 카탈로그 정책 pull, 600]

=== 강제 모드 켜기

. 위 **감사 로그 보내기** 의 1단계대로 서비스 토큰을 발급합니다. 강제 모드는 서비스 토큰이 있어야 저장됩니다.
. **서버 설정** 예시를 서버 `config.yaml` 에 넣고 토큰을 `ARGUS_CATALOG_TOKEN` 환경변수로 줍니다.
. **승인 정책** 탭에서 모드를 **강제(enforce)** 로 바꿔 저장합니다.

이후 서버가 서비스 토큰으로 `GET /api/v1/mcp-deployments/{배포}/policy-bundle` 을 주기적으로 받아 갑니다.
카드에는 마지막 pull 시각 · 받아 간 번들 버전 · 서버 인스턴스 · 연결 에이전트 수와 적용 상태 배지가 표시됩니다.

image::governance-mcp-server-catalog/enforce-applied.png[강제 모드 — 적용 상태, 900]

[cols="1,3",options="header"]
|===
| 적용 상태 | 의미

| 최신 적용
| 서버가 최신 번들을 받아 갔습니다.
| 이전 번들
| 정책이나 에이전트 범위가 바뀌었는데 서버가 아직 새 번들을 받아 가지 않았습니다.
| 오래 안 받아감
| 서버가 한동안 번들을 받아 가지 않았습니다. 서버 상태와 서비스 토큰을 확인합니다.
| 받아간 적 없음
| 강제 모드로 바꾼 뒤 아직 pull 이 없습니다. 강제 모드에서 pull 이 오래 없으면 **enforce 정책 미적용** finding 이 생깁니다.
|===

NOTE: 번들 응답에는 `ETag` 가 붙고, 같은 값을 `If-None-Match` 로 보내면 304 를 돌려줍니다.
