= 오류 신고 처리
:toc: macro
:toclevels: 2

**오류 신고 처리**는 데이터셋 댓글로 들어온 *오류 신고* · *개선 요청* 을 한곳에서 보고, 처리 기한을 넘긴 신고를 찾는 화면입니다.
행정안전부 · NIA 「공공데이터의 인공지능 친화적 관리 가이드라인」 V1.0 의 체크리스트 *C31*(오류 신고 · 개선 요청을 접수 · 처리하는 절차와
피드백 체계)에 대응합니다. 가이드라인은 "신고 후 10일 안에 수정 또는 소명"을 기준 예시로 듭니다.

toc::[]

== 시작하기 전에

=== 신고는 어떻게 들어오나요

이용자가 데이터셋 상세의 xref:catalog/datasets.adoc#help-dataset-comments[댓글 탭] 에서 분류를 *오류 신고* 나 *개선 요청* 으로 골라 댓글을 남기면
접수됩니다(답글은 접수되지 않습니다). 접수 시각에 xref:ops/settings.adoc#_ai_ready[설정 › AI-Ready] 의 *처리 기한* (기본 10일)을 더한 값이
기한으로 저장됩니다. 설정을 바꾸면 새로 접수되는 신고부터 적용됩니다.

=== 메뉴 위치

왼쪽 메뉴 **거버넌스 › 오류 신고 처리** (`/dashboard/data-reports`). 권한 관리에서 메뉴를 닫지 않았으면 누구나 볼 수 있습니다.

== 화면

* **상태 카드** — *미처리*(접수 · 처리 중) · *기한 넘김* · *끝남*(해결 · 소명) · *전체* 건수입니다. 카드를 누르면 목록이 그 상태로 바뀝니다.
  기한을 넘긴 신고가 있으면 *기한 넘김* 숫자가 빨갛게 보입니다.
* **분류** — *모든 분류* · *오류 신고* · *개선 요청* 으로 거릅니다.
* **범위** — *모든 신고* · *내 데이터셋*(내가 소유자 — 생성자이거나 소유자 목록에 오른 데이터셋) · *내가 낸 신고* 로 거릅니다.
  상태 카드의 건수도 이 범위를 따릅니다.
* **목록** — 데이터셋 경로(`db.dataset`), 분류, 내용 앞부분, 접수일 · 작성자, 상태, 기한입니다. 처리 결과나 소명이 있으면 내용 아래에 함께 보입니다.
  미처리 신고는 기한이 이른 순, 끝난 신고는 처리가 최근인 순입니다. 기한을 넘긴 행은 붉은 배경입니다.
* 데이터셋 경로를 누르면 그 데이터셋의 댓글 탭에서 그 신고가 있는 쪽이 열리고, 신고로 스크롤해 잠깐 강조합니다. 답글로 신고자와 이야기합니다.
* 처리할 수 있는 신고(내가 소유자인 데이터셋의 신고, 관리자는 모두)에는 줄 끝에 *처리* 단추가 있습니다. 댓글 탭의 *처리* 와 같은 대화상자입니다.

== 처리하기

처리는 데이터셋 소유자와 관리자가 이 화면의 *처리* 단추나 댓글 탭에서 합니다. 기능 권한 *오류 신고 처리* 가 있어야 합니다. 소유자는 데이터셋 생성자와 메타데이터 탭 *소유자* 목록에 오른 사용자로,
접수 · 기한 알림을 받는 사람과 같습니다. 상태와 처리 결과 · 소명은
xref:catalog/datasets.adoc#help-dataset-reports[댓글 탭 › 오류 신고 · 개선 요청 처리] 를 참고하세요.

[cols="1,3",options="header"]
|===
| 상태 | 뜻

| 접수 | 새로 들어온 신고
| 처리 중 | 확인하고 고치는 중
| 해결 | 데이터를 고침 — 처리 결과를 적어 둡니다
| 소명 | 고치지 않는 이유를 설명 — 사유 필수
|===

[TIP]
.고급 사용자 — API
====
`GET /api/v1/comments/reports?state=open|overdue|closed|all&category=bug|suggestion&dataset_id=…&mine=owned|reported&page=…`
(목록과 상태별 건수, 줄마다 처리할 수 있는지 `can_handle`. `mine` 은 로그인 필요),
`PUT /api/v1/comments/{댓글 ID}/status` (`{"status": "RESOLVED", "resolution": "…"}`, 데이터셋 소유자 · 관리자).
처리 상태는 `catalog_comments` 의 `status` · `due_at` · `resolved_at` · `resolution` · `handled_by` 에 있습니다.
특정 댓글로 가는 주소는 `/dashboard/datasets/{데이터셋 ID}?tab=comments&comment={댓글 ID}` 입니다(`GET /api/v1/comments?…&focus={댓글 ID}` 가 그 댓글이 있는 쪽을 돌려줍니다).
====

== 자주 묻는 질문

**기한을 넘기면 어떻게 되나요?**::
기한을 넘긴 미처리 신고가 하나라도 있는 데이터셋은 AI-Ready 체크리스트 C31 이 *미흡* 이 되고,
xref:governance/ai-ready.adoc[AI-Ready 점검] 의 필수 충족률이 내려갑니다. 해결하거나 소명하면 바로 적정으로 돌아옵니다.

**접수 · 기한을 알림으로 받을 수 있나요?**::
네. xref:governance/alerts.adoc[알림] 의 규칙 탭에서 트리거 *오류 신고·개선 요청 접수* 와 *신고 처리 기한 임박·넘김* 으로 규칙을 만듭니다.
기한 알림은 1시간마다 확인해 임박(기본 2일 전)이면 경고, 넘기면 치명으로 알립니다. 신고를 해결 · 소명하거나 지우면
그 신고의 접수 · 기한 알림이 그 자리에서 해결됩니다(처리자 `system`). 접수 알림은 신고마다 한 번만 옵니다 — 분류를 바꿨다 되돌려도 다시 오지 않습니다.
수신자는 규칙의 구독자와 데이터셋 소유자 · 생성자입니다. 알림 상세의 데이터셋 링크는 댓글 탭의 그 신고로 갑니다.

**신고한 사람이 처리 결과를 알 수 있나요?**::
댓글 탭의 신고 아래에 처리 결과 · 소명이 보이고, 이 화면의 *내가 낸 신고* 로 내 신고의 상태를 모아 봅니다.
알림으로 받으려면 관리자가 트리거 *신고 처리 결과 (신고한 사람에게)* 로 규칙을 만듭니다. 신고를 해결 · 소명할 때 바로 발행되고,
수신자는 규칙의 구독자와 **신고한 사람** 입니다(처리한 쪽인 데이터셋 소유자는 받지 않습니다). 처리 결과 문구만 고치면 다시 알리지 않고,
해결을 소명으로 바꾸면 새로 알립니다. 알림 목록은 사용자별 받은 편지함이 아니라 알림 메뉴를 볼 수 있는 사람이 함께 보는 목록이므로,
신고한 사람이 알림 메뉴 권한이 없으면 Webhook 채널(예: 메신저)로 받거나 *내가 낸 신고* 로 확인합니다.

**기능 요청도 접수되나요?**::
아니요. *기능 요청* 은 카탈로그 기능에 대한 요청이라 데이터 처리 대상이 아닙니다. *일반* 댓글도 접수되지 않습니다.
나중에 분류를 *오류 신고* 로 고치면 그때 접수되고, 기한은 처음 작성 시각부터 셉니다.

**해결된 신고의 분류를 바꿀 수 있나요?**::
아니요. 해결 · 소명된 신고는 분류를 바꾸면 처리 기록이 사라지므로 바꿀 수 없습니다(본문은 고칠 수 있습니다).
다른 내용이면 새 댓글로 남기고, 처리가 잘못됐으면 담당자가 *다시 열기* 한 뒤 바꿉니다.
