= MCP Server 카탈로그
:toc: macro
:toclevels: 2

AI 에이전트가 쓰는 MCP(Model Context Protocol) 서버를 등록하고 통제하는 화면입니다.
서버가 실제로 노출하는 도구 · 리소스 범위(**관측값**)와 운영자가 정한 기준(**승인 정책**)을 비교해, 어긋난 곳(**finding**)을 찾아 줍니다.

이 문서는 처음 사용하는 분을 기준으로 화면(메뉴) 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.
서버의 감사 로그 수집과 강제(enforce) 모드 정책 집행은 xref:governance/mcp-server-catalog-advanced.adoc[MCP Server 카탈로그 — 감사와 정책 집행] 에서 다룹니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **서버 등록** — 화면에서, 또는 `server.json` · `mcp.json` 을 붙여 넣어 MCP 서버를 등록합니다.
* **배포 관리** — DEV · PROD 처럼 실제로 띄운 서버(배포)를 등록하고 상태를 수집합니다.
* **승인 정책 정하기** — 켜도 되는 도구 그룹, 차단할 도구, 허용 리소스 범위, 제한값을 정합니다.
* **차이 찾기** — 정책과 실제 서버 상태가 다르면 finding 으로 알려 줍니다.
* **접근 미리 확인** — "이 리소스에 이 동작을 하면 허용되는가"를 시뮬레이터로 확인합니다.
* **에이전트별 통제** — 어떤 AI Agent 가 이 서버를 쓰는지 보고, 에이전트마다 범위를 더 좁힙니다.

=== 먼저 알아 둘 용어

.MCP 서버 배포·정책·감사 흐름
image::diagrams/governance-mcp-server-catalog-01.png[MCP 서버 배포·정책·감사 흐름,role="diagram"]

[cols="1,3",options="header"]
|===
| 용어 | 설명

| 서버 정의
| MCP 서버 "제품"입니다(예: `kafka-mcp`). 도구 · 도구 그룹 · 리소스 · 프롬프트, 버전 이력을 가집니다.
| 배포
| 서버 정의를 실제로 띄운 인스턴스입니다. 환경(DEV · PROD 등) · 엔드포인트 · 자격증명을 가지며, 승인 정책과 감사는 배포 단위로 관리합니다.
| 관측값
| 서버가 보고한 manifest(또는 수집)로 알게 된 실제 상태입니다. 어떤 도구 그룹이 켜져 있는지, 리소스 범위 · 제한값(limits) · 배포 버전 · 보안 경고 등입니다.
| 승인 정책
| 운영자가 "이렇게 돼 있어야 한다"고 정한 기준입니다. 관측값이 이를 벗어나면 finding 이 생깁니다.
| finding
| 승인 정책과 관측값의 차이, 헬스 실패, 정책 위반 호출 같은 점검 항목입니다. 심각도가 있고 **확인** 처리할 수 있습니다.
| 정책 번들
| 서버가 받아 가는 승인 정책 문서입니다. 강제(enforce) 모드에서 서버가 이 번들로 호출을 거부합니다.
|===

=== 누가 무엇을 할 수 있나요

[cols="1,3",options="header"]
|===
| 작업 | 할 수 있는 사람

| 조회(감사 이벤트 포함)
| 로그인한 사용자 누구나
| 서버 정의 등록 · 가져오기, 배포 등록
| 기능 권한 **MCP 서버·배포 등록**(`mcp.register`)이 있는 사용자(권한 관리에서 설정하지 않았으면 로그인한 사용자 누구나). 권한이 없으면 등록 버튼이 보이지 않습니다.
| 서버 정의 · 배포 수정, manifest 가져오기, 헬스 체크 · 수집, 서비스 토큰, 폐기
| 그 서버 · 배포를 등록한 사람 또는 관리자. 배포의 **소유자 이메일** 은 권한과 무관합니다.
| 배포 자격증명 저장 · 삭제
| 그 배포를 등록한 사람 또는 관리자이면서, 관리자가 아니면 기능 권한 **MCP 배포 자격증명 저장**(`mcp.credential`)이 역할에 명시적으로 허용돼 있어야 합니다(권한 관리에서 설정하지 않았으면 관리자만).
| 승인 정책 변경, 관측값 채택, 에이전트별 리소스 범위
| 위 조건에 더해, 관리자가 아니면 기능 권한 **MCP 승인 정책 변경**(`mcp.policy`)이 필요합니다(권한 관리에서 설정하지 않았으면 허용).
| Argus Forge 서버 정의 일괄 등록, 미등록 MCP 연결을 배포로 연결
| 관리자만
|===

권한이 없으면 버튼이 보이지 않고 입력이 비활성이며, 승인 정책 탭 아래에 "읽기 전용 — …" 안내가 표시됩니다.
접근 시뮬레이터 · 정책 이력 · server.json · 감사 이벤트 조회는 그대로 쓸 수 있습니다.

== 서버 정의 등록

**가져오기** 메뉴와 **서버 등록** 버튼으로 서버 정의를 만듭니다. 세 가지 방법이 있습니다.

image::governance-mcp-server-catalog/import-menu.png[가져오기 메뉴 (관리자), 900]

[cols="1,3",options="header"]
|===
| 방법 | 설명

| **서버 등록**
| 대화상자 **MCP 서버 정의 등록** 에서 이름(고유 식별자, 영문 소문자 · 숫자 · `.` `-` `_`) · 표시명 · 제공자 · 분류 등을 넣습니다.
| **가져오기 → server.json / mcp.json 가져오기**
| MCP Registry 의 `server.json`, 또는 클라이언트 설정 `mcp.json` 을 붙여 넣어 서버 정의(와 배포)를 만듭니다. **미리보기** 로 결과를 확인한 뒤 **가져오기** 합니다.
| **가져오기 → Argus Forge 서버 정의 일괄 등록 (관리자)**
| Argus Forge 가 제공하는 MCP 서버 정의(kafka-mcp 등)를 도구 · 그룹 정보와 함께 한 번에 등록합니다. 다시 실행하면 기존 정의를 갱신합니다.
|===

image::governance-mcp-server-catalog/register-dialog.png[MCP 서버 정의 등록, 500]

`mcp.json` 을 가져올 때 **배포 환경** 을 고르면 서버 정의와 함께 그 환경의 배포가 만들어집니다.
헤더 값(예: `Authorization: Bearer …`)은 저장하지 않고 키 이름만 기록합니다.

image::governance-mcp-server-catalog/mcp-json-import.png[server.json / mcp.json 가져오기, 600]

== 서버 정의 상세

목록에서 서버를 누르면 상세가 열립니다. 헤더에서 **편집** · **manifest** · **배포 등록** · **폐기** 를 합니다.

[cols="1,3",options="header"]
|===
| 탭 | 내용

| 개요
| 제공자 · 프레임워크 · 대상 플랫폼 · 패키지 등 기본 정보와 MCP Registry 메타데이터
| 도구 (N)
| 도구 목록입니다. 행을 펼치면 그룹 · 위험도 · 승인 필요 · 메모를 고칠 수 있고, 맨 아래 **도구 이름 (수동 등록)** 으로 도구를 직접 추가합니다.
| 리소스·프롬프트
| 서버가 제공하는 리소스와 프롬프트입니다. 직접 추가한 행은 휴지통 아이콘으로 지웁니다.
| 배포 (N)
| 이 서버 정의의 배포 목록입니다.
| 버전 이력
| 서버가 보고한 버전별 도구 목록 변화입니다.
| server.json
| MCP Registry `server.json` 형식으로 내보낸 문서입니다.
| 이력
| 상태 변경 이력입니다.
|===

image::governance-mcp-server-catalog/server-tools.png[서버 정의 — 도구 탭, 900]

도구는 **그룹**(예: 조회 `read`, 메시지 조회 `peek`, 토픽 관리 `topics`, 파괴적 작업 `destructive`)으로 묶이고,
변경 도구 여부와 위험도가 함께 표시됩니다. 승인 정책은 그룹 단위로 켜고 끄며, 특정 도구만 따로 차단할 수 있습니다.

== 배포 등록과 관측값 수집

=== 배포 등록

. 서버 정의 상세의 **배포 등록** 을 누릅니다.
. 배포 이름 · 환경 · 전송 방식 · MCP 엔드포인트 · 인증 방식을 넣고 저장합니다.
. 화면에서 등록한 배포는 **초안** 상태로 시작합니다. 운영에 들어가면 **편집** 에서 상태를 **활성** 으로 바꿉니다.

image::governance-mcp-server-catalog/deploy-dialog.png[MCP 배포 등록, 500]

=== 관측값 가져오기

서버의 실제 상태(관측값)는 다음 방법으로 들어옵니다. 카탈로그가 서버에 접속할 수 있으면 **수집** 이 가장 간단합니다.

[cols="1,3",options="header"]
|===
| 방법 | 설명

| **수집**
| 카탈로그가 배포 엔드포인트에 접속해 manifest 와 도구 목록을 읽어 옵니다. 서버가 인증을 요구하면 **자격증명** 탭에 토큰을 저장해 둡니다.
| **manifest**
| 서버가 보고한 manifest(`GET /api/v1/manifest` 응답)를 붙여 넣습니다. 카탈로그가 서버에 닿지 않는 망에서 씁니다.
| **설정 가져오기**
| Argus Forge 서버의 설정 파일(`config.yaml`)로 그룹 on/off · 범위를 추정합니다.
| **헬스 체크**
| 엔드포인트 응답 여부를 확인합니다. 연속으로 실패하면 **헬스 연속 실패** finding 이 생깁니다.
|===

image::governance-mcp-server-catalog/manifest-preview.png[manifest 가져오기 — 미리보기, 700]

반영하면 **개요** 탭에 배포 버전 · 인스턴스 ID · 제한값(limits) · 서버 보고 정보가 채워집니다.
서버가 보낸 보안 경고는 상세 위쪽 노란 **보안 경고** 상자에 표시됩니다.

image::governance-mcp-server-catalog/deployment-overview.png[배포 상세 — 개요 탭, 900]

=== 자격증명 저장

**자격증명** 탭에서는 수집 · 헬스 체크에 쓸 인증 정보(bearer 등)를 저장합니다. 저장한 비밀값은 다시 보여 주지 않고
마스킹해서 표시하며, 삭제할 때는 확인을 한 번 더 받습니다.
저장 · 삭제는 배포를 등록한 사람 또는 관리자만 할 수 있고, 관리자가 아니면 기능 권한 **MCP 배포 자격증명 저장**(`mcp.credential`)이 명시적으로 허용돼 있어야 합니다(설정하지 않았으면 관리자만).

image::governance-mcp-server-catalog/credential.png[자격증명 탭, 900]

== 실효 상태와 접근 시뮬레이터

=== 실효 상태

**실효 상태** 탭은 도구 그룹마다 서버 설정값(관측)과 승인 여부, 그리고 그 결과 실제로 노출되는 도구를 보여 줍니다.
꺼진 그룹의 도구는 노출되지 않습니다.

image::governance-mcp-server-catalog/effective.png[실효 상태 탭, 900]

=== 리소스 범위와 접근 시뮬레이터

**리소스 범위** 탭에는 서버 설정의 allow · protect 규칙이 표시됩니다. 아래 **접근 시뮬레이터** 로 "이 리소스에 이 동작을 하면 허용되는가"를 미리 확인할 수 있습니다.

. 기준을 관측 · 승인 · 둘 다 중에서 고릅니다.
. 리소스와 동작을 넣습니다. 에이전트를 지정하면 에이전트별 범위까지 적용합니다.
. 판정과 사유를 확인합니다.

image::governance-mcp-server-catalog/scopes.png[리소스 범위 탭과 접근 시뮬레이터, 900]

[cols="1,3",options="header"]
|===
| 규칙 효과 | 의미

| allow
| 이 패턴의 리소스만 허용합니다. allow 규칙이 있는데 패턴에 맞지 않으면 거부됩니다.
| deny
| 이 패턴의 리소스를 거부합니다.
| protect
| 보호 대상입니다. 다른 규칙보다 우선해 거부합니다(예: 내부 토픽 `__*`).
|===

규칙의 우선순위는 protect > deny > allow 목록 순입니다.

== 승인 정책 정하기

**승인 정책** 탭에서 배포가 지켜야 할 기준을 정합니다.

TIP: 처음 정책을 만들 때는 **관측값 채택** 이 편합니다. 지금 서버에서 관측된 값을 그대로 승인 기준선으로 가져오며,
도구 그룹 on/off · 리소스 범위 · 제한값 · 배포 버전 중 필요한 항목만 골라 채택할 수 있습니다.

image::governance-mcp-server-catalog/adopt-dialog.png[관측값을 승인 기준선으로 채택, 500]

. (처음이라면) **관측값 채택** 으로 기준선을 가져옵니다.
. 아래 항목을 필요한 만큼 고칩니다.
. **변경 메모** 를 적고 **정책 저장** 을 누릅니다. 정책 버전이 올라가고 finding 을 다시 계산합니다.

image::governance-mcp-server-catalog/policy-edit.png[승인 정책 편집, 900]

[cols="1,3",options="header"]
|===
| 항목 | 설명

| 모드
| **관측** — 카탈로그에서 차이만 찾고 서버에 강제하지 않습니다. **강제(enforce)** — 서버가 정책 번들을 받아 호출을 거부합니다(서비스 토큰 필요, xref:governance/mcp-server-catalog-advanced.adoc#_정책_집행_강제_모드[정책 집행] 참고).
| 도구 그룹
| 그룹마다 **승인: 켜짐 / 꺼짐** 을 정합니다. 승인되지 않은 그룹이 서버에서 켜져 있으면 finding 이 생깁니다.
| 도구 차단 · 사람 승인
| 특정 도구를 **차단** 하거나 사람 승인이 필요한 도구로 지정합니다.
| 승인 리소스 범위
| **규칙 추가** 로 리소스 유형(예: `topic`) · 동작 · 효과(allow/deny/protect) · 패턴(쉼표 구분, fnmatch)을 넣습니다.
| 제한값(limits)
| **제한 추가** 로 키(예: `kafka.peek.max_messages`)와 승인값을 넣습니다. 관측값이 더 크면 finding 이 생깁니다.
| 승인 버전
| 승인한 서버 버전입니다. 배포 버전과 다르면 finding 이 생깁니다.
| 변경 메모
| 이력에 남는 메모입니다.
|===

**이력** 에서 누가 언제 어떤 메모로 바꿨는지 봅니다.

image::governance-mcp-server-catalog/policy-history.png[승인 정책 이력, 600]

== finding 확인하기

**finding** 탭은 승인 정책과 관측값의 차이 등 미해소 점검 항목을 심각도와 함께 보여 줍니다.
정책이나 관측값이 바뀌면 자동으로 다시 계산되고, **다시 계산** 으로 직접 돌릴 수도 있습니다.

image::governance-mcp-server-catalog/findings.png[finding 탭, 900]

[cols="1,3",options="header"]
|===
| 종류 | 의미

| 승인되지 않은 그룹 켜짐
| 승인 정책에서 꺼진 도구 그룹이 서버에서 켜져 있습니다.
| 차단 도구 노출
| 차단한 도구가 서버에 노출돼 있습니다.
| 위험도 미확정 도구
| 새로 나타난 도구의 위험도를 아직 검토하지 않았습니다.
| 리소스 범위가 승인보다 넓음
| 서버의 리소스 범위가 승인 범위를 벗어납니다.
| 제한값 초과
| 서버 제한값이 승인값보다 큽니다.
| 승인 버전과 다름
| 배포 버전이 승인 버전과 다릅니다.
| 보안 경고
| 서버가 보고한 보안 경고입니다(예: TLS 인증서 검증 꺼짐).
| 헬스 연속 실패
| 헬스 체크가 연속으로 실패했습니다.
| 승인 정책 위반 호출
| 감사 로그에서 승인 정책을 벗어난 도구 호출이 발견됐습니다.
| enforce 정책 미적용
| 강제 모드인데 서버가 한동안 정책 번들을 받아 가지 않았습니다.
|===

바로 고칠 수 없는 항목은 행의 **확인** 을 눌러 메모와 함께 **확인됨** 으로 표시합니다. 다시 열 수도 있습니다.

image::governance-mcp-server-catalog/ack-dialog.png[finding 확인, 500]

TIP: 알림 규칙에서 트리거 `MCP_POLICY_DRIFT`(정책 드리프트, 최소 심각도 지정 가능)와 `MCP_SECURITY_WARNING`(보안 경고)을 걸면
finding 이 생길 때 알림을 받을 수 있습니다. xref:governance/alerts.adoc[알림] 을 참고하세요.

== AI Agent 연계

AI Agent 상세의 **도구·통합** 탭에서 카탈로그 배포를 연결하면 배포 상세의 **사용 에이전트** 탭에 나타납니다.
에이전트별 허용 그룹 · 도구와 실효 도구 수, 에이전트 리소스 범위를 보여 줍니다.

image::governance-mcp-server-catalog/agents-tab.png[사용 에이전트 탭, 900]

=== 에이전트별 리소스 범위

특정 에이전트에게만 범위를 더 좁히고 싶을 때 씁니다(예: 이 에이전트는 `secret-*` 토픽 읽기 금지).

. **사용 에이전트** 탭에서 에이전트 행의 **범위 편집** 을 누릅니다.
. 규칙을 넣고 저장합니다.

에이전트 범위는 배포의 승인 범위 위에 더해지는 제한입니다. 저장하면 정책 번들이 바뀌어 강제 모드 서버가 다음 갱신 때 반영합니다.

image::governance-mcp-server-catalog/agent-scope-dialog.png[에이전트 리소스 범위, 600]

접근 시뮬레이터에서 에이전트를 지정하면 에이전트 범위까지 적용한 판정을 확인할 수 있습니다.

image::governance-mcp-server-catalog/simulate-agent.png[에이전트를 지정한 접근 시뮬레이션, 900]

=== 미등록 연결

AI Agent 에 주소만 직접 입력한 MCP 연결은 목록의 **미등록 연결** 탭에 모입니다. 카탈로그 배포 연결로 바꾸는 방법은 두 가지입니다.

* **에이전트 소유자** — AI Agent 상세에서 직접 **카탈로그 배포와 연결** 을 누릅니다.

== 폐기

서버 정의 · 배포 헤더의 **폐기** 는 기록을 남긴 채 상태를 **폐기** 로 바꿉니다(같은 이름으로 다시 만들 수 없습니다).
다음 경우에는 폐기할 수 없습니다.

* 배포를 사용하는 AI Agent 가 있을 때 — 오류에 에이전트 이름이 표시됩니다. 에이전트의 연결을 먼저 정리합니다.
* 서버 정의에 폐기되지 않은 배포가 있을 때 — 배포를 먼저 폐기합니다.

image::governance-mcp-server-catalog/retire-conflict.png[사용 중인 배포 폐기 시도, 900]

서비스 토큰 폐기는 xref:governance/mcp-server-catalog-advanced.adoc#_서비스_토큰_폐기[감사와 정책 집행] 을 참고하세요.

== 통합 검색에서 찾기

헤더 검색칸에 서버 이름이나 도구 이름(예: `delete_topic`)을 넣고 Enter 를 치면 검색 결과의 **MCP 서버** 항목에 나옵니다.
누르면 서버 정의 상세로 이동합니다.

== 자주 묻는 질문

[qanda]
등록 버튼이 보이지 않습니다.::
  기능 권한 **MCP 서버·배포 등록**(`mcp.register`)이 없습니다. 관리자에게 요청하세요.

승인 정책 탭이 "읽기 전용" 입니다.::
  그 배포를 등록한 사람 또는 관리자가 아니거나, 기능 권한 **MCP 승인 정책 변경**(`mcp.policy`)이 없습니다.

**수집** 이 실패합니다.::
  서버가 인증을 요구하면 **자격증명** 탭에 토큰을 저장하세요. 카탈로그가 서버에 닿지 않는 망이면 **manifest** 를 붙여 넣어 반영하세요.

폐기가 되지 않습니다.::
  이 배포를 쓰는 AI Agent 가 있거나(오류에 이름이 나옵니다), 서버 정의에 폐기되지 않은 배포가 남아 있습니다. 먼저 정리하세요.

강제(enforce) 모드로 저장되지 않습니다.::
  강제 모드는 서비스 토큰이 있어야 저장됩니다. xref:governance/mcp-server-catalog-advanced.adoc[감사와 정책 집행] 을 참고해 먼저 발급하세요.
