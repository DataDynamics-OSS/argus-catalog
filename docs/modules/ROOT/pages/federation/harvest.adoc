= 가져오기 (HARVEST)
:toc: macro
:toclevels: 2

**가져오기(HARVEST)** 는 peer 의 메타데이터를 이 카탈로그의 로컬 **미러** 로 받아 오는 작업입니다.
받아 온 데이터셋은 허브 임베딩 모델로 다시 임베딩되어 통합 검색 · 탐색에 나오고, 샘플 데이터와 리니지도 함께 로컬에 보관됩니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **가져오기 (증분)** — 지난번 이후 바뀐 데이터셋만 빠르게 받아 옵니다.
* **전체 재동기화** — 전부 다시 받아 오고, peer 에서 사라진 데이터셋을 정리합니다.
* **동기화 이력** — 수동 · 자동 실행 기록과 결과를 봅니다.
* **실패 원인 확인** — 실패 사유를 보고 조치합니다.

평소에는 스케줄러가 peer 마다 정한 **동기화 주기** 에 맞춰 자동으로 가져오므로, 버튼은 "지금 바로" 받고 싶을 때만 누르면 됩니다.

=== 가져오기 대상

* `ACTIVE` 상태이면서 `HARVEST`·`HYBRID` 모드인 peer 에만 적용됩니다.
* `LIVE` 모드나 `PAUSED` 상태 peer 는 가져오기 대상이 아니며, 화면에서도 가져오기 버튼이 보이지 않습니다.

=== 메뉴 위치

**데이터 카탈로그 → 페더레이션** → **인스턴스 관리** 탭의 인스턴스 행 오른쪽 아이콘에서 시작합니다.

=== 누가 무엇을 할 수 있나요

가져오기는 **관리자만** 실행할 수 있습니다.

== 가져오기 (증분)

. 인스턴스 행의 **가져오기 (증분)** 아이콘(구름 아래 화살표)을 누릅니다.
. 행 아래에 진행 바가 나타납니다. 첫 페이지를 받기 전에는 "가져오는 중..." 이 보이고, 이후 `가져오기 n / N` → `재임베딩 n / N · 관측 N` → `샘플 …` → `정리 …`
  순으로 바뀌며 % 가 올라갑니다. 진행 중에는 같은 버튼이 비활성입니다.
. 끝나면 진행 바 자리에 "가져오기 완료 관측 N · 갱신 N · 임베딩 N · 정리 N" 이 표시되었다가 약 8초 뒤 사라집니다(팝업은 쓰지 않습니다).

image::federation/harvest-running.png[가져오기 (증분) 진행 바, 900]

image::federation/harvest-done.png[가져오기 완료 결과 표시, 900]

[cols="1,3",options="header"]
|===
| 숫자 | 의미

| 관측 | peer 에서 받은 데이터셋 수
| 갱신 | 미러에 새로 넣거나 바뀐 데이터셋 수
| 임베딩 | 다시 임베딩한 데이터셋 수
| 정리 | peer 에서 사라져 미러에서 지운 데이터셋 수(전체 동기화에서만)
|===

TIP: 진행 중에 다른 탭으로 갔다가 돌아와도 진행 바가 복원됩니다. 같은 peer 의 가져오기가 이미 돌고 있으면
"이미 가져오기가 진행 중입니다" 로 거절되니 잠시 뒤 다시 시도하세요. 스케줄러가 막 실행 중일 때도 그렇습니다.

=== 증분과 전체는 무엇이 다른가요

* **증분(기본)** — 마지막으로 성공한 가져오기 이후 바뀐 데이터셋만 가져옵니다.
  변경분만 보기 때문에 **peer 에서 지운 데이터셋은 증분으로는 사라지지 않습니다**. 샘플은 아직 없는 것만 받습니다.
* **전체** — 전량을 받아 사라진 항목을 정리(prune)하고, 샘플도 전량 갱신합니다.

증분으로 요청해도 다음 경우에는 자동으로 **전체** 로 실행됩니다.

* 그 peer 의 첫 가져오기(성공 이력이 없을 때)
* 마지막 전체 동기화 후 `federation.full_sync_interval_seconds`(기본 86400초 = 1일)가 지났을 때

[TIP]

== 전체 재동기화

. 인스턴스 행의 **전체 재동기화** 아이콘(원형 화살표)을 누릅니다.
. 확인 대화상자에서 **전체 재동기화** 를 누릅니다.

peer 의 데이터셋 전체를 다시 가져오고, peer 가 더 이상 노출하지 않는 미러 데이터셋을 이 카탈로그에서도 정리합니다.

image::federation/full-resync-confirm.png[전체 재동기화 확인 대화상자, 900]

== 동기화 이력

인스턴스 행의 **동기화 이력** 아이콘(시계)을 누르면 "동기화 이력: <인스턴스 이름>" 대화상자에 실행 이력이 최신순으로 나옵니다.
열은 상태(`SUCCESS` / `FAILED` / 실행 중 + `전체`·`증분`) · 관측/갱신/임베딩/정리 · 시작입니다.
수동 실행과 스케줄러 실행이 모두 기록됩니다.

image::federation/sync-runs.png[동기화 이력 — 전체 · 증분 실행 이력, 900]

[[_실패했을_때]]
== 실패했을 때

peer 에 연결할 수 없거나 토큰이 틀리면 가져오기는 오류로 멈추지 않고 그 실행만 `FAILED` 로 기록합니다.
행 아래에 빨간 "가져오기 실패 <사유>" 가 표시되고, 동기화 이력과 **관측성** 탭에도 같은 사유가 남습니다.

image::federation/harvest-failed.png[가져오기 실패 — 서비스 토큰 확인 안내, 900]

[cols="1,3",options="header"]
|===
| 사유 | 조치

| `peer 인증 실패(HTTP 401) — 서비스 토큰을 확인하세요` | 인스턴스 수정에서 서비스 토큰을 peer 의 export 토큰과 맞춥니다.
| `peer 연결 실패: …` | Base URL · 네트워크 · peer 기동 상태를 확인합니다. 행의 **점검** 으로 먼저 확인하면 편합니다.
| `peer 응답 시간 초과` | peer 부하나 네트워크 지연을 확인합니다.
| `peer 응답 오류(HTTP n): …` | peer 쪽 로그를 확인합니다.
|===

실패한 실행은 증분 기준 시각을 앞으로 옮기지 않으므로, 원인을 고친 뒤 다시 가져오면 빠진 변경분까지 받아 옵니다.

실행 이력과 미러 규모는 **관측성** 탭에서도 볼 수 있습니다(xref:federation/governance.adoc#_관측성[관측성] 참고).

== 자주 묻는 질문

[qanda]
가져오기 버튼이 보이지 않습니다.::
  `PAUSED` 상태이거나 `LIVE` 모드인 peer 입니다. 관리자가 아니면 인스턴스 관리 탭 자체가 보이지 않습니다.

"이미 가져오기가 진행 중입니다" 가 나옵니다.::
  같은 peer 의 가져오기(스케줄러 실행 포함)가 이미 돌고 있습니다. 잠시 뒤 다시 시도하세요.

peer 에서 지운 데이터셋이 아직 보입니다.::
  증분 가져오기는 삭제를 정리하지 않습니다. **전체 재동기화** 를 실행하거나, 자동 전체 동기화 주기(기본 1일)를 기다리세요.

모든 peer 를 한 번에 가져오는 버튼이 있나요?::
  화면에는 없습니다. 아래 고급 내용의 API 를 쓰세요.

== 고급 — 동작 원리와 설정

이 절은 운영자를 위한 내용입니다.

=== 단계와 진행률

가져오기는 다음 단계로 진행되며, 진행률 바는 단계별 가중치(40 / 35 / 20 / 5)로 전체 %를 계산합니다.

[cols="1,4",options="header"]
|===
| 단계 | 동작
| 가져오기(FETCH) | peer `export/datasets` 를 페이지로 받아 미러 테이블에 upsert. 논리명·컬럼 수·원본 등록 시각도 함께 가져온다.
| 재임베딩(EMBED) | 내용이 바뀐 항목만 **허브 임베딩 모델** 로 재임베딩한다.
| 샘플(SAMPLE) | peer 가 샘플을 노출하고 허브가 표시하기로 했으면 각 데이터셋 샘플을 받아 로컬에 저장한다(아래 참고).
| 정리(FINALIZE) | 전체 동기화 시 peer 에서 사라진 항목 prune + 리니지 엣지 가져오기.
|===

=== 스케줄러와 API

백엔드 스케줄러는 `federation.harvest_tick_seconds`(기본 300초)마다 깨어나, `ACTIVE`·미러 모드 peer 중
각자의 **동기화 주기** 가 지난 것을 가져옵니다(`federation.harvest_enabled`, 기본 켜짐).

* 모든 peer 를 한꺼번에 가져오기: `POST /api/v1/federation/harvest`
* 개별 peer: `POST /api/v1/federation/instances/{id}/harvest?full=true|false`

2시간(`federation.stale_run_seconds`) 넘게 **실행 중** 으로 남은 이력은 비정상 종료로 보고 다음 실행 때 `FAILED` 로 정리합니다.

=== 샘플 미러링

peer 가 샘플을 노출하고 허브의 **표시 정보 선택** 에서 **샘플 데이터** 를 끄지 않았다면, 가져오기 때 각 데이터셋의 샘플을 받아 로컬에 저장합니다.

* 저장 경로 — `data_dir/federation/samples/{인스턴스 id}/{미러 데이터셋 id}.json`
  (로컬 데이터셋 샘플 경로와 **분리된 네임스페이스**).
* 서빙 — 원격 상세의 샘플은 **미러 우선**(오프라인, peer 가 꺼져도 동작), 미러가 없으면 peer 에서 실시간으로 조회합니다.
* peer 가 샘플 노출을 끄거나 허브가 표시하지 않기로 바꾸면, 다음 가져오기 때 저장된 샘플을 정리합니다.
* 설정 — `federation.harvest_samples`(기본 true), `federation.sample_limit`(기본 100행).

=== 관련 설정

[cols="2,1,3",options="header"]
|===
| 설정(`federation.*`) | 기본값 | 설명
| `harvest_enabled` | `true` | 스케줄러 자동 가져오기
| `harvest_tick_seconds` | `300` | 스케줄러가 대상을 확인하는 간격
| `full_sync_interval_seconds` | `86400` | 이 간격마다 증분을 전체 동기화로 승격(0 이면 끔)
| `watermark_overlap_seconds` | `300` | 증분 기준 시각을 앞당기는 여유
| `stale_run_seconds` | `7200` | 오래된 실행 중 이력을 실패로 정리하는 기준
| `harvest_samples` · `sample_limit` | `true` · `100` | 샘플 미러링과 행 수
|===
