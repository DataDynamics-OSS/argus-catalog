= 탐색 · 통합 검색 · 리니지
:toc: macro
:toclevels: 2

다른 팀 카탈로그(peer)의 데이터셋을 찾고 둘러보는 화면입니다. **통합 검색** 으로 모든 카탈로그를 한 번에 검색하고,
**탐색** 으로 트리를 따라 둘러본 뒤, 원격 상세에서 스키마 · 샘플 · 리니지를 봅니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **통합 검색** — 이 카탈로그와 연합한 모든 peer 의 데이터셋을 한 번에 검색합니다.
* **탐색** — 가져온 peer 데이터셋을 인스턴스 → 데이터 소스 트리와 표로 둘러봅니다.
* **원격 상세 보기** — peer 데이터셋의 개요 · 스키마 · 샘플 · DDL 을 봅니다.
* **cross-instance 리니지** — 팀 경계를 넘는 데이터 흐름을 한 그래프로 봅니다.

=== 메뉴 위치

[cols="1,2,3",options="header"]
|===
| 메뉴 | 주소 | 용도

| 페더레이션 → 통합 검색 (기본 탭) | `/dashboard/federation?q=…` | 전체 카탈로그 검색
| 페더레이션 → 탐색 | `/dashboard/federation` | 미러 데이터셋 트리 · 그리드
| 원격 데이터셋 상세 | `/dashboard/federation/datasets?urn=<federated URN>` | peer 데이터셋 상세. 링크로 공유할 수 있습니다.
|===

=== 누가 무엇을 할 수 있나요

[cols="3,1,1",options="header"]
|===
| 작업 | 로그인 사용자 | 관리자

| 통합 검색 · 탐색 · 원격 상세 · 리니지 보기 | ✓ | ✓
| 원격 샘플 · DDL 보기 2+| 기능 권한 **샘플 데이터 조회** · **DDL 조회** 에 따름
| 원격 상세에서 **로컬로 가져오기** | – | ✓
|===

== 통합 검색

페더레이션 > **통합 검색** (기본 탭)은 이 카탈로그의 로컬 데이터셋과 연합한 peer 데이터셋을 한 번에 검색합니다.

. **모든 팀 카탈로그를 한 번에 검색...** 에 검색어를 넣습니다.
. **검색**(또는 Enter)을 누릅니다.
. 결과 카드에서 **상세** 나 **리니지** 를 누릅니다.

image::federation/search-results.png[통합 검색 결과 — 결과 건수와 조회한 인스턴스 수, 900]

* 결과 위에 `N건 · M개 인스턴스 조회` 가 표시됩니다(로컬도 1개로 셉니다).
* 결과 카드에는 출처 배지 · 이름 · 매칭 방식(`keyword` / 시맨틱)과 점수 · 데이터 소스 · 유형 · 환경 · 설명 요약(두 줄) · URN 이 보입니다.
* 출처 배지는 로컬 결과가 회색 `로컬`, peer 결과가 지구 아이콘과 인스턴스 이름(예: `IT Peer`)입니다.
* peer 결과에는 **상세** 버튼이 있어 원격 상세로 이동합니다. 로컬 결과는 일반 데이터셋 화면에서 봅니다.
* 모든 결과에 **리니지** 버튼이 있어 cross-instance 리니지를 바로 볼 수 있습니다(<<_cross_instance_리니지>>).
* 검색어는 주소(`/dashboard/federation?q=…`)에 남아, 상세를 보고 브라우저 **뒤로** 를 누르면 같은 결과로 돌아옵니다.

image::federation/search-results-peer.png[peer 결과 — 출처 배지와 상세 · 리니지 버튼, 900]

=== 일부 peer 결과가 빠질 때

* 응답하지 않은 `LIVE` peer 는 결과 위에 주황 `실패: <식별 키>` 로 표시되고, 나머지 결과만 보여 줍니다.
* `PAUSED` peer 는 검색 대상에서 빠집니다.
* `HARVEST`·`HYBRID` peer 는 로컬 미러에서 찾으므로 peer 가 꺼져 있어도 결과가 나옵니다.

image::federation/search-live-partial.png[LIVE peer 실패 — 실패 인스턴스 표시와 부분 결과, 900]

NOTE: 임베딩이 꺼져 있으면 키워드 검색(`keyword`)만으로 동작합니다. 시맨틱 검색을 쓰려면
xref:ops/embedding.adoc[임베딩] 을 켜고 peer 를 다시 가져오세요.

[TIP]
.고급 사용자 — 검색 경로
====
* `HARVEST`·`HYBRID` peer 는 **로컬 미러** 에서 찾으므로 peer 를 호출하지 않고 빠르게 응답합니다.
* `LIVE` peer 는 검색할 때마다 peer 로 요청을 보냅니다(fan-out).

검색 한 번이 여러 경로로 흩어졌다가(scatter) 한 목록으로 모이는(gather) 과정은 다음과 같습니다.

.미러와 LIVE peer 통합 검색
image::diagrams/federation-browse-search-01.png[미러와 LIVE peer 통합 검색,role="diagram"]

== 탐색

페더레이션 > **탐색** 탭에서는 가져온 미러 데이터셋을 둘러봅니다. **좌측 트리 + 우측 그리드** 구조입니다.

. 좌측 트리에서 인스턴스를 펼칩니다.
. 데이터 소스를 누르면 오른쪽 그리드에 데이터셋 목록이 나옵니다.
. 데이터셋 이름을 누르면 원격 상세로 이동합니다.

image::federation/browse-tree.png[탐색 탭 — 미러를 가진 인스턴스 트리, 900]

* **좌측 트리** — 미러를 가진 `ACTIVE` peer 가 인스턴스 → 데이터 소스 순으로 펼쳐지고, 옆에 데이터셋 수가 보입니다.
  `LIVE` 모드와 `PAUSED` peer 는 나오지 않습니다. 아무것도 없으면 "미러(HARVEST) 데이터셋을 가진 인스턴스가 없습니다…" 안내가 보입니다.
* **우측 그리드** — 제목(`인스턴스 › 데이터 소스` · 건수)과 함께 데이터셋 목록이 나옵니다.
  열은 이름 · 환경 · 필드 · 등록일 · 동기화일이고, 아래에 페이지당 행 수 선택과 번호 페이저가 있습니다.
* **이름 표시** — 논리명(예: 배우)이 있으면 그대로 쓰고, 없으면 물리명에서 스키마를 뗀
  테이블명(예: `sakila.film` → `film`)을 씁니다. 마우스를 올리면 전체 이름이 보입니다.

image::federation/browse-grid.png[데이터 소스를 고른 그리드 — 이름 · 환경 · 필드 · 등록일 · 동기화일, 900]

=== 트리 좁히기

위쪽 **데이터셋 이름/설명으로 트리 좁히기...** 에 단어를 넣고 **필터**(또는 Enter)를 누르면 트리 건수와 그리드가
그 조건에 맞는 데이터셋으로 줄어듭니다. 입력을 비우고 **필터** 를 누르면 원래대로 돌아오고, 원형 화살표는 **새로고침** 입니다.

image::federation/browse-filter.png[필터 적용 — 트리 건수가 줄어든 모습, 900]

TIP: 데이터 소스 하나에 데이터셋이 아주 많으면 일부만 표시하고 "일부만 표시(전체 N)" 안내를 붙입니다. 필터로 범위를 좁혀 찾으세요.

[[_원격_데이터셋_상세]]
== 원격 데이터셋 상세

검색 결과의 **상세** 나 탐색 그리드의 이름을 누르면 "페더레이션 · 데이터셋 상세" 화면이 열립니다.
주소는 `/dashboard/federation/datasets?urn=<federated URN>` 이라 링크로 공유할 수 있습니다.

머리글에는 데이터셋 이름 · federated URN 과 출처 배지(인스턴스 이름) · 환경 · 상태가 있고, 관리자에게는
**로컬로 가져오기** 버튼이 보입니다(xref:federation/import.adoc[로컬 승격] 참고). 왼쪽 위 **뒤로** 로 이전 화면으로 돌아갑니다.

image::federation/detail-overview.png[원격 데이터셋 상세 — 개요 탭과 출처 배지, 900]

탭은 다음과 같습니다. peer 가 내보내지 않거나 허브가 표시하지 않기로 한 항목의 탭은 나타나지 않습니다.

[cols="1,3",options="header"]
|===
| 탭 | 내용

| 개요
| 로컬 데이터셋 상세와 같은 메타데이터 표(데이터셋명 · 요약설명 · URN · 태그 · 데이터 소스 유형 · 데이터 소스명 · 상태 · 환경 · 보존 기한 등)와 **상세 설명**
| 스키마 (N)
| 열 # · 필드 · 논리명 · 타입 · 네이티브 타입 · PK · 고유 · 인덱스 · 파티션 · 분산 · Null · PII · 설명
| 샘플
| 탭을 고를 때 불러옵니다. 미러에 저장된 샘플이 있으면 그것을, 없으면 peer 에서 실시간으로 가져옵니다.
| DDL
| peer 가 DDL 을 제공할 때만 나타납니다.
| 리니지
| 탭을 고를 때 불러옵니다. 아래 cross-instance 리니지와 같은 내용입니다.
|===

image::federation/detail-schema.png[원격 상세 — 스키마 탭, 900]

image::federation/detail-sample.png[원격 상세 — 미러 샘플, 900]

* 메타데이터(개요 · 스키마)는 모드와 관계없이 열 때마다 peer 에서 실시간으로 가져오므로, peer 에서 설명을 고치면 바로 반영됩니다.
* 샘플은 기능 권한 **샘플 데이터 조회**, DDL 은 **DDL 조회** 로 통제됩니다. 권한이 막힌 사용자에게는 해당 정보가 보이지 않습니다.
* peer 가 응답하지 않으면 빨간 안내가 뜹니다. 같은 peer 가 연달아 실패하면 잠시 차단(circuit open)되어 "peer 일시 차단됨(circuit open) — 잠시 후 재시도" 가 보입니다(xref:federation/governance.adoc#_circuit_breaker[Circuit breaker] 참고).

[#_cross_instance_리니지]
== cross-instance 리니지

여러 카탈로그에 흩어진 리니지를 한 그래프로 합쳐 팀 경계를 넘는 데이터 흐름을 보여 줍니다.

* 통합 검색 카드의 **리니지** 를 누르면 "Cross-instance 리니지: <이름>" 대화상자가 열립니다.
* 원격 상세의 **리니지** 탭에서도 같은 흐름을 볼 수 있습니다.
* 각 노드에는 출처 배지(로컬 / peer 인스턴스)가 붙고, 각 엣지에는 그 관계를 알려 준 쪽(`보고: <식별 키>`)이 표시됩니다.

image::federation/lineage-dialog.png[Cross-instance 리니지 대화상자 — 보고 출처 표시, 900]

image::federation/detail-lineage.png[원격 상세 — 리니지 탭, 900]

NOTE: 미러 리니지는 가져오기 때 함께 받아 오며, peer 가 리니지를 노출하지 않으면 비어 있습니다. `PAUSED` peer 의 리니지는 그래프에서 빠집니다.

[TIP]
.고급 사용자 — 리니지를 합치는 방법
====
엔드포인트 URN 은 데이터 소스 전역에서 유일하므로, 로컬 리니지와 여러 peer 가 보고한 미러 리니지를
같은 URN 키로 합쳐(stitch) 그래프를 만듭니다.
====

== 자주 묻는 질문

[qanda]
검색 결과 위에 주황 `실패: <식별 키>` 가 보입니다.::
  그 `LIVE` peer 가 응답하지 않았습니다. 나머지 결과는 정상입니다. 계속되면 관리자에게 peer 상태 확인을 요청하세요.

시맨틱 검색이 안 되고 `keyword` 결과만 나옵니다.::
  임베딩이 꺼져 있습니다. xref:ops/embedding.adoc[임베딩] 을 켜고 peer 를 다시 가져오세요.

탐색 트리에 아무것도 없습니다.::
  미러(HARVEST) 데이터셋을 가진 `ACTIVE` peer 가 없습니다. `LIVE` 모드와 `PAUSED` peer 는 트리에 나오지 않습니다.

원격 상세에 "peer 일시 차단됨(circuit open)" 이 나옵니다.::
  peer 가 연달아 실패해 잠시 호출을 막은 상태입니다. 잠시 후 다시 시도하세요.

샘플 · DDL 탭이 없습니다.::
  peer 가 내보내지 않거나, 허브가 표시하지 않기로 했거나, 기능 권한 **샘플 데이터 조회** · **DDL 조회** 가 없는 경우입니다.
