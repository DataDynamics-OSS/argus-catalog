= 노출 거버넌스 · 운영
:toc: macro
:toclevels: 2

이 카탈로그가 다른 허브에 **무엇을 내보낼지** 정하고(노출자 관점), 허브로서 **연합 상태를 지켜보는**(운영 관점) 방법을 설명합니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
중간중간 나오는 **고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **노출 항목 고르기** — 샘플 · DDL · 리니지처럼 다른 허브에 내보낼 정보 항목을 화면에서 고릅니다.
* **노출 데이터셋 제한** — PII · 민감도 · 데이터 소스 기준으로 데이터셋 자체를 숨깁니다(설정 파일).
* **서비스 토큰** — 허락된 허브만 export API 를 쓰게 합니다.
* **관측성** — peer 별 동기화 결과 · 미러 규모 · 회로 차단 상태를 한눈에 봅니다.

| 페더레이션 → **관측성** 탭 | peer 동기화 상태 · 미러 규모 · circuit breaker(관리자)
|===

== 노출 설정 탭

이 인스턴스가 다른 허브(소비자)에 **API 로 제공할 정보 항목** 을 고릅니다.
체크를 해제한 항목은 페더레이션 목록 · 검색 · 상세 · 샘플 · 리니지에서 모두 빠집니다.

. 페더레이션 > **노출 설정** 탭을 엽니다.
. 내보내지 않을 항목의 체크를 풉니다. 그룹마다 **전체 해제** / **전체 선택** 이 있습니다.
. **저장** 을 누릅니다. "노출 정책을 저장했습니다." 안내가 뜹니다.

image::federation/export-policy.png[노출 설정 탭 — 그룹별 제공 항목 체크리스트, 900]

* 기본값은 전체(25개) 노출입니다. 아래 **저장** 옆에 `N개 항목 노출` 이 표시됩니다.

image::federation/export-policy-saved.png[DDL 을 해제하고 저장한 결과, 900]

[cols="1,3",options="header"]
|===
| 그룹 | 대표 항목

| 기본정보 | 설명 · 정규화 이름 · 테이블 유형 · 저장 포맷 · 상태 · 환경(origin) · 동기화 여부 · 확장 메타데이터
| 스키마 | 스키마(컬럼 목록), 컬럼 타입 · Null 허용 · 기본키(PK) · Unique · Indexed · Partition Key · Distribution Key · PII 타입 · 컬럼 설명
| 거버넌스/관계 | 태그 · 오너 · 속성(properties) · 용어집(glossary) · 리니지
| 데이터 | 샘플 데이터 · DDL
|===

=== 상대 허브에서는 어떻게 보이나요

* 원격 상세에서 해당 탭이 사라집니다. 예를 들어 **샘플 데이터** · **리니지** 를 끄면 탭이 **개요** · **스키마** 만 남습니다.
* **컬럼 타입** 을 끄면 스키마 탭의 타입 칸이 비어 보입니다.
* 상대 허브가 이미 받아 둔 미러 샘플 · 리니지는 상대의 다음 가져오기 때 정리됩니다.

image::federation/detail-peer-limited.png[peer 가 노출을 줄인 뒤 상대 허브의 상세 — 개요 · 스키마 탭만, 900]

NOTE: 상대 허브도 자기 쪽에서 **표시 정보 선택** 으로 보여 줄 항목을 더 줄일 수 있습니다. 최종적으로 보이는 것은
(peer 노출 항목 ∩ 허브 표시 선택) 입니다(xref:federation/instances.adoc#_표시_정보_선택[표시 정보 선택] 참고).

== 관측성

페더레이션 > **관측성** 탭(관리자 전용)은 "peer 동기화 상태·미러 규모·circuit breaker 를 한눈에 봅니다." 화면입니다.
오른쪽 위 **새로고침** 으로 다시 읽습니다.

image::federation/observability.png[관측성 탭 — 요약 카드와 peer 상태 표, 900]

[cols="1,3",options="header"]
|===
| 항목 | 의미

| 인스턴스 (활성) | 등록된 peer 수와 그중 `ACTIVE` 수
| 미러 데이터셋 · 미러 리니지 엣지 | 가져온 미러 규모
| 회로 열림(breaker) | 지금 회로가 열려 있는 peer 수
| 표: 인스턴스 · 모드 · 미러(DS/리니지) | peer 별 미러 규모
| 표: 최근 동기화 | 마지막 가져오기 결과(`성공` / `실패` + 시각). 실패면 아래에 사유가 표시되고, 한 번도 가져오지 않았으면 `미수집`
| 표: Breaker | `정상` 또는 `열림 (연속 실패 수)`
|===

image::federation/observability-failed.png[최근 동기화 실패와 사유, 900]

[[_circuit_breaker]]
== Circuit breaker (peer 일시 차단)

죽은 peer 하나가 연합 전체를 느리게 만드는 것을 막기 위해, 연달아 실패한 peer 는 잠시 호출하지 않습니다(회로 열림).
회로가 열린 동안 원격 상세에는 다음 안내가 표시됩니다.

image::federation/detail-circuit-open.png[원격 상세 — peer 일시 차단됨(circuit open) 안내, 900]

`HARVEST`·`HYBRID` peer 의 통합 검색과 미러 샘플은 peer 를 부르지 않으므로 회로와 관계없이 계속 동작합니다.

[TIP]
.고급 사용자 — 회로 동작과 설정
====
peer 를 실시간으로 부르는 호출(LIVE 검색 fan-out · 원격 상세 · 샘플 폴백)을 peer 단위로 감쌉니다. 연속 실패가
`federation.breaker_threshold`(기본 3)에 도달하면 `federation.breaker_cooldown_seconds`(기본 60초)
동안 회로를 열어 그 peer 호출을 즉시 실패(`503`)시킵니다.
쿨다운이 지나면 한 번 시험 호출을 해서 성공하면 회로를 닫습니다. `404` · `401` 같은 4xx 응답은 실패로 세지 않습니다.
====

== 서비스 토큰 인증

export API 를 허락된 허브만 쓰도록 서비스 토큰을 정합니다.

. **peer(내보내는) 쪽** — `federation.export_token`(또는 환경변수 `ARGUS_FEDERATION_TOKEN`, 환경변수가 우선)에 토큰을 설정합니다.
. **허브(가져오는) 쪽** — 인스턴스 등록 · 수정의 **서비스 토큰** 에 같은 값을 넣습니다.

WARNING: 운영 환경에서는 반드시 서비스 토큰을 설정하세요. 허브에 저장되는 토큰은 `ARGUS_SECRET_KEY` 로 암호화되어 보관됩니다.

[TIP]
.고급 사용자 — 토큰 검증 방식과 토큰이 없을 때
====
* export API 는 `Authorization: Bearer <token>` 을 **상수시간 비교** 로 검증합니다. 토큰이 없거나 틀리면 `401` 로 거절하고 경고 로그를 남깁니다(토큰 값 자체는 기록하지 않습니다).
* 토큰을 설정하지 않으면 export API 가 인증 없이 열리고, 기동 로그에 경고가 남습니다. 이때도 **샘플 데이터** 는
  노출하지 않으며, 익명 샘플까지 허용하려면 `federation.export_allow_anonymous_sample=true` 를 따로 켜야 합니다.
====

== 노출 대상 데이터셋 제한 (설정 파일)

항목이 아니라 **데이터셋 단위** 로 노출을 막으려면 설정 파일(`config.yml`)의 `federation.*` 값을 씁니다.
export 의 목록 · 검색 · 드릴다운 · 샘플 · 리니지 전 경로에 적용되며, **바꾼 뒤 백엔드를 재시작해야 합니다.**

[cols="1,3",options="header"]
|===
| 설정(`federation.*`) | 설명
| `export_exclude_pii` | PII 컬럼이 있는 데이터셋을 노출에서 제외(기본 `false`)
| `export_exclude_sensitivity` | 노출에서 뺄 민감도 등급(쉼표, 예: `RESTRICTED,CONFIDENTIAL`)
| `export_datasource_allowlist` | 노출을 허용할 데이터 소스 이름(쉼표, 빈 값=전체)
|===

* 노출할 수 없는 데이터셋은 상세 요청에도 `404` 로 응답해 **존재 여부** 까지 가립니다.
* 리니지는 양 끝 데이터셋이 모두 노출 가능한 엣지만 내보냅니다.
* 로컬로 가져온 데이터셋(Federation Imports)은 설정과 관계없이 항상 제외됩니다.
* 상대 허브는 다음 **전체 재동기화** 때 더 이상 노출되지 않는 미러를 정리합니다.

== 자주 묻는 질문

[qanda]
노출 설정에서 항목을 껐는데 상대 허브에 아직 샘플이 보입니다.::
  상대 허브가 이미 받아 둔 미러 샘플은 상대의 다음 가져오기 때 정리됩니다.

설정 파일로 데이터셋을 제외했는데 그대로 노출됩니다.::
  `federation.*` 노출 설정은 백엔드를 재시작해야 적용됩니다. 상대 허브의 미러는 다음 **전체 재동기화** 때 정리됩니다.

관측성의 Breaker 가 `열림` 입니다.::
  그 peer 가 연달아 실패했습니다. 쿨다운(기본 60초) 뒤 자동으로 다시 시도합니다. peer 상태를 **인스턴스 관리** 의 **점검** 으로 확인하세요.

최근 동기화가 `실패` 입니다.::
  아래에 표시된 사유를 보고 xref:federation/harvest.adoc#_실패했을_때[가져오기 실패] 의 조치를 따르세요.
