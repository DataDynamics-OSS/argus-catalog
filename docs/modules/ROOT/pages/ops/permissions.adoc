= 권한 관리
:toc: macro
:toclevels: 2

**권한 관리** 화면에서는 역할별로 **어떤 메뉴를 볼 수 있는지**(메뉴 권한)와 **메뉴 안의 어떤 기능을 쓸 수 있는지**
(기능 권한)를 정합니다. 사용자에게 역할을 주는 일은 xref:ops/users.adoc[사용자 관리] 에서 합니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **메뉴 숨기기** — 역할별로 사이드바 메뉴를 열거나 막습니다.
* **기능 막기** — 메뉴 안의 버튼 · 탭 · 민감 데이터(샘플 데이터, 접속 정보 등)를 역할별로 통제합니다.
* **한꺼번에 바꾸기** — 역할 전체 · 그룹 단위 · 항목 하나씩 체크를 바꿉니다.
* **저장 전에 미리 보기** — 역할별로 보이게 될 메뉴와 기능을 미리 확인합니다.
* **변경 이력 확인** — 누가 언제 권한을 바꿨는지 봅니다.

=== 먼저 알아 둘 용어

[cols="1,3",options="header"]
|===
| 용어 | 뜻

| 메뉴 권한 | 사이드바 메뉴를 볼 수 있는지 정합니다.
| 기능 권한 | 메뉴 안의 버튼 · 탭 · 민감 데이터를 쓸 수 있는지 정합니다.
| 역할 | 관리자(Admin) · 슈퍼유저(Superuser) · 사용자(User). 자세한 설명은 xref:ops/users.adoc#_역할[사용자 관리 → 역할] 을 보세요.
|===

=== 메뉴 위치

좌측 사이드바의 **관리 → 권한 관리** (`/dashboard/permissions`) 로 들어갑니다.

=== 누가 무엇을 할 수 있나요

[cols="3,1,1",options="header"]
|===
| 작업 | 일반 사용자·슈퍼유저 | 관리자

| 권한 관리 화면 보기 · 변경 | × | ✓
|===

== 기본 규칙 — 먼저 읽어 주세요

* **관리자(Admin)는 항상 모든 권한** 을 가집니다. 표의 Admin 열은 항상 체크된 채 잠겨 있습니다.
* 설정하는 대상은 **슈퍼유저(Superuser)** 와 **사용자(User)** 두 역할입니다.
* **설정하지 않은 항목은 모든 역할에 허용** 됩니다 (open-by-default). 잠그고 싶은 항목만 체크를 해제하세요.
* 단, 설명에 **"미설정 시 관리자만"** 이라고 적힌 기능은 반대로 **명시 허용형** 입니다. 허용할 역할을 직접 체크해야
  그 역할이 쓸 수 있습니다.
* 관리 메뉴(사용자 관리 · 설정 · 권한 관리)는 **관리자 전용(고정)** 이라 다른 역할에 열 수 없습니다.
* 저장한 내용은 서버 API 검사에는 바로 적용되고, 사용자 화면에는 탭으로 돌아오거나 1분 안에 반영됩니다.

== 메뉴 권한

image::ops-permissions/menu.png[메뉴 권한, 900]

메뉴는 사이드바와 같은 그룹(데이터 카탈로그 · AI 카탈로그 · API 카탈로그 · 거버넌스 · 관리)으로 묶여 있습니다.
메뉴를 막으면 사이드바에서 숨겨지고, 주소를 직접 입력해 들어와도 페이지를 열 수 없습니다.

. 막을 메뉴를 찾아 해당 역할(Superuser / User) 열의 체크를 해제합니다.
. 표 오른쪽 위의 **저장** 을 누릅니다 (<<_저장_취소>> 참고).

각 메뉴 이름 옆의 배지는 막았을 때 어디까지 막히는지 알려 줍니다.

[cols="1,3",options="header"]
|===
| 배지 | 의미

| 서버 API 차단
| 화면뿐 아니라 그 메뉴의 API 를 직접 호출해도 서버가 403 으로 막습니다.
| 화면만
| 여러 메뉴가 함께 쓰는 API 라서 화면에서만 막습니다. 데이터 자체를 감춰야 한다면 기능 권한을 함께 쓰세요.
| 관리자 전용(고정)
| 관리 메뉴입니다. 바꿀 수 없습니다.
|===

=== 한꺼번에 바꾸기

체크박스는 세 단계로 한꺼번에 바꿀 수 있습니다.

* **역할 열 머리글** (Superuser / User 옆) — 그 역할의 모든 항목을 허용하거나 해제합니다.
* **그룹 행** (진한 배경의 그룹 이름 줄) — 그 그룹에 속한 항목만 허용하거나 해제합니다.
* **항목 행** — 하나씩 바꿉니다.

일부만 허용된 그룹이나 역할은 체크박스에 `−` 표시가 나타납니다.

== 기능 권한

image::ops-permissions/feature.png[기능 권한, 900]

기능 권한은 메뉴 안의 버튼 · 탭 · 민감 데이터를 역할별로 통제합니다. 어느 메뉴의 기능인지에 따라 그룹으로
묶여 있고, 그룹 이름을 누르면 접히거나 펼쳐집니다. **전체 펼치기 / 접기** 로 한꺼번에 바꿀 수 있습니다.

권한이 없는 기능은 화면에서 버튼이나 메뉴가 숨겨지거나 비활성화되고, 서버도 같은 기준으로 403 을 돌려줍니다
(**화면만** 배지가 붙은 기능은 화면에서만 숨깁니다).

아래 표의 **미설정 시** 열이 **관리자만** 인 기능은 명시 허용형입니다. 슈퍼유저 · 사용자에게 열어 주려면 직접 체크하세요.

[cols="2,3,1",options="header"]
|===
| 그룹 · 기능 | 통제 대상 | 미설정 시

3+| *데이터셋*
| 샘플 데이터 조회 (`datasets.sample-view`) | 실데이터 샘플 노출 — 민감 | 모두 허용
| DDL 조회 (`datasets.ddl-view`) | 테이블 DDL 노출 (로컬 · 페더레이션 상세) | 모두 허용
| 이관 코드 탭 (`datasets.transfer-code`) | PySpark · Kestra · Airflow 적재 코드 (화면만) | 모두 허용
| 데이터셋 등록 (`datasets.create`) | 데이터셋 직접 등록 (동기화로 생기는 데이터셋과 무관) | 모두 허용
| 품질 규칙 관리 (`quality.rules-manage`) | 품질 규칙 추가 · 수정 · 삭제, 규칙 추천 | 모두 허용
| 품질 검증 실행 (`quality.run`) | 프로파일 · 검증 실행 (원천 DB 에 쿼리) | 모두 허용
| 검증 주기 설정 (`quality.schedule`) | 데이터셋별 자동 검증 주기 | 모두 허용
| AI 메타데이터 생성 (`ai.generate`) | 설명 · 요약 · 컬럼 · 태그 · PII 생성 (자기 데이터셋만, LLM 호출 비용) | 모두 허용

3+| *데이터 소스*
| 데이터 소스 관리 (`datasources.manage`) | 데이터 소스 · 조직 · 시스템 생성 · 수정 · 삭제, 접속 설정 저장 | *관리자만*
| 연결 설정 조회 (`datasources.connection`) | 접속 정보 조회 (비밀번호는 항상 마스킹) | *관리자만*
| 메타데이터 동기화 (`datasources.sync`) | 원본 스키마 동기화 실행 | *관리자만*

3+| *MLflow 모델 · OCI 모델 허브*
| MLflow 모델 등록 (`models.register`) | 새 모델 등록 (화면 · SDK · MLflow 클라이언트) | 모두 허용
| 운영(Production) 단계 변경 (`models.promote`) | 버전을 Production 으로 올리거나 내림 — 모델 소유자여도 필요 | *관리자만*
| OCI 모델 등록 (`oci.register`) | OCI 모델 직접 등록 | 모두 허용

3+| *AI Agent · MCP Server*
| AI Agent 등록 (`agents.register`) | 에이전트 등록 · 가져오기 · manifest 적용 · 미등록 에이전트 등록 | 모두 허용
| MCP 서버 · 배포 등록 (`mcp.register`) | MCP 서버 등록 · 가져오기, 배포 등록 | 모두 허용
| MCP 배포 자격증명 저장 (`mcp.credential`) | 배포 접속 자격증명 저장 · 삭제 (자기 배포만) — 민감 | *관리자만*
| MCP 승인 정책 변경 (`mcp.policy`) | 배포 승인 정책 저장 · 관측값 채택 (자기 배포만 — 해제한 역할은 자기 배포여도 불가) | 모두 허용

3+| *API*
| API 등록 (`apis.register`) | API 등록 | 모두 허용
| 저장된 자격증명 사용 (`apis.credentials`) | 저장된 API 자격증명 조회 · Try-it 호출에 사용 (추가 · 삭제는 관리자만) — 민감 | 모두 허용

3+| *거버넌스*
| 표준 사전 편집 (`standards.edit`) | 사전 · 단어 · 용어 · 도메인 · 코드 관리 | *관리자만*
| 용어집 편집 (`glossary.edit`) | 분류 · 용어 추가 · 수정 · 이동 · 삭제 | *관리자만*
| 태그 관리 (`tags.manage`) | 태그 생성 · 수정 · 삭제 | *관리자만*
| 알림 규칙 관리 (`alerts.rules`) | 규칙 추가 · 수정 · 삭제, 모든 알림 상태 변경 | *관리자만*
| 분류 체계 편집 (`taxonomies.edit`) | 분류체계 · 분류 추가 · 수정 · 삭제, 데이터셋 매핑 | *관리자만*

3+| *변경 관리 · 대시보드*
| 변경 요청 생성 (`changes.create`) | 변경 요청(CR) 작성 | 모두 허용
| 변경 요청 결재 (`changes.approve`) | 승인 · 반려 (현재 차례 결재자 본인만 — 이 권한이 없으면 결재 차례여도 불가) | 모두 허용
| 데이터 소비자 등록 (`changes.consumers`) | 데이터셋 소비자(변경 통지 대상) 등록 | 모두 허용
| AI 어시스턴트 사용 (`ai.assistant`) | 플로팅 챗 노출 · 어시스턴트 대화 API | 모두 허용
|===

TIP: 권한을 통과하더라도 데이터셋 · 모델 · 배포처럼 **소유자가 있는 자산** 은 소유자(또는 관리자)만 수정할 수 있습니다.
기능 권한은 "이 역할이 이 기능을 쓸 수 있는가"를, 소유권은 "이 자산을 고칠 수 있는가"를 정합니다.

[[_저장_취소]]
== 저장 · 취소

메뉴 권한과 기능 권한은 표마다 따로 저장합니다.

. 체크를 바꾸면 표 오른쪽 위에 **저장 안 된 변경 N건** 이 나타나고 **저장** 이 켜집니다.
. **저장** 을 누르면 적용됩니다. **변경 취소** 를 누르면 마지막으로 저장한 상태로 돌아갑니다.

저장하지 않은 채 브라우저 탭을 닫거나 새로고침하면 확인을 묻습니다.

== 역할별 미리보기

image::ops-permissions/preview.png[역할별 미리보기, 900]

화면 아래의 **역할별 미리보기** 는 지금 표(저장 전 변경 포함) 기준으로, 고른 역할의 사용자가 **보게 될 메뉴 / 막힌 메뉴**,
**쓸 수 있는 기능 / 막힌 기능** 을 한눈에 보여 줍니다. 오른쪽의 **Superuser** · **User** 버튼으로 역할을 바꿔 보며
저장하기 전에 결과를 확인하세요.

== 변경 이력

오른쪽 위의 **변경 이력** 은 권한 매트릭스를 누가 언제 어떻게 바꿨는지 보여 줍니다. 사용 방법은
xref:ops/users.adoc#_사용자_변경_이력[사용자 관리 → 변경 이력] 과 같습니다.

== 자주 묻는 질문

[qanda]
권한을 바꿨는데 사용자 화면에 그대로 보입니다.::
  서버 API 검사에는 바로 적용되지만, 사용자 화면에는 탭으로 돌아오거나 1분 안에 반영됩니다.

체크한 적이 없는데 슈퍼유저 · 사용자가 기능을 쓸 수 있습니다.::
  설정하지 않은 항목은 모든 역할에 허용됩니다(open-by-default). 막으려면 체크를 해제하고 저장하세요.

반대로, 체크하지 않은 기능을 슈퍼유저가 쓸 수 없습니다.::
  **미설정 시 관리자만** 인 명시 허용형 기능입니다. 허용할 역할을 직접 체크하세요.

메뉴를 막았는데 API 로는 데이터가 보입니다.::
  **화면만** 배지가 붙은 메뉴입니다. 데이터 자체를 감추려면 관련 기능 권한도 함께 막으세요.

기능 권한이 있는데 데이터셋을 수정할 수 없습니다.::
  소유자가 있는 자산은 소유자(또는 관리자)만 수정할 수 있습니다.
