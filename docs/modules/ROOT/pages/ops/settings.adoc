= 설정
:toc: macro
:toclevels: 2

**설정** 화면에서는 인증 방식, AI 기능, 메일·알림 연동처럼 시스템 전체에 적용되는 값을 바꿉니다.
저장하면 서버에 바로 적용되며, 재시작할 필요가 없습니다. 영향이 큰 화면이라 관리자만 쓸 수 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 설정 키 이름 같은 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **로그인 방식 바꾸기** — Local(내장 사용자 관리)과 Keycloak 중에서 고릅니다.
* **AI 기능 켜기** — 시맨틱 검색용 임베딩, AI 메타데이터 생성(LLM), AI 어시스턴트를 연결합니다.
* **외부 서비스 연동** — 오브젝트 스토리지, 이메일(SMTP), Slack·Mattermost 알림을 설정합니다.
* **관리 작업 실행** — 쿼리 이력 재분석, External API 캐시 비우기 등을 합니다.
* **변경 이력 확인** — 누가 언제 어떤 설정을 바꿨는지 봅니다.

=== 메뉴 위치

좌측 사이드바의 **관리 → 설정** (`/dashboard/settings`) 로 들어갑니다.

=== 누가 무엇을 할 수 있나요

[cols="3,1,1",options="header"]
|===
| 작업 | 일반 사용자·슈퍼유저 | 관리자

| 설정 화면 보기·변경 | × | ✓
|===

설정 메뉴는 관리자(`argus-admin`) 전용이며, xref:ops/permissions.adoc[권한 관리] 에서도 다른 역할에 열 수 없습니다.

== 설정 화면 둘러보기

화면 왼쪽의 항목 목록은 네 묶음으로 나뉩니다. 항목을 고르면 주소에 `?tab=` 이 붙으므로, 그 주소를 그 항목을 바로 여는 링크로 쓸 수 있습니다.

[cols="1,3",options="header"]
|===
| 묶음 | 항목

| 인증 · 보안 | <<_auth,인증>> · <<_cors,CORS>> · <<_dataset_create,데이터셋 등록>>
| AI | <<_embedding,임베딩>> · <<_llm,LLM / AI>> · <<_assistant,AI 어시스턴트>> · <<_query_analysis,쿼리 분석>>
| 연동 | <<_object_storage,오브젝트 스토리지>> · <<_email,이메일>> · <<_notify,알림>> · <<_change,변경관리>>
| 시스템 | <<_cache,캐시>>
|===

. 왼쪽 목록에서 항목을 고릅니다.
. 값을 바꾸고 **저장** 을 누릅니다. 저장하면 바로 서버에 적용됩니다.
. 연결이 필요한 항목은 **연결 테스트**(또는 **테스트**) 버튼으로 확인합니다.

저장하지 않은 입력은 다른 항목으로 옮겨 가도 유지되지만, 페이지를 떠나면 사라집니다.

=== 비밀값 입력란

비밀번호·API 키 같은 비밀값은 화면에 `••••••••` 으로 가려져 보입니다.
비밀값 입력란을 **비워 두고 저장하면 기존 값이 그대로 유지**되므로, 다른 항목을 바꿀 때 비밀값을 다시 넣지 않아도 됩니다.

[[_비밀값_마스킹]]
[TIP]
.고급 사용자 — 비밀값 마스킹 규칙
====
설정 API 응답에서 이름이 `*_secret`, `*_api_key`, `*_password`, `*_secret_key` 인 키는 `••••••••` 으로 마스킹됩니다.
====

=== 값 출처

대부분의 항목 아래에는 접힌 **값 출처** 패널이 있습니다. 항목별로 값이 어디서 왔는지(설정 파일 · 화면 변경 · 기본값)와
설정 파일 값과의 차이를 보여 줍니다. 비밀값은 값 자체를 보여 주지 않습니다.
"설정 파일을 고쳤는데 왜 안 바뀌지?" 싶을 때 먼저 여기를 확인하세요.

[TIP]
.고급 사용자 — 설정 파일과 DB 의 우선순위
====
설정 값은 DB (`catalog_configuration`) 에 카테고리 · 키 단위로 저장됩니다.
설정 파일(`config.yml` · properties)은 **최초 기동 때 DB 에 없는 항목만** 채우고, 이후에는 이 화면(DB)의 값이 우선합니다.
====

=== 변경 이력

오른쪽 위의 **변경 이력** 은 설정을 누가 · 언제 · 어떤 항목을 바꿨는지 최신순으로 보여 줍니다.
행을 누르면 바뀐 키가 펼쳐지고, 비밀값은 "(변경됨)"으로만 남습니다.

[[_auth]]
== 인증

image::ops-settings/auth.png[인증, 700]

로그인 인증 방식을 고릅니다.

* **Local (내장 사용자 관리)** — 사용자를 Argus Catalog DB 에서 관리합니다. 외부 ID 제공자가 필요 없습니다.
* **Keycloak** — Keycloak SSO 를 씁니다. 고르면 서버 URL · Realm · Client 등 입력란이 나타납니다.

모드별 차이와 Keycloak 준비 절차는 xref:ops/authentication.adoc[인증] 을 참고하세요.

[TIP]
.고급 사용자 — 인증 설정 키
====
[cols="1,3",options="header"]
|===
| 키 | 설명

| `auth_type` | `local` / `keycloak`.
| `auth_keycloak_server_url` | Keycloak 서버 URL.
| `auth_keycloak_realm` | Realm 이름 (`argus`).
| `auth_keycloak_client_id` | Client ID.
| `auth_keycloak_client_secret` | Client Secret 입니다. 응답에서는 마스킹됩니다.
| `auth_keycloak_admin_role` | 관리자 역할 (`argus-admin`).
| `auth_keycloak_superuser_role` | 슈퍼유저 역할.
| `auth_keycloak_user_role` | 기본 사용자 역할.
|===
====

== CORS

image::ops-settings/cors.png[CORS, 700]

API 를 호출할 수 있는 브라우저 출처(origin)를 콤마로 구분해 적습니다. 저장하면 바로 반영됩니다.

----
http://localhost:3000,http://my-internal-host:3000
----

`*` 는 모든 출처를 허용하므로 개발 환경에서만 쓰세요.

[[_dataset_create]]
== 데이터셋 등록

데이터셋 목록의 **데이터셋 추가** 로 데이터셋을 직접 등록할 수 있는 사람을 정합니다.

[cols="2,1,3",options="header"]
|===
| 항목 | 기본값 | 설명

| 일반 사용자의 데이터셋 직접 등록 허용
| 꺼짐
| 꺼 두면 관리자만 직접 등록할 수 있습니다. 켜면 일반 사용자 · 슈퍼유저도 등록할 수 있으며, 이때도
xref:ops/permissions.adoc[권한 관리] 의 기능 권한 *데이터셋 등록*(`datasets.create`)에서 해제한 역할은 등록할 수 없습니다.
|===

. **일반 사용자의 데이터셋 직접 등록 허용** 스위치를 켜거나 끕니다.
. **저장** 을 누릅니다. 바로 적용되며, 사용자 화면의 **데이터셋 추가** 버튼은 1분 안에(또는 탭으로 돌아올 때) 나타나거나 사라집니다.

꺼져 있을 때 일반 사용자가 API 로 등록을 시도하면 403 과 "일반 사용자의 데이터셋 직접 등록이 허용되어 있지 않습니다." 안내가 돌아옵니다.

[TIP]
.고급 사용자 — 동기화로 생기는 데이터셋
====
이 옵션은 사람이 직접 등록하는 경우에만 적용됩니다.

* 데이터 소스 화면의 **메타데이터 동기화**(서버 안에서 실행)는 영향을 받지 않습니다.
* 외부 xref:extensions/metadata-sync.adoc[메타데이터 동기화 서비스] 는 `catalog.username` 계정으로 같은 등록 API 를 부릅니다.
  이 계정이 관리자이거나, 그 역할에 기능 권한 *메타데이터 동기화*(`datasources.sync`)가 허용돼 있으면 옵션과 무관하게 등록됩니다.
  일반 계정을 쓰고 있다면 둘 중 하나를 갖춰 주세요(아니면 동기화가 403 으로 실패합니다).
* 설정 키는 `catalog_dataset_create_by_users`(범주 `catalog`)이며, 값이 없으면 꺼짐으로 봅니다.
====

[[_embedding]]
== 임베딩

image::ops-settings/embedding.png[임베딩, 700]

시맨틱 검색에 쓰는 임베딩을 설정합니다. 화면은 세 카드로 나뉩니다.

* **임베딩 상태** — 커버리지(임베딩된 데이터셋 수 / 전체)와 엔터티별 건수(용어집 · Agent · API · MCP 서버)를 보여 줍니다.
* **임베딩 제공자** — 시맨틱 검색 활성화, 쓰기 시 자동 임베딩, 제공자 · 모델을 고르고 **저장** · **연결 테스트** 를 합니다.
  연결 테스트는 텍스트 한 줄을 실제로 임베딩해 응답 시간 · 차원 · 모델을 보여 줍니다.
* **임베딩 관리** — **전체 데이터셋 백필** 로 빠진 임베딩을 채우거나, **모든 임베딩 삭제** 로 비웁니다.

처음 켤 때는 다음 순서로 합니다.

. **임베딩 제공자** 카드에서 시맨틱 검색을 켜고 제공자 · 모델을 고릅니다.
. **연결 테스트** 로 응답을 확인한 뒤 **저장** 합니다.
. **임베딩 관리** 카드에서 **전체 데이터셋 백필** 을 누릅니다.

모델을 바꾼 뒤에도 백필만 다시 실행하면 이전 모델로 만든 임베딩이 새 모델로 바뀝니다.

NOTE: 벡터 컬럼이 384 차원 고정이라 384 차원이 아닌 모델은 저장되지 않습니다.

자세한 운영 절차는 xref:ops/embedding.adoc[임베딩 운영] · xref:ops/search.adoc[검색] 을 참고하세요.

[TIP]
.고급 사용자 — 임베딩 설정 키
====
[cols="1,3",options="header"]
|===
| 키 | 설명

| `embedding_enabled` | 기능 활성화.
| `embedding_provider` | `local` / `openai` / `ollama`.
| `embedding_model` | 모델 식별자 또는 로컬 경로 (에어갭).
| `embedding_api_key` | OpenAI 키 (마스킹).
| `embedding_api_url` | Azure / Ollama URL 오버라이드.
| `embedding_dimension` | 벡터 차원 (현재 384 고정).
|===
====

[[_llm]]
== LLM / AI

image::ops-settings/llm.png[LLM / AI, 700]

AI 가 메타데이터(테이블 설명 · 요약 · 컬럼 설명 · 태그 추천 · PII 감지)를 만들어 주는 기능입니다.

* **AI 메타데이터 상태** — 설명 커버리지와 생성 건수(적용 · 대기) · 사용 토큰을 보여 줍니다.
* **LLM 제공자** — 활성화, 제공자 · 모델 · API Key · API URL, 생성 언어, Temperature, 최대 토큰 수, 동기화 시 자동 생성을
  정하고 **저장** · **연결 테스트** 를 합니다.
* **AI 일괄 생성** — 설명이 비어 있는 데이터셋에 대해 **설명 생성** 또는 **전체 생성(설명 + 컬럼 + 태그 + PII)** 을 한 번에
  실행합니다. 결과는 바로 적용됩니다.

데이터셋 화면에서 쓰는 방법은 xref:ai/metadata-generation.adoc[메타데이터 자동 생성] 을 참고하세요.

[TIP]
.고급 사용자 — LLM 설정 키와 생성 이력
====
[cols="1,3",options="header"]
|===
| 키 | 설명

| `llm_enabled` | 기능 활성화.
| `llm_provider` | `openai` / `ollama` / `anthropic`.
| `llm_model` | 모델 (`gpt-4o-mini`, `llama3.1` 등).
| `llm_api_key` | API 키 (마스킹).
| `llm_api_url` | 커스텀 URL.
| `llm_temperature` | 기본 0.3. 낮을수록 사실 중심입니다.
| `llm_max_tokens` | 기본 1024.
| `llm_auto_generate_on_sync` | 동기화 후 새로 추가된 데이터셋의 설명을 자동으로 생성합니다.
| `llm_language` | 생성 언어 (`ko`, `en` ...).
|===

생성 이력은 `catalog_ai_generation_log` 테이블에 토큰 사용량과 함께 기록됩니다.
====

[[_assistant]]
== AI 어시스턴트

image::ops-settings/assistant.png[AI 어시스턴트, 700]

화면 우측 아래의 AI 어시스턴트가 쓸 AI 서비스를 연결합니다. 위 카드는 어시스턴트가 할 수 있는 일(데이터셋 검색,
스키마 · 상세 조회, ERD · 리니지, 품질 · 표준, SQL 작성 · 검증)을 소개합니다.

. **AI 서비스 기반 어시스턴트 활성화** 를 켭니다. 켜면 AI 서비스(`argus-catalog-ai assistant`)의 도구 호출 답변을 씁니다.
  끄면 도구 없이 동작하는 **내장 단순 대화** 로 폴백합니다.
. **AI 서비스 URL** 을 넣습니다. 예: `http://localhost:8930`.
. **연결 테스트** 로 응답을 확인하고 저장합니다.

NOTE: 화면 우측 아래의 플로팅 챗 버튼은 <<_llm,LLM / AI>> 탭에서 LLM 제공자가 활성화돼 있어야 나타납니다.

설치와 도구 목록은 xref:ai/ai-service.adoc[AI 서비스], 사용법은 xref:ai/assistant.adoc[AI 어시스턴트] 를 참고하세요.

[[_query_analysis]]
== 쿼리 분석

image::ops-settings/relationships.png[쿼리 분석, 900]

수집된 쿼리 이력(Trino · Hive · Impala · StarRocks)을 다시 분석하는 관리 작업입니다. 평소에는 누를 필요가 없습니다.

* **컬럼 관계 분석 → 전체 재계산** — 실제 쿼리의 JOIN 패턴으로 컬럼 간 사용 관계(암묵 FK / 조인키)를 다시 구합니다.
  파서가 개선됐거나 기능 도입 이전 이력을 반영할 때 씁니다.
* **쿼리 lineage 해석 → lineage 전체 해석** — 쿼리에서 만든 데이터 흐름의 테이블명을 실제 데이터셋과 연결합니다.
  데이터셋이 생길 때 자동으로도 해석되므로, 이 버튼은 과거 이력을 일괄 백필할 때 씁니다.

[[_object_storage]]
== 오브젝트 스토리지

image::ops-settings/oci-model-registry.png[오브젝트 스토리지, 700]

MLflow 모델과 OCI 모델 허브의 파일(아티팩트)을 저장하는 S3 호환 스토리지(MinIO · AWS S3)입니다.

. 엔드포인트 URL, Access Key · Secret Key, 리전, SSL 사용 여부, 버킷을 넣습니다.
. **테스트** 를 누릅니다. 버킷 접근을 검증하고, 버킷이 없으면 만들어 줍니다.
. 저장합니다.

[TIP]
.고급 사용자 — 오브젝트 스토리지 설정 키
====
[cols="1,3",options="header"]
|===
| 키 | 설명

| `object_storage_endpoint` | S3 호환 엔드포인트 URL (필수).
| `object_storage_access_key` | Access Key.
| `object_storage_secret_key` | Secret Key (마스킹).
| `object_storage_region` | 리전 (`us-east-1`).
| `object_storage_use_ssl` | SSL 사용.
| `object_storage_bucket` | 버킷 (`model-artifacts`).
| `object_storage_presigned_url_expiry` | 다운로드용 presigned URL 만료 시간(초, 기본 3600).
|===
====

[[_email]]
== 이메일

image::ops-settings/email.png[이메일, 700]

알림 · 결재 등에 쓰는 SMTP 메일 발송을 설정합니다.

. **이메일 발송 활성화** 를 켭니다.
. SMTP 호스트 · 포트, STARTTLS / SSL, 발신자 이메일 · 표시 이름, SMTP 사용자 · 비밀번호(Gmail 은 앱 비밀번호),
  제목 접두어, 기본 수신자를 넣습니다.
. **테스트 메일 발송** 을 누릅니다. 현재 입력값을 **먼저 저장한 뒤** **테스트 수신자**(비우면 발신자)에게 보냅니다.

[[_notify]]
== 알림

image::ops-settings/notify.png[알림, 700]

Slack · Mattermost Incoming Webhook 으로 알림 메시지를 보냅니다.

. **알림 발송 활성화** 를 켜고 제공자를 고릅니다.
. Webhook URL, 채널 · 표시 이름 · 아이콘을 넣습니다.
. **테스트 메시지 발송** 을 누릅니다. 현재 입력값을 먼저 저장한 뒤 고른 제공자로 보냅니다.

[[_change]]
== 변경관리

image::ops-settings/change.png[변경관리, 700]

변경 요청(CR)을 만들 때 참조자(CC)에게 보낼 통지를 설정합니다. 참조자 통지 활성화와 통지 채널(이메일 · Slack ·
Mattermost)을 고릅니다. 이메일은 참조자별 주소로, Slack · Mattermost 는 <<_notify,알림>> 탭의 기본 Webhook 으로 보냅니다.
자세한 흐름은 xref:governance/change-management.adoc[변경 관리] 를 참고하세요.

[[_cache]]
== 캐시

image::ops-settings/cache.png[캐시, 700]

xref:appendix/api.adoc[External API] 의 메타데이터 캐시입니다.

* 캐시 활성화, 최대 크기(항목 수, 기본 1000), TTL(초, 기본 300)을 정합니다.
* **캐시 비우기** 로 전체를 비웁니다.
* 아래 **캐시 통계** 에서 현재 크기 · 적중률 · 적중 · 미스를 확인합니다.

== 자주 묻는 질문

[qanda]
설정 파일을 고쳤는데 값이 바뀌지 않습니다.::
  설정 파일은 최초 기동 때 DB 에 없는 항목만 채웁니다. 이후에는 이 화면의 값이 우선하니 화면에서 바꾸세요.
  항목 아래 **값 출처** 패널에서 값이 어디서 왔는지 확인할 수 있습니다.

다른 항목을 바꿀 때마다 비밀번호를 다시 넣어야 하나요?::
  아닙니다. 비밀값 입력란을 비워 두고 저장하면 기존 값이 그대로 유지됩니다.

임베딩 모델을 바꿨는데 저장되지 않습니다.::
  벡터 컬럼이 384 차원 고정이라 384 차원이 아닌 모델은 저장되지 않습니다. **연결 테스트** 로 모델의 차원을 확인하세요.

AI 어시스턴트 버튼(플로팅 챗)이 보이지 않습니다.::
  <<_llm,LLM / AI>> 탭에서 LLM 제공자가 활성화돼 있어야 나타납니다.
