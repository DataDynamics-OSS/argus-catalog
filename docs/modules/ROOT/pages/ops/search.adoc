= 검색

검색은 키워드와 시맨틱을 함께 쓰는 *하이브리드* 방식으로 동작합니다. 데이터셋의
이름·설명·플랫폼·태그·소유자를 벡터로 임베딩해 두기 때문에, 단어가 정확히 일치하지
않아도 의미가 비슷한 데이터셋까지 찾아 줍니다.

== 진입 경로

검색은 두 곳에서 시작할 수 있습니다.

* *전역 헤더 검색바* — 어느 화면에서나 곧바로 검색할 수 있습니다.
* *Search 페이지* (`/dashboard/search`) — 결과 페이지로 바로 들어갑니다.

== 검색 방식

[cols="1,2,3"]
|===
| 방식 | 쿼리 예 | 동작

| 키워드 | `customer` | 이름·설명·URN 의 부분 일치 (`ILIKE`)
| 시맨틱 | `고객 구매 이력` | 의미가 유사한 `fact_purchases`, `order_history` 까지 매칭
| 하이브리드 | `customer purchase` | 키워드 + 시맨틱 점수의 가중 결합 (기본 30% / 70%)
|===

임베딩이 꺼져 있거나 아직 설정되지 않았다면, 자동으로 키워드 검색으로 폴백됩니다.

== 임베딩 프로바이더

시맨틱 검색을 하려면 텍스트를 벡터로 바꿔 줄 *임베딩 프로바이더* 가 필요합니다. 다음
세 가지 중 하나를 고르면 됩니다.

[cols="1,2,1,1,1"]
|===
| 프로바이더 | 기본 모델 | 차원 | 한국어 | Air-gapped

| Local (sentence-transformers) | `all-MiniLM-L6-v2` | 384 | △ | O
| OpenAI | `text-embedding-3-small` | 1536 | O | X
| Ollama (로컬 호스팅) | `nomic-embed-text` | 768 | O | O
|===

한국어가 중요하다면 Local 의 `paraphrase-multilingual-MiniLM-L12-v2` 나 Ollama 의
`nomic-embed-text` 를 권장합니다.

설정 위치는 xref:ops/settings.adoc#_embedding[설정 → Embedding] 입니다.

== 임베딩 저장 (pgvector)

생성된 벡터는 PostgreSQL `catalog_dataset_embeddings` 테이블에 저장됩니다. 이때
pgvector 확장과 IVFFlat 인덱스 (코사인 유사도) 를 사용합니다.

임베딩 소스 텍스트::
----
{name} | {description} | {qualified_name} | {platform_name} | {platform_type} | {tags...} | {owners...}
----

데이터셋을 만들거나 수정하면 임베딩이 비동기로 자동 생성됩니다. 이미 있던 기존
데이터셋은 *Settings → Embedding* 의 *Backfill* 버튼을 누르거나 다음 API 로 한꺼번에
임베딩할 수 있습니다.

[source,bash]
----
POST /api/v1/catalog/search/embeddings/backfill
GET  /api/v1/catalog/search/embeddings/stats
----

stats 응답을 보면 *임베딩 커버리지* 가 어느 정도인지 확인할 수 있습니다.

[source,json]
----
{
  "total_datasets": 135,
  "embedded_datasets": 120,
  "coverage_pct": 88.9,
  "provider": "local",
  "model": "all-MiniLM-L6-v2",
  "dimension": 384
}
----

== 결과 화면

검색 결과의 각 행에는 다음 정보가 표시됩니다.

* *이름 · 플랫폼 · 환경 · 설명 (요약)*
* *score* — 0~1 범위의 점수입니다. 높을수록 잘 맞는 결과입니다.
* *match_type* — `keyword` / `semantic` / `hybrid` 중 하나입니다.
* *태그 / 소유자 카운트*

행을 클릭하면 xref:catalog/datasets.adoc[데이터셋 상세] 로 이동합니다.

== 임계값과 가중치

검색 동작은 URL 파라미터로 세밀하게 조정할 수 있습니다 (API 및 일부 UI 토글).

[cols="1,1,3"]
|===
| 파라미터 | 기본값 | 설명

| `threshold` | 0.3 | 시맨틱 최소 유사도입니다. 결과가 너무 적으면 0.1 까지 낮출 수 있습니다.
| `keyword_weight` | 0.3 | 하이브리드에서 키워드에 주는 가중치입니다.
| `semantic_weight` | 0.7 | 하이브리드에서 시맨틱에 주는 가중치입니다.
| `limit` | 20 | 최대 결과 수입니다 (1~100).
|===

== 프로바이더 전환

프로바이더를 바꾸면 벡터 공간 자체가 달라지므로 기존 임베딩과는 호환되지 않습니다.
그래서 다음 순서로 전체를 다시 임베딩해야 합니다.

. *Settings → Embedding* 에서 새 프로바이더를 저장합니다.
. *Embeddings → Reset* 으로 기존 임베딩을 삭제합니다.
. *Backfill* 로 전체를 다시 임베딩합니다.
. 차원이 다르면 (예: 384 → 1536) DBA 가 `ALTER TABLE catalog_dataset_embeddings ALTER COLUMN embedding TYPE vector(1536)` 를 실행한 뒤 backfill 합니다.
