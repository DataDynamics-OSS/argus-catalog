= 사용자 · 권한

이 화면에서는 사용자 계정과 역할 기반 권한을 관리합니다. 로그인 흐름·SSO 설정·토큰
정책 같은 인증 자체는 여기가 아니라 xref:ops/authentication.adoc[인증] 에서 다룹니다.

== 진입 경로

좌측 사이드바에서 *Administration → Users* (`/dashboard/users`) 로 들어갑니다.
`argus-admin` 역할을 가진 사용자만 접근할 수 있습니다.

== 사용자 관리

[cols="1,3"]
|===
| 동작 | 위치

| 등록
| Users 페이지의 *+ Add User* 로 등록합니다. 사용자명 · 이메일 · 비밀번호 · 역할을 지정합니다.
| 수정
| 행을 클릭해 상세로 들어간 뒤 편집합니다.
| 활성화 / 비활성화
| 상세 화면의 토글로 전환합니다.
| 비밀번호 재설정
| 상세 화면의 *Reset Password* 로 재설정합니다. Keycloak 모드라면 Keycloak 에 위임합니다.
| 삭제
| 상세에서 *Delete* 로 삭제합니다. 소프트 삭제 방식이라 감사 로그는 보존됩니다.
|===

== 역할

기본으로 제공되는 시스템 역할은 3 종입니다.

[cols="1,3"]
|===
| 역할 | 권한 범위

| `argus-admin`
| 전체 권한입니다 — 사용자 · 설정 · 모든 객체를 CRUD 할 수 있습니다.
| `argus-superuser`
| 관리 권한입니다 — 사용자 관리를 빼면 거의 모든 작업을 할 수 있습니다.
| `argus-user`
| 읽기가 기본이며, 본인이 소유한 데이터셋 / 모델은 수정할 수 있습니다.
|===

`argus-*` 역할이 *하나도 없는* 사용자는 로그인이 거부됩니다 (403).

Keycloak 모드에서는 위 역할이 Realm Role 로 매핑됩니다. 신규 사용자에게는 default
role 로 `argus-user` 가 자동으로 부여되고, `argus-admin` / `argus-superuser` 는
수동으로 부여합니다. 자세한 절차는 xref:ops/authentication.adoc#_keycloak_수동_설정[인증 →
Keycloak 수동 설정] 을 참고하세요.

== 그룹

Keycloak 모드에서는 Keycloak 의 그룹 기능을 사용합니다. 그룹에 역할을 부여하면 그
그룹 멤버에게 일괄로 상속됩니다. UI 에서의 그룹 관리는 Keycloak Admin 콘솔에
위임합니다.
