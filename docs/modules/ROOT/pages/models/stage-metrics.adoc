= Stage · 성능 · 리니지
:toc: macro
:toclevels: 2

모델을 등록하고 나면 "이 버전을 지금 운영에 쓰고 있나?", "이전 버전보다 성능이
나아졌나?", "어떤 데이터로 학습했더라?" 같은 질문이 따라옵니다. 이 장에서는 모델
버전의 배포 단계 관리, 버전별 성능 비교, 학습 데이터셋 연결을 다룹니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **스테이지 바꾸기** — 버전을 스테이징 · 운영 · 보관 단계로 옮깁니다.
* **성능 비교** — 버전별 지표를 나란히 보고 추이 차트를 확인합니다.
* **학습 데이터셋 연결** — 모델이 어떤 데이터셋으로 학습 · 평가되었는지 기록합니다.

=== 먼저 알아 둘 용어

각 모델 버전에는 다음 4 가지 스테이지 중 하나를 붙입니다.

[cols="1,1,3",options="header"]
|===
| Stage | 화면 표시 | 의미

| `NONE` | 스테이지 없음 | 초기 상태입니다 (등록 직후).
| `STAGING` | 스테이징 | 검증 중입니다 (테스트 환경 배포).
| `PRODUCTION` | 운영 | 운영 환경에서 쓰는 버전입니다.
| `ARCHIVED` | 보관 | 더 이상 쓰지 않는 버전입니다.
|===

정해진 순서는 없고 네 단계 사이를 자유롭게 오갈 수 있습니다. 다만 *운영* 으로 올리거나 *운영* 에서 내리는 변경은 별도 권한과 확인이 필요합니다.

.모델 Stage 전이
image::diagrams/models-stage-metrics-01.png[모델 Stage 전이,role="diagram"]

=== 메뉴 위치

모두 **AI 카탈로그 → MLflow 모델** 에서 모델을 눌러 연 상세 화면(`/dashboard/models/<이름>`)의 탭에서 합니다.

[cols="1,3",options="header"]
|===
| 탭 | 용도

| 버전 | 스테이지 변경
| 성능 | 버전별 지표 비교
| 리니지 | 데이터셋 연결
|===

[[_누가_바꿀_수_있나]]
=== 누가 무엇을 할 수 있나요

[cols="2,3",options="header"]
|===
| 변경 | 할 수 있는 사람

| 스테이지 없음 · 스테이징 · 보관 사이
| 관리자, 모델을 등록한 사람, 소유자
| 운영으로 올리기 · 운영에서 내리기
| 위 사람 중 *운영(Production) 단계 변경* (`models.promote`) 기능 권한이 있는 사람. 권한 관리에서 역할에 허용하지 않으면 관리자만 할 수 있습니다.
| 메트릭 기록, 데이터셋 연결 · 삭제
| 편집 권한자 (관리자, 모델을 등록한 사람, 소유자)
|===

권한이 없으면 선택 상자의 *운영* 항목이 "(권한 필요)" 로 꺼져 있고, 운영 중인 버전의 선택 상자는 비활성입니다.
편집 권한이 없는 사용자에게는 선택 상자 대신 스테이지 배지와 변경 이력만 보입니다.

[[_stage_변경]]
== 스테이지 바꾸기

. 모델 상세의 *버전* 탭을 엽니다.
. 바꿀 버전 카드 오른쪽 선택 상자에서 스테이지를 고릅니다.
. "v1 스테이지를 '스테이징'(으)로 변경했습니다." 알림이 뜨고, 선택 상자 아래에 "방금 변경 · admin" 처럼 변경 시각과 변경자가 남습니다.

*운영* 으로 올리거나 *운영* 에서 내릴 때는 확인 대화상자가 먼저 뜹니다. 이미 운영 중인 다른 버전이 있으면 함께 알려 주며,
그 버전은 그대로 운영으로 남으므로 필요하면 따로 *보관* 으로 바꿉니다.

image::models-stage-metrics/stage-confirm-production.png[운영 스테이지로 변경 확인 대화상자, 900]

[[_성능_비교]]
== 성능 비교하기

버전마다 학습 · 평가 결과를 기록해 두면 *성능* 탭에서 버전끼리 비교할 수 있습니다.

* 최신 버전이 위에 오고, 지표마다 가장 좋은 값에 *최고* 표시와 직전 버전 대비 변화가 붙습니다.
* 버전이 3개 이상이면 지표별 추이 차트도 나타납니다.
* 지표 이름은 자유롭게 정할 수 있습니다.

image::models-stage-metrics/performance.png[성능 탭 — 버전별 지표, 900]

메트릭 기록은 화면이 아니라 API 로 하며, 편집 권한자만 할 수 있습니다. 같은 이름의 지표를 다시 보내면 값이 바뀝니다.
방법은 <<_스테이지_rest_api>> 의 메트릭 항목을 보세요.

[[_모델_데이터셋_리니지]]
== 학습 데이터셋 연결하기 (리니지)

모델이 어떤 데이터셋으로 학습되었는지 기록해 둘 수 있습니다. 원천 데이터가
바뀌었을 때 *재학습이 필요한지 판단* 하는 근거가 되어 줍니다.

. *리니지* 탭에서 *데이터셋 연결* 을 누릅니다.
. 데이터셋 이름으로 검색해 고릅니다.
. *관계* · *모델 버전*(기본 *전체 버전*) · *설명* 을 정하고 *연결* 을 누릅니다.

image::models-stage-metrics/lineage-connect.png[데이터셋 연결 대화상자, 900]

*관계* 는 다음 중에서 고릅니다.

[cols="1,1,3",options="header"]
|===
| relation_type | 화면 표시 | 의미

| `TRAINING_DATA` | 학습 데이터 | 학습에 사용된 데이터입니다 (기본값).
| `EVALUATION_DATA` | 평가 데이터 | 평가/검증에 사용된 데이터입니다.
| `FEATURE_SOURCE` | 피처 소스 | 피처 추출의 원천입니다.
|===

연결하면 그래프에 데이터셋 → 모델 흐름이 그려지고 아래 목록에 행이 추가됩니다. 이 모델에서 만든 OCI 모델이
있으면 그래프 오른쪽(출력)에 함께 보입니다. 데이터셋 노드의 *열기* 로 데이터셋 상세로 이동하고, 행의 휴지통 아이콘으로 연결을 지웁니다.

image::models-stage-metrics/lineage.png[리니지 탭 — 그래프와 연결 목록, 900]

== 자주 묻는 질문

*Q. 스테이지 선택 상자에서 '운영' 이 "(권한 필요)" 로 꺼져 있습니다.* +
A. *운영(Production) 단계 변경*(`models.promote`) 기능 권한이 필요합니다. 관리자에게 요청하세요.

*Q. 새 버전을 운영으로 올렸는데 이전 운영 버전도 그대로 운영입니다.* +
A. 이전 버전은 자동으로 내려가지 않습니다. 필요하면 그 버전을 따로 *보관* 으로 바꾸세요.

*Q. 성능 탭이 비어 있습니다.* +
A. 지표는 API 로 기록해야 나타납니다. <<_스테이지_rest_api>> 를 보세요.

*Q. 데이터셋을 연결하는데 409 오류가 납니다.* +
A. 같은 데이터셋 · 관계 · 버전 조합이 이미 연결되어 있습니다.

[[_스테이지_rest_api]]
== 부록: REST API

[[_api]]
=== 스테이지 변경

[source,bash]
----
PUT /api/v1/models/{name}/versions/{ver}/stage
{ "stage": "PRODUCTION" }
→ {"status": "ok", "model": "...", "version": 1, "stage": "PRODUCTION",
   "stage_changed_by": "admin", "stage_changed_at": "2026-11-07T10:00:00+00:00"}
----

* `stage` 는 `NONE` · `STAGING` · `PRODUCTION` · `ARCHIVED` 중 하나이며 대소문자를 가리지 않습니다. 그 밖의 값은 400 입니다.
* *변경자* 는 요청 본문이 아니라 로그인한 사용자로 기록됩니다(본문의 `changed_by` 는 무시). 버전 조회 응답의 `stage_changed_by` · `stage_changed_at` 으로 확인합니다.
* 편집 권한이 없거나, 운영 변경인데 `models.promote` 권한이 없으면 403 입니다.

=== 메트릭 기록 · 조회

[source,bash]
----
POST /api/v1/models/{name}/versions/3/metrics
{ "metrics": { "accuracy": 0.91, "f1": 0.88, "latency_ms": 18 } }
→ {"status": "ok", "model": "...", "version": 3, "metrics_count": 3}

GET /api/v1/models/{name}/metrics
→ [
    {"version": 1, "metrics": {"accuracy": 0.82, "f1": 0.78}},
    {"version": 3, "metrics": {"accuracy": 0.91, "f1": 0.88, "latency_ms": 18.0}}
  ]
----

`metrics` 는 `{이름: 숫자}` 형식의 비어 있지 않은 객체여야 하고(아니면 400), 없는 버전이면 404 입니다.

=== 데이터셋 연결

편집 권한자만 호출할 수 있습니다. `model_version` 을 빼거나 `null` 로 두면 전체 버전에 연결됩니다.

[source,bash]
----
POST /api/v1/models/{name}/lineage
{
  "dataset_id": 42,
  "model_version": 3,
  "relation_type": "TRAINING_DATA",
  "description": "2025년 고객 주문 데이터"
}
→ {"id": 7, "model": "...", "dataset_id": 42, "relation_type": "TRAINING_DATA"}

GET    /api/v1/models/{name}/lineage          # 연결 목록 (데이터셋 이름 · 소스 종류 포함)
DELETE /api/v1/models/{name}/lineage/{id}
----

`dataset_id` 누락 · 잘못된 `relation_type` 은 400, 없는 데이터셋 · 버전은 404, 같은 데이터셋 · 관계 · 버전 조합이 이미 있으면 409 입니다.
