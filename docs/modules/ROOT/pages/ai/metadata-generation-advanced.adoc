= AI 메타데이터 자동 생성 — 고급
:toc: macro

이 페이지는 xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 의 고급 사용자용 부록입니다.
내부 동작, 프롬프트 컨텍스트, REST API 와 응답 형식, 제안 관리 · 통계 API 를 다룹니다.
화면에서 생성하는 방법은 본문 페이지를 먼저 보세요.

toc::[]

== 동작 개요

UI 에서 트리거하면 서버의 AI 모듈이 데이터셋 정보로 컨텍스트를
조립해 LLM 프로바이더에 보내고, 돌아온 결과를 파싱해 다시 UI 에 돌려줍니다.

----
┌────────────┐    ┌──────────────┐    ┌────────────────────┐
│  UI        │───▶│ 서버 AI 모듈 │───▶│ LLM Provider       │
│  (트리거)  │◀───│ (컨텍스트    │◀───│ Ollama / OpenAI /  │
│            │    │  조립·파싱)  │    │ Claude             │
└────────────┘    └──────┬───────┘    └────────────────────┘
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
       Dataset/Schema  Parquet     ai_generation_log
                       샘플 데이터  (감사 이력)
----

어느 경로로 호출하든 내부적으로는 대상 데이터셋의 정보를 모아 프롬프트를 구성하고,
LLM 에 보낸 뒤 돌아온 결과를 검수해 반영하는 순서로 진행됩니다.

[[_프롬프트_컨텍스트]]
== 프롬프트 컨텍스트

생성 품질은 LLM 에 어떤 정보를 함께 전달하느냐에 달려 있습니다. 서버 AI 모듈은 다음
정보를 모아 프롬프트에 담아 보냅니다.

[cols="1,2",options="header"]
|===
| 정보 | 출처

| 테이블명, DB명 | `catalog_datasets`
| 컬럼명, 타입, 제약조건 | `catalog_dataset_schemas`
| DDL | `catalog_datasets.datasource_properties` 의 `ddl`
| 샘플 데이터 (최대 5행) | `<data.dir>/samples/<데이터 소스 ID>/<데이터셋 이름>/sample.parquet`
| 행 수 추정치 | `catalog_datasets.datasource_properties` 의 `estimated_rows`
| 데이터 소스 유형 | `catalog_datasources.type`
| 표준 단어 (약어 → 이름) | 활성 데이터 표준 사전의 단어 — 설명 · 컬럼 설명 · 태그 · PII 생성에 사용
| 상 · 하류 데이터셋 (각 최대 10개) | 리니지 — 설명 · 컬럼 설명 · 태그 생성에 사용
| Few-shot 예시 (최대 3건) | 같은 데이터 소스 유형에서 적용된 이전 AI 생성 결과(없으면 직접 작성된 설명) — 설명 생성에 사용
|===

샘플 데이터는 메타데이터 동기화 시 자동으로 수집된 Parquet 파일을 그대로 재사용합니다.

[[_설정_api]]
== 설정 API

화면의 *설정 → LLM / AI* 와 같은 설정을 API 로도 적용할 수 있습니다.

[source,bash]
----
curl -X PUT http://<server>:4600/api/v1/settings/llm \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "provider": "ollama",
    "model": "qwen2.5:7b",
    "api_key": "",
    "api_url": "http://localhost:11434",
    "temperature": 0.3,
    "max_tokens": 1024,
    "auto_generate_on_sync": false,
    "language": "ko"
  }'
----

설정 항목은 다음과 같습니다.

[cols="1,1,3",options="header"]
|===
| 키 | 기본값 | 설명

| `enabled` | false | 기능 활성화
| `provider` | openai | openai / ollama / anthropic
| `model` | gpt-4o-mini | 모델 식별자
| `api_key` | (빈값) | API 키 (Ollama 불필요)
| `api_url` | (빈값) | 엔드포인트 오버라이드
| `temperature` | 0.3 | 0.0~1.0, 낮을수록 사실적
| `max_tokens` | 1024 | 응답 토큰 한도
| `auto_generate_on_sync` | false | sync 후 빈 설명 자동 채움
| `language` | ko | 생성 언어 (`ko`, `en`, `ja`, `zh`)
|===

== 5가지 생성 유형과 API

생성할 수 있는 메타데이터는 다섯 가지입니다. 각각 별도 엔드포인트로 호출하며,
용도에 따라 필요한 것만 골라 쓸 수 있습니다.

[cols="1,2,3",options="header"]
|===
| 기능 | 엔드포인트 | 설명

| 요약 | `POST /api/v1/ai/datasets/{id}/summarize` | 한 줄 요약
| 테이블 설명 | `POST /api/v1/ai/datasets/{id}/describe` | 테이블 목적·내용 텍스트
| 컬럼 설명 | `POST .../describe-columns` | 모든 컬럼 용도 일괄 생성
| 태그 추천 | `POST .../suggest-tags` | 기존 태그 활용 + 새 태그 제안
| PII 탐지 | `POST .../detect-pii` | 개인정보 컬럼 탐지
|===

`POST /api/v1/ai/datasets/{id}/generate-all` 을 호출하면 요약을 뺀 설명 · 컬럼 설명 · 태그 · PII 네 가지를 한 번에 수행합니다.

데이터셋 단위 생성 API 는 기능 권한 *AI 메타데이터 생성*(`ai.generate`)과 그 데이터셋의 편집 권한(생성자 또는
관리자)이 있어야 호출할 수 있습니다.

=== API로 개별 생성

[source,bash]
----
# 미리보기 (apply=false)
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/describe \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"apply": false}'

# 즉시 적용 (apply=true)
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/describe \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"apply": true}'

# 전체 생성
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/generate-all \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"apply": true}'
----

[[_일괄_생성_api]]
=== 일괄 생성 API

UI 의 *설정 → LLM / AI → AI 일괄 생성* 과 같은 기능을 API 로 호출합니다. 일괄 생성은 관리자 전용입니다.
`generation_types` 에는 `description` · `columns` · `tags` · `pii` 를 넣을 수 있습니다(요약은 일괄 생성 대상이 아님).

[source,bash]
----
# 설명 없는 데이터셋에만 description 자동 생성
curl -X POST http://<server>:4600/api/v1/ai/bulk-generate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "generation_types": ["description"],
    "apply": true,
    "empty_only": true
  }'

# 특정 데이터 소스만 전체 생성 (datasource_id 는 데이터 소스의 내부 숫자 ID)
curl -X POST http://<server>:4600/api/v1/ai/bulk-generate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "generation_types": ["description", "columns", "tags", "pii"],
    "apply": true,
    "empty_only": true,
    "datasource_id": 1
  }'
----

== 응답 스키마

각 생성 유형이 돌려주는 결과의 형태입니다.

테이블 설명::
[source,json]
----
{
  "dataset_id": 1,
  "description": "영화 텍스트 정보(제목, 설명)를 전문 검색용으로 저장하는 테이블",
  "confidence": 0.87,
  "applied": false,
  "log_id": 42
}
----

컬럼 설명::
[source,json]
----
{
  "dataset_id": 1,
  "columns": [
    {"field_path": "film_id", "description": "영화 고유 식별자 (PK)", "confidence": 0.95, "had_existing": false},
    {"field_path": "title", "description": "영화 제목", "confidence": 0.92, "had_existing": false}
  ],
  "total_generated": 2,
  "applied": false
}
----

태그 추천::
[source,json]
----
{
  "dataset_id": 1,
  "suggested_tags": ["영화", "미디어"],
  "new_tags": [{"name": "콘텐츠", "description": "콘텐츠 관련 데이터"}],
  "applied_tags": ["영화"],
  "created_tags": ["콘텐츠"]
}
----

PII 탐지::
[source,json]
----
{
  "dataset_id": 1,
  "pii_columns": [
    {"name": "email", "pii_type": "EMAIL", "confidence": 0.95,
     "reason": "Column name and sample values match email pattern"},
    {"name": "phone_number", "pii_type": "PHONE", "confidence": 0.88,
     "reason": "Column contains phone number format"}
  ]
}
----

PII 유형 — `EMAIL`, `PHONE`, `SSN`, `NAME`, `ADDRESS`, `CREDIT_CARD`, `IP_ADDRESS`,
`DATE_OF_BIRTH`, `NATIONAL_ID`, `OTHER`. 탐지 결과는
`catalog_dataset_schemas.pii_type` 컬럼에 저장됩니다.

[[_제안_관리]]
== 제안 관리

미리보기 모드(`apply=false`)로 생성한 결과와 AI 서비스 enrich 가 반입한 결과(`provider=agent`)는
`catalog_ai_generation_log` 에 `applied=false` 로 보존되므로, 나중에 하나씩 적용하거나 거부할 수 있습니다.
화면에서는 데이터셋 상세의 *AI 제안* 버튼으로 합니다 — xref:ai/metadata-generation.adoc#_제안_검토[제안을 나중에 검토하기].
아래 API 는 같은 동작을 스크립트로 할 때 씁니다. 적용 · 거부는 그 데이터셋의 생성자 또는 관리자만 할 수 있습니다(일괄 적용은
목록에 남의 데이터셋 제안이 하나라도 섞이면 403).

[source,bash]
----
# 미적용 제안 목록
curl -H "Authorization: Bearer $TOKEN" http://<server>:4600/api/v1/ai/datasets/1/suggestions

# 적용 / 거부
curl -X POST -H "Authorization: Bearer $TOKEN" http://<server>:4600/api/v1/ai/suggestions/42/apply
curl -X POST -H "Authorization: Bearer $TOKEN" http://<server>:4600/api/v1/ai/suggestions/42/reject

# 여러 제안을 한 번에 적용
curl -X POST http://<server>:4600/api/v1/ai/suggestions/apply-batch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"suggestion_ids": [42, 43]}'
----

목록의 각 항목에는 비교용 현재 값 `current_text` 가 들어 있습니다. 설명 · 요약 · 컬럼 설명은 평문, 태그는 현재 태그 이름의
JSON 배열, PII 는 제안에 나온 컬럼별 현재 유형의 JSON 배열(`[{"name", "pii_type"}]`)입니다. 태그 제안의 `generated_text` 는
서버 생성이면 `{"tags": [...], "new_tags": [...]}`, enrich 반입이면 태그 이름 배열이며, 적용할 때 없는 태그는 새로 만듭니다.

== 통계 / 감사

지금까지 얼마나 생성했고 적용률은 어떤지 보려면 통계 API 를 호출합니다.

[source,bash]
----
curl -H "Authorization: Bearer $TOKEN" http://<server>:4600/api/v1/ai/stats
----

응답 예시는 다음과 같습니다.

[source,json]
----
{
  "total_generations": 156,
  "applied_count": 120,
  "pending_count": 36,
  "total_prompt_tokens": 89420,
  "total_completion_tokens": 34210,
  "description_coverage": {
    "total_datasets": 200,
    "described_datasets": 120,
    "coverage_pct": 60.0
  },
  "provider": "ollama",
  "model": "qwen2.5:7b"
}
----

모든 호출은 *입력 / 출력 / 토큰 / 적용 여부* 와 함께 `catalog_ai_generation_log`
테이블에 기록됩니다. 감사 추적이 필요할 때 그대로 활용할 수 있습니다.
