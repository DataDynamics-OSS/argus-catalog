= Fine-tuning 가이드
:toc: macro
:toclevels: 2

[IMPORTANT]
.이 페이지는 고급 사용자용입니다
====
GPU 서버 · Python 학습 환경 · LLM 학습 경험이 필요한 작업을 다룹니다.
일반 사용자는 xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 만 알면 충분합니다.
Fine-tuning 없이 품질을 올리려면 아래 <<_stage_1_프롬프트_강화,1. 프롬프트 강화>> 만 해도 효과가 큽니다.
====

범용 LLM 만으로도 메타데이터를 그럴듯하게 생성할 수 있지만, 고객사만의 약어나
도메인 용어까지 정확히 담아내기는 어렵습니다. 이 가이드는
xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 의 품질을 고객사 도메인에
맞춰 *극대화* 하기 위한 LLM Fine-tuning 파이프라인을 다룹니다. 범용 LLM 대신 고객사
데이터로 학습한 전용 모델을 사내 Ollama 에서 서빙합니다.

== 한눈에 보기

전체 작업은 다음 순서로 진행합니다. 각 단계는 아래 같은 번호의 절에서 설명합니다.

. *준비* — 학습용 GPU 서버와 Python 환경을 갖춥니다.
. *프롬프트 강화* — 용어사전(표준 단어)을 등록해 학습 없이 품질을 올립니다.
. *학습 데이터 추출* — 카탈로그 DB 와 합성 데이터를 JSONL 로 뽑습니다.
. *베이스 모델 선정* — 기본 권장은 Qwen2.5-7B-Instruct 입니다.
. *LoRA 학습* — `scripts/finetune.py` 로 학습합니다.
. *병합 · 변환 · 등록* — LoRA 를 병합하고 GGUF 로 바꿔 Ollama 에 등록합니다.
. *운영 연동* — 설정에서 모델을 `argus-metadata` 로 바꿉니다.
. *재학습* — 승인된 결과가 쌓이면 주기적으로 다시 학습합니다.

== 왜 Fine-tuning 이 필요한가

범용 LLM 은 똑똑하지만, 고객사 현장에 그대로 쓰기에는 다음과 같은 한계가 있습니다.

[cols="1,3",options="header"]
|===
| 한계 | 예시

| 약어 해석 불가 | `eqp_stat_cd` → "장비상태코드"를 알 수 없음
| 도메인 지식 부족 | 반도체 Fab 의 FDC / SPC / Yield 용어 모름
| 설명 스타일 불일치 | 고객사 선호 톤·표현이 반영되지 않음
| 비용 / 레이턴시 | 외부 API 호출 비용 + 네트워크 지연
| 보안 | 메타데이터가 외부 API 로 전송 (에어갭 불가)
|===

Fine-tuning 으로 이 한계들을 넘어 *도메인 특화*, *스타일 일관성*, *자체 서빙*,
*비용 0* 을 달성합니다.

=== 데이터 플라이휠 (Data Flywheel)

Fine-tuning 은 한 번 하고 끝나는 작업이 아닙니다. 쓸수록 데이터가 쌓이고, 그
데이터로 모델이 다시 좋아지는 선순환 구조로 돌아갑니다.

.프롬프트 강화부터 운영 피드백까지
image::diagrams/ai-fine-tuning-01.png[프롬프트 강화부터 운영 피드백까지,role="diagram"]

각 단계를 좀 더 풀어 쓰면 다음과 같습니다.

----
[Stage 1 — 즉시]
용어사전 시드 → 프롬프트 컨텍스트 주입 → 범용 LLM 생성 → 사용자 검수 (적용 / 닫기)
                                                       ↓
[Stage 2 — Fine-tuning]
applied=True 데이터 축적 → 학습 데이터 추출 → LoRA Fine-tuning → 병합 + GGUF + Ollama 등록
                                                                            ↓
[Stage 3 — 운영]
Fine-tuned 모델로 생성 → 검수 → 추가 학습 데이터 축적 → 주기적 재학습
----

== 준비 — 인프라 요구사항

학습은 일반 서버보다 높은 사양을 요구합니다. Fine-tuning 서버 사양 예시는 다음과
같습니다.

[cols="1,3",options="header"]
|===
| 항목 | 사양

| GPU | NVIDIA GB10 (120 GB unified memory)
| CPU | Grace (ARM aarch64), 20 코어
| RAM | 128 GB
| 디스크 | 1.9 TB NVMe (학습 산출물 + GGUF)
| OS | Ubuntu 24.04 LTS
| Ollama | 0.13+
|===

학습 환경 — Python 3.12, PyTorch 2.11 (cu130), transformers 5.3, peft 0.18,
trl 0.29, datasets 4.8, accelerate 1.13.

[NOTE]
====
GPU 가 부족한 환경에서는 *QLoRA + 4-bit 양자화* 를 쓰면 단일 16 GB GPU 에서도 7B
모델을 fine-tuning 할 수 있습니다. 다만 `scripts/finetune.py` 는 모델을 BF16 으로 읽고 4-bit 양자화
옵션이 없으므로, QLoRA 를 쓰려면 스크립트의 모델 로드 부분을 직접 고쳐야 합니다.
====

이 페이지의 스크립트는 모두 소스의 `backend/` 에서 실행합니다.

[[_stage_1_프롬프트_강화]]
== 프롬프트 강화 (Stage 1)

가장 먼저 할 일은 학습이 아니라 프롬프트를 풍부하게 만드는 것입니다. Fine-tuning
없이도 *즉시* 품질을 올릴 수 있습니다. 서버는 다음 3 가지 컨텍스트를 프롬프트에 자동으로
주입합니다.

[cols="1,2,3",options="header"]
|===
| 컨텍스트 | 출처 | 효과

| 용어사전
| `catalog_standard_word` 테이블
| 약어 → 한글/영문 의미 매핑 (예: `LOT` → 로트, `EQP` → 장비)

| 리니지
| `argus_dataset_lineage` 테이블
| 업/다운스트림 데이터 흐름 이해

| Few-shot
| `catalog_ai_generation_log` (applied=True) 또는 수동 description
| 설명 스타일·톤 학습
|===

설계 원칙은 다음과 같습니다.

* 용어사전은 *컬럼명에 실제 등장하는 약어만* 필터링합니다 (토큰 효율).
* Few-shot 은 *같은 플랫폼 타입* 의 승인된 예시를 우선합니다.
* 모든 컨텍스트는 *선택적*입니다 — 데이터가 없으면 빈 문자열로 처리해 하위 호환을 유지합니다.

자세한 사용자 워크플로우는 xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 을 참조하세요.

미리 등록하면 *Fine-tuning 없이도* 약어 해석 품질이 크게 향상됩니다.

| StandardDomain | 33 | 식별자(7), 명칭(2), 코드(2), 수량(4), 측정값(7종), 날짜(3), 기타(3)

+
[source,bash]

[[_stage_2_fine_tuning]]
== 학습 데이터 추출 (Stage 2 시작)

프롬프트 강화만으로 부족하다면 본격적으로 모델을 학습시킬 차례입니다. 학습 데이터를
모아 LoRA 방식으로 전용 모델을 만듭니다. 먼저 두 데이터 소스를 JSONL (ChatML 포맷) 으로 변환합니다.

소스 1 — 카탈로그 DB의 기존 메타데이터::
[cols="2,1,3",options="header"]
|===
| 태스크 | 건수 | 추출 기준

| 데이터셋 설명 | 17 | `description IS NOT NULL AND LENGTH >= 10`
| 컬럼 설명 | 10 | 2개 이상 컬럼에 설명 있는 데이터셋
| 태그 추천 | 15 | 1개 이상 태그 매핑된 데이터셋
|===

소스 2 — 합성 도메인 데이터::
반도체 Fab 의 경우 15 개 표준 테이블 (`mes.tb_lot_mst`, `fdc.tb_fdc_trace`,
`spc.tb_spc_data`, `yield.tb_wafer_sort` 등) 에 전문가 수준의 설명을
직접 작성해 45 건을 추가합니다.

추출 스크립트를 실행합니다.

[source,bash]
----
cd backend

# DB + 합성 데이터 합산
python3 scripts/export_training_data.py --output-dir ./training_data

# DB 없이 합성 데이터만 (초기 부트스트랩)
python3 scripts/export_training_data.py --output-dir ./training_data --skip-db
----

JSONL 포맷 (ChatML) 의 예시는 다음과 같습니다.

[source,json]
----
{
  "messages": [
    {"role": "system", "content": "You are a data catalog assistant..."},
    {"role": "user", "content": "Generate a concise description for this database table.\n\n== Terminology glossary ==\n  LOT: 로트 (Lot)\n  ...\n\nTable: mes.tb_lot_mst\nColumns:\n  lot_id (VARCHAR(30)) PK NOT NULL\n  ..."},
    {"role": "assistant", "content": "{\"description\": \"로트 마스터 테이블. ...\", \"confidence\": 0.95}"}
  ]
}
----

== 베이스 모델 선정

어떤 모델을 토대로 학습할지도 중요합니다. 후보는 다음과 같습니다.

[cols="2,1,1,2",options="header"]
|===
| 후보 | 한국어 | JSON 안정성 | 라이선스

| *Qwen2.5-7B-Instruct (권장)* | 우수 | 매우 좋음 | Apache 2.0
| EXAONE-3.5-7.8B | 최우수 | 좋음 | 비상업 무료
| Llama-3.1-8B | 보통 | 좋음 | Llama License
|===

Apache 2.0 라이선스에 한국어와 JSON 안정성까지 두루 좋은 *Qwen2.5-7B-Instruct* 를
권장합니다.

== LoRA 학습 실행

다음 명령으로 학습을 실행합니다.

[source,bash]
----
python3 scripts/finetune.py \
    --base-model Qwen/Qwen2.5-7B-Instruct \
    --train-file ./training_data/train.jsonl \
    --eval-file ./training_data/eval.jsonl \
    --output-dir ./output/argus-metadata-7b-lora \
    --epochs 5 --batch-size 2 --grad-accum 4 --lora-r 16
----

=== LoRA 하이퍼파라미터

학습에 사용하는 주요 하이퍼파라미터와 그 이유는 다음과 같습니다.

[cols="2,1,3",options="header"]
|===
| 파라미터 | 값 | 이유

| LoRA rank (r) | 16 | 7B 모델 대비 적절한 표현력 (40 M params, 0.53%)
| LoRA alpha | 32 | r 의 2배 (일반 권장값)
| Target modules | q/k/v/o/gate/up/down_proj | Attention + FFN 전체
| Learning rate | 2e-4 | LoRA 표준 범위
| Epochs | 5 | 87건 소량 데이터에 적합
| Batch size | 2 × 4 (accum) = 8 | GPU 메모리 활용
| Precision | BF16 | 고VRAM GPU(120 GB급)로 양자화 불필요
| Max seq length | 2048 | 프롬프트 + 응답 포함
|===

=== 학습 결과 예시

실제 87 건 데이터로 학습했을 때의 결과 예시는 다음과 같습니다.

[cols="1,1,1,1",options="header"]
|===
| Epoch | Train Loss | Eval Loss | Token Accuracy

| 1 | 0.7164 | 0.9466 | 82.0 %
| 2 | 0.4638 | 0.5934 | 90.3 %
| 3 | 0.2501 | 0.5061 | 92.4 %
| 4 | 0.1428 | 0.4862 | 92.5 %
| 5 | 0.1838 | 0.4847 | 92.6 %
|===

학습 시간은 *10 분* (고VRAM GPU 기준), Best eval loss 는 *0.48*, Trainable params 는
*40 M / 7.6 B (0.53 %)* 로, 소량 데이터로도 짧은 시간에 충분한 품질에 도달합니다.

== 모델 병합 + GGUF + Ollama 등록

학습이 끝나면 LoRA 어댑터를 베이스 모델에 합치고, Ollama 가 읽을 수 있는 GGUF
형식으로 변환해 등록합니다. 전체 변환 흐름은 다음과 같습니다.

----
Qwen2.5-7B-Instruct (베이스) + LoRA adapter
    ↓ merge_and_unload()
Merged SafeTensors (FP16, ~15 GB)
    ↓ llama.cpp convert_hf_to_gguf.py
GGUF FP16 (15.2 GB)
    ↓ ollama create
argus-metadata:latest (Ollama)
----

. LoRA 를 병합합니다.
+
[source,bash]
----
python3 scripts/merge_and_convert.py \
    --base-model Qwen/Qwen2.5-7B-Instruct \
    --lora-dir ./output/argus-metadata-7b-lora/checkpoint-40 \
    --output-dir ./output/argus-metadata-7b-merged
----
. GGUF 로 변환합니다 (llama.cpp 필요).
+
[source,bash]
----
cd /path/to/llama.cpp
python3 convert_hf_to_gguf.py \
    /path/to/argus-metadata-7b-merged \
    --outfile argus-metadata-7b-f16.gguf --outtype f16
----
. Modelfile 을 만들고 Ollama 에 등록합니다.
+
[source,bash]
----
cat > Modelfile << 'EOF'
FROM ./argus-metadata-7b-f16.gguf

SYSTEM "You are a data catalog assistant that generates metadata for database tables. Always respond with valid JSON only, no markdown fences or extra text."

PARAMETER temperature 0.3
PARAMETER num_predict 1024
PARAMETER top_p 0.9
PARAMETER stop "<|im_end|>"
PARAMETER stop "<|endoftext|>"
EOF

ollama create argus-metadata -f Modelfile
----

[[_stage_3_운영_연동]]
== 운영 연동 (Stage 3)

이제 만든 모델을 실제 운영에 붙일 차례입니다. Fine-tuned 모델은 *코드 변경 없이*
Catalog Server 의 AI 모듈과 그대로 연동됩니다.

. xref:ops/settings.adoc#_llm[설정 → LLM / AI] 에서 제공자를 `ollama`, 모델을 `argus-metadata`, API URL 을 `http://<ollama-host>:11434` 로 바꿉니다.
. *연결 테스트* 후 *저장* 합니다.

[TIP]
.고급 사용자 — DB 에서 직접 바꾸기
====
DB 에서 다음과 같이 한 줄씩 변경해도 됩니다. DB 를 직접 바꾼 경우에는 카탈로그 서버를 재시작해야 반영됩니다.

[source,sql]
----
UPDATE catalog_configuration SET config_value = 'ollama'          WHERE config_key = 'llm_provider';
UPDATE catalog_configuration SET config_value = 'argus-metadata'  WHERE config_key = 'llm_model';
UPDATE catalog_configuration SET config_value = 'http://<ollama-host>:11434' WHERE config_key = 'llm_api_url';
UPDATE catalog_configuration SET config_value = 'true'            WHERE config_key = 'llm_enabled';
----
====

=== 운영 흐름

연동이 끝나면 한 건의 생성은 다음 단계를 거칩니다.

.생성 결과 검수와 학습 데이터 누적
image::diagrams/ai-fine-tuning-02.png[생성 결과 검수와 학습 데이터 누적,role="diagram"]

. UI 또는 자동 동기화가 `POST /api/v1/ai/datasets/{id}/describe` 를 호출합니다.
. 서버가 데이터셋 + 스키마 + 용어사전 + 리니지 + Few-shot 을 로드합니다.
. 프롬프트를 빌드한 뒤 `argus-metadata` 모델을 호출합니다.
. 결과를 `catalog_ai_generation_log` 에 저장합니다 (`applied=false`).
. 사용자가 검수해 *적용* 하면 `applied=true` 로 마킹됩니다.
. *applied=true* 행이 다음 Fine-tuning 학습 데이터로 자동 누적됩니다.

[[_재학습_continuous_improvement]]
== 재학습 (Continuous Improvement)

데이터가 쌓이면 모델도 한 번 더 좋아질 수 있습니다. 다만 매번 재학습할 필요는
없으므로, 다음 시점을 기준으로 삼습니다.

=== 언제 재학습하나

* 신규 `applied=True` 데이터가 이전 학습 대비 *+50 건* 이상 쌓였을 때.
* 고객사에 신규 도메인 테이블이 대량으로 등록되었을 때.
* Reject 비율이 *30 %* 이상일 때.

=== 절차

재학습은 처음 학습과 거의 같은 절차를 따릅니다.

[source,bash]
----
# 1. 최신 학습 데이터 추출
python3 scripts/export_training_data.py --output-dir ./training_data_v2

# 2. 베이스 모델에서 다시 학습 (이전 모델 누적 학습 X)
python3 scripts/finetune.py \
    --train-file ./training_data_v2/train.jsonl \
    --eval-file ./training_data_v2/eval.jsonl \
    --output-dir ./output/argus-metadata-7b-lora-v2

# 3. 병합 + GGUF + Ollama 재등록
----

=== 고객사별 모델 관리

고객사마다 도메인이 다르므로 모델도 따로 두는 편이 좋습니다. 각 고객사가 자체
데이터로 별도 모델을 학습해 독립적으로 운영할 수 있습니다.

----
고객사 A (제조)  → argus-metadata-mfg   : 반도체 MES/FDC/SPC 특화
고객사 B (금융)  → argus-metadata-fin   : 거래/계좌/리스크 특화
고객사 C (공공)  → argus-metadata-gov   : 민원/예산/인사 특화
----
