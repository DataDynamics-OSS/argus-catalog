= AI 서비스 (argus-catalog-ai-service)
:toc: macro
:toclevels: 2

AI 서비스는 카탈로그 서버와 따로 띄우는 AI 전용 프로그램입니다.
화면 우하단 xref:ai/assistant.adoc[AI 어시스턴트] 의 답변을 만들고, 데이터셋 설명을 LLM 으로 대량 생성합니다.

이 문서는 AI 서비스를 설치하고 카탈로그에 연결하는 **운영자**를 위한 안내입니다. 순서대로 따라 하면 됩니다.
**고급 사용자** 상자와 맨 끝 부록은 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **AI 어시스턴트 답변** — 어시스턴트가 카탈로그 도구(검색 · 스키마 · 품질 · 리니지 등)를 직접 호출해 실데이터를 근거로 답하게 합니다.
* **메타데이터 대량 생성** — 데이터셋의 설명 · 요약 · 컬럼 설명 · 태그 · PII 를 LLM 으로 만들어 카탈로그에 넣습니다.
* **빈 설명 자동 채우기** — 상시 워커가 설명 없는 데이터셋을 주기적으로 찾아 채웁니다.
* **로컬 LLM 사용** — ollama 같은 로컬 모델을 쓰면 스키마 · 샘플이 외부로 나가지 않습니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| assistant
| AI 어시스턴트의 채팅 서버입니다. 기본 포트는 `8930` 입니다.

| enrich
| LLM 으로 메타데이터를 생성해 카탈로그에 넣는 배치 명령과 상시 워커입니다.

| LLM 엔드포인트
| OpenAI 호환 LLM 주소입니다(ollama · vLLM · OpenAI 등). 기본값은 로컬 ollama 의 `qwen2.5:7b` 입니다.

| AI 제안
| 생성 결과를 바로 반영하지 않고 승인 · 거절을 기다리도록 남긴 것입니다.
|===

패키지 이름은 `argus-catalog-ai-service`, 명령은 `argus-catalog-ai` 입니다. 하나의 패키지가 assistant 와 enrich 를 모두 담고 있습니다.

[NOTE]
====
카탈로그 서버에도 xref:ai/metadata-generation.adoc[메타데이터 자동 생성] 기능이 내장되어 있습니다.
화면에서 데이터셋 하나씩 생성할 때는 내장 기능이 편하고, AI 서비스의 enrich 는 **서버 밖에서**
대량으로 돌리거나 주기적으로 빈 설명을 채울 때 씁니다. 둘 다 결과를 같은 *AI 제안* 으로 남기므로
승인 · 거절 방식은 같습니다.
====

=== 메뉴 위치

[cols="1,3",options="header"]
|===
| 메뉴 | 용도

| 설정 → AI 어시스턴트 | AI 서비스 기반 어시스턴트 활성화, AI 서비스 URL 지정 · 연결 테스트
| 설정 → LLM / AI | 내장 단순 대화와 내장 메타데이터 생성이 쓰는 LLM 제공자
|===

=== 누가 무엇을 할 수 있나요

[cols="2,3",options="header"]
|===
| 작업 | 필요한 권한

| AI 어시스턴트로 채팅 | 기능 권한 *AI 어시스턴트 사용*(`ai.assistant`, 기본은 모든 역할 허용)
| enrich 실행 | 결과를 카탈로그에 반입하므로 **관리자 권한 계정**이 필요합니다. 운영에서는 전용 서비스 계정 `argus` 를 만들어 씁니다(<<_서비스_계정_만들기>>).
| AI 제안 승인 · 거절 | 데이터셋을 만든 사람(생성자) 또는 관리자 — 데이터셋 상세의 *AI 제안* 버튼
|===

assistant 는 카탈로그 서버가 넘겨준 **사용자 토큰**으로 도구를 호출합니다. 사용자가 볼 수 없는
데이터는 어시스턴트도 보지 못하며, 별도 계정이 필요 없습니다.

[TIP]
.고급 사용자 — 왜 별도 서비스인가, 전체 구성
====
[cols="1,3",options="header"]
|===
| 관점 | 효과

| 자원 분리 | LLM(GPU)을 API 서버와 다른 머신에 둘 수 있어 카탈로그 서버를 가볍게 유지합니다.
| 데이터 주권 | 로컬 모델을 쓰면 스키마 · 샘플이 외부로 나가지 않습니다(PII 감지에 중요).
| 독립 확장 | 대량 생성 시 AI 서비스만 늘리면 됩니다.
| 가벼운 설치 | Python 표준 라이브러리만 사용해 별도 의존성이 없습니다.
|===

== 설치하기

설치 환경에 맞는 방법 하나를 고릅니다.

=== RPM · tar.gz (폐쇄망 운영 환경)

Rocky Linux / RHEL 8 · 9 용 패키지가 릴리스에 포함됩니다. 인터넷 없이 설치되며 `python3.11` 만 있으면 됩니다.

. 패키지를 설치합니다.
+
[source,bash]
----
dnf install -y ./argus-catalog-ai-service-<버전>-1.x86_64.rpm
# 또는
tar xzf argus-catalog-ai-service-<버전>-x86_64.tar.gz
sudo ./argus-catalog-ai-service-<버전>/install.sh
----
. enrich 를 쓸 거라면 카탈로그에 서비스 계정 `argus` 를 먼저 만듭니다. 방법은 아래 <<_서비스_계정_만들기>> 를 보세요.
  assistant 만 쓸 때는 필요 없습니다.
. 설정 파일 `/etc/argus-catalog-ai-service/ai-service.env` 에서 카탈로그 서버 주소(`ARGUS_API_URL`)와 LLM 주소(`ARGUS_AI_LLM_URL`)를 맞춥니다.
  enrich 를 쓸 거라면 `ARGUS_USERNAME=argus`(기본으로 들어 있음)는 그대로 두고, 앞 단계에서 정한 비밀번호를 `ARGUS_PASSWORD` 에 적습니다.
  전체 항목은 <<_부록_a_환경변수>> 를 보세요.

설치된 파일 위치는 다음과 같습니다.

[cols="1,3",options="header"]
|===
| 항목 | 위치

| 프로그램 | `/opt/argus-catalog-ai-service/` (venv 포함)
| 명령 | `argus-catalog-ai` (RPM: `/usr/bin`, tar.gz: `/usr/local/bin`)
| 설정 | `/etc/argus-catalog-ai-service/ai-service.env`
| 서비스 | `argus-catalog-ai-assistant` (assistant), `argus-catalog-ai-enrich` (enrich 워커)
|===

[[_서비스_계정_만들기]]
==== 서비스 계정 만들기 (enrich 용)

enrich 는 이 계정으로 카탈로그에 로그인해 데이터셋 · 샘플 · 용어를 읽고, 결과를 *AI 제안* 으로 반입합니다.
반입 API 가 관리자만 허용하므로 계정에 **관리자** 역할이 있어야 합니다.

. 카탈로그에 관리자로 로그인해 **관리 → 사용자 관리** 로 들어갑니다.
. **작업 → 추가** 를 누르고 사용자명 `argus`, 역할 **관리자**, 비밀번호를 넣어 저장합니다(자세한 항목은 xref:ops/users.adoc[사용자 관리]).
. 그 비밀번호를 `ai-service.env` 의 `ARGUS_PASSWORD` 에 적습니다. 예시 값을 그대로 쓰지 말고 운영 환경마다 정한 값으로 바꿉니다.

인증 방식이 Keycloak 이면 사용자 관리에 *추가* 메뉴가 없습니다. Keycloak 에서 `argus` 사용자를 만들고 `argus-admin` 역할을 주세요.

NOTE: 관리자가 *비밀번호 변경* 메뉴로 비밀번호를 다시 정하면 임시 비밀번호가 되어 다음 로그인 때 변경을 요구하고,
그동안 enrich 의 API 호출이 막힙니다. 이때는 `argus` 로 화면에 한 번 로그인해 비밀번호를 바꾼 뒤 그 값을 `ARGUS_PASSWORD` 에 적으세요.

=== Docker

소스의 `ai-service/` 에 ollama 까지 묶은 compose 파일이 있습니다. 아래 명령을 차례로 실행합니다.

[source,bash]
----
cd ai-service
cp .env.example .env                 # ARGUS_API_URL, ARGUS_USERNAME/ARGUS_PASSWORD 등 수정
docker compose up -d ollama          # LLM 서버
docker compose up ollama-pull        # qwen2.5:7b 받기 (최초 1회, 끝나면 종료)
docker compose up -d assistant       # :8930
docker compose up -d worker          # enrich 워커 (ARGUS_AI_DATASOURCE_ID)
----

`.env.example` 은 개발용으로 기본 `admin` 계정을 씁니다. 운영처럼 쓸 때는 <<_서비스_계정_만들기>> 처럼 `argus` 계정을 만들고
`ARGUS_USERNAME=argus` 와 그 비밀번호로 바꾸세요.

[TIP]
.고급 사용자 — 네이티브 설치 (개발)
====
[source,bash]
----
cd ai-service
python3 -m venv .venv && .venv/bin/pip install -e .
.venv/bin/argus-catalog-ai --help
----
====

== AI 어시스턴트 연결하기

. AI 서비스에서 assistant 를 시작하고 상태를 확인합니다.
+
[source,bash]
----
systemctl enable --now argus-catalog-ai-assistant
curl -s http://127.0.0.1:8930/health      # {"status": "ok", "model": "qwen2.5:7b"}
----
. 카탈로그 화면 `설정 > AI 어시스턴트` 탭에서 **AI 서비스 기반 어시스턴트 활성화** 를 켭니다.
. **AI 서비스 URL** 에 `http://<AI 서비스 호스트>:8930` 을 넣고 **연결 테스트** 후 **저장** 합니다.

저장하면 재시작 없이 다음 채팅부터 AI 서비스로 프록시됩니다.

[NOTE]
====
우하단 플로팅 챗 버튼은 `설정 > AI 어시스턴트` 탭의 **AI 서비스 기반 어시스턴트 활성화** 가 켜져 있고,
사용자에게 기능 권한 *AI 어시스턴트 사용*(`ai.assistant`, 기본은 모든 역할 허용)이 있을 때만 표시됩니다.
활성화했지만 AI 서비스 URL 이 비어 있으면(설정 파일의 `assistant.service.url` 도 없으면) 도구 없는
*내장 단순 대화* 로 동작하며, 이때는 `설정 > LLM / AI` 탭의 LLM 제공자가 활성화돼 있어야 합니다.
====

[TIP]
.고급 사용자 — 설정 파일 기본값, 어시스턴트 도구, 셀프-텔레메트리
====
*설정 파일 기본값* — 설치 직후 기본값을 설정 파일로 주려면 카탈로그 서버 설정의 `assistant.service.url` 을 사용합니다(DB 에 값이 없을 때만 적용).

*어시스턴트 도구* — 질문에 따라 LLM 이 필요한 도구를 골라 최대 6 라운드까지 호출하고, 그 결과를 근거로 답합니다.

[cols="2,3",options="header"]
|===
| 도구 | 용도

| `search_datasets` | 데이터셋 시맨틱 통합 검색 — "고객 테이블 뭐 있어?"
| `get_dataset_detail` | 스키마(타입 · PK · PII) · 태그 · 행 수
| `get_erd` | FK 조인 경로 — 여러 테이블 SQL 의 조인 근거
| `get_quality` | 품질 점수 · 실패 규칙 · 위반 샘플
| `get_quality_rule_recommendations` | 프로파일 기반 품질 규칙 후보
| `get_lineage` | 원천 · 영향 범위와 업스트림 품질 경고
| `get_glossary_term` | 비즈니스 용어 정의
| `get_standard_compliance` | 표준 용어 준수율 · 비준수 컬럼
| `validate_sql` | 작성한 SQL 의 SELECT 단일 문장 검증 (SQL 은 실행하지 않음)
|===

*셀프-텔레메트리* — assistant 는 첫 채팅 때 자신을 xref:governance/ai-agent-catalog.adoc[AI Agent 카탈로그] 에
`ARGUS_AI_AGENT_NAME` 이름으로 등록하고, 채팅마다 지연 · 토큰 · 성공 여부를 보고합니다.
사용자 토큰으로 수행하며, 실패해도 채팅에는 영향이 없습니다. 끄려면 `ARGUS_AI_TELEMETRY=off` 로 둡니다.
====

== 메타데이터 생성하기 (enrich)

enrich 는 다음 작업을 지원합니다.

[cols="1,3,2",options="header"]
|===
| 작업 | 생성 내용 | 결과 처리

| `describe` | 데이터셋 상세 설명 (markdown) | 제안 또는 직접 적용
| `summarize` | 한 줄 요약 | 항상 제안
| `columns` | 컬럼별 설명 | 항상 제안
| `tags` | 분류 태그 추천 | 항상 제안
| `pii` | PII 컬럼 감지와 근거 | *항상 제안* (사람 승인 필수)
| `all` | 위 작업 전부 | 작업별 규칙
| `worker` | 설명 없는 데이터셋을 주기적으로 찾아 생성하는 상시 실행 | 작업별 규칙
|===

=== 한 번 실행하기

대상은 데이터셋 하나(`--urn`) 또는 데이터 소스 전체(`--datasource-id`)로 지정합니다.

. 설정 파일의 환경변수를 불러옵니다(패키지 설치 환경).
+
[source,bash]
----
set -a; . /etc/argus-catalog-ai-service/ai-service.env; set +a
----
. 원하는 작업을 실행합니다.
+
[source,bash]
----
argus-catalog-ai enrich describe --urn sakila-mysql.sakila.film.dataset
argus-catalog-ai enrich all --datasource-id sakila-mysql
argus-catalog-ai enrich worker --datasource-id sakila-mysql --once   # 1회만 (cron 용)
----
. 결과는 카탈로그의 *AI 제안* 으로 들어갑니다. 데이터셋 상세 제목 오른쪽의 *AI 제안* 버튼(대기 건수 배지)을 눌러
  제안값과 현재 값을 비교하고 승인 · 거절합니다 — xref:ai/metadata-generation.adoc#_제안_검토[제안을 나중에 검토하기] 참고.

일괄 실행은 일부 데이터셋 · 작업이 실패해도 나머지를 계속 처리하고, 실패가 있으면 종료 코드 1 을
반환합니다. 스케줄러의 실패 알림에 그대로 연결할 수 있습니다.

=== 상시 워커로 돌리기

. `ai-service.env` 에 `ARGUS_AI_DATASOURCE_ID` 를 지정합니다.
. 서비스를 켜고 로그를 확인합니다.
+
[source,bash]
----
systemctl enable --now argus-catalog-ai-enrich
journalctl -u argus-catalog-ai-enrich -f
----

워커 하나는 데이터 소스 하나를 맡습니다. 여러 데이터 소스는 unit 을 복사해 ID 만 바꿔 띄웁니다.

[TIP]
.고급 사용자 — enrich 한 번의 실행 순서
====
. 서비스 계정(`ARGUS_USERNAME`, 기본 `argus`)으로 로그인하고 대상 데이터셋을 정합니다.
. 스키마 · 샘플(상위 5행) · 용어집을 모아 컨텍스트를 만듭니다.
. 작업별 한국어 프롬프트로 LLM 에 생성을 요청합니다. 존재하지 않는 컬럼 결과는 걸러냅니다.
. 결과를 카탈로그의 *AI 제안* 으로 반입합니다(`POST /api/v1/ai/datasets/{id}/suggestions/import`, 출처 `agent`).
  `ARGUS_AI_MODE=apply` 이면 데이터셋 설명만 직접 적용하고 나머지(요약 · 컬럼 설명 · 태그 · PII)는 제안으로 남깁니다.
. 사람이 화면의 *AI 제안* 에서 승인 · 거절합니다. 스크립트로 처리하려면 REST API(`/api/v1/ai/suggestions/...`)를 씁니다 — xref:ai/metadata-generation-advanced.adoc#_제안_관리[고급 — 제안 관리] 참고.
====

== 운영 점검

[cols="1,3",options="header"]
|===
| 항목 | 방법

| 상태 확인 | `curl http://<호스트>:8930/health`, `systemctl status argus-catalog-ai-assistant`
| 로그 | `journalctl -u argus-catalog-ai-assistant`, `journalctl -u argus-catalog-ai-enrich`
| 방화벽 | 카탈로그 서버에서 AI 서비스의 8930/tcp 로 접근할 수 있어야 합니다 (브라우저는 직접 접근하지 않음)
| 사용량 | `GET /api/v1/ai-agents/argus-catalog-assistant/metering` — 호출 · 토큰 · 지연 집계
|===

== 자주 묻는 질문

*Q. 어시스턴트가 도구 없이 단순하게만 답합니다.* +
A. `설정 > AI 어시스턴트` 의 AI 서비스 URL 이 비어 있으면(설정 파일의 `assistant.service.url` 도 없으면) 내장 단순 대화로 동작합니다. URL 을 넣고 연결 테스트 후 저장하세요.

*Q. 우하단 챗 버튼이 보이지 않습니다.* +
A. **AI 서비스 기반 어시스턴트 활성화** 가 켜져 있는지, 사용자에게 *AI 어시스턴트 사용*(`ai.assistant`) 권한이 있는지 확인하세요.

*Q. 연결 테스트가 실패합니다.* +
A. AI 서비스에서 `curl http://127.0.0.1:8930/health` 가 응답하는지, 카탈로그 서버에서 AI 서비스의 8930/tcp 로 접근할 수 있는지 확인하세요.

*Q. 예전 `argus-agent` 명령을 쓰고 있습니다.* +
A. 한 버전 동안은 경고와 함께 그대로 동작합니다. <<_부록_b_이전_이름과의_호환>> 표를 보고 새 이름으로 옮기세요.

[[_부록_a_환경변수]]
== 부록 A. 환경변수

설정은 *명령 인자 > 환경변수 > 기본값* 순으로 적용됩니다. 패키지 설치 시 환경변수는
`/etc/argus-catalog-ai-service/ai-service.env` 에 둡니다.

[cols="2,2,3",options="header"]
|===
| 환경변수 | 기본값 | 설명

| `ARGUS_API_URL` | `http://localhost:4600` | 카탈로그 서버 주소
| `ARGUS_USERNAME` / `ARGUS_PASSWORD` | `admin` / (없음) — 패키지의 `ai-service.env` 는 `argus` | enrich 가 로그인하는 서비스 계정. 관리자 역할로 사용자 관리에서 먼저 만들어야 합니다(<<_서비스_계정_만들기>>). assistant 는 불필요
| `ARGUS_AI_LLM_URL` | `http://localhost:11434/v1` | OpenAI 호환 LLM 엔드포인트
| `ARGUS_AI_MODEL` | `qwen2.5:7b` | 모델 이름
| `ARGUS_AI_LLM_API_KEY` | `ollama` | LLM API 키 (ollama 는 아무 값이나 됨)
| `ARGUS_AI_MODE` | `suggest` | enrich 결과 처리: `suggest`(제안) / `apply`(직접 적용)
| `ARGUS_AI_TEMPERATURE` | `0.3` | 생성 온도
| `ARGUS_AI_MAX_TOKENS` | `2048` | 최대 생성 토큰
| `ARGUS_AI_DATASOURCE_ID` | — | enrich 워커 서비스가 맡을 데이터 소스 ID
| `ARGUS_AI_POLL_INTERVAL` | `300` | enrich 워커 폴링 주기(초)
| `ARGUS_AI_WORKER_TARGET` | `missing` | 워커 대상 — 설명이 없는 데이터셋
| `ARGUS_AI_AGENT_NAME` | `argus-catalog-assistant` | assistant 가 AI Agent 카탈로그에 등록하는 이름
| `ARGUS_AI_TELEMETRY` | `on` | assistant 셀프-텔레메트리 on/off
| `ARGUS_AI_PORT` | `8930` | assistant 포트 (systemd 서비스)
|===

[[_부록_b_이전_이름과의_호환]]
== 부록 B. 이전 이름과의 호환

0.5.0 에서 `argus-agent` 가 `argus-catalog-ai-service` 로 바뀌었습니다. 이전 이름은 한 버전 동안
경고와 함께 그대로 동작하므로, 그 사이에 새 이름으로 옮기면 됩니다.

[cols="1,1",options="header"]
|===
| 이전 | 현재

| 소스 `agent/`, 모듈 `argus_agent` | `ai-service/`, 모듈 `argus_catalog_ai`
| `argus-agent serve` | `argus-catalog-ai assistant`
| `argus-agent describe` … `pii` | `argus-catalog-ai enrich describe` … `pii`
| `argus-agent generate-all` | `argus-catalog-ai enrich all`
| `argus-agent worker` | `argus-catalog-ai enrich worker`
| 환경변수 `AGENT_*` | `ARGUS_AI_*` (`AGENT_NAME` → `ARGUS_AI_AGENT_NAME`)
| 카탈로그 서버 설정 `assistant.agent.url` | `assistant.service.url`
|===
