= AI 메타데이터 자동 생성

데이터셋마다 설명을 일일이 손으로 채우는 일은 번거롭습니다. 이 기능은 LLM 으로
데이터셋의 *테이블 설명 · 컬럼 설명 · 태그 · PII* 를 자동으로 생성해 줍니다.
Ollama (로컬), OpenAI, Anthropic (Claude) 프로바이더를 지원합니다.

== 동작 개요

전체 흐름은 단순합니다. UI 에서 트리거하면 AI 서비스가 데이터셋 정보로 컨텍스트를
조립해 LLM 프로바이더에 보내고, 돌아온 결과를 파싱해 다시 UI 에 돌려줍니다.

----
┌────────────┐    ┌──────────────┐    ┌────────────────────┐
│  UI        │───▶│ AI Service   │───▶│ LLM Provider       │
│  (트리거)  │◀───│ (컨텍스트    │◀───│ Ollama / OpenAI /  │
│            │    │  조립·파싱)  │    │ Claude             │
└────────────┘    └──────┬───────┘    └────────────────────┘
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
       Dataset/Schema  Parquet     ai_generation_log
                       샘플 데이터  (감사 이력)
----

== LLM 프로바이더

어떤 LLM 으로 생성할지는 환경에 맞게 고르면 됩니다. 외부로 데이터를 보낼 수 없는
환경이라면 로컬 Ollama 를, 더 높은 품질이 필요하다면 클라우드 API 를 선택합니다.

[cols="1,2,3,3"]
|===
| 프로바이더 | 기본 모델 | API URL | 특성

| `ollama` | `qwen2.5:7b` | `http://localhost:11434` | 로컬 실행. API 키 불필요. 한국어 우수. 에어갭 가능.
| `openai` | `gpt-4o-mini` | `https://api.openai.com/v1` | 클라우드 API. 고품질. API 키 필요.
| `anthropic` | `claude-sonnet-4-...` | `https://api.anthropic.com` | 클라우드 API. 고품질. API 키 필요.
|===

=== Ollama 권장 모델

[cols="2,1,1,3"]
|===
| 모델 | 크기 | 한국어 | 권장 용도

| `qwen2.5:7b` | 4.4 GB | 우수 | *한국어 메타데이터 기본 권장*
| `qwen2.5:14b` | 8.7 GB | 우수 | 한국어 고품질 (RAM 16 GB+)
| `llama3.1:8b` | 4.7 GB | 보통 | 범용 영문
| `gemma2:9b` | 5.4 GB | 보통 | 다국어
| `EEVE-Korean-10.8B` | 6.5 GB | 최우수 | 한국어 특화
|===

Ollama 를 설치하고 모델을 내려받는 과정은 다음과 같습니다.

[source,bash]
----
curl -fsSL https://ollama.ai/install.sh | sh
ollama pull qwen2.5:7b
ollama list
curl http://localhost:11434/api/tags
----

== 설정

기능을 쓰기 전에 먼저 어떤 LLM 을 어떻게 연결할지 설정해야 합니다. UI 에서는
*Settings → LLM / AI* 탭에서 다음 순서로 진행합니다.

. *Enable AI Metadata Generation* 토글을 ON 으로 켭니다.
. Provider · Model · API URL · Generation Language 를 지정합니다.
. *Test Connection* 으로 연결을 검증한 뒤 *Save* 합니다.

같은 설정을 API 로도 동일하게 적용할 수 있습니다.

[source,bash]
----
curl -X PUT http://<server>:4600/api/v1/settings/llm \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "provider": "ollama",
    "model": "qwen2.5:7b",
    "api_key": "",
    "api_url": "http://localhost:11434",
    "temperature": 0.3,
    "max_tokens": 1024,
    "auto_generate_on_sync": false,
    "language": "ko"
  }'
----

image::ai-metadata-generation/ai-setting.png[AI Generate 설정, 800]

설정 항목은 다음과 같습니다.

[cols="1,1,3"]
|===
| 키 | 기본값 | 설명

| `enabled` | false | 기능 활성화
| `provider` | openai | openai / ollama / anthropic
| `model` | gpt-4o-mini | 모델 식별자
| `api_key` | (빈값) | API 키 (Ollama 불필요)
| `api_url` | (빈값) | 엔드포인트 오버라이드
| `temperature` | 0.3 | 0.0~1.0, 낮을수록 사실적
| `max_tokens` | 1024 | 응답 토큰 한도
| `auto_generate_on_sync` | false | sync 후 빈 설명 자동 채움
| `language` | ko | 생성 언어 (`ko`, `en`, `ja`, `zh`)
|===

== 4가지 생성 유형

생성할 수 있는 메타데이터는 네 가지입니다. 각각 별도 엔드포인트로 호출하며,
용도에 따라 필요한 것만 골라 쓸 수 있습니다.

[cols="1,2,3"]
|===
| 기능 | 엔드포인트 | 설명

| 테이블 설명 | `POST /api/v1/ai/datasets/{id}/describe` | 테이블 목적·내용 텍스트
| 컬럼 설명 | `POST .../describe-columns` | 모든 컬럼 용도 일괄 생성
| 태그 추천 | `POST .../suggest-tags` | 기존 태그 활용 + 새 태그 제안
| PII 탐지 | `POST .../detect-pii` | 개인정보 컬럼 탐지
|===

`POST /api/v1/ai/datasets/{id}/generate-all` 을 호출하면 위 4 개를 한 번에 수행합니다.

== 프롬프트 컨텍스트

생성 품질은 LLM 에 어떤 정보를 함께 전달하느냐에 달려 있습니다. 어시스턴트는 다음
정보를 모아 프롬프트에 담아 보냅니다.

[cols="1,2"]
|===
| 정보 | 출처

| 테이블명, DB명 | `catalog_datasets`
| 컬럼명, 타입, 제약조건 | `catalog_dataset_schemas`
| DDL | `platform_properties.ddl`
| 샘플 데이터 (최대 5행) | `samples/{platform}/{dataset}/sample.parquet`
| 행 수 추정치 | `platform_properties.estimated_rows`
| 플랫폼 타입 | `catalog_platforms.type`
|===

샘플 데이터는 메타데이터 동기화 시 자동으로 수집된 Parquet 파일을 그대로 재사용합니다.

== 사용 방법

실제로 생성하는 방법은 여러 가지입니다. 데이터셋 하나만 빠르게 처리할 때는 UI 가
편하고, 자동화하거나 대량으로 처리할 때는 API 와 일괄 생성을 활용합니다.

=== UI에서 개별 생성

. 데이터셋 상세 화면 우측 상단의 *AI Generate* 드롭다운을 엽니다.
. 원하는 기능을 선택합니다 — Generate Description / Generate Column Descriptions / Suggest Tags / Detect PII.
. Description / Columns 는 *미리보기 다이얼로그* 에서 결과를 확인한 뒤 *Apply* 또는 *Dismiss* 합니다.
. Tags / PII 는 *즉시 적용*되며 토스트 메시지로 알려 줍니다.

=== API로 개별 생성

[source,bash]
----
# 미리보기 (apply=false)
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/describe \
  -H "Content-Type: application/json" \
  -d '{"apply": false}'

# 즉시 적용 (apply=true)
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/describe \
  -H "Content-Type: application/json" \
  -d '{"apply": true}'

# 전체 생성
curl -X POST http://<server>:4600/api/v1/ai/datasets/1/generate-all \
  -H "Content-Type: application/json" \
  -d '{"apply": true}'
----

=== 일괄 생성 (Bulk)

데이터셋이 많다면 하나씩 처리하기 어렵습니다. 일괄 생성을 쓰면 여러 데이터셋을
한 번에 채울 수 있습니다. UI 의 *Settings → LLM / AI → Bulk AI Generation* 또는
다음 API 로 호출합니다.

[source,bash]
----
# 설명 없는 데이터셋에만 description 자동 생성
curl -X POST http://<server>:4600/api/v1/ai/bulk-generate \
  -H "Content-Type: application/json" \
  -d '{
    "generation_types": ["description"],
    "apply": true,
    "empty_only": true
  }'

# 특정 플랫폼만 전체 생성
curl -X POST http://<server>:4600/api/v1/ai/bulk-generate \
  -H "Content-Type: application/json" \
  -d '{
    "generation_types": ["description", "columns", "tags", "pii"],
    "apply": true,
    "empty_only": true,
    "platform_id": 1
  }'
----

=== 동기화 후 자동 생성

`auto_generate_on_sync: true` 로 설정하면, 메타데이터 동기화가 끝난 뒤 비어 있는
설명을 백그라운드에서 자동으로 채워 줍니다. 자세한 내용은
xref:catalog/platforms.adoc#_메타데이터_동기화[플랫폼 → 메타데이터 동기화] 를 참조하세요.

== 응답 스키마

각 생성 유형이 어떤 형태의 결과를 돌려주는지 살펴보겠습니다.

테이블 설명::
[source,json]
----
{
  "dataset_id": 1,
  "description": "영화 텍스트 정보(제목, 설명)를 전문 검색용으로 저장하는 테이블",
  "confidence": 0.87,
  "applied": false,
  "log_id": 42
}
----

컬럼 설명::
[source,json]
----
{
  "dataset_id": 1,
  "columns": [
    {"field_path": "film_id", "description": "영화 고유 식별자 (PK)", "confidence": 0.95, "had_existing": false},
    {"field_path": "title", "description": "영화 제목", "confidence": 0.92, "had_existing": false}
  ],
  "total_generated": 2,
  "applied": false
}
----

태그 추천::
[source,json]
----
{
  "dataset_id": 1,
  "suggested_tags": ["영화", "미디어"],
  "new_tags": [{"name": "콘텐츠", "description": "콘텐츠 관련 데이터"}],
  "applied_tags": ["영화"],
  "created_tags": ["콘텐츠"]
}
----

PII 탐지::
[source,json]
----
{
  "dataset_id": 1,
  "pii_columns": [
    {"name": "email", "pii_type": "EMAIL", "confidence": 0.95,
     "reason": "Column name and sample values match email pattern"},
    {"name": "phone_number", "pii_type": "PHONE", "confidence": 0.88,
     "reason": "Column contains phone number format"}
  ]
}
----

PII 유형 — `EMAIL`, `PHONE`, `SSN`, `NAME`, `ADDRESS`, `CREDIT_CARD`, `IP_ADDRESS`,
`DATE_OF_BIRTH`, `NATIONAL_ID`, `OTHER`. 탐지 결과는
`catalog_dataset_schemas.pii_type` 컬럼에 저장됩니다.

== 제안 관리

바로 적용하지 않고 검토부터 하고 싶을 때가 있습니다. 미리보기 모드(`apply=false`)로
생성한 결과는 `catalog_ai_generation_log` 에 보존되므로, 나중에 하나씩 적용하거나
거부할 수 있습니다.

[source,bash]
----
# 미적용 제안 목록
curl http://<server>:4600/api/v1/ai/datasets/1/suggestions

# 적용 / 거부
curl -X POST http://<server>:4600/api/v1/ai/suggestions/42/apply
curl -X POST http://<server>:4600/api/v1/ai/suggestions/42/reject
----

== 통계 / 감사

지금까지 얼마나 생성했고 적용률은 어떤지 한눈에 보고 싶다면 통계 API 를 호출합니다.

[source,bash]
----
curl http://<server>:4600/api/v1/ai/stats
----

응답 예시는 다음과 같습니다.

[source,json]
----
{
  "total_generations": 156,
  "applied_count": 120,
  "pending_count": 36,
  "total_prompt_tokens": 89420,
  "total_completion_tokens": 34210,
  "description_coverage": {
    "total_datasets": 200,
    "described_datasets": 120,
    "coverage_pct": 60.0
  },
  "provider": "ollama",
  "model": "qwen2.5:7b"
}
----

모든 호출은 *입력 / 출력 / 토큰 / 적용 여부* 와 함께 `catalog_ai_generation_log`
테이블에 기록됩니다. 나중에 감사 추적이 필요할 때 그대로 활용할 수 있습니다.
