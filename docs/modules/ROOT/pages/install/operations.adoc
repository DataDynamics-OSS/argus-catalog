= 운영 가이드

설치한 Argus Catalog 를 안정적으로 운영하기 위한 일상 작업 — 헬스체크, 로그, 백업, 업그레이드, 문제 해결 — 을 모은 페이지입니다.

[NOTE]
.이런 분께 필요합니다
====
* 설치를 마치고 카탈로그 서버를 **관리·운영하는** 분
* 오류 메시지를 보고 원인을 찾는 분

처음 설치하는 중이라면 xref:install/docker.adoc[Docker Compose 배포] 또는 xref:install/setup.adoc[직접 설치] 를 먼저 보세요.
====

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **상태 확인** — 서버·UI 가 살아 있는지 봅니다.
* **로그 보기** — 문제가 생겼을 때 원인을 추적합니다.
* **백업과 복구** — DB 와 모델 아티팩트를 보관합니다.
* **업그레이드** — 새 버전을 안전한 순서로 적용합니다.
* **문제 해결** — 자주 나오는 오류를 바로 고칩니다.

== 헬스체크

서버가 살아 있는지는 헬스 엔드포인트를 호출해 확인합니다.

[source,bash]
----
curl http://<server>:4600/health
# {"status":"ok","service":"argus-catalog-server","uptime":12345,"version":"0.5.0"}
----

UI 쪽 헬스는 Next.js 의 응답 코드로 판단합니다. 로드 밸런서에서는 `/` 또는 `/login` 이 200 을 돌려주는지 확인하면 됩니다.

== 로그

문제가 생기면 가장 먼저 로그를 봅니다.

[cols="1,3"]
|===
| 위치 | 설명

| `${log.dir}/argus-catalog-server.log` | 서버 로그. 일별 롤링 (자정 기준), 30 일 보관.
| stdout / stderr | systemd · Docker 환경에서 함께 캡쳐.
| `catalog_ai_generation_log` | LLM 호출 이력 (토큰 사용량 · 적용 여부).
|===

로그 레벨은 `log.level` 설정으로 바꿉니다(DEBUG / INFO / WARNING / ERROR). 운영 환경에서는 INFO 를 권장합니다.
SQL 쿼리 출력은 로그 레벨과 별개로 `db.echo`(config.yml 의 `database.echo`, 기본 `false`) 설정으로 켭니다.

== 메트릭 · 모니터링

* `/health` — uptime, version.
* 외부 모니터링 도구(Prometheus 등)는 향후 지원 예정입니다.
* 데이터 측면은 *대시보드* 페이지의 통계 차트와 임베딩 커버리지(`/api/v1/catalog/search/embeddings/stats`)로 확인합니다.

== 백업

백업 대상은 두 곳입니다.

. *PostgreSQL DB* — 모든 메타데이터
+
[source,bash]
----
pg_dump -U argus -F c -f argus_catalog_$(date +%F).dump argus_catalog
----

. *모델 아티팩트*
** 로컬 모드 — `${data.dir}/model-artifacts/` 를 백업합니다.
** S3 / MinIO 모드 — 버킷 복제 또는 라이프사이클 정책을 씁니다.

복구는 역순입니다. DB 를 복구한 뒤 서버를 다시 기동하세요. 시드는 *이미 있는 행을 건너뛰므로* 다시 실행해도 안전합니다.

== 업그레이드

. 새 버전 패키지 / 컨테이너 이미지를 준비합니다.
. *DB 를 백업*합니다.
. 서버를 멈추고 패키지를 교체합니다.
. *새 버전의 스키마 DDL 을 적용*(`argus-catalog-postgresql.sql` / `argus-catalog-mariadb.sql`)한 뒤 서버를 기동합니다.
. `/health` 의 `version` 값으로 업그레이드를 확인합니다.

순서가 중요합니다. *DB 백업 이후에 패키지를 교체하고, 새 DDL 을 먼저 적용한 뒤 기동* 하는 순서를 지켜 주세요.

.버전 업그레이드 순서

[TIP]
.고급 사용자 — 스키마 관리 방식
====
스키마는 *SQL DDL 이 전담*합니다. 서버는 시작할 때 테이블/컬럼을 자동으로 생성하거나
변경하지 않습니다 (런타임 `create_all` 및 `reconcile_schema` 제거). 업그레이드할 때는
새 버전 DDL 과 기존 스키마의 차이를 확인해 적용해 주세요 — 향후 Alembic 도입을 계획하고 있습니다.
====

== 자주 발생하는 이슈

=== `ERROR: type "vector" does not exist`

스키마 DDL 을 적용할 때 pgvector 확장이 설치되지 않았거나 활성화되지 않은 경우입니다. DDL 맨 앞의
`CREATE EXTENSION IF NOT EXISTS vector;` 는 슈퍼유저 권한이 필요하므로, 슈퍼유저로 확장을 먼저 활성화한 뒤 DDL 을 다시 적용합니다.

[source,bash]
----
sudo -u postgres psql -d argus_catalog -c "CREATE EXTENSION IF NOT EXISTS vector;"
----

=== `RuntimeError: sentence-transformers is required`

Local 임베딩을 쓸 때 나옵니다. 아래처럼 설치하세요.

[source,bash]
----
pip install "sentence-transformers>=3.0.0"
----

OpenAI · Ollama 만 쓴다면 설치하지 않아도 됩니다.

=== 메타데이터 동기화 실패

* 데이터 소스의 *연결 테스트* 로 자격 증명 / 네트워크를 확인합니다.
* 서버 로그의 `sync` 모듈 메시지를 확인합니다.
* MySQL/MariaDB 는 `aiomysql`, PostgreSQL 은 `asyncpg` 드라이버를 씁니다 — 방화벽 · TLS 설정을 확인합니다.

=== 모델 버전 `PENDING_REGISTRATION` 에서 멈춤

MLflow 클라이언트가 finalize 호출 전에 종료된 경우입니다. *1 시간이 지나면* stuck 으로
판단합니다. 해당 버전을 삭제하고 다시 등록하세요.

=== Keycloak 로그인 거부 ("Argus 역할이 할당되지 않았습니다. 접근 권한이 필요하면 관리자에게 문의하십시오.")

사용자에게 `argus-*` Realm Role 이 하나도 없는 경우입니다. Keycloak Admin → Users
→ Role Mapping 에서 `argus-user` 이상의 역할을 부여하세요.

== 부록: 감사 추적과 보안

[TIP]
.고급 사용자 — 감사 추적
====
* 사용자 관리 · 설정 · 권한 관리 변경 — `argus_admin_audit_log` 테이블 (작업자 · 분류 · 작업 · 대상 · 요약 · 상세 · 접속 IP. 비밀값은 값 없이 "(변경됨)" 만 기록).
* 사용자별 작업 — JWT `sub` 와 함께 서버 로그에 기록 (INFO 레벨 이상).
* AI 메타데이터 생성 — `catalog_ai_generation_log` 테이블 (입력 / 출력 / 토큰 / 적용 여부).
* 스키마 변경 — `catalog_schema_snapshots`.
* 모델 Stage 전이 — `catalog_model_versions.stage_changed_by` / `stage_changed_at`.
* 알림 전달 — `argus_alert_notification`.
====

[TIP]
.고급 사용자 — 보안 동작
====
* 토큰은 sessionStorage 에 저장 — 탭 종료 시 무효화.
* 시크릿은 설정 응답에서 `••••••••` 으로 마스킹.
* 보안 헤더 자동 부착: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`.
* CORS 는 *DB 백킹 동적 설정* — 운영 중 변경 가능.
* API 는 UI 의 `proxy.ts`(`frontend/apps/web/proxy.ts`) 가 `/api/v1/*` 를 서버로 프록시하므로 백엔드 포트를 외부에 직접 노출하지 않아도 됩니다.
====
