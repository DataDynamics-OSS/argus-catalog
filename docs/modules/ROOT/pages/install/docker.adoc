= Docker Compose 배포

Argus Catalog 를 띄우는 **가장 쉬운 방법**입니다. 명령 한 줄로 웹 UI · API 서버 · 변경 관리 워커 · 데이터베이스 · Temporal · MinIO 를 한 번에 띄웁니다.
처음 써 보거나 데모·로컬 개발이 목적이라면 이 페이지 하나만 따라 하면 됩니다.

[WARNING]
====
이 스택의 기본 계정·비밀번호(`admin`·`minioadmin`·`argus` 등)는 **로컬/데모용**입니다.
운영 배포는 xref:install/production.adoc[운영 배포] 를 따르세요.
====

== 시작하기 전에

=== 필요한 것

* **Docker 와 Docker Compose** — `docker compose` 명령을 쓸 수 있어야 합니다.
* **Argus Catalog 저장소** — 모든 명령은 저장소 루트에서 실행합니다. 관련 파일은 `deploy/` 디렉터리에 있습니다.
* **비어 있는 포트** — 웹 UI `3000`, API `4600`, Temporal `7233`·`8233`, MinIO `9000`·`9001`.
* **사양** — xref:install/requirements.adoc[시스템 요구사항] 의 최소 사양(메모리 8 GB 이상 등)을 확인하세요.

Python · Node.js · pnpm · PostgreSQL 은 따로 설치하지 않아도 됩니다. 모두 컨테이너 안에서 동작합니다.

=== 이 방법으로 생기는 것

[cols="1,3",options="header"]
|===
| 서비스 | 역할

| `catalog-postgres` | 카탈로그 DB (`pgvector/pgvector:pg16`). 최초 기동 때 스키마 DDL 을 적용
| `minio` | 모델 파일 저장용 S3 호환 스토리지
| `temporal` · `temporal-postgresql` · `temporal-ui` | 변경 관리 워크플로 엔진과 그 DB · 웹 UI
| `backend` | 카탈로그 API 서버
| `backend-worker` | 변경 관리 Temporal 워커 (`python -m app.change_mgmt.worker`, backend 와 같은 이미지)
| `frontend` | 웹 UI (Next.js)
|===

== 빠른 설치

. 저장소 루트로 이동합니다.
. 풀스택을 띄웁니다.
+
[source,bash]
----
docker compose -f deploy/docker-compose.yml up -d --build
----
. 기동이 끝날 때까지 기다립니다. `catalog-postgres` 는 처음 뜰 때 스키마 DDL 을 적용하고, 적용이 끝나야 healthy 가 됩니다. 상태는 다음 명령으로 봅니다.
+
[source,bash]
----
docker compose -f deploy/docker-compose.yml ps
----
. 브라우저에서 http://localhost:3000 에 접속해 `admin` / `admin` 으로 로그인합니다.
. 첫 로그인 때 나오는 안내에 따라 관리자 비밀번호를 바꿉니다.

이제 카탈로그를 쓸 수 있습니다. 풀스택은 **로컬 인증 모드**로 동작하므로 Keycloak 같은 별도 인증 서버가 필요 없습니다.

== 접속 주소와 기본 계정

[cols="2,2,2",options="header"]
|===
| 서비스 | URL | 기본 계정

| Web UI | http://localhost:3000 | `admin` / `admin` (첫 로그인 때 비밀번호 변경)
| API (Swagger) | http://localhost:4600/docs | —
| Temporal gRPC | localhost:7233 | —
| Temporal UI | http://localhost:8233 | —
| MinIO Console | http://localhost:9001 | `minioadmin` / `minioadmin`
|===

`catalog-postgres` 는 호스트 포트를 열지 않습니다. 컨테이너 안에서만 접근할 수 있습니다.

== 멈추기와 초기화

[source,bash]
----
docker compose -f deploy/docker-compose.yml down       # 컨테이너만 멈추고 지움(데이터는 남음)
docker compose -f deploy/docker-compose.yml down -v    # 볼륨까지 삭제(데이터 초기화)
----

`down -v` 로 볼륨을 지우면 다음 기동 때 스키마 DDL 이 다시 적용되고, `admin` / `admin` 계정도 새로 만들어집니다.

[TIP]
.고급 사용자 — 내부 동작
====
* 서버는 테이블을 만들지 않습니다. `catalog-postgres` 가 최초 기동 때(데이터 볼륨이 비어 있을 때만) `deploy/initdb/catalog/00-init.sh` 로
  `backend/packaging/config/argus-catalog-postgresql.sql` 스키마 DDL 을 적용합니다.
* 관리자 계정 `admin` / `admin` 은 DDL 이 아니라 서버가 기동할 때 만듭니다.
* Temporal 은 기본으로 활성(`temporal.enabled=true`)이며, `backend-worker` 와 함께
  xref:governance/change-management.adoc[변경 관리] 에 사용됩니다.
====

[TIP]
.고급 사용자 — 서비스 구성도
====
사용자는 웹 UI 로만 접속하고, 나머지는 내부에서 서로를 호출합니다. 풀스택에는 Keycloak 이 없습니다(Keycloak 은 인프라 compose 에만 있음).

[TIP]
.고급 사용자 — 인프라만 띄우기 (백엔드 개발용)
====
백엔드를 로컬에서 `make run` 으로 띄우고 의존 서비스만 컨테이너로 쓰려면 인프라 compose 를 씁니다.

[source,bash]
----
docker compose -f deploy/docker-compose.infra.yml up -d
----

* 인프라 compose 에는 **카탈로그 DB 가 들어 있지 않습니다.** PostgreSQL + pgvector 를 따로 준비하고 스키마 DDL 을 직접 적용하세요
  (xref:install/setup.adoc[직접 설치] 의 *PostgreSQL + pgvector* 참고).
* 변경 관리 워커도 로컬에서 `python -m app.change_mgmt.worker` 로 띄웁니다.
* Keycloak(http://localhost:8180, `admin` / `admin`)과 MariaDB Sakila(localhost:3306)도 함께 뜹니다.
====

[TIP]
.고급 사용자 — `deploy/` 구성 파일
====
[cols="2,3",options="header"]
|===
| 파일 | 용도

| `docker-compose.yml` | 풀스택 — backend·frontend·Temporal·의존 서비스 일괄 기동
| `docker-compose.infra.yml` | 인프라만 — MinIO·Temporal·Keycloak(+Sakila). 카탈로그 DB 는 들어 있지 않음
| `docker-compose.infra.openldap.seed.yml` | (선택) LDAP 사용자 동기화 테스트용 OpenLDAP + 시드 데이터
| `docker-compose.infra.openldap.changed.yml` | (선택) 같은 OpenLDAP 의 변경(삭제 · 추가 · 부서 변경) 시나리오
| `docker-compose.prod.yml` | 운영 오버라이드(xref:install/production.adoc[운영 배포] 참고)
| `config/` | 카탈로그 서버 설정과 Keycloak realm
| `initdb/catalog/` | 풀스택 `catalog-postgres` 최초 기동 때 스키마 DDL 적용
|===

더 자세한 구성과 샘플 데이터는 `deploy/README.md` 를 참고하세요.
====
