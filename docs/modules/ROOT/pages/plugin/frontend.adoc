= 프론트엔드 화면 플러그인 만들기

오픈소스 코어를 수정하지 않고 고객사 전용 *화면(메뉴 + 페이지)* 을 추가해 보겠습니다.
화면은 새 라우트 파일 없이 *"순수 컴포넌트 + 레지스트리 한 줄"* 로만 추가됩니다.

== 위치

모든 고객 코드는 인리포 오버레이 디렉토리에 격리됩니다.

[source,text]
----
frontend/apps/web/plugins/
├── types.ts            # 플러그인 타입 (코어 제공, 수정 불필요)
├── registry.ts         # 활성 플러그인 등록 — "단 한 곳"
└── <고객사>/           # 예: acme/
    ├── index.tsx       # ArgusPlugin 정의 (메뉴·화면·아이콘)
    └── *-screen.tsx    # 화면 컴포넌트("use client")
----

== 플러그인 계약 (`ArgusPlugin`)

[source,ts]
----
export interface PluginScreen {
  slug: string                 // /dashboard/x/<slug> 로 매핑. 예: "acme/billing"
  component: ComponentType     // 렌더링할 화면 컴포넌트
}

export interface ArgusPlugin {
  id: string                   // 플러그인 식별자(백엔드 plugins.enabled 와 맞추면 편함)
  menu?: MenuGroup[]           // 사이드바에 병합할 메뉴 그룹/아이템
  screens?: PluginScreen[]     // 제공하는 화면들
  icons?: Record<string, LucideIcon>  // 코어 icon-map 에 없는 아이콘만
}
----

== 4단계로 추가하기

아래 네 단계만 따라 하면 화면 하나가 완성됩니다.

=== 1. 폴더 생성

`frontend/apps/web/plugins/<고객사>/` 를 만듭니다. (예: `plugins/acme/`)

=== 2. 화면 컴포넌트 작성

코어의 `DashboardHeader`, `@workspace/ui` 컴포넌트, `authFetch` 를 그대로 재사용하면
룩앤필이 일관되게 유지됩니다.

[source,tsx]
----
"use client"

import { Receipt } from "lucide-react"
import { Card, CardContent, CardHeader, CardTitle } from "@workspace/ui/components/card"
import { DashboardHeader } from "@/components/dashboard-header"

export function BillingScreen() {
  return (
    <>
      <DashboardHeader title="정산 (ACME)" />
      <div className="flex flex-1 flex-col gap-4 p-4">
        <p className="text-sm text-muted-foreground">
          이 화면은 ACME 고객사 전용 플러그인 화면입니다.
        </p>
        {/* 카드/표/차트 등 코어 컴포넌트로 구성 */}
      </div>
    </>
  )
}
----

[TIP]
백엔드 데이터가 필요하면 코어의 `authFetch("/api/v1/acme/...")` 로 플러그인 API 를
호출하면 됩니다. → xref:plugin/backend.adoc[백엔드 API 플러그인]

=== 3. `ArgusPlugin` 정의 (`index.tsx`)

[source,tsx]
----
import { Receipt } from "lucide-react"
import type { ArgusPlugin } from "../types"
import { BillingScreen } from "./billing-screen"

export const acmePlugin: ArgusPlugin = {
  id: "acme",
  icons: { Receipt },                          // 코어 icon-map 에 없는 아이콘만
  menu: [
    {
      id: "acme",                              // 기존 그룹 id 와 같으면 그 그룹에 덧붙음
      label: "ACME",
      items: [
        {
          id: "acme-billing",
          title: "정산",
          url: "/dashboard/x/acme/billing",    // /dashboard/x/<slug>
          icon: "Receipt",
        },
      ],
    },
  ],
  screens: [
    { slug: "acme/billing", component: BillingScreen },  // slug == url 의 x/ 뒤 경로
  ],
}
----

[IMPORTANT]
====
메뉴 `url` 의 `/dashboard/x/` 뒤 경로와 화면 `slug` 가 *정확히 일치* 해야 합니다.

* `url: "/dashboard/x/acme/billing"`
* `slug: "acme/billing"`
====

=== 4. 레지스트리에 등록

`frontend/apps/web/plugins/registry.ts` 의 `plugins` 배열에 한 줄 추가합니다.

[source,ts]
----
import { acmePlugin } from "./acme"

const plugins: ArgusPlugin[] = [
  acmePlugin,        // ← 추가
]
----

이게 전부입니다. 사이드바에 메뉴가 뜨고, 클릭하면 `/dashboard/x/acme/billing` 호스트
라우트가 `BillingScreen` 을 렌더합니다.

== 권한 게이팅

플러그인 메뉴도 코어와 동일하게 `urlToMenuKey(url)` → 권한 매트릭스를 통과합니다.

* 관리자 전용으로 두려면 메뉴 아이템에 `adminOnly: true` 를 지정합니다.
* 역할별 노출 제어는 *권한 관리* 화면의 권한 매트릭스에서 해당 메뉴 키를 설정합니다.

== 대용량 화면

번들이 큰 화면은 `screens` 의 `component` 를 `next/dynamic` 으로 지연 로딩합니다.

[source,tsx]
----
import dynamic from "next/dynamic"
const BillingScreen = dynamic(() => import("./billing-screen").then((m) => m.BillingScreen))
----

== OSS 기본 동작 보장

`registry.ts` 의 `plugins` 배열을 비우면(`[]`) 메뉴·화면·아이콘이 전혀 추가되지 않아
오픈소스 코어와 *완전히 동일* 하게 동작합니다.

== 검증

마지막으로 다음 명령으로 화면이 제대로 붙었는지 확인합니다.

[source,bash]
----
cd frontend
pnpm install
pnpm --filter web typecheck    # 타입 일치 확인
pnpm --filter web lint
pnpm --filter web dev          # 사이드바 메뉴·화면 동작 확인
----
