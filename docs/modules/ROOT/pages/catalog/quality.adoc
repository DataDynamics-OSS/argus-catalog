= 데이터 품질
:toc: macro
:toclevels: 2

데이터가 믿을 만한지 확인하려면 두 가지가 필요합니다. 하나는 실제 값이 어떻게 분포하는지 들여다보는 일이고,
다른 하나는 그 분포가 기준을 지키는지 따져 보는 일입니다. 데이터 품질 기능은 원본 DB 에 직접 연결해 컬럼 통계를
수집하는 *프로파일링* 과, 그 결과를 규칙으로 평가하는 *품질 검증* 을 데이터셋 상세의 *품질* 탭 한 화면에서 제공합니다.

화면의 검증은 저장해 둔 프로파일 통계만 보고 빠르게 판정합니다. 통계만으로는 판단할 수 없는 규칙(허용 값 · 정규식 ·
커스텀 SQL · 커스텀 Python)은 원본 전체 데이터를 읽는 *품질 배치* 가 평가해 같은 화면에 결과를 올립니다.

.프로파일·검증·품질 배치와 알림
image::diagrams/catalog-quality-01.png[프로파일·검증·품질 배치와 알림,role="diagram"]

image::catalog-quality/dashboard.png[품질 탭 — 점수 영역 · 결과 표 · 규칙 목록, 900]

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **프로파일** — 원본 DB 에 접속해 컬럼별 NULL 비율 · 고유 비율 · 값 범위를 수집합니다.
* **규칙 만들기** — NULL 없음 · 고유값 · 값 범위 · 행 수 · 최신성 같은 품질 규칙을 직접 만들거나 추천받습니다.
* **검증과 점수** — 규칙을 검증해 품질 점수와 데이터셋 품질 상태(GOOD · WARN · BAD)를 얻습니다.
* **주기 검증** — 매시간 · 매일 · 매주 자동으로 검증합니다.
* **원천 문제 추적** — 리니지상 원천 데이터셋의 품질 문제를 경고로 봅니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| 프로파일
| 원본에서 수집한 컬럼 통계의 *스냅숏* 입니다. 원본이 바뀌면 다시 수집해야 합니다.
| 품질 규칙
| 데이터가 지켜야 할 기준입니다(10종). 심각도는 *치명* · *경고* · *정보* 중 하나입니다.
| 검증 실행
| 최신 프로파일 통계로 규칙을 판정하는 화면 기능입니다.
| 품질 배치
| 원본 전체 데이터를 읽어 규칙을 판정하는 명령줄 스크립트입니다. xref:catalog/quality-batch.adoc[품질 배치] 참고.
| 미평가
| 아직 판정 결과가 없어 점수 계산에서 빠진 규칙입니다.
|===

=== 메뉴 위치

*데이터 카탈로그 → 데이터셋* 에서 데이터셋을 열고 *품질* 탭을 누릅니다. 데이터셋 상세 화면 전체는
xref:catalog/datasets.adoc[데이터셋] 에서 설명합니다.

=== 누가 무엇을 할 수 있나요

탭을 보는 것은 로그인한 사용자 누구나 할 수 있습니다. 버튼마다 필요한 기능 권한은 다음과 같습니다.

[cols="1,3"]
|===
| 작업 | 필요한 기능 권한

| *프로파일* · *검증 실행* (빈 화면의 *데이터 프로파일* 포함)
| *품질 검증 실행* (`quality.run`)
| *규칙 추가* · *규칙 추천*, 규칙 편집 · 삭제
| *품질 규칙 관리* (`quality.rules-manage`)
| *주기* 선택
| *검증 주기 설정* (`quality.schedule`)
| 품질 배치 결과 반입, 원천 데이터 시간대 설정
| 관리자만
|===

세 기능 권한은 *기본 허용형* 입니다. xref:ops/permissions.adoc[권한 관리] 의 *기능 권한* 표에서 아무 역할도
제한하지 않으면 로그인 사용자 모두 쓸 수 있고, 특정 역할의 체크를 해제하면 그 역할 사용자에게는 해당 버튼이
보이지 않습니다.

image::catalog-quality/feature-permissions.png[권한 관리 — 데이터셋 그룹의 품질 규칙 관리 · 품질 검증 실행 · 검증 주기 설정, 900]

권한이 없는 사용자에게는 *프로파일* · *검증 실행* · *규칙 추가* · *규칙 추천* 버튼과 규칙의 편집 · 삭제 아이콘이 보이지 않고,
*주기* 선택은 비활성으로 표시됩니다. 점수 · 결과 · 규칙 · 프로파일은 그대로 볼 수 있습니다.

image::catalog-quality/read-only.png[품질 관련 권한이 없는 사용자의 품질 탭 — 실행 · 편집 버튼 없음, 900]

== 품질 탭 화면 구성

품질 탭은 위에서부터 다음 순서로 구성됩니다. 해당 내용이 없으면 그 영역은 나타나지 않습니다.

[cols="1,3"]
|===
| 영역 | 내용

| 업스트림 품질 경고
| 리니지상 원천 데이터셋 중 품질 상태가 나쁜 것이 있을 때만 보입니다. <<_업스트림_품질_경고,업스트림 품질 경고>> 참고.
| 품질 점수 영역
| 점수와 막대, 통과 · 실패 · 전체 개수, 점수 추세, 마지막 검증 시각, 검증 *주기*, 실행 버튼이 모여 있는 품질 대시보드입니다.
| 결과 표
| 규칙별 최신 판정입니다. 상태 · 규칙 · 검증 유형 · 컬럼 · 실제 값 · 상세 · 심각도를 보여 줍니다.
| 품질 규칙 (N)
| 등록된 규칙 목록입니다. 편집 · 삭제 아이콘이 있습니다.
| 데이터 프로파일
| 최신 프로파일의 컬럼별 통계입니다.
| 도움말
| *도움말 — 프로파일과 검증은 어떻게 동작하나요?* 를 누르면 권장 순서, 규칙 유형, 커스텀 Python 작성법이 펼쳐집니다.
|===

=== 품질 점수 영역 (품질 대시보드)

image::catalog-quality/batch-result.png[품질 점수 영역 — 100%, 통과 5 / 실패 0 / 전체 5개, 최근 2회 추세, 900]

* *품질 점수* — 아직 검증한 적이 없으면 `—` 로 표시됩니다. 막대는 80% 이상이면 초록, 50% 이상이면 주황, 그 아래는 빨강입니다.
* *통과 · 실패 · 전체 N개* — 체크 아이콘이 통과, X 아이콘이 실패 규칙 수입니다. *전체* 는 점수 계산에 들어간 규칙 수로,
  미평가 규칙은 빠집니다.
* *점수 추세* — 검증이 2회 이상 쌓이면 최근 20회까지의 점수를 선으로 보여 주고 옆에 *최근 N회* 를 표시합니다.
  직전 검증보다 점수가 바뀌면 `▲ 10.0%p`(초록) 또는 `▼ 26.7%p`(빨강)처럼 변화폭이 함께 나옵니다.
* *마지막 검증* — `방금 전`, `10분 전`, `23시간 전` 처럼 마지막 점수 산출 시각입니다.
* *주기* — <<_검증_주기,검증 주기>> 를 정합니다.
* *프로파일* · *검증 실행* · *규칙 추가* · *규칙 추천* — 각 기능은 아래 절에서 설명합니다. 실행 중에는 버튼이
  *프로파일링...*, *실행 중...* 으로 바뀌고 다시 누를 수 없습니다.

== 프로파일링

프로파일은 원본 DB 에 직접 통계 SQL 을 실행해 컬럼별 분포를 수집한 *스냅숏* 입니다. 규칙이 하나도 없는 데이터셋은
빈 화면에 *데이터 프로파일* · *규칙 추가* 버튼이 보이고, 규칙이 있으면 상단의 *프로파일* 버튼을 씁니다.

image::catalog-quality/empty-state.png[규칙이 없는 데이터셋의 품질 탭 — 데이터 프로파일 · 규칙 추가, 900]

버튼을 누르면 별도 알림 없이 잠시 뒤 *데이터 프로파일* 표가 나타납니다.

image::catalog-quality/profile.png[데이터 프로파일 표 — NULL 비율 20% 를 빨간색으로 강조, 900]

[cols="1,3"]
|===
| 열 | 내용

| 컬럼 · 타입
| 컬럼 이름과 카탈로그에 등록된 타입입니다.
| NULL
| NULL 비율입니다. 0% 보다 크면 빨간색으로 강조됩니다.
| 고유
| 고유 값 비율입니다.
| 최소 · 최대
| 최솟값 · 최댓값입니다. 긴 문자열은 말줄임으로 표시되고, 마우스를 올리면 전체 값이 보입니다.
| 평균
| 숫자형 컬럼만 계산합니다.
| 최빈값
| 고유 값이 20개 이하인 코드성 컬럼의 상위 5개 값과 건수(`BRONZE ×2`)입니다.
|===

바이너리 컬럼은 *바이너리 — 통계 생략* 으로 표시됩니다.

[NOTE]
====
* 화면의 *프로파일* 은 MySQL · MariaDB · PostgreSQL 원본을 지원합니다. 데이터 소스에 저장된 연결 설정(SSL 포함)으로
  접속하며, 접속 10초 · 쿼리 120초 제한이 있습니다. 그 밖의 유형은 xref:catalog/quality-batch.adoc[품질 배치] 로 프로파일을 반입합니다.
* 원본에 접속하지 못하면 카탈로그의 스키마 정보만으로 기본 프로파일(행 수 0, 통계 없음)을 만들고
  *원천 DB 조회에 실패해 스키마 기반 프로파일로 대체했습니다.* 같은 경고 알림에 분류된 사유를 함께 띄웁니다.
  이때는 xref:catalog/platforms.adoc[데이터 소스] 의 연결 설정을 확인하세요.
* 프로파일은 실행 시점의 스냅숏입니다. 원본 데이터가 바뀐 뒤에는 *프로파일* 을 다시 실행해야 검증이 최신 데이터를 반영합니다.
====

== 품질 규칙

=== 규칙 유형

규칙은 10종입니다. *규칙 추가* 대화상자의 *검증 유형* 에는 `유형 — 화면 이름` 형식으로 표시되고, 고르면 바로 아래에 설명이 나옵니다.

[cols="2,4,1,1",options="header"]
|===
| 유형 (화면 이름) | 통과 조건 | 검증 실행 | 품질 배치

| `NOT_NULL` (NULL 없음) | 비-NULL 비율 ≥ 임계값(%) | ✓ | ✓
| `UNIQUE` (고유값) | 고유 값 비율 ≥ 임계값(%) | ✓ | ✓
| `MIN_VALUE` (최소값 하한) | 최솟값 ≥ 기대값 (예: 금액 ≥ 0) | ✓ | ✓
| `MAX_VALUE` (최대값 상한) | 최댓값 ≤ 기대값 | ✓ | ✓
| `ROW_COUNT` (행 수 하한) | 전체 행 수 ≥ 기대값. 테이블 수준이라 컬럼을 지정하지 않습니다. | ✓ | ✓
| `FRESHNESS` (최신성) | 최신 데이터 이후 경과 시간 ≤ 기대값(시간, 기본 24) — 아래 설명 참고 | ✓ | ✓
| `ACCEPTED_VALUES` (허용 값 목록) | 값이 쉼표로 나열한 허용 목록 안에만 있음 (예: `G,PG,PG-13,R,NC-17`) | — | ✓
| `REGEX` (정규식 패턴) | 값이 정규식과 일치 (예: `^[^@]+@[^@]+$`) | — | ✓
| `CUSTOM_SQL` (커스텀 SQL) | 직접 작성한 SELECT 쿼리의 첫 행 첫 컬럼(위반 건수)이 0 | — | ✓
| `CUSTOM_PYTHON` (커스텀 Python) | `quality/custom_checks/` 플러그인 함수가 통과를 반환 | — | ✓
|===

*검증 실행* 열이 `—` 인 4종은 화면의 검증이 직접 판정하지 않습니다. 품질 배치가 남긴 최근 결과를 이어받아 점수에 반영하고,
배치 결과가 없으면 *미평가* 로 둡니다(<<_미평가와_이어받기,미평가와 이어받기>> 참고).

*임계값(%)* 은 `NOT_NULL` · `UNIQUE` 에서만 씁니다.::
* 0 ~ 100 사이 값이며 기본은 100(NULL · 중복을 1건도 허용하지 않음)입니다. 다른 유형에서는 입력란이 비활성이고
  규칙 목록에도 임계값이 표시되지 않습니다.
* `0` 도 그대로 적용됩니다. 임계값 0 인 규칙은 비율과 관계없이 통과하므로 추이만 보고 싶은 컬럼에 쓸 수 있습니다.
* 판정은 반올림한 비율이 아니라 *정확한 건수* 로 합니다. 예를 들어 16,044행 중 NULL 이 183건이면 비율은 98.9% 로 보이지만
  임계값 98.86 에서는 실패, 98.85 에서는 통과입니다. 결과 상세에 `NULL 183건 / 16,044행` 처럼 건수가 함께 표시되니 이것으로 구분하세요.

image::catalog-quality/threshold-results.png[임계값 경계 — 같은 98.9% 라도 임계값 98.86 은 실패, 98.85 · 0 은 통과, 900]

*FRESHNESS* 는 컬럼 지정 여부에 따라 기준이 다릅니다.::
* *시각 컬럼을 지정한 경우* (예: `updated_at`, `last_update`) — 그 컬럼의 *최댓값(가장 최근 데이터 시각)* 이후 지난 시간으로
  판정합니다. 적재가 멈추면 시간이 지날수록 실패로 바뀌므로, 실제 데이터 신선도를 보려면 이 방식을 쓰세요.
  시간대 정보가 없는 값(MySQL `DATETIME` 등)은 xref:catalog/quality-batch.adoc#_원천_데이터_시간대[원천 데이터 시간대] 로 해석합니다.
* *컬럼을 지정하지 않은 경우* — 데이터 시각을 알 수 없으므로 *검증 실행* 은 마지막 프로파일 이후 경과 시간으로 판정하고
  상세에 `프로파일 이후 0.1시간 (최대 24.0시간) — 데이터 시각 기준으로 보려면 시각 컬럼을 지정하세요` 처럼 안내합니다.
  품질 배치는 방금 원본을 읽었으므로 0시간(통과)으로 봅니다.

*심각도* 는 규칙을 만들 때 고르며, 목록과 결과 표에는 한글 배지로 표시됩니다.::
* `BREAKING` → *치명* — 데이터 사용 불가 수준입니다(예: PK NULL, 행 수 0). 치명 실패가 하나라도 있으면 데이터셋 상태가 *BAD* 가 됩니다.
* `WARNING` → *경고* — 주의가 필요합니다(예: NULL 비율 증가, 범위 초과). 기본값입니다.
* `INFO` → *정보* — 참고용입니다.

=== 규칙 추가

*규칙 추가* 를 누르면 *품질 규칙 추가* 대화상자가 열립니다.

image::catalog-quality/rule-add.png[품질 규칙 추가 — ACCEPTED_VALUES 허용 값 목록 입력, 900]

[cols="1,3"]
|===
| 항목 | 설명

| 규칙 이름
| 필수입니다(최대 255자). 비어 있으면 *규칙 추가* 버튼이 비활성입니다.
| 검증 유형
| 위 10종 중 하나를 고릅니다.
| 컬럼 (선택)
| 데이터셋 스키마의 컬럼 목록에서 고릅니다. `ROW_COUNT` · 컬럼 미지정 `FRESHNESS` 처럼 테이블 수준 규칙은
  *선택 안 함 (테이블 수준 — ROW_COUNT/FRESHNESS)* 을 고릅니다.
| 기대값
| 유형에 맞는 값을 적습니다(예시가 입력란에 표시됩니다). `NOT_NULL` · `UNIQUE` 처럼 기대값을 쓰지 않는 유형은
  *이 유형은 기대값을 사용하지 않습니다* 로 비활성입니다.
| 임계값 (%)
| `NOT_NULL` · `UNIQUE` 에서만 입력합니다(기본 100).
| 심각도
| `BREAKING` · `WARNING` · `INFO` 중 하나입니다(기본 `WARNING`).
|===

`CUSTOM_SQL` 을 고르면 기대값 칸이 *검증 SQL* 편집기로, `CUSTOM_PYTHON` 을 고르면 *플러그인 설정 (JSON)* 편집기로 바뀝니다.

image::catalog-quality/rule-custom-sql.png[CUSTOM_SQL — 검증 SQL 편집기, 900]

image::catalog-quality/rule-custom-python.png[CUSTOM_PYTHON — 플러그인 설정 (JSON) 편집기, 900]

저장하면 대화상자가 닫히고 *규칙 '<이름>' 을(를) 추가했습니다.* 알림이 뜨며 규칙 목록에 추가됩니다.
저장에 실패하면 *규칙을 저장하지 못했습니다.* 와 서버가 알려 준 사유가 표시되고, 대화상자는 입력한 값 그대로 열려 있습니다.

image::catalog-quality/rule-add-toast.png[규칙 추가 성공 알림, 900]

TIP: 새 규칙은 다음 *검증 실행* 부터 판정됩니다. 화면이 판정하지 않는 4종(허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python)은
검증 전에도 결과 표에 *미평가* 로 미리 보입니다.

=== 규칙 추천

*규칙 추천* 은 최신 프로파일 통계를 근거로 규칙 후보를 만들어 줍니다. 프로파일이 없거나 후보가 없으면
*추천할 규칙이 없습니다 — 프로파일을 먼저 수집했는지, 이미 같은 규칙이 등록돼 있지 않은지 확인하세요.* 가 표시됩니다.

image::catalog-quality/recommend.png[규칙 추천 (프로파일 기반) — 11 / 11 선택, 900]

[cols="1,3"]
|===
| 프로파일 통계 | 추천 규칙

| NULL 0% | `NOT_NULL` — 지금 깨끗한 컬럼을 계속 깨끗하게 유지
| 고유 100% (10행 이상) | `UNIQUE` — 키 후보
| 최빈값이 수집된 코드성 컬럼 | `ACCEPTED_VALUES` — 현재 값 목록을 허용 목록으로
| 숫자형 최솟값 ≥ 0 | `MIN_VALUE 0` — 음수 유입 감지
| 행 수 > 0 | `ROW_COUNT` — 현재 행 수의 90% 를 하한으로(급감 감지)
|===

후보는 기본으로 모두 선택돼 있고, 아래에 *N / N 선택* 이 표시됩니다. 추천은 *현재 데이터가 깨끗하다* 는 가정에서 나오므로,
의도된 예외가 있는 컬럼(예: 이미 잘못된 값이 섞인 코드 컬럼)은 체크를 해제하세요. *선택한 규칙 N개 생성* 을 누르면
*추천 규칙 N건을 추가했습니다.* 알림과 함께 대화상자가 닫힙니다. 일부만 만들어졌다면 만들어진 건수와 실패 사유를 알려 줍니다.

image::catalog-quality/recommend-toast.png[추천 규칙 생성 성공 알림, 900]

이미 같은 유형 · 같은 컬럼의 규칙(비활성 포함)이 있으면 그 후보는 추천에서 빠지므로, 다시 열어도 중복 후보가 나오지 않습니다.

=== 규칙 수정 · 삭제

규칙 목록 오른쪽의 연필 아이콘(*규칙 편집*)을 누르면 *품질 규칙 수정* 대화상자가 열립니다. 항목은 추가와 같고,
*저장* 하면 *규칙 '<이름>' 을(를) 수정했습니다.* 알림이 뜹니다. 바뀐 기준은 다음 *검증 실행* 부터 반영됩니다.

image::catalog-quality/rule-edit.png[품질 규칙 수정 — ROW_COUNT 기대값 변경, 900]

휴지통 아이콘(*규칙 삭제*)을 누르면 확인 창이 먼저 뜹니다. *삭제* 를 눌러야 지워지며, *규칙 '<이름>' 을(를) 삭제했습니다.* 알림이 뜹니다.

image::catalog-quality/rule-delete.png[규칙 삭제 확인 — 검증 결과 이력도 함께 삭제, 900]

WARNING: 규칙을 지우면 그 규칙의 검증 결과 이력도 함께 지워집니다. 잠시 빼 두려는 것이라면 아래의 비활성화를 쓰세요.

== 검증 실행과 결과

*검증 실행* 을 누르면 다음 순서로 진행됩니다.

. 프로파일이 없으면 먼저 프로파일을 수집합니다. 있으면 *최신 프로파일을 그대로* 씁니다(다시 수집하지 않습니다).
. 활성 규칙 전체를 프로파일 통계와 대조해 통과 / 실패를 판정합니다.
. 화면이 판정하지 않는 4종은 품질 배치의 최근 결과를 이어받고, 없으면 미평가로 둡니다.
. 결과를 저장하고 점수와 데이터셋 품질 상태를 갱신합니다. 실패가 있으면 알림 규칙을 평가합니다.

image::catalog-quality/check-result.png[검증 결과 — 75%, 통과 3 / 실패 1 / 전체 4개 (sakila.staff), 900]

=== 결과 표 읽기

[cols="1,3",options="header"]
|===
| 상태 아이콘 | 의미

| 초록 체크 | 통과
| 빨간 X | 실패 — *실제 값* 과 *상세* 칸에 판정 근거가 표시됩니다(예: `비-NULL 80.0%, NULL 1건 / 5행 (임계값 100.0%)`).
| 회색 물음표 | *미평가 — 점수에서 제외*. 마우스를 올리면 같은 문구가 보입니다.
|===

품질 배치가 반입한 실패에는 위반 행 샘플(최대 5행)이 함께 실립니다. *상세* 칸의 *위반 샘플 N행* 을 누르면 행이 펼쳐지고,
위반한 컬럼 값이 빨간색으로 강조됩니다. 샘플은 `NOT_NULL` · `UNIQUE` · `ACCEPTED_VALUES` · `REGEX` · `MIN_VALUE` · `MAX_VALUE` 처럼
위반 행을 특정할 수 있는 유형에만 붙습니다.

image::catalog-quality/failed-samples.png[위반 샘플 1행 펼침 — 위반 컬럼 password 를 빨간색으로 강조, 900]

[[_미평가와_이어받기]]
=== 미평가와 이어받기

*검증 실행* (수동 · 예약 모두)은 허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python 규칙에 새 결과를 남기지 않습니다.

* 품질 배치가 남긴 결과가 있으면 그 결과를 *이어받아* 점수에 반영합니다. 배치가 찾아낸 실패는 다음 배치 실행 전까지 사라지지 않습니다.
* 배치 결과가 없으면 *미평가* 로 표시하고 점수 계산에서 뺍니다. 상세 칸에 `정규식 검사는 프로파일 통계만으로 평가할 수 없습니다 —
  품질 배치(quality/*.py)에서 전체 데이터로 평가됩니다 — 이전 평가 결과가 없어 점수에서 제외했습니다` 처럼 이유가 나옵니다.

image::catalog-quality/unevaluated.png[배치 결과가 없는 새 REGEX 규칙 — 미평가, 전체 3개에서 제외, 900]

== 품질 점수와 이력

----
점수 = 통과 규칙 수 / 평가된 규칙 수 × 100%
       (평가된 규칙 = 이번에 판정한 규칙 + 배치 결과를 이어받은 규칙, 미평가 제외)
----

* 미평가 규칙은 분모에서 빠지므로 점수를 올리지도 내리지도 않습니다. 화면의 *전체 N개* 도 평가된 규칙 수입니다.
* 평가된 규칙이 하나도 없으면 점수는 100% 입니다.
* 점수에 따라 데이터셋의 품질 상태가 자동으로 바뀌고, 데이터셋 목록 · 상세와 <<_업스트림_품질_경고,업스트림 품질 경고>> 에 쓰입니다.
+
[cols="1,3"]
|===
| 상태 | 조건

| *BAD* | 치명(BREAKING) 실패가 있거나 점수 70% 미만
| *WARN* | 그 밖에 실패가 있거나 점수 90% 미만
| *GOOD* | 모두 통과
|===
* 실패가 있으면 xref:governance/alerts.adoc[알림] 의 품질 실패 규칙이 평가되어 구독자에게 알림이 갑니다.
* 검증할 때마다 점수 이력이 쌓이며, 점수 영역의 추세선이 최근 20회까지 보여 줍니다.

[[_검증_주기]]
== 검증 주기

점수 영역의 *주기* 를 *매시간* · *매일* · *매주* 중 하나로 정하면 서버가 10분마다 도래 여부를 확인해 *검증 실행* 을
자동으로 합니다. *없음* 으로 두면 자동 검증을 하지 않습니다. 값은 바로 저장되며, 저장에 실패하면
*검증 주기를 저장하지 못했습니다.* 알림과 함께 이전 값으로 되돌아갑니다.

image::catalog-quality/schedule.png[검증 주기 선택 — 없음 · 매시간 · 매일 · 매주, 900]

[NOTE]
====
자동 검증도 수동과 똑같이 *최신 프로파일을 재사용* 합니다. 프로파일을 새로 수집하지 않으므로 원본 데이터가 바뀌어도
점수가 그대로이고, 시간이 지나면 컬럼 미지정 `FRESHNESS` 만 실패로 바뀔 수 있습니다. 원본 전체 데이터로 주기적으로
평가하려면 xref:catalog/quality-batch.adoc[품질 배치] 를 스케줄러에 등록하세요.
====

[[_업스트림_품질_경고]]
== 업스트림 품질 경고

xref:catalog/lineage.adoc[리니지] 상 이 데이터셋의 원천 중 품질 상태가 *WARN* 또는 *BAD* 인 데이터셋이 있으면, 품질 탭 맨 위에
*업스트림 품질 경고* 배너가 나타납니다. 원천 데이터셋 이름을 누르면 그 데이터셋으로 이동하고, 옆 배지에 상태와 점수(예: `WARN 75%`)가 보입니다.
파생 데이터의 품질 문제가 원천에서 왔는지 먼저 확인할 때 씁니다.

image::catalog-quality/upstream-warning.png[업스트림 품질 경고 — 원천 sakila.staff WARN 75%, 900]

[[_품질_배치_원본_전체_데이터_검증]]
== 품질 배치 — 원본 전체 데이터 검증

*품질 배치* 는 원본 DB 의 *전체 데이터* 를 읽어 규칙을 평가하고 결과를 품질 탭으로 반입하는 명령줄 스크립트입니다(pandas · PySpark 두 버전).
화면이 판정하지 못하는 허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python 규칙과, 화면 프로파일이 지원하지 않는 원본 유형은 품질 배치로 평가합니다.
설치 · 실행 방법과 인자, 원본 접속, 원천 데이터 시간대 설정은 xref:catalog/quality-batch.adoc[품질 배치] 에서 설명합니다.

== 자주 묻는 질문

[qanda]
허용 값 · 정규식 규칙이 *미평가* 로만 나옵니다.::
  이 4종(허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python)은 화면의 검증이 판정하지 않습니다. xref:catalog/quality-batch.adoc[품질 배치] 를 실행하세요.

원본 데이터를 고쳤는데 점수가 그대로입니다.::
  검증은 최신 프로파일을 재사용합니다. *프로파일* 을 다시 실행한 뒤 *검증 실행* 하세요.

*프로파일* · *검증 실행* · *규칙 추가* 버튼이 보이지 않습니다.::
  해당 기능 권한이 제한된 역할입니다. 관리자에게 요청하세요.

== 사용 시나리오

데이터 신뢰성 확인 (분석가)::
품질 탭 → *프로파일* → NULL · 고유 비율 · 값 범위 확인 → 이상치를 발견하면 원천 담당자에게 확인합니다.

핵심 테이블 SLO 설정 (DBA)::
주문 · 결제 같은 핵심 테이블에서 *규칙 추천* 으로 기본 규칙을 만들고, PK `UNIQUE` 를 *치명* 으로, 금액 `MIN_VALUE` 0,
`ROW_COUNT`, 수정 시각 컬럼을 지정한 `FRESHNESS` 24 를 추가 → *주기* 를 *매일* 로 설정 → 점수 추세로 모니터링합니다.

코드값 · 형식 검증 (데이터 엔지니어)::
상태 코드에 `ACCEPTED_VALUES`, 이메일에 `REGEX`, 참조 무결성에 `CUSTOM_SQL` 을 등록 → 품질 배치를 야간 스케줄에 등록 →
아침에 품질 탭에서 실패 규칙의 *위반 샘플* 을 확인합니다.

전사 품질 거버넌스::
데이터셋 품질 상태(GOOD · WARN · BAD)로 낮은 데이터셋을 먼저 정제하고, xref:governance/alerts.adoc[알림] 규칙과 결합해
품질 실패를 자동으로 통보받습니다. 파생 데이터셋은 *업스트림 품질 경고* 로 원천 문제를 함께 추적합니다.
