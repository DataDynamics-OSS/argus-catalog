= 분류 체계
:toc: macro
:toclevels: 2

분류 체계는 데이터셋을 업무 관점이나 데이터 성격 같은 *기준별 트리* 로 묶어 보는 화면입니다.
태그가 데이터셋에 자유롭게 붙이는 평면 라벨이라면, 분류 체계는 "업무 도메인 › 거래 › 대여" 처럼
상하 관계가 있는 분류에 데이터셋을 배치합니다. 분류 체계는 여러 개를 함께 둘 수 있어서, 같은 데이터셋을
`업무 도메인` 에서는 *거래 › 대여* 로, `데이터 유형` 에서는 *트랜잭션* 으로 동시에 분류할 수 있습니다.

.분류체계와 데이터셋 매핑
image::diagrams/catalog-taxonomies-01.png[분류체계와 데이터셋 매핑,role="diagram"]

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **분류 기준 만들기** — `업무 도메인`, `데이터 유형` 처럼 기준별로 분류체계를 여러 개 둡니다.
* **분류 트리 편집** — 분류와 하위 분류를 만들고, 이름을 바꾸고, 끌어서 순서를 바꿉니다.
* **데이터셋 배치** — 데이터셋을 분류에 매핑하고, 필요 없으면 매핑을 제거합니다.
* **분류별로 찾기** — 분류(하위 포함) 또는 *미분류* 를 골라 데이터셋을 모아 봅니다.

=== 먼저 알아 둘 용어

[cols="1,3"]
|===
| 용어 | 뜻

| 분류체계
| 분류 기준 하나입니다(예: `업무 도메인`, `데이터 유형`). 이름은 전체에서 겹칠 수 없습니다.
| 분류
| 분류체계 안의 트리 노드입니다. 하위 분류를 두어 여러 단계로 나눌 수 있습니다. 같은 상위 분류 아래에서는 이름이 겹칠 수 없습니다.
| 매핑
| 데이터셋을 분류에 연결한 것입니다. 한 데이터셋을 여러 분류(여러 분류체계)에 매핑할 수 있습니다.
| 미분류
| 현재 분류체계의 어느 분류에도 매핑되지 않은 데이터셋입니다.
|===

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 분류 체계* (`/dashboard/taxonomies`) 로 들어갑니다.

=== 누가 무엇을 할 수 있나요

조회는 메뉴가 열려 있는 사용자 누구나 할 수 있고, 편집은 기능 권한 *분류 체계 편집* (`taxonomies.edit`) 이 필요합니다.
이 권한은 따로 허용하지 않으면 관리자만 가집니다.

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 분류체계 · 분류 트리 · 데이터셋 목록 조회
| 메뉴가 열려 있는 사용자 누구나
| 분류체계 추가 · 수정 · 삭제
| 관리자, *분류 체계 편집* 권한을 받은 역할
| 분류 추가 · 이름 변경 · 삭제 · 순서 변경
| 관리자, *분류 체계 편집* 권한을 받은 역할
| 데이터셋 매핑 · 매핑 제거
| 관리자, *분류 체계 편집* 권한을 받은 역할
|===

권한이 없는 사용자에게는 *분류체계 추가* · *분류체계 수정* · *분류체계 삭제* 버튼, 트리 우클릭 메뉴, 끌어서 순서 바꾸기,
*데이터셋 매핑* 버튼과 행 끝의 *제거* 가 나타나지 않습니다. 설명 · 트리 · 데이터셋 목록은 그대로 볼 수 있습니다.

image::catalog-taxonomies/user-readonly.png[편집 권한이 없는 사용자의 화면 — 조회만 가능, 900]

TIP: 일반 사용자에게 편집을 맡기려면 xref:ops/permissions.adoc[권한 관리] 의 기능 권한에서 *분류 체계 편집* 에 해당 역할을 체크해 저장합니다.

== 화면 구성

image::catalog-taxonomies/business-domain.png[분류 체계 화면 — 업무 도메인 트리와 전체 데이터셋, 900]

화면은 세 부분으로 나뉩니다.

[cols="1,3"]
|===
| 영역 | 설명

| 상단 막대
| *분류체계 선택* 상자에서 볼 분류체계를 고릅니다. 처음 열면 목록의 첫 분류체계가 자동으로 선택됩니다.
오른쪽에 편집 버튼과 선택한 분류체계의 설명이 보입니다.
| 왼쪽 트리
| 맨 위 *카테고리* 가 루트이고, 그 아래에 분류가 단계별로 펼쳐집니다. 맨 끝에는 *미분류* 노드가 있습니다.
각 노드 오른쪽 숫자는 그 분류에 속한 데이터셋 수이며, *하위 분류까지 합친 수* 입니다.
화살표로 접고 펼 수 있고, 트리와 오른쪽 목록 사이 경계선을 끌어 트리 폭을 조절할 수 있습니다.
| 오른쪽 목록
| 트리에서 고른 노드의 데이터셋을 보여 줍니다. 목록 열과 카드 보기 전환은 xref:catalog/datasets.adoc[데이터셋] 목록과 같습니다.
|===

오른쪽 목록 제목은 트리에서 무엇을 골랐는지에 따라 달라집니다.

[cols="1,1,3"]
|===
| 선택 | 제목 | 보이는 데이터셋

| 아무것도 고르지 않음
| 전체 데이터셋 (N)
| 모든 데이터셋입니다.
| 분류
| 데이터셋 (N)
| 그 분류와 *모든 하위 분류* 에 매핑된 데이터셋입니다.
| 미분류
| 미분류 (N)
| 현재 분류체계의 어느 분류에도 매핑되지 않은 데이터셋입니다.
|===

NOTE: 숫자와 목록에는 *삭제됨(removed)* 상태 데이터셋이 들어가지 않습니다. 그래서 트리 숫자와 오른쪽 목록 건수는 항상 같습니다.

분류체계를 바꾸면 트리 모양도 바뀝니다. 아래는 단계 없이 분류 네 개만 둔 `데이터 유형` 분류체계입니다.

image::catalog-taxonomies/data-type.png[데이터 유형 — 단계 없는 평면 트리, 900]

=== 기본 제공 분류체계

샘플 데이터(Sakila)와 함께 설치하면 다음 두 분류체계가 들어 있습니다. 그대로 쓰거나 참고용으로 두고 새 분류체계를 만들어도 됩니다.

[cols="1,2,3"]
|===
| 분류체계 | 기준 | 분류

| 업무 도메인
| 비즈니스 기능 관점
| 고객(회원 관리 · 주소·지역), 상품(영화 카탈로그 · 장르·출연), 운영(재고 관리 · 점포·인사), 거래(대여 · 결제)
| 데이터 유형
| 데이터 모델링 역할 관점
| 마스터 · 트랜잭션 · 매핑 · 파생
|===

== 분류체계 관리

=== 분류체계 추가

. 상단의 *분류체계 추가* 를 누릅니다.
. *분류체계 추가* 대화상자에 *이름* (필수)과 *설명* (분류체계의 용도·기준)을 적고 *생성* 을 누릅니다. 이름이 비어 있으면 *생성* 버튼이 눌리지 않습니다.
. "분류체계를 생성했습니다." 알림과 함께 새 분류체계가 선택됩니다. 트리에는 아직 분류가 없다는 안내와, 모든 데이터셋이 들어 있는 *미분류* 만 보입니다.

image::catalog-taxonomies/create-dialog.png[분류체계 추가 대화상자, 900]

이미 있는 이름으로 만들면 "분류체계를 저장하지 못했습니다." 와 함께 "같은 이름(키)의 항목이 이미 있습니다. 다른 값을 사용하세요." 가 표시되고 대화상자는 열린 채로 남습니다.

=== 분류체계 수정

분류체계를 고른 상태에서 *분류체계 수정* 을 누르면 현재 이름과 설명이 채워진 *분류체계 수정* 대화상자가 열립니다.
고친 뒤 *저장* 하면 "분류체계를 수정했습니다." 알림이 뜨고 상단 설명이 바로 바뀝니다. 설명을 비우고 저장하면 설명이 지워집니다.

image::catalog-taxonomies/edit-dialog.png[분류체계 수정 대화상자, 900]

=== 분류체계 삭제

*분류체계 삭제* 를 누르면 확인 대화상자 "분류체계를 삭제할까요?" 가 열립니다.
분류체계 안에 분류가 남아 있으면 "분류 N개가 있어 삭제되지 않습니다. 분류를 먼저 정리하세요." 라는 안내가 함께 보입니다.
N 은 모든 단계의 분류를 합친 수입니다.

image::catalog-taxonomies/taxonomy-delete-confirm.png[분류체계 삭제 확인 — 남은 분류 수 안내, 900]

분류가 남아 있는 상태에서 *삭제* 를 누르면 삭제되지 않고 "분류체계를 삭제할 수 없습니다: 하위 분류 N개가 있습니다." 오류가 표시됩니다.
분류를 모두 지운 뒤에 다시 삭제합니다. *취소* 를 누르면 아무것도 바뀌지 않습니다.

== 분류 트리 편집

분류는 트리에서 *마우스 오른쪽 버튼* 메뉴로 편집합니다.

[cols="1,3"]
|===
| 우클릭 위치 | 메뉴

| *카테고리* (루트)
| *분류 추가* — 최상위 분류를 만듭니다.
| 분류
| *하위 분류 추가* · *이름 변경* · *삭제*
|===

image::catalog-taxonomies/context-menu.png[분류 우클릭 메뉴 — 하위 분류 추가 · 이름 변경 · 삭제, 900]

=== 분류 추가

. 최상위 분류는 *카테고리* 를, 하위 분류는 부모가 될 분류를 우클릭합니다.
. *분류 추가* 또는 *하위 분류 추가* 를 고릅니다. 두 경우 모두 *분류 추가* 대화상자가 열립니다.
. *이름* 을 적고 *저장* 을 누르면 트리가 바로 갱신됩니다.

image::catalog-taxonomies/add-child-dialog.png[분류 추가 대화상자, 900]

같은 상위 분류(최상위끼리 포함) 아래에 이미 같은 이름이 있으면 "분류를 저장하지 못했습니다." 와 함께
"같은 이름(키)의 항목이 이미 있습니다. 다른 값을 사용하세요." 가 표시되고 대화상자가 열린 채로 남습니다.
상위 분류가 다르면 같은 이름을 써도 됩니다.

=== 이름 변경

분류를 우클릭해 *이름 변경* 을 고르면 현재 이름이 채워진 *분류 이름 변경* 대화상자가 열립니다.
고친 뒤 *저장* 하면 트리에 바로 반영됩니다.

image::catalog-taxonomies/rename-dialog.png[분류 이름 변경 대화상자, 900]

NOTE: 화면에서는 분류를 다른 상위 분류 아래로 옮길 수 없습니다. 위치를 바꾸려면 새 위치에 분류를 만들고 매핑을 다시 하거나,
REST API(`PUT /api/v1/catalog/categories/{id}` 의 `parent_id`)를 사용합니다(<<_rest_api,부록: REST API>> 참고).

=== 순서 바꾸기

같은 상위 분류 아래의 분류(형제)끼리는 *끌어서 놓기* 로 순서를 바꿉니다.

. 옮길 분류를 끌어 다른 형제 분류 위에 올립니다. 끄는 분류는 흐리게 보입니다.
. 놓을 자리에 파란 선이 위쪽 또는 아래쪽에 나타납니다. 대상 분류의 위쪽 절반에 놓으면 그 앞, 아래쪽 절반에 놓으면 그 뒤로 들어갑니다.
. 놓으면 순서가 저장되고 새로고침해도 유지됩니다.

image::catalog-taxonomies/drag-reorder.png[끌어서 순서 바꾸기 — 놓을 자리에 파란 선 표시, 900]

상위 분류가 다른 분류 위에서는 파란 선이 나타나지 않고 놓아도 바뀌지 않습니다.
순서를 한 번도 바꾸지 않은 분류는 이름순으로 표시됩니다.

=== 분류 삭제

분류를 우클릭해 *삭제* 를 고르면 확인 대화상자 "분류를 삭제할까요?" 가 열립니다. 상황에 따라 안내가 다릅니다.

[cols="1,3"]
|===
| 분류 상태 | 결과

| 하위 분류가 있음
| "하위 분류 N개가 있어 삭제되지 않습니다. 하위 분류를 먼저 정리하세요." 안내가 보이고, *삭제* 를 눌러도 "분류를 삭제할 수 없습니다: 하위 분류 N개가 있습니다." 오류로 끝납니다. 아래 단계부터 지웁니다.
| 하위 분류는 없고 매핑된 데이터셋이 있음
| "이 분류에 매핑된 데이터셋 N개의 매핑도 함께 해제됩니다(데이터셋 자체는 삭제되지 않음)." 안내가 보이고, *삭제* 하면 분류와 매핑이 함께 지워집니다.
| 하위 분류도 매핑도 없음
| 바로 삭제됩니다.
|===

image::catalog-taxonomies/category-delete-confirm.png[매핑된 분류 삭제 확인 — 매핑도 함께 해제됨을 안내, 900]

== 데이터셋 매핑

=== 분류에 데이터셋 추가

. 트리에서 데이터셋을 넣을 분류를 고릅니다. 오른쪽 제목 옆에 *데이터셋 매핑* 버튼이 나타납니다.
. *데이터셋 매핑* 을 누르면 같은 이름의 대화상자가 열리고 데이터셋 목록이 보입니다.
. *데이터셋 검색...* 칸에 검색어를 적어 좁힙니다. 이름 · 표시 이름 · 요약 · 설명 · URN 으로 찾으며, 한 번에 최대 50건까지 보입니다.
. 넣을 데이터셋의 체크박스를 고릅니다. 머리글 체크박스로 보이는 행을 모두 고를 수도 있습니다. 왼쪽 아래에 "N개 선택됨" 이 표시됩니다.
. *선택 추가* 를 누르면 "데이터셋 N개를 매핑했습니다." 알림과 함께 목록과 트리 숫자가 갱신됩니다.

image::catalog-taxonomies/map-dialog.png[데이터셋 매핑 대화상자 — 검색 후 여러 개 선택, 900]

이미 매핑된 데이터셋을 다시 골라도 중복으로 들어가지 않습니다.

매핑 후 트리 숫자를 보면 하위 분류의 수가 상위 분류로 합산되고, *미분류* 수는 매핑한 만큼 줄어든 것을 확인할 수 있습니다.

image::catalog-taxonomies/rollup.png[매핑 후 — 상위 분류에 하위 수가 합산되고 미분류가 줄어듦, 900]

=== 분류별 데이터셋 보기

상위 분류를 고르면 하위 분류에 매핑된 데이터셋까지 모두 보입니다.

image::catalog-taxonomies/subtree.png[상위 분류(상품) 선택 — 하위 분류 데이터셋까지 7개, 하위 분류 행에는 제거 없음, 900]

*미분류* 를 고르면 아직 이 분류체계로 정리되지 않은 데이터셋만 모아 볼 수 있습니다. 분류 작업을 할 때 남은 데이터셋을 찾는 데 유용합니다.

image::catalog-taxonomies/uncategorized.png[미분류 선택 — 매핑되지 않은 데이터셋, 900]

목록 아래 페이지 표시줄에서 *페이지당 행 수* (10 · 20 · 30 · 40 · 50, 기본 50)와 페이지를 바꿀 수 있습니다.
행 수를 바꾸거나 트리에서 다른 노드를 고르면 1페이지로 돌아갑니다.

image::catalog-taxonomies/pagination.png[페이지당 10행, 2페이지, 900]

=== 매핑 제거

. 분류를 고른 상태에서 데이터셋 행 끝의 *제거* 를 누릅니다.
. 확인 대화상자 "분류에서 데이터셋을 제거할까요?" 에서 *제거* 를 누릅니다. 데이터셋 자체는 삭제되지 않고 매핑만 해제됩니다.
. "매핑을 제거했습니다." 알림과 함께 목록과 트리 숫자가 줄어듭니다.

image::catalog-taxonomies/remove-confirm.png[매핑 제거 확인 대화상자, 900]

*제거* 는 지금 고른 분류에 직접 매핑된 데이터셋 행에만 나타납니다. 상위 분류를 고르면 하위 분류의 데이터셋도
목록에 함께 보이지만 그 행에는 *제거* 가 없습니다. 이런 데이터셋은 실제로 매핑된 하위 분류를 골라 제거하세요.

== 데이터셋 상세에서 보기

데이터셋이 어떤 분류에 들어 있는지는 xref:catalog/datasets.adoc[데이터셋] 상세의 *개요* 탭에서도 확인할 수 있습니다.
*메타데이터* 표 맨 위에 *분류 체계* 행이 매핑마다 하나씩 `분류체계 > 상위 분류 > 분류` 경로로 표시됩니다.

image::catalog-taxonomies/dataset-categories.png[데이터셋 상세 개요 — 분류 체계 행, 900]

== 자주 묻는 질문

[qanda]
"같은 이름(키)의 항목이 이미 있습니다" 가 나옵니다.::
  분류체계 이름은 전체에서, 분류 이름은 같은 상위 분류 아래에서 겹칠 수 없습니다. 다른 이름을 쓰세요.

분류체계나 분류가 지워지지 않습니다.::
  안에 (하위) 분류가 남아 있습니다. 가장 아래 단계 분류부터 지운 뒤 다시 삭제하세요.

상위 분류를 골랐는데 일부 행에 *제거* 가 없습니다.::
  하위 분류에 매핑된 데이터셋입니다. 실제로 매핑된 하위 분류를 골라 제거하세요.

분류를 다른 상위 분류 아래로 옮기고 싶습니다.::
  화면에서는 옮길 수 없습니다. 새 위치에 분류를 만들어 다시 매핑하거나 REST API 를 쓰세요.

편집 버튼과 우클릭 메뉴가 보이지 않습니다.::
  *분류 체계 편집* 권한이 없습니다. 관리자에게 요청하세요.

[[_rest_api]]
== 부록: REST API

화면과 같은 기능을 REST API 로도 쓸 수 있습니다. 모든 API 에 로그인 토큰(`Authorization: Bearer <토큰>`)이 필요하고, 쓰기는 *분류 체계 편집* 권한도 필요합니다
(로그인하지 않으면 401, 권한이 없으면 403).

[cols="2,3"]
|===
| API | 용도

| `GET /api/v1/catalog/taxonomies`
| 분류체계 목록
| `POST` · `PUT` · `DELETE /api/v1/catalog/taxonomies[/{id}]`
| 분류체계 추가 · 수정 · 삭제 (분류가 남아 있으면 삭제 409)
| `GET /api/v1/catalog/taxonomies/{id}/tree`
| 분류 트리와 분류별 데이터셋 수(하위 포함), 미분류 수
| `POST` · `PUT` · `DELETE /api/v1/catalog/categories[/{id}]`
| 분류 추가 · 수정(이름 · 상위 분류 · 순서) · 삭제 (하위 분류가 있으면 삭제 409)
| `POST` · `DELETE /api/v1/catalog/datasets/{dataset_id}/categories/{category_id}`
| 데이터셋 매핑 · 매핑 제거
| `GET /api/v1/catalog/datasets/{dataset_id}/categories`
| 데이터셋이 속한 분류 목록(경로 포함)
| `GET /api/v1/catalog/categories/{id}/direct-dataset-ids`
| 그 분류에 직접 매핑된 데이터셋 ID 목록(하위 분류 매핑 제외 — 화면에서 *제거* 를 보일 행을 가릴 때 씀, 분류가 없으면 404)
| `GET /api/v1/catalog/datasets?category_id={id}`
| 분류(하위 포함)의 데이터셋 목록
| `GET /api/v1/catalog/datasets?taxonomy_id={id}&uncategorized=true`
| 분류체계의 미분류 데이터셋 목록
|===

분류를 다른 상위 분류로 옮길 때는 `PUT /api/v1/catalog/categories/{id}` 에 `parent_id` 를 보내고, 최상위로 올릴 때는 `"parent_id": null` 을 보냅니다.
자기 자신이나 자기 하위 분류 아래로, 또는 다른 분류체계의 분류 아래로는 옮길 수 없습니다(400).
