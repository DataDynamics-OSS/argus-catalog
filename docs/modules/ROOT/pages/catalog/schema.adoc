= 스키마
:toc: macro
:toclevels: 2

데이터셋 상세의 *스키마* 탭은 테이블이 어떤 컬럼으로 이뤄져 있는지 보여 주고, 필요하면 직접 고칠 수 있는 곳입니다.
스키마가 바뀔 때마다 스냅샷이 남아 *변경 이력* 에서 언제 어떤 컬럼이 추가 · 삭제 · 변경되었는지 되짚어 볼 수 있고,
같은 스키마로 만든 *Avro 스키마* 를 외부 시스템이 받아 갈 수도 있습니다.

.스키마 편집·변경 이력·Avro 조회
image::diagrams/catalog-schema-01.png[스키마 편집·변경 이력·Avro 조회,role="diagram"]

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **컬럼 보기** — 컬럼 이름 · 타입 · 키 · NULL 허용 · 설명을 한 표에서 봅니다.
* **스키마 수정** — 컬럼을 추가 · 삭제하고 논리명 · 타입 · 설명을 고칩니다.
* **변경 이력** — 언제 어떤 컬럼이 추가 · 삭제 · 변경되었는지 스냅샷으로 되짚어 봅니다.
* **Avro 스키마** — 스키마로 만든 Avro 스키마를 보고, 고치고, 외부 시스템에서 받아 갑니다.

=== 메뉴 위치

xref:catalog/datasets.adoc[데이터셋] 목록에서 데이터셋을 연 뒤 다음 탭으로 이동합니다.

[cols="1,3"]
|===
| 위치 | 내용

| *스키마 (N)* 탭
| 컬럼 목록과 스키마 수정입니다. 괄호 안 숫자는 컬럼 수입니다.
| *더보기 → 변경 이력*
| 스키마 스냅샷과 컬럼 변경 내역입니다.
| *더보기 → Avro*
| 자동 생성 Avro 스키마, 편집, 가져오기 가이드입니다.
|===

=== 누가 무엇을 할 수 있나요

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 스키마 · 변경 이력 · Avro 조회
| 로그인한 사용자 누구나
| *스키마 수정*, Avro *편집* · *초기화*
| 관리자, 그 데이터셋을 만든 사람(생성자)
|===

권한이 없으면 *스키마 수정* 버튼과 Avro 의 *편집* · *초기화* 버튼이 보이지 않습니다. Avro 의 *가져오기 가이드* 는 누구나 볼 수 있습니다.

== 스키마 탭 보기

image::catalog-schema/overview.png[스키마 탭 — 컬럼 목록, 900]

컬럼마다 다음 정보가 보입니다.

[cols="1,3"]
|===
| 칸 | 내용

| 필드
| 컬럼 물리명입니다.
| 논리명
| 화면에 보일 컬럼 이름입니다. 없으면 `-` 로 표시됩니다.
| 타입
| 카탈로그에서 쓰는 타입입니다(예: `INTEGER`, `VARCHAR`, `DECIMAL(14,2)`).
| 네이티브 타입
| 원천 DB 의 실제 타입입니다(예: `SMALLINT UNSIGNED`). 25자를 넘으면 잘라서 보여 주고, 마우스를 올리면 전체 값이 보입니다.
| PK · 고유 · 인덱스
| 기본 키, 고유 제약, 인덱스 여부입니다. 체크 표시로 나타납니다.
| 파티션 · 분산
| 파티션 키, 분산 키(StarRocks · Greenplum 등) 여부입니다.
| Null
| NULL 허용 여부입니다.
| 설명
| 컬럼 설명입니다. 직접 쓰거나 xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 으로 채울 수 있습니다.
|===

Hive · MySQL 등 데이터 소스에 따라 컬럼 목록 아래에 그 데이터 소스만의 속성(저장 형식, 엔진, 파티션 정보 등)을 모은
카드가 함께 표시됩니다. 이 카드는 동기화로 채워지며 화면에서는 읽기 전용입니다.

TIP: 컬럼을 데이터 표준 용어와 연결하는 일은 *표준 용어* 탭에서 합니다. xref:governance/standards.adoc[데이터 표준] 을 참고하세요.

== 스키마 수정

편집 권한이 있으면 스키마 탭 오른쪽 위에 *스키마 수정* 버튼이 보입니다. 누르면 표가 편집 그리드로 바뀝니다.

image::catalog-schema/edit-grid.png[스키마 수정 그리드 — 타입 선택, 900]

[cols="1,3"]
|===
| 그리드 칸 | 입력 방법

| Field *
| 컬럼 이름입니다. 필수입니다.
| Logical Name · Native Type · Description
| 셀을 한 번 눌러 바로 입력합니다.
| Type *
| 셀을 누르면 데이터 소스 종류에 맞는 타입 목록(예: PostgreSQL 이면 `integer`, `varchar`, `money` 등)에서 고릅니다.
| PK · Unique · Partition · Nullable
| `true` / `false` 중에서 고릅니다.
| Index
| 직접 고르지 않습니다. PK 이거나 Unique 이면 자동으로 체크됩니다.
| (휴지통)
| 그 행을 삭제합니다.
|===

* *Add Field* 로 맨 아래에 새 행을 추가합니다.
* 고친 뒤 *Update* 를 누르면 저장되고, *Cancel* 을 누르면 편집 전으로 돌아갑니다.
* 편집 그리드 아래의 *Datasource Features* 는 데이터 소스별 속성으로, 여기서는 확인만 할 수 있습니다.

=== 저장할 때 알아 둘 점

* 같은 필드 이름이 두 번 들어 있으면 저장되지 않습니다. 오류 알림에 겹친 필드 이름이 표시됩니다.
* 저장은 컬럼 이름 기준으로 바뀐 부분만 반영합니다. 그래서 동기화로 스키마가 다시 들어오면서 설명이 비어 있어도,
  사용자가 적어 둔 컬럼 설명은 그대로 유지됩니다.
+
image::catalog-schema/description-kept.png[타입이 바뀌어도 유지된 컬럼 설명, 900]
* 저장 결과는 곧바로 변경 이력에 스냅샷으로 남습니다.

[[_키_표시_규칙]]
[TIP]
.고급 사용자 — 키 표시 규칙
====
그리드는 키 표시를 다음 규칙으로 자동 정리합니다. ER 다이어그램이 이 값으로 관계의 카디널리티(1:1 · N:1)를 판단하므로,
실제 제약과 어긋나지 않도록 맞춰 줍니다.

* PK 가 *한 컬럼* 이면 그 컬럼은 *고유* 로도 표시됩니다.
* 여러 컬럼이 함께 PK 를 이루는 *복합 PK* 이면 각 컬럼은 고유로 표시되지 않습니다. 컬럼 하나만으로는 유일하지 않기 때문입니다.
* *인덱스* 는 PK 이거나 고유인 컬럼에 자동으로 표시됩니다.
====

[[_변경_이력]]
== 변경 이력

*더보기 → 변경 이력* 을 열면 *스키마 변경 이력* 카드가 보입니다. 데이터 소스 동기화나 스키마 수정으로 컬럼에 변화가
생길 때마다 스냅샷이 하나씩 쌓이며, 화면에는 최근 20개가 표시됩니다.

image::catalog-schema/history.png[스키마 변경 이력 — 스냅샷을 펼친 모습, 900]

[cols="1,3"]
|===
| 칸 | 내용

| 동기화 시각
| 스냅샷이 만들어진 시각입니다. 행을 누르면 변경 내역이 펼쳐집니다.
| 필드
| 그 시점의 컬럼 수입니다.
| 변경 내역
| "추가 1개, 변경 2개, 삭제 1개" 처럼 요약한 문장입니다.
| 건수
| 변경된 컬럼 수입니다.
|===

행을 펼치면 컬럼마다 변경 종류가 색으로 구분되어 보입니다.

[cols="1,3"]
|===
| 표시 | 의미

| *+ 추가* (녹색)
| 새로 생긴 컬럼입니다. 컬럼의 속성(타입 · NULL 허용 · 키 등)이 함께 표시됩니다.
| *− 삭제* (빨간색)
| 없어진 컬럼입니다. 삭제 전 속성이 취소선으로 표시됩니다.
| *변경* (주황색)
| 속성이 바뀐 컬럼입니다. 바뀌기 전 값(취소선) → 바뀐 값 순서로 보여 줍니다.
|===

image::catalog-schema/history-modify.png[타입만 바뀐 스냅샷 — 변경 1개, 900]

데이터셋의 첫 스냅샷은 비교할 이전 상태가 없으므로 펼치면 "최초 동기화 — 비교할 이전 상태 없음" 으로 표시됩니다.

NOTE: 스키마 수정 그리드로 처음 저장할 때는 <<_키_표시_규칙,키 표시 규칙>> 에 따라 PK 컬럼의 고유 · 인덱스 표시가 정리되면서
그 컬럼이 *변경* 으로 함께 기록될 수 있습니다.

스냅샷의 변경 내역은 xref:governance/alerts.adoc[알림] 의 입력으로도 쓰입니다. 알림 규칙이 있으면 변경 종류에 따라

|===

[[_avro_스키마]]
== Avro 스키마

*더보기 → Avro* 는 데이터셋 스키마로 만든 Avro 레코드 스키마를 보여 줍니다. Kafka producer/consumer, Spark/Flink 작업처럼
Avro 스키마가 필요한 외부 시스템이 이 값을 그대로 가져다 쓸 수 있습니다.

image::catalog-schema/avro.png[Avro 스키마 — 자동 생성, 900]

[[_자동_생성_규칙]]
[TIP]
.고급 사용자 — 자동 생성 규칙
====
[cols="1,3"]
|===
| 필드 | 값

| `name`
| 물리명의 `.` 을 `_` 로 바꾼 값입니다(예: `sakila.film` → `sakila_film`).
| `namespace`
| 데이터 소스 ID 입니다.
| `doc`
| 데이터셋 설명을 한 줄 평문으로 바꾼 값입니다. 서식 · 마크다운 기호는 빠집니다. 설명이 없으면 `Avro schema for <물리명>` 입니다.
| `fields`
| 컬럼마다 하나씩 만들어집니다. 타입은 컬럼 타입으로 정해지며(예: `INTEGER` → `int`, `DECIMAL(12,2)` → `bytes` + `decimal` 논리 타입),
NULL 을 허용하는 컬럼은 `["null", 타입]` 형식에 `"default": null` 이 붙습니다.
|===
====

스키마 필드가 하나도 없으면 "스키마 필드를 먼저 정의하면 Avro 스키마가 자동 생성됩니다." 라고 안내합니다.

=== 편집과 초기화

자동 생성 결과를 그대로 쓰기 어렵다면 직접 고친 *사용자 편집본* 을 저장할 수 있습니다.

. *편집* 을 누르면 JSON 편집기가 열립니다.
. 값을 고칩니다. JSON 이 올바르지 않으면 편집기 아래에 "유효하지 않은 JSON 입니다." 가 표시되고 *저장* 이 꺼집니다.
  고친 내용이 없을 때도 *저장* 은 꺼져 있습니다.
+
image::catalog-schema/avro-edit.png[Avro 편집기, 900]
. *저장* 을 누르면 "Avro 스키마를 저장했습니다." 알림이 뜨고 제목 옆에 *사용자 편집본* 배지가 붙습니다.
+
image::catalog-schema/avro-saved.png[저장된 사용자 편집본, 900]
. 자동 생성으로 되돌리려면 *초기화* 를 누릅니다. "자동 생성 스키마로 초기화했습니다." 알림과 함께 배지가 사라집니다.

사용자 편집본은 화면뿐 아니라 외부 조회 API 에도 그대로 반영됩니다. 편집본이 있는 동안에는 스키마를 고쳐도
Avro 가 자동으로 바뀌지 않으니, 스키마를 크게 바꿨다면 *초기화* 후 다시 편집하세요.

=== 가져오기 가이드

*가져오기 가이드* 를 누르면 외부 시스템에서 Avro 스키마를 받아 가는 예시가 *curl* · *wget* · *Python* 탭으로 열립니다.
예시에는 지금 보고 있는 데이터셋의 URN 과 ID 가 채워져 있어 그대로 복사해 쓸 수 있습니다.

image::catalog-schema/avro-fetch-guide.png[Avro 스키마 가져오기 가이드, 900]

모든 `/api/v1` 호출에는 로그인 토큰이 필요하므로 예시에는 `Authorization: Bearer $TOKEN` 헤더가 들어 있습니다.
토큰은 *curl* 탭 맨 위의 *0)* 처럼 로그인 API(`POST /api/v1/auth/login`)로 받습니다. 외부 시스템용 계정을 따로 만들어 쓰는 것을 권장합니다.

[TIP]
.고급 사용자 — 외부 조회 API
====
[source,bash]
----
# 0) 토큰 받기 — 외부 시스템용 계정으로 로그인 (Access 토큰 8시간 유효)
TOKEN=$(curl -s -X POST "http://<server>/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"<사용자명>","password":"<비밀번호>"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# URN 으로 조회 (외부 시스템에 권장 — 데이터셋 식별자가 안정적)
curl -s -H "Authorization: Bearer $TOKEN" "http://<server>/api/v1/external/avro-schema?urn=<URN>"

# 내부 데이터셋 ID 로도 조회 가능
curl -s -H "Authorization: Bearer $TOKEN" "http://<server>/api/v1/external/datasets/<ID>/avro-schema"

# 캐시를 거치지 않고 최신 값 조회 (편집 직후 등)
curl -s -H "Authorization: Bearer $TOKEN" "http://<server>/api/v1/external/avro-schema?urn=<URN>&no_cache=true"

# wget 으로 파일 저장
wget -O dataset.avsc --header="Authorization: Bearer $TOKEN" "http://<server>/api/v1/external/avro-schema?urn=<URN>"
----

[source,python]
----
import json, urllib.parse, urllib.request

BASE = "http://<server>"
login = urllib.request.Request(
    f"{BASE}/api/v1/auth/login",
    data=json.dumps({"username": "<사용자명>", "password": "<비밀번호>"}).encode(),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(login, timeout=10) as resp:
    token = json.load(resp)["access_token"]

url = f"{BASE}/api/v1/external/avro-schema?urn=" + urllib.parse.quote("<URN>")
req = urllib.request.Request(url, headers={"Authorization": f"Bearer {token}"})
with urllib.request.urlopen(req, timeout=10) as resp:
    print(json.dumps(json.load(resp), indent=2, ensure_ascii=False))
----

외부 조회 API 도 로그인 토큰(`Authorization: Bearer <토큰>`)이 있어야 호출할 수 있고, 응답을 잠시(기본 300초) 캐시합니다. 편집 직후 바로 확인하려면
`no_cache=true` 를 붙이세요. 자세한 사용법과 캐시 설정은 xref:appendix/api.adoc[API] 를 참고하세요.
====

  같은 필드 이름이 두 번 들어 있습니다. 오류 알림에 표시된 필드 이름을 고치세요.

스키마를 바꿨는데 Avro 스키마가 그대로입니다.::
  *사용자 편집본* 이 있는 동안에는 Avro 가 자동으로 바뀌지 않습니다. *초기화* 후 다시 편집하세요.

Avro 를 고쳤는데 외부 조회 결과가 예전 값입니다.::
  외부 조회 API 는 응답을 잠시(기본 300초) 캐시합니다. `no_cache=true` 를 붙여 조회하세요.

데이터 소스 속성 카드를 고칠 수 없습니다.::
  저장 형식 · 엔진 같은 데이터 소스 속성은 동기화로 채워지며 화면에서는 읽기 전용입니다.
