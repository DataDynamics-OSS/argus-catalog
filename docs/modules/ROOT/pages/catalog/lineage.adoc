= 리니지 & ERD
:toc: macro
:toclevels: 2

리니지는 데이터가 어디에서 와서 어디로 흘러가는지를 보여 줍니다. 데이터셋 사이의 흐름은 물론, 어떤 컬럼이
어떤 컬럼으로 이어지는지까지 따라갈 수 있어 "이 컬럼을 바꾸면 어디가 영향을 받을까?" 를 미리 확인할 수 있습니다.
데이터셋 상세에는 리니지 외에도 테이블 사이의 관계를 보여 주는 *관계* · *ER 다이어그램* 화면이 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **흐름 보기** — 데이터셋으로 들어오고 나가는 데이터 흐름을 그래프로 봅니다.
* **영향 확인** — 컬럼 매핑으로 어떤 컬럼이 어떤 컬럼으로 이어지는지 따라갑니다.
* **흐름 등록** — 관리자는 ETL · 복제 같은 흐름을 직접 등록합니다.
* **함께 쓰이는 테이블** — 실제 쿼리에서 함께 조인된 데이터셋과 컬럼을 봅니다.
* **ER 다이어그램** — 외래 키로 연결된 테이블 구조를 그림으로 보고 Mermaid 소스로 복사합니다.

=== 먼저 알아 둘 용어

[cols="1,3"]
|===
| 용어 · 화면 | 뜻

| 리니지
| 데이터 *흐름* 입니다. 쿼리 로그에서 자동으로 모은 흐름과 사람이 등록한 흐름(ETL · 복제 · 파생 등)을 그래프로 보여 줍니다.
| 관계
| 실제 쿼리에서 *함께 조인된* 데이터셋과 컬럼입니다. 사용 빈도 기반입니다.
| ER 다이어그램
| DDL 의 *외래 키(FK)* 로 정의된 구조적 관계입니다.
| 업스트림 · 다운스트림
| 이 데이터셋으로 데이터를 보내는 쪽(원천)이 업스트림, 이 데이터셋에서 데이터를 받는 쪽이 다운스트림입니다.
|===

.리니지·관계·ER 다이어그램의 수집 경로

=== 메뉴 위치

xref:catalog/datasets.adoc[데이터셋] 상세에서 *더보기* 를 누르고 *리니지* · *관계* · *ER 다이어그램* 중 하나를 고릅니다.
고른 항목은 탭 자리에 이름이 표시됩니다. *ER 다이어그램* 은 관계형 DB(MySQL · MariaDB · PostgreSQL · Greenplum ·
Oracle · SQL Server · StarRocks · Tibero) 데이터 소스의 데이터셋에만 나타납니다.

=== 누가 무엇을 할 수 있나요

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 리니지 · 관계 · ER 다이어그램 조회
| 로그인한 사용자 누구나
| *리니지 추가*, 리니지 삭제
| 관리자만
|===

관리자가 아니면 *리니지 추가* 버튼과 리니지 상세의 휴지통 아이콘이 보이지 않습니다.

== 리니지 그래프 보기

image::catalog-lineage/graph.png[리니지 그래프 — sakila.rental 중심, 900]

지금 보고 있는 데이터셋이 *현재* 배지와 함께 강조되고, 그 데이터셋으로 들어오는 쪽(업스트림)은 왼쪽에, 나가는 쪽(다운스트림)은
오른쪽에 그려집니다. 다른 데이터 소스에 있는 데이터셋도 하나의 그래프에 함께 나타납니다.

[cols="1,3"]
|===
| 요소 | 설명

| 노드
| 데이터셋입니다. 이름, 데이터 소스 종류 배지(`mysql`, `postgresql` 등), 데이터 소스 이름이 보입니다. 이름을 누르면 그 데이터셋 상세로 이동합니다.
| 노드의 색 점
| 품질 상태가 좋지 않은 데이터셋입니다(주황 · 빨강). 원천의 품질 문제가 아래로 퍼지는지 한눈에 볼 수 있습니다.
| 엣지
| 데이터 흐름입니다. 선의 색과 모양, 라벨로 출처를 구분합니다(아래 범례).
| 범례 (오른쪽 위)
| *QUERY* (파란 점선), *수동* (주황 실선), *PIPELINE* (초록 실선)입니다.
| 확대 · 축소 (왼쪽 아래)
| 그래프를 확대 · 축소합니다. 빈 곳을 끌어 화면을 옮기고, 노드도 끌어서 옮길 수 있습니다.
|===

리니지가 하나도 없으면 "이 데이터셋에 사용 가능한 리니지 정보가 없습니다." 가 표시되고, 관리자에게는 그 아래 *리니지 추가* 버튼이 보입니다.

NOTE: 외래 키(FK)로 만들어진 관계는 데이터 흐름이 아니라 테이블 구조이므로 리니지 그래프에 그리지 않습니다.
FK 관계는 <<_er_다이어그램,ER 다이어그램>> 에서 확인하세요.

=== 리니지 출처

[cols="1,1,3"]
|===
| 출처 | 엣지 · 배지 | 설명

| 쿼리 기반 자동 수집
| QUERY · *Auto*
| xref:extensions/index.adoc[Extension] (Trino · Impala · StarRocks · Hive 등)이 쿼리 로그에서 "어느 테이블을 읽어 어느 테이블에 썼는지" 를 집계합니다.
| 수동 등록
| 수동 · *Manual*
| 관리자가 화면의 *리니지 추가* 나 API 로 등록합니다.
| 파이프라인
| PIPELINE · *Pipeline*
| 등록할 때 파이프라인(Airflow DAG · Kestra Flow 등)을 지정한 흐름입니다.
|===

=== 리니지 상세

엣지를 누르면 *리니지 상세* 창이 열립니다. 창은 끌어서 옮기거나 크기를 바꿀 수 있습니다.

image::catalog-lineage/edge-detail.png[리니지 상세 — 수동 등록 엣지, 900]

[cols="1,3"]
|===
| 항목 | 설명

| 출처 배지
| Manual · Pipeline · Auto 입니다. 한 쌍의 데이터셋 사이에 출처가 여러 개면 출처별로 구역이 나뉘어 보입니다.
| 소스 → 타겟
| 흐름의 방향입니다.
| 관계 · 설명
| 수동 · 파이프라인 등록에서 지정한 관계 유형과 설명입니다.
| JOIN 컬럼
| 쿼리 기반 리니지에서 조인에 쓰인 컬럼 쌍입니다.
| 컬럼 매핑 (N)
| `소스 컬럼 → 타겟 컬럼` 과 변환 유형입니다.
| 휴지통
| 수동 · 파이프라인 리니지를 삭제합니다(관리자만). 삭제하면 "리니지를 삭제했습니다." 알림이 뜹니다.
|===

== 리니지 추가

관리자는 그래프 왼쪽 위의 *리니지 추가* 로 흐름을 직접 등록합니다. 대화상자는 *방향 → 데이터셋 → 컬럼* 세 단계입니다.

. *방향* — "이 데이터셋의 역할:" 을 고릅니다.
** *소스 (상위)* — 이 데이터셋이 다른 데이터셋에 데이터를 제공합니다.
** *타겟 (하위)* — 이 데이터셋이 다른 데이터셋으로부터 데이터를 받습니다.
. *데이터셋* — 상대 데이터셋과 관계를 지정합니다.
+
image::catalog-lineage/add-step2.png[리니지 추가 ② 데이터셋 · 관계 유형 · 파이프라인, 700]
+
[cols="1,3"]
|===
| 항목 | 설명

| 데이터 소스
| 상대 데이터셋 검색 범위를 좁힙니다. 기본은 *전체 데이터 소스* 입니다.
| 타겟 데이터셋 / 소스 데이터셋
| 이름으로 검색해 고릅니다. 1단계에서 고른 역할에 따라 이름이 바뀝니다.
| 관계 유형
| ETL · 파일 내보내기 · CDC · 복제 · 파생 · 읽기/쓰기 중에서 고릅니다.
| 파이프라인 (선택)
| 이 흐름을 실행하는 파이프라인입니다. 지정하면 출처가 *Pipeline* 으로 표시됩니다.
| 설명 (선택)
| 예: "HR 데이터를 Parquet 으로 내보내 Impala 에 적재"
|===
. *컬럼* — 컬럼 매핑을 추가합니다(선택). *행 추가* 를 누르고 소스 컬럼 · 타겟 컬럼 · 유형을 고릅니다.
  컬럼 선택지에는 각 데이터셋의 스키마가 타입과 함께 보입니다.
+
image::catalog-lineage/add-step3.png[리니지 추가 ③ 컬럼 매핑, 700]
+
매핑 없이 등록하려면 *건너뛰고 저장*, 매핑과 함께 등록하려면 *저장* 을 누릅니다.

저장하면 "리니지를 추가했습니다." 알림과 함께 그래프에 새 엣지가 나타납니다. 엣지를 눌러 등록한 내용을 확인할 수 있습니다.

image::catalog-lineage/column-mapping.png[파이프라인을 지정해 등록한 리니지와 컬럼 매핑, 900]

NOTE: 같은 소스 · 타겟 · 관계 유형의 리니지는 한 번만 등록할 수 있습니다. 자기 자신을 소스와 타겟으로 동시에 지정할 수도 없습니다.

== 컬럼 수준 매핑

컬럼 매핑은 입력 컬럼이 어떤 변환을 거쳐 출력 컬럼이 되는지를 기록합니다. 업스트림 컬럼을 바꾸거나 지울 때 어떤
다운스트림 컬럼이 영향을 받는지 판단하는 근거가 됩니다.

.컬럼 변환과 매핑 관계
image::diagrams/catalog-lineage-02.png[컬럼 변환과 매핑 관계,role="diagram"]

[cols="1,1,3"]
|===
| 유형 | 화면 선택지 | 의미

| DIRECT
| 직접
| 값을 그대로 옮깁니다.
| CAST
| 캐스팅
| 타입만 바꿔 옮깁니다.
| EXPRESSION
| 표현식
| 계산식을 거칩니다(예: `SUM(amount)`, `UPPER(name)`).
| DERIVED
| 파생
| 여러 입력에서 만들어집니다.
| AGGREGATION · JOIN_KEY
| (자동 수집)
| 쿼리 기반 리니지에서 집계 · 조인 키로 발견된 컬럼입니다.
|===

image::catalog-lineage/expression-mapping.png[EXPRESSION 유형의 컬럼 매핑, 900]

화면에서는 등록한 리니지의 컬럼 매핑만 따로 고칠 수 없습니다. 바꾸려면 리니지를 지우고 다시 등록합니다.

[TIP]
.고급 사용자 — API 로 컬럼 매핑 바꾸기
====
관리자 계정으로 카탈로그 REST API(`PUT /api/v1/catalog/lineage/{리니지 ID}/column-mappings`)를 호출하면 매핑을 통째로 바꿀 수 있습니다.
====

== 관계

*더보기 → 관계* 는 실제 쿼리에서 이 데이터셋과 *함께 조인된* 데이터셋과 컬럼을 보여 줍니다. 데이터 흐름을 나타내는 리니지와는
별개로, "이 테이블은 보통 어떤 테이블과 같이 쓰이는가" 를 알려 줍니다. 관계 데이터는
xref:extensions/relationship-analyzer.adoc[Relationship Analyzer] 가 쿼리 로그의 JOIN 을 분석해 채웁니다.

image::catalog-lineage/relationships.png[관계 그래프 — 1홉, 900]

[cols="1,3"]
|===
| 영역 | 설명

| 관계 그래프
| 이 데이터셋을 중심으로 함께 조인되는 데이터셋의 관계망입니다. 왼쪽 위에서 *1홉 · 2홉 · 3홉* 범위를 고릅니다(기본 1홉). 선 굵기는 함께 조인된 빈도이고, 엣지를 누르면 어떤 컬럼끼리 조인되었는지 보여 줍니다.
| 함께 쓰인 데이터셋
| 실제 쿼리에서 이 데이터셋과 자주 함께 조인된 데이터셋과 횟수입니다.
| 컬럼 관계
| 이 데이터셋의 컬럼이 다른 데이터셋의 어떤 컬럼과 JOIN 키로 쓰였는지 보여 줍니다.
|===

image::catalog-lineage/column-relationships.png[함께 쓰인 데이터셋과 컬럼 관계 표, 900]

컬럼 관계 표의 칸은 다음과 같습니다.

[cols="1,3"]
|===
| 칸 | 내용

| 내 컬럼 · 관련 컬럼
| 이 데이터셋의 컬럼과, 함께 조인된 상대 데이터셋 · 컬럼입니다.
| 유형
| 관계 종류입니다(예: `JOIN_KEY`).
| 빈도
| 함께 조인된 횟수입니다. 그 아래에 *명시*(`JOIN … ON a.x = b.y`) · *암묵*(`FROM a, b WHERE a.x = b.y`) 건수가 나뉘어 보입니다.
| 마지막 발견
| 이 관계가 마지막으로 발견된 날짜입니다.
|===

아직 수집된 관계가 없으면 "수집된 쿼리에서 발견된 관계가 없습니다." 가 표시됩니다. 쿼리 수집이 켜지면 JOIN 패턴으로 자동 발견됩니다.

[[_er_다이어그램]]
== ER 다이어그램

*더보기 → ER 다이어그램* 은 이 데이터셋을 가운데 두고, 외래 키로 직접 연결된 테이블을 상자와 선으로 그립니다.

image::catalog-lineage/erd.png[ER 다이어그램 — sakila.film 중심, 900]

* 가운데 상자가 지금 보고 있는 테이블입니다(*현재* 배지).
* *왼쪽* 에는 이 테이블을 참조하는 자식 테이블이, *오른쪽* 에는 이 테이블이 참조하는 부모 테이블이 놓입니다.
* 상자에는 컬럼과 타입이 보이고, 컬럼이 많으면 "… N개 더보기" 로 펼치고 *접기* 로 줄입니다.

위쪽 범례의 의미는 다음과 같습니다.

[cols="1,3"]
|===
| 표시 | 의미

| 열쇠 아이콘 (PK) · 링크 아이콘 (FK)
| 기본 키 컬럼과 외래 키 컬럼입니다.
| `?`
| NULL 을 허용하는 컬럼입니다.
| 파란 실선 (DDL 제약)
| DDL 에 정의된 외래 키입니다.
| 회색 점선 (리니지 추정)
| DDL 에 외래 키가 없어 리니지 정보로 추정한 관계입니다.
| 엣지 라벨
| FK 컬럼과 카디널리티입니다. 자식 쪽에서 부모 쪽으로 `N:1`, 자식의 FK 컬럼이 단독으로 고유하면 `1:1` 로 표시됩니다.
|===

TIP: 오른쪽 위 *Mermaid 복사* 를 누르면 지금 다이어그램을 Mermaid `erDiagram` 소스로 복사합니다("Mermaid erDiagram 소스를 복사했습니다.").
설계 문서나 위키에 그대로 붙여 넣을 수 있습니다.

[[_관계를_찾는_규칙]]
[TIP]
.고급 사용자 — 관계를 찾는 규칙
====
* 여러 컬럼이 함께 PK 를 이루는 테이블(예: `film_actor`)의 FK 컬럼은 단독으로 고유하지 않으므로 `N:1` 로 표시됩니다.
* FK 의 참조 대상에 스키마를 적지 않았다면 자식 테이블과 *같은 스키마* 의 테이블을 먼저 찾습니다. 다른 스키마의 같은 이름 테이블을
  가리키려면 `REFERENCES 스키마.테이블` 처럼 스키마를 명시하세요.
* 상태가 제거된 데이터셋은 상대 테이블로 그리지 않습니다.
====

image::catalog-lineage/erd-orders.png[DDL 외래 키로 그린 orders → order_summary 관계, 900]

DDL 도 스키마 정보도 없으면 "ERD 를 구성할 수 없습니다 — DDL 또는 스키마 정보가 필요합니다." 가 표시됩니다.
DDL 은 데이터셋 상세의 *DDL* 탭에서 확인할 수 있습니다(xref:catalog/datasets.adoc#_ddl_탭[데이터셋 → DDL 탭]).

== 파이프라인

리니지에 연결하는 파이프라인(Airflow DAG · Kestra Flow 등)은 xref:extensions/index.adoc[Extension] 이나 API 로
등록되며, 리니지 추가 2단계의 *파이프라인 (선택)* 에서 고를 수 있습니다. 파이프라인을 지정한 리니지는 그래프에서
*PIPELINE* (초록 실선)으로 구분되어, 어떤 흐름이 어떤 작업으로 실행되는지 바로 알 수 있습니다.

== 자주 묻는 질문

[qanda]
*리니지 추가* 버튼이 보이지 않습니다.::
  리니지 추가 · 삭제는 관리자만 할 수 있습니다.

리니지를 저장할 수 없습니다.::
  같은 소스 · 타겟 · 관계 유형의 리니지가 이미 있거나, 자기 자신을 소스와 타겟으로 동시에 지정했습니다.

외래 키(FK) 관계가 리니지 그래프에 없습니다.::
  FK 는 데이터 흐름이 아니라 테이블 구조이므로 리니지에 그리지 않습니다. *ER 다이어그램* 에서 확인하세요.

*더보기* 에 *ER 다이어그램* 이 없습니다.::
  ER 다이어그램은 관계형 DB 데이터 소스의 데이터셋에만 나타납니다.

"ERD 를 구성할 수 없습니다" 가 표시됩니다.::
  DDL 도 스키마 정보도 없는 데이터셋입니다. ER 다이어그램은 DDL 이나 스키마 정보가 있어야 그릴 수 있습니다.

*관계* 화면이 비어 있습니다.::
  아직 수집된 쿼리에서 JOIN 이 발견되지 않았습니다. 쿼리 수집이 켜지면 자동으로 채워집니다.
