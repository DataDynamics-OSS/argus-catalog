= 리니지

리니지는 데이터가 어디에서 와서 어디로 흘러가는지를 보여 줍니다. 서로 다른 시스템을
넘나드는 데이터 흐름을 데이터셋·컬럼 수준까지 추적합니다.

== 그래프 화면

데이터셋 상세의 *Lineage* 탭에서 진입합니다. 그래프는 노드와 엣지로 그려집니다.

* *노드* — 데이터셋을 나타내며, 플랫폼 종류별로 아이콘/색상이 다릅니다.
* *엣지* — 데이터 흐름을 나타내며, 굵기는 매핑된 컬럼 수에 비례합니다.
* *컨트롤* — 줌, 드래그, 업/다운스트림 토글, 깊이(hops) 조절을 제공합니다.

업스트림 (입력) 과 다운스트림 (출력) 을 각각 N hops 까지 펼칠 수 있습니다. 그래프가
너무 크면 *Focus on Node* 로 특정 데이터셋을 중심으로 한 부분 뷰만 그릴 수 있습니다.

== Cross-Platform 리니지

리니지 관계는 플랫폼이 서로 달라도 하나의 그래프에 함께 표시됩니다.

예시 흐름::
Kafka 토픽 → Spark 잡 → Hive 테이블 → ETL → MySQL 마트 → BI 도구

이렇게 여러 시스템에 걸친 흐름이 한 화면에 그려지며, 각 단계의 변환 종류 (`ETL`,
`CDC`, `FILE_EXPORT`, `REPLICATION` 등) 가 엣지 라벨로 표시됩니다.

== 컬럼 수준 매핑

// TODO: screenshot - 컬럼 매핑 뷰 (입력 컬럼 → 출력 컬럼 선)
image::catalog-lineage/column-mapping.png[컬럼 매핑, 800]

엣지를 클릭하면 컬럼과 컬럼이 어떻게 이어지는지 펼쳐서 볼 수 있습니다.

[cols="1,3"]
|===
| 매핑 종류 | 설명

| DIRECT
| 1:1 로 그대로 복사합니다.
| CAST
| 타입을 변환합니다.
| EXPRESSION
| 표현식입니다 (`UPPER(x)`, `CONCAT(a, b)` 등). 표현식 텍스트도 함께 저장됩니다.
| DERIVED
| 여러 입력에서 파생됩니다.
|===

컬럼 매핑은 영향 분석의 입력으로도 쓰입니다. 업스트림 컬럼을 DROP 하면, 그에 매핑된
다운스트림 컬럼이 자동으로 영향 대상에 나열됩니다.

== 리니지 출처

각 엣지에는 그 관계가 어디서 왔는지 출처가 기록됩니다.

* *QUERY_AGGREGATED* — Extension (Trino · Impala · StarRocks · Hive 등) 이 쿼리
  로그에서 자동으로 집계합니다.
* *PIPELINE* — 파이프라인 레지스트리에 등록된 정의를 기반으로 합니다.
* *MANUAL* — UI 또는 SDK 로 직접 등록합니다.

UI 의 필터를 쓰면 출처별로 표시하거나 숨길 수 있습니다.

데이터셋 상세의 *Pipelines* 탭 또는 카탈로그 메뉴의 *Pipelines* 에서 진입합니다.
파이프라인 단위로 입력/출력 데이터셋을 등록합니다.

* *이름* — 식별자입니다 (예: `airflow.dag.customer_etl`).
* *종류* — Airflow / Kestra / NiFi / 기타 중에서 고릅니다.
* *입력 / 출력 데이터셋* — URN 으로 선택합니다.
* *스케줄 · 상태* — 외부 시스템에서 가져온 메타데이터입니다.

Argus Catalog 의 xref:appendix/extensions.adoc[Extension] 을 설치하면 Airflow DAG ·
Kestra Flow · NiFi Flow 가 자동으로 등록됩니다.
