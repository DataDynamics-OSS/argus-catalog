= 카탈로그
:toc: macro
:toclevels: 2

카탈로그는 데이터셋을 묶는 단위입니다. 두 가지가 있습니다.

* *데이터 소스와 함께 생긴 카탈로그* — xref:catalog/platforms.adoc[데이터 소스] 를 등록하면 자동으로 만들어지고,
  메타데이터 동기화로 들어온 데이터셋이 여기에 담깁니다.
* *직접 등록한 카탈로그* — 데이터 소스 없이 카탈로그 화면에서 만듭니다. 엑셀로 관리하는 자료, 아직 접속 정보를 받지 못한 업무 시스템처럼
  메타데이터를 자동으로 가져올 수 없는 데이터셋을 사람이 직접 등록합니다. 이 데이터셋을 *수동 데이터셋* 이라 부릅니다.

수동 데이터셋은 나중에 실제 데이터 소스의 테이블에 *원천 매핑* 할 수 있습니다. 매핑하면 품질 진단과 쿼리 리니지가 그 테이블을
이 데이터셋으로 보고, 메타데이터 수집은 그 테이블을 건너뛰어 같은 테이블이 두 번 등록되지 않습니다.

== 시작하기 전에

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 카탈로그* (`/dashboard/catalogs`) 로 들어갑니다.

=== 누가 무엇을 할 수 있나요

[cols="2,3",options="header"]
|===
| 작업 | 필요한 권한

| 카탈로그 보기
| 메뉴 권한 *카탈로그*
| 카탈로그 등록 · 편집 · 삭제, 조회 엔진 연결, 원천 매핑 · 해제 · 다시 확인 · 원천 스키마 가져오기
| 기능 권한 *카탈로그 관리*(`catalogs.manage`) 또는 *데이터 소스 관리*(`datasources.manage`). 정하지 않으면 관리자만
| 카탈로그에 데이터셋 추가
| 기능 권한 *데이터셋 등록*(`datasets.create`) — xref:catalog/datasets.adoc#_데이터셋_추가[데이터셋 추가] 와 같습니다
|===

변경은 모두 xref:ops/audit.adoc[감사 로그] 의 *카탈로그* 범주에 남습니다.

== 카탈로그 목록

왼쪽에 카탈로그가 보이고, 고르면 오른쪽에 상세가 열립니다. 직접 등록한 카탈로그가 위에 옵니다.
각 행에는 이름, 데이터셋 수, *직접 등록* 또는 *데이터 소스와 함께 생성* 표시와 수집하는 데이터 소스 이름이 보입니다.
위쪽 검색 칸으로 이름 · 종류 · 요약 · 소유자를 거를 수 있습니다.

== 카탈로그 등록

오른쪽 위 *카탈로그 등록* 을 누릅니다.

[cols="1,3"]
|===
| 항목 | 설명

| 이름
| 카탈로그 이름입니다(필수). 데이터셋 URN 의 앞부분은 이름이 아니라 자동으로 정해지는 카탈로그 식별자라, 나중에 이름을 바꿔도 URN 은 그대로입니다.
| 종류 (선택)
| 자료의 종류를 자유롭게 적습니다(예: `excel`, `업무 시스템`).
| 요약 · 설명 · 소유자
| 카탈로그를 설명하는 정보입니다. 나중에 *편집* 으로 고칠 수 있습니다.
| 시스템 (선택)
| 이 카탈로그의 자료를 운영하는 시스템입니다. 시스템이 속한 조직이 이 카탈로그 데이터셋의 *소관기관* 이 되어
  AI-Ready 필수 메타데이터(C05)를 채웁니다. 목록은 xref:catalog/platforms.adoc[데이터 소스] 화면의 조직 · 시스템입니다.
  나중에 *편집* 으로 바꾸거나 *지정 안 함* 으로 비울 수 있습니다.
|===

== 카탈로그 상세

헤더에 이름, *직접 등록* 표시, 종류, 카탈로그 식별자가 보이고 오른쪽에 *편집* · *삭제* 가 있습니다.

* 데이터 소스와 함께 생긴 카탈로그는 이름을 바꾸거나 삭제할 수 없습니다(데이터 소스를 따릅니다). 요약 · 설명 · 소유자는 고칠 수 있습니다.
* 직접 등록한 카탈로그는 데이터셋이 남아 있으면 삭제할 수 없습니다. 데이터셋을 먼저 지웁니다.

=== 개요 탭

원천(직접 등록 / 외부), 데이터셋 수, 소유자, 설명을 봅니다. 직접 등록한 카탈로그는 *시스템* 과 그 조직(소관기관)도 보입니다.

=== 데이터셋 탭

이 카탈로그의 데이터셋 목록입니다. *데이터셋 추가* 를 누르면 카탈로그가 이미 정해진 데이터셋 추가 대화상자가 열립니다.
직접 등록한 카탈로그에서는 *원천 매핑* 열에 데이터셋마다 매핑 상태가 보입니다.

[cols="1,3",options="header"]
|===
| 상태 | 뜻

| 매핑 없음 | 아직 실제 테이블에 매핑하지 않았습니다.
| 확인 안 함 | 매핑은 했지만 원천을 확인하지 않았습니다.
| 일치 | 원천 테이블이 있고 컬럼 이름 · 타입이 같습니다.
| 스키마 다름 | 원천 테이블은 있지만 컬럼이 다릅니다.
| 원천에 없음 | 그 경로의 테이블이 원천에 없습니다.
| 확인 불가 | 원천에 접속하지 못했습니다(접속 정보 · 네트워크 확인).
| 비교 미지원 | 이 데이터 소스 유형은 아직 원천 비교를 하지 않습니다(지금은 MySQL · PostgreSQL 만).
|===

=== 데이터 소스 연결 탭

이 카탈로그를 수집(SYNC)하는 데이터 소스와 조회(QUERY)하는 쿼리 엔진이 보입니다.
직접 등록한 카탈로그는 수집하지 않으므로, 이 카탈로그를 읽는 쿼리 엔진(Impala · Trino · StarRocks)만 *조회 엔진 연결* 로 더할 수 있습니다.
엔진 안에서 이 카탈로그를 부르는 이름이 다르면 *엔진 안 카탈로그 이름* 에 적습니다.

== 원천 매핑 [[help-catalog-source-map]]

수동 데이터셋의 상세 화면 *개요* 탭 아래에 *원천 매핑* 영역이 있습니다. 헤더에는 *수동 등록* 표시가 붙습니다.

. *원천 매핑* 을 누릅니다.
. *데이터 소스* 를 고르고 *원천 경로* 를 적습니다(예: `sales.orders`, PostgreSQL 은 `db.schema.table` 도 됩니다). 기본값은 데이터셋의 경로입니다.
. *확인* 을 누르면 세 가지를 검사합니다.
** *겹침* — 그 테이블에 이미 수집된 데이터셋이 있거나 다른 수동 데이터셋이 매핑되어 있으면 저장할 수 없습니다. 겹치는 데이터셋 링크가 보입니다.
** *존재* · *스키마* — 원천에 테이블이 있는지, 컬럼이 같은지 봅니다. 결과는 참고용이라 다르거나 확인하지 못해도 저장할 수 있습니다.
. *매핑 저장* 을 누릅니다.

매핑한 뒤에는 다음 단추를 씁니다.

* *다시 확인* — 원천을 다시 읽어 상태를 갱신합니다.
* *원천 스키마 가져오기* — 원천의 컬럼을 데이터셋에 더하고 타입을 원천에 맞춥니다. 이 데이터셋에만 있는 컬럼과 설명 · 표시 이름은 그대로 둡니다.
* *매핑 변경* · *해제* — 언제든 바꿀 수 있습니다. 해제하면 다음 메타데이터 수집부터 그 테이블이 별도의 수집 데이터셋으로 등록될 수 있습니다.

[TIP]
.고급 사용자 — 매핑이 하는 일
====
* *메타데이터 수집* — 매핑된 테이블은 수집하지 않고 실행 기록의 *건너뜀* 으로 셉니다. 내장 수집과 Metadata Sync 모두 같습니다.
* *품질 진단* — 수동 데이터셋의 프로파일링 · 정밀 진단은 매핑된 데이터 소스와 경로로 원천을 읽습니다. 매핑이 없으면 품질 탭 위에
  안내 띠가 나오고 *원천 매핑* 단추로 이 영역에 옵니다. 품질 규칙은 매핑 전에도 만들어 둘 수 있습니다.
* *쿼리 리니지* — 매핑된 테이블을 읽거나 쓴 쿼리는 이 데이터셋의 리니지로 이어집니다.
* 경로는 입력한 대소문자 그대로 저장하고, 겹침 검사는 대소문자를 가리지 않습니다.
====
