= 데이터셋
:toc: macro
:toclevels: 2

데이터셋은 Argus Catalog 의 중심 항목입니다. 여러 데이터 소스에 흩어진 테이블 · 뷰를 한곳에 모아,
누가 책임지는지 · 어떤 컬럼으로 이뤄졌는지 · 어디서 와서 어디로 흘러가는지 · 품질은 어떤지를 함께 관리합니다.
대부분의 데이터셋은 데이터 소스 동기화로 자동 등록되고, 필요하면 화면에서 직접 추가할 수도 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **찾기** — 이름 · 설명 · 데이터 소스 · 환경 · 조직으로 데이터셋을 찾습니다.
* **설명 달기** — 논리명 · 요약 · 상세 설명을 적고 소유자 · 태그 · 용어집을 연결합니다.
* **살펴보기** — 스키마 · DDL · 샘플 · 품질 · 리니지를 한 화면의 탭에서 봅니다.
* **함께 쓰기** — 댓글로 질문 · 제안을 남기고 변경 요청을 올립니다.
* **관리하기** — 데이터셋을 직접 추가하고 상태 · 환경을 바꾸거나 삭제합니다.

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 데이터셋* (`/dashboard/datasets`) 으로 들어갑니다.
목록에서 행을 누르면 상세 화면(`/dashboard/datasets/<ID>`)이 열리며, 이 주소를 그대로 링크로 공유할 수 있습니다.

=== 누가 무엇을 할 수 있나요

화면을 쓰려면 로그인해야 하고, xref:ops/permissions.adoc[권한 관리] 에서 *데이터셋* 메뉴가 열려 있어야 합니다.
작업별로 할 수 있는 사람은 다음과 같습니다.

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 목록 · 상세 조회, 댓글 작성
| 로그인한 사용자 누구나
| *데이터셋 추가*
| 관리자. 관리자가 xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서 허용하면 일반 사용자도(기본은 꺼짐 — 버튼이 관리자에게만 보입니다)
| 논리명 · 요약 · 설명 편집, 메타데이터 저장, 소유자 · 태그 · 용어집 연결, 스키마 수정, 샘플 업로드, Avro 편집, AI 제안 승인 · 거절, 상태 · 환경 변경, 삭제
| 관리자, 그 데이터셋을 만든 사람(생성자)
| 리니지 추가 · 삭제
| 관리자만
| 댓글 수정 · 삭제
| 댓글 작성자, 관리자
|===

NOTE: 데이터셋을 편집할 수 있는지는 *생성자* 기준으로 판단합니다. 메타데이터 탭의 *소유자* 로 등록되었다고 해서
편집 권한이 생기지는 않습니다. 동기화로 등록된 데이터셋은 보통 관리자 계정이 생성자입니다.

권한이 없는 사용자에게는 편집 컨트롤이 아예 보이지 않습니다. 아래는 일반 사용자가 남의 데이터셋을 연 화면으로,
헤더의 작업(⋯) 버튼과 *추가* 버튼이 없고 입력란은 비활성으로 표시됩니다.

image::catalog-datasets/metadata-read-only.png[권한이 없는 사용자의 메타데이터 탭 — 읽기 전용, 900]

[TIP]
.고급 사용자 — 기능 권한으로 탭 숨기기
====
권한 관리의 *기능 권한* 으로 일부 탭을 역할별로 숨길 수 있습니다.

[cols="1,3"]
|===
| 기능 권한 | 막으면

| 샘플 데이터 조회 (`datasets.sample-view`)
| *샘플* 탭이 보이지 않고, 샘플 조회 요청도 거부됩니다.
| DDL 조회 (`datasets.ddl-view`)
| *DDL* 탭이 보이지 않고, 상세 응답에서도 DDL 이 빠집니다.
| 이관 코드 탭 (`datasets.transfer-code`)
| *더보기* 메뉴의 PySpark · Kestra · Airflow 항목이 보이지 않습니다.
| AI 메타데이터 생성 (`ai.generate`)
| 헤더 작업 메뉴의 *AI 자동 생성* 항목이 보이지 않습니다.
|===
====

| 상태

| 동기화
| 데이터 소스 동기화로 등록·갱신된 데이터셋에는 *동기화됨* 배지가 붙습니다.
| 필드 · 등록일
| 컬럼 수와 카탈로그에 등록된 날짜입니다.
| ⋯
| *상세 보기* 와 *삭제* 메뉴입니다. *삭제* 는 편집 권한이 있는 데이터셋에만 보입니다.
|===

| 검색어와 필터를 모두 지웁니다.

=== 테이블 보기와 카드 보기

검색 버튼 오른쪽의 두 아이콘으로 *테이블 뷰* 와 *카드 뷰* 를 전환합니다. 고른 보기는 브라우저에 기억됩니다.
카드에는 논리명 아래에 스키마를 포함한 물리명이 함께 표시됩니다. 화면 아래에서 *페이지당 행 수* 와 페이지를
바꿀 수 있고, 이때도 적용한 필터는 그대로 유지됩니다.

== 데이터셋 추가

동기화 대상이 아닌 테이블을 카탈로그에 올리고 싶을 때 씁니다. 목록 오른쪽 위 *데이터셋 추가* 를 누릅니다.

버튼은 기본적으로 관리자에게만 보입니다. 관리자가 xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서
*일반 사용자의 데이터셋 직접 등록 허용* 을 켜면 일반 사용자에게도 보입니다. 이때도 xref:ops/permissions.adoc[권한 관리] 의
기능 권한 *데이터셋 등록*(`datasets.create`)에서 해제된 역할에는 보이지 않습니다. 등록한 사람이 그 데이터셋의 생성자가 되어 편집할 수 있습니다.

image::catalog-datasets/add-dialog.png[데이터셋 추가 대화상자, 700]

[cols="1,3"]
|===
| 항목 | 설명

| 물리명 (테이블명)
| 원천의 실제 이름입니다. `스키마.테이블` 형식을 권장합니다(예: `shop.orders`). 대소문자는 입력한 그대로 저장됩니다.
| 논리명 (선택, 표시용)
| 화면에 보일 이름입니다(예: `주문`).
| 데이터 소스
| 데이터셋이 속한 데이터 소스입니다. 선택지 옆에 그 데이터 소스의 환경이 함께 보입니다.
| 요약 (한 줄, 최대 200자)
| 목록과 헤더에 보이는 한 줄 설명입니다.
| 상세 설명
| 자세한 설명입니다. 나중에 개요 탭에서 서식을 넣어 다시 고칠 수 있습니다.
|===

*환경* 은 따로 입력하지 않습니다. 대화상자에 "환경은 데이터 소스의 값 DEV 을 따릅니다." 처럼 안내되며,
고른 데이터 소스의 환경이 그대로 적용됩니다. *생성* 을 누르면 "데이터셋 '<이름>' 을(를) 추가했습니다." 알림과 함께
목록 맨 위에 새 데이터셋이 보입니다. 같은 데이터 소스에 같은 물리명이 이미 있으면 대화상자 안에 오류가 표시되고 만들어지지 않습니다.

NOTE: 데이터 소스 선택지에는 메타데이터 동기화를 지원하는 종류(PostgreSQL · MySQL · Hive · Impala 등)의 데이터 소스만 나옵니다.
태그 · 소유자 · 용어집 · 스키마는 만든 뒤 상세 화면에서 추가합니다.

[[_urn]]
[TIP]
.고급 사용자 — URN
====
데이터셋은 카탈로그 전체에서 URN 으로 식별됩니다. 리니지 · 알림 · 외부 조회 API 가 이 값을 키로 씁니다.

----
{데이터 소스 ID}.{물리명}.dataset
예: sakila-mysql.sakila.film.dataset
----

환경은 URN 에 들어가지 않습니다. 그래서 데이터셋의 환경을 DEV 에서 PROD 로 바꿔도 URN 은 그대로입니다.
예전 형식(`….sakila.film.DEV.dataset`)으로 조회해도 같은 데이터셋을 찾아 줍니다.
====

=== 헤더

헤더에는 논리명과 괄호 안의 물리명(원천의 대소문자 그대로), 한 줄 요약, URN 이 보이고, 오른쪽에 상태 · 환경 배지와
*동기화됨* 배지가 붙습니다. 편집 권한이 있으면 맨 오른쪽에 작업(⋯) 버튼이 나타납니다.

=== 탭 구성

[cols="1,3"]
|===
| 탭 | 내용

| 개요
| 메타데이터 요약 표(분류 체계 · URN · 용어집 · 태그 · 데이터 소스 · 소유자 · 상태 · 환경 · 등급 · 품질 점수 등)와 상세 설명입니다.
| 메타데이터
| 소유자 · 태그 · 용어집 연결과 생명주기 · 형식 · 보안 · 비즈니스 메타데이터를 편집합니다.
| DDL
| 원천의 생성 DDL 입니다. DDL 이 수집된 데이터셋에만 보입니다.
| 스키마 (N)
| 컬럼 목록입니다. 괄호 안 숫자는 컬럼 수입니다. 자세한 내용은 xref:catalog/schema.adoc[스키마] 를 참고하세요.
| 표준 용어
| 컬럼을 데이터 표준 사전의 표준 용어와 매핑합니다. xref:governance/standards.adoc[데이터 표준] 을 참고하세요.
| 품질
| 프로파일 · 품질 규칙 · 품질 점수입니다. xref:catalog/quality.adoc[데이터 품질] 을 참고하세요.
| 샘플
| 업로드한 샘플 데이터 미리보기입니다.
| 댓글
| 데이터셋에 대한 질문 · 제안 · 토론입니다.
| 더보기
| 아래 표의 항목을 고르는 메뉴입니다. 고른 항목은 탭 자리에 이름이 표시됩니다.
|===

== 기본 정보 편집

편집 권한이 있으면 헤더와 개요 탭의 글자를 바로 눌러 고칠 수 있습니다. 권한이 없으면 눌러도 편집기가 열리지 않습니다.

* *논리명* — 헤더의 제목을 누르면 입력란이 열립니다. *저장* 또는 *취소* 를 누릅니다.
* *요약* — 제목 아래 요약을 누릅니다. 오른쪽에 글자 수(최대 200자)가 표시되고, Enter 로 저장 · Esc 로 취소합니다.
* *상세 설명* — 개요 탭 아래쪽 설명을 누르면 서식 편집기(굵게 · 목록 · 표 · 코드 블록 · 링크 등)가 열립니다.
  설명이 비어 있으면 "클릭해서 설명을 추가할 수 있습니다." 를 누릅니다.

image::catalog-datasets/title-edit.png[헤더 논리명 편집, 900]

image::catalog-datasets/description-editor.png[상세 설명 서식 편집기, 900]

저장하지 못하면 화면에 오류 알림이 뜨고 입력한 내용은 그대로 남습니다.

=== 상태 · 환경 변경과 AI 자동 생성

헤더 오른쪽의 작업(⋯) 버튼을 누르면 다음 메뉴가 나옵니다.

image::catalog-datasets/action-menu.png[헤더 작업 메뉴, 900]

[cols="1,3"]
|===
| 메뉴 | 설명

| AI 자동 생성
| 요약 · 설명 · 컬럼 설명 생성, 태그 추천, PII 감지입니다. 결과를 미리 본 뒤 *적용* 합니다. LLM 이 꺼져 있으면 "(LLM 비활성 — 설정에서 활성화)" 로 표시되고 누를 수 없습니다. 자세한 내용은 xref:ai/metadata-generation.adoc[AI 메타데이터 자동 생성] 을 참고하세요.
| 상태 변경
| 활성 · 비활성 · 사용 중단 중 현재 값이 아닌 것만 보입니다.
| 환경 변경
| PROD · STAGING · DEV 중 현재 값이 아닌 것만 보입니다. 환경을 바꿔도 URN 은 바뀌지 않습니다.
| 데이터셋 삭제
| 아래 <<_데이터셋_삭제,데이터셋 삭제>> 를 참고하세요.
|===

미리보기에서 적용하지 않은 결과나 AI 서비스가 반입한 결과가 있으면 작업(⋯) 버튼 왼쪽에 *AI 제안* 버튼과 대기 건수가 보입니다.
누르면 제안값과 현재 값을 비교해 승인 · 거절할 수 있습니다. 자세한 내용은
xref:ai/metadata-generation.adoc#_제안_검토[AI 메타데이터 자동 생성 → 제안을 나중에 검토하기] 를 참고하세요.

== 메타데이터 탭

메타데이터 탭은 *영역 · 항목 · 설정값 · 설명* 네 칸의 표입니다. 항목마다 오른쪽에 의미가 적혀 있어 처음 쓰는 사람도
값을 고르기 쉽습니다.

image::catalog-datasets/metadata-tab.png[메타데이터 탭 — 분류 · 소유 영역, 900]

=== 분류 · 소유 (즉시 반영)

소유자 · 태그 · 용어집은 *추가* 를 눌러 고르는 즉시 반영됩니다. 칩의 X 를 누르면 바로 해제됩니다.

[cols="1,3"]
|===
| 항목 | 사용 방법

| 소유자
| 왼쪽에서 유형(*기술 소유자* · *비즈니스 소유자* · *데이터 스튜어드*)을 고른 뒤 *추가* 를 눌러 이름으로 사용자를 검색합니다. 이미 추가된 사용자는 "이미 추가됨" 으로 표시됩니다.
| 태그
| *추가* 를 누르고 태그를 검색해 고릅니다. 태그 자체는 xref:governance/tags.adoc[태그] 에서 만듭니다.
| 용어집
| *추가* 를 누르면 왼쪽에 용어집 폴더 트리, 오른쪽에 *용어 검색...* 이 있는 선택 창이 열립니다. 분류(폴더)가 아닌 용어만 연결할 수 있습니다. 용어는 xref:governance/glossary.adoc[용어집] 에서 관리합니다.
|===

image::catalog-datasets/owner-search.png[소유자 추가 — 사용자 검색, 900]

image::catalog-datasets/glossary-picker.png[용어집 용어 선택, 900]

[cols="1,3"]
|===

[[_ddl_탭]]
== DDL 탭

원천에서 수집한 DDL 을 읽기 전용으로 보여 줍니다. 오른쪽 위 복사 버튼으로 전체를 복사할 수 있습니다.
DDL 이 없는 데이터셋(직접 추가했거나 데이터 소스가 DDL 수집을 지원하지 않는 경우)에는 탭이 나타나지 않습니다.

카드 제목은 DDL 종류에 맞춰 바뀝니다.

[cols="1,3"]
|===
| 제목 | 언제

| CREATE TABLE DDL
| 일반 테이블
| CREATE VIEW DDL
| 뷰 — `CREATE VIEW`, `CREATE OR REPLACE VIEW` 등으로 시작하는 DDL
| CREATE MATERIALIZED VIEW DDL
| 구체화 뷰
|===

image::catalog-datasets/ddl.png[DDL 탭 — CREATE TABLE DDL, 900]

TIP: 뷰 데이터셋은 DDL 탭에서 뷰 정의(`SELECT …`)를 그대로 확인할 수 있어, 어떤 테이블을 어떻게 조합한 뷰인지 파악할 때 편리합니다.

== 샘플 탭

실제 데이터가 어떤 모양인지 보여 주는 작은 샘플을 올려 둡니다. 편집 권한이 있는 사람만 올리고 지울 수 있고,
그 밖의 사용자에게는 샘플이 없으면 "샘플 데이터가 없습니다." 만 보입니다.

. *CSV 파일을 업로드하려면 클릭하세요* 를 눌러 파일을 고릅니다(지원 형식 `.csv` · `.tsv`, 최대 100 KB).
+
image::catalog-datasets/sample-upload.png[샘플 업로드 영역, 900]
. 미리보기 위의 *인코딩 · 줄 구분자 · 필드 구분자 · 헤더 · 인용 부호* 를 파일에 맞게 고르고 *새로 고침* 을 누릅니다.
  오른쪽에 "3행 · 3컬럼" 처럼 결과가 표시됩니다. 새로 고침은 서버에 보내지 않고 화면에서만 다시 읽습니다.
+
image::catalog-datasets/sample-preview.png[구분자를 세미콜론으로 바꾼 미리보기, 900]
. *저장* 을 누르면 구분자 설정대로 Parquet 형식으로 변환되고 "샘플 데이터를 Parquet 형식으로 변환했습니다." 알림이 뜹니다.
+
image::catalog-datasets/sample-parquet.png[Parquet 로 변환된 샘플, 900]
. 필요 없으면 오른쪽 위 *삭제* 로 지웁니다.

NOTE: 샘플은 실제 데이터라 민감할 수 있습니다. 기능 권한 *샘플 데이터 조회* 로 역할별로 탭 자체를 숨길 수 있습니다.

== 댓글 탭

데이터셋에 대한 질문 · 제안 · 버그 제보를 남기고 답글로 토론합니다. 탭 제목 옆에 최상위 댓글 수가 *댓글 (N)* 으로 표시됩니다.

=== 작성과 답글

편집기에서 굵게 · 목록 · 표 · 코드 블록 · 이모지 등 서식을 넣어 작성하고, 왼쪽 아래에서 분류(*일반* · *제안* · *기능 요청* · *버그*)를
고른 뒤 *등록* 을 누릅니다. 작성자 이름은 로그인한 사용자로 자동 기록됩니다.

image::catalog-datasets/comment-editor.png[댓글 작성 — 서식과 분류, 900]

댓글 오른쪽의 *댓글* 을 누르면 그 아래에 답글을 달 수 있습니다.

image::catalog-datasets/comment-reply.png[답글, 900]

=== 수정과 삭제

자기 댓글(관리자는 모든 댓글)의 ⋯ 를 누르면 *수정* 과 *삭제* 가 나옵니다. 권한이 없는 댓글에는 ⋯ 가 보이지 않습니다.

image::catalog-datasets/comment-menu.png[댓글 ⋯ 메뉴 — 수정 · 삭제, 900]

*수정* 을 누르면 같은 편집기에 기존 본문과 분류가 채워져 열립니다. 고친 뒤 *저장* 하면 작성 시각 옆에 *(수정됨)* 이 붙고,
*취소* 하면 원래대로 돌아갑니다. 답글이 달리는 것만으로는 원래 댓글에 *(수정됨)* 이 붙지 않습니다.

image::catalog-datasets/comment-edited.png[수정된 댓글 — (수정됨) 표시, 900]

*삭제* 를 누르면 댓글이 지워지고 댓글 수도 함께 갱신됩니다. 답글이 달린 댓글을 지우면 답글은 그대로 남고,
원래 댓글 자리에 "삭제된 댓글입니다." 가 표시됩니다.

== 변경 요청

*더보기 → 변경 요청* 은 이 데이터셋을 대상으로 한 변경 요청 목록입니다. *새 변경 요청* 을 누르면 대상 데이터셋이
채워진 상태로 작성 화면이 열립니다. 변경 요청의 흐름은 xref:governance/change-management.adoc[변경 관리] 를 참고하세요.

[[_데이터셋_삭제]]
== 데이터셋 삭제

상세 헤더의 ⋯ → *데이터셋 삭제*, 또는 목록 행의 ⋯ → *삭제* 를 누릅니다. 확인 대화상자에서 입력란에 `삭제` 를 정확히
입력해야 *삭제* 버튼이 켜집니다.

image::catalog-datasets/delete-confirm.png[데이터셋 삭제 확인, 700]

삭제하면 "데이터셋 "<이름>" 을 삭제했습니다." 알림과 함께 목록으로 돌아갑니다.

WARNING: 삭제는 되돌릴 수 없습니다. 데이터셋과 함께 스키마 · 속성 · 태그 · 소유자 · 리니지 정보가 모두 지워집니다.
잠시 쓰지 않게 하려는 것이라면 삭제 대신 상태를 *사용 중단* 이나 *비활성* 으로 바꾸세요.

== 자주 묻는 질문

[qanda]
메타데이터 탭에 *소유자* 로 등록돼 있는데 편집할 수 없습니다.::
  편집 권한은 소유자가 아니라 데이터셋을 만든 사람(생성자)과 관리자에게 있습니다. 동기화로 등록된 데이터셋은 보통 관리자 계정이 생성자이니 관리자에게 요청하세요.

*데이터셋 추가* 버튼이 보이지 않습니다.::
  기본 설정에서는 관리자만 데이터셋을 직접 등록할 수 있습니다. 관리자에게 등록을 요청하거나,
  xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서 일반 사용자 등록을 허용해 달라고 요청하세요.
  허용돼 있는데도 보이지 않으면 권한 관리에서 내 역할의 *데이터셋 등록* 기능 권한이 해제된 것입니다.

데이터셋 추가 대화상자에 원하는 데이터 소스가 없습니다.::
  메타데이터 동기화를 지원하는 종류의 데이터 소스만 선택지에 나옵니다.

데이터셋을 만들 때 오류가 납니다.::
  같은 데이터 소스에 같은 물리명이 이미 있습니다. 목록에서 기존 데이터셋을 찾아 보세요.

필터를 골랐는데 목록이 그대로입니다.::
  필터 값을 고른 뒤 *검색* 을 눌러야 적용됩니다.

*샘플* · *DDL* 탭이 보이지 않습니다.::
  DDL 이 수집되지 않은 데이터셋에는 DDL 탭이 없습니다. 그 밖에는 관리자가 기능 권한으로 탭을 숨겼을 수 있습니다.
