= 데이터셋
:toc: macro
:toclevels: 2

데이터셋은 Argus Catalog 의 중심 항목입니다. 여러 데이터 소스에 흩어진 테이블 · 뷰를 한곳에 모아,
누가 책임지는지 · 어떤 컬럼으로 이뤄졌는지 · 어디서 와서 어디로 흘러가는지 · 품질은 어떤지를 함께 관리합니다.
대부분의 데이터셋은 데이터 소스 동기화로 자동 등록되고, 필요하면 화면에서 직접 추가할 수도 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **찾기** — 이름 · 설명 · 데이터 소스 · 환경 · 조직으로 데이터셋을 찾습니다.
* **설명 달기** — 논리명 · 요약 · 상세 설명을 적고 소유자 · 태그 · 용어집을 연결합니다.
* **살펴보기** — 스키마 · DDL · 샘플 · 품질 · 리니지를 한 화면의 탭에서 봅니다.
* **함께 쓰기** — 댓글로 질문 · 제안을 남기고 변경 요청을 올립니다.
* **관리하기** — 데이터셋을 직접 추가하고 상태 · 환경을 바꾸거나 삭제합니다.

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 데이터셋* (`/dashboard/datasets`) 으로 들어갑니다.
목록에서 행을 누르면 상세 화면(`/dashboard/datasets/<ID>`)이 열리며, 이 주소를 그대로 링크로 공유할 수 있습니다.

=== 누가 무엇을 할 수 있나요

화면을 쓰려면 로그인해야 하고, xref:ops/permissions.adoc[권한 관리] 에서 *데이터셋* 메뉴가 열려 있어야 합니다.
작업별로 할 수 있는 사람은 다음과 같습니다.

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 목록 · 상세 조회, 댓글 작성
| 로그인한 사용자 누구나
| *데이터셋 추가*
| 관리자. 관리자가 xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서 허용하면 일반 사용자도(기본은 꺼짐 — 버튼이 관리자에게만 보입니다)
| 논리명 · 요약 · 설명 편집, 메타데이터 저장, 소유자 · 태그 · 용어집 연결, 스키마 수정, 샘플 업로드, Avro 편집, AI 제안 승인 · 거절, 상태 · 환경 변경, 삭제
| 관리자, 그 데이터셋을 만든 사람(생성자)
| 리니지 추가 · 삭제
| 관리자만
| 댓글 수정 · 삭제
| 댓글 작성자, 관리자
|===

NOTE: 데이터셋을 편집할 수 있는지는 *생성자* 기준으로 판단합니다. 메타데이터 탭의 *소유자* 는 책임자를 알리는 정보이고,
소유자로 등록되었다고 해서 편집 권한이 생기지는 않습니다. 동기화로 수집된 데이터셋은 생성자가 없으므로 *관리자만* 편집할 수 있습니다.
이런 데이터셋을 바꾸고 싶으면 관리자에게 요청하거나, 결재자를 지정한 변경 요청을 올립니다.

권한이 없는 사용자에게는 편집 컨트롤이 아예 보이지 않습니다. 아래는 일반 사용자가 남의 데이터셋을 연 화면으로,
헤더의 작업(⋯) 버튼과 *추가* 버튼이 없고 입력란은 비활성으로 표시됩니다.

image::catalog-datasets/metadata-read-only.png[권한이 없는 사용자의 메타데이터 탭 — 읽기 전용, 900]

[TIP]
.고급 사용자 — 기능 권한으로 탭 숨기기
====
권한 관리의 *기능 권한* 으로 일부 탭을 역할별로 숨길 수 있습니다.

[cols="1,3"]
|===
| 기능 권한 | 막으면

| 샘플 데이터 조회 (`datasets.sample-view`)
| *샘플* 탭이 보이지 않고, 샘플 조회 요청도 거부됩니다.
| DDL 조회 (`datasets.ddl-view`)
| *DDL* 탭이 보이지 않고, 상세 응답에서도 DDL 이 빠집니다.
| 이관 코드 탭 (`datasets.transfer-code`)
| *더보기* 메뉴의 PySpark · Kestra · Airflow 항목이 보이지 않습니다.
| AI 메타데이터 생성 (`ai.generate`)
| 헤더 작업 메뉴의 *AI 자동 생성* 항목이 보이지 않습니다.
|===
====

== 데이터셋 목록

image::catalog-datasets/list.png[데이터셋 목록 — 테이블 보기, 900]

목록에는 데이터셋마다 다음 정보가 보입니다. 논리명이 있으면 논리명과 한 줄 요약을, 없으면 물리명을 크게 보여 줍니다.

[cols="1,3"]
|===
| 칸 | 내용

| 이름
| 논리명(없으면 물리명)과 한 줄 요약입니다.
| 데이터 소스
| 데이터셋이 속한 데이터 소스입니다. 데이터 소스는 xref:catalog/platforms.adoc[데이터 소스] 에서 관리합니다.
| 환경
| DEV · STAGING · PROD 중 하나입니다.
| 상태
| 활성 · 비활성 · 사용 중단입니다.
| 동기화
| 데이터 소스 동기화로 등록·갱신된 데이터셋에는 *동기화됨* 배지가 붙습니다.
| 필드 · 등록일
| 컬럼 수와 카탈로그에 등록된 날짜입니다.
| ⋯
| *새 탭에서 열기* · *링크 복사* · *URN 복사* 와 *삭제* 메뉴입니다. 상세 화면은 이름을 누르면 열립니다. *삭제* 는 편집 권한이 있는 데이터셋에만 보입니다.
|===

=== 검색과 필터

[cols="1,3"]
|===
| 도구 | 설명

| *데이터셋 검색…*
| 물리명 · 논리명 · 요약 · 설명 · URN 에 검색어가 들어간 데이터셋을 찾습니다. 설명까지 찾기 때문에 이름에 없는 단어로도 찾을 수 있습니다.
| *데이터 소스* · *환경* · *상태* · *태그*
| 여러 값을 골라 조합할 수 있습니다. 같은 필터 안에서는 하나라도 맞으면, 서로 다른 필터끼리는 모두 맞아야 나옵니다. 상태 필터의 선택지는 활성 · 비활성 · 사용 중단입니다.
| *조직: 전체* · *시스템: 전체*
| 분류 체계에 등록된 조직 · 시스템 단위로 좁힙니다. 시스템 선택지는 "시스템 · 조직" 형식으로 보입니다.
| *검색*
| 검색어와 필터를 적용합니다. 필터 값을 고르기만 해서는 적용되지 않으니 꼭 눌러 주세요. 검색어는 Enter 로도 적용됩니다.
| *초기화*
| 검색어와 필터를 모두 지웁니다.
|===

image::catalog-datasets/list-filters.png[데이터 소스 · 환경 · 상태 필터를 고른 모습, 900]

검색어 · 필터 · 페이지는 주소(예: `/dashboard/datasets?tag=3&status=active&page=2`)에 남습니다. 상세 화면에 갔다가 뒤로 돌아오거나
주소를 다른 사람에게 보내도 같은 목록이 보입니다.

용어집 용어나 분류로 거른 목록은 태그 · 용어집 · 분류 체계 화면이나 데이터셋 상세의 링크로 들어옵니다. 이때는 툴바 위에
*조건 용어: 고객* · *조건 분류: 업무 > 영업* 같은 칩이 보이고, 칩의 X 를 누르면 그 조건만 지워집니다.

TIP: 상단 바의 *이름·설명·의미로 데이터셋 검색…* 은 전체 카탈로그를 대상으로 하는 전역 검색입니다.
"고객 거래 내역" 처럼 의미로 찾고 싶다면 xref:ops/search.adoc[검색] 을 참고하세요.

=== 테이블 보기와 카드 보기

검색 버튼 오른쪽의 두 아이콘으로 *테이블 뷰* 와 *카드 뷰* 를 전환합니다. 고른 보기는 브라우저에 기억됩니다.
화면 아래에서 *페이지당 행 수* 와 페이지를 바꿀 수 있고, 이때도 적용한 필터는 그대로 유지됩니다.

카드는 화면 너비에 맞춰 한 줄에 들어가는 만큼 놓이고, 한 줄의 카드 높이는 같습니다. 카드 한 장에는 다음이 들어갑니다.

* *경로와 이름* — "데이터 소스 › 스키마" 경로, 논리명(없으면 물리명), 논리명이 있으면 그 아래 물리명. 논리명은 한 단계 큰 글씨입니다.
* *환경* — 색 점과 "운영 (PROD)" 같은 글자. 상태는 활성이 아닐 때만(*사용 중단* 등) 배지로 보이고, 원천에서 수집한 데이터셋은 *동기화됨* 이 붙습니다.
* *요약* — 요약(없으면 설명)을 두 줄까지. 둘 다 없으면 흐린 글씨로 *설명 없음* 이 보입니다.
* *컬럼 미리보기* — 순서상 앞쪽 컬럼 3개와 나머지 수(+N).
* *바닥 줄* — 컬럼 · 태그 · 담당자 수와 마지막 갱신("3일 전 갱신"). 마우스를 올리면 갱신일과 등록일이 날짜로 보입니다.

카드 어디를 눌러도 상세 화면으로 갑니다. 오른쪽 위 ⋯ 메뉴(새 탭에서 열기 · 링크 복사 · URN 복사 · 삭제)는 마우스를 올리면 나타나고, 터치 화면에서는 늘 보입니다.

== 데이터셋 추가

동기화 대상이 아닌 테이블을 카탈로그에 올리고 싶을 때 씁니다. 목록 오른쪽 위 *데이터셋 추가* 를 누릅니다.

버튼은 기본적으로 관리자에게만 보입니다. 관리자가 xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서
*일반 사용자의 데이터셋 직접 등록 허용* 을 켜면 일반 사용자에게도 보입니다. 이때도 xref:ops/permissions.adoc[권한 관리] 의
기능 권한 *데이터셋 등록*(`datasets.create`)에서 해제된 역할에는 보이지 않습니다. 등록한 사람이 그 데이터셋의 생성자가 되어 편집할 수 있습니다.

image::catalog-datasets/add-dialog.png[데이터셋 추가 대화상자, 700]

[cols="1,3"]
|===
| 항목 | 설명

| 물리명 (테이블명)
| 원천의 실제 이름입니다. `스키마.테이블` 형식을 권장합니다(예: `shop.orders`). 대소문자는 입력한 그대로 저장됩니다.
| 논리명 (선택, 표시용)
| 화면에 보일 이름입니다(예: `주문`).
| 데이터 소스
| 데이터셋이 속한 데이터 소스입니다. 선택지 옆에 그 데이터 소스의 환경이 함께 보입니다.
| 요약 (한 줄, 최대 200자)
| 목록과 헤더에 보이는 한 줄 설명입니다.
| 상세 설명
| 자세한 설명입니다. 나중에 개요 탭에서 서식을 넣어 다시 고칠 수 있습니다.
|===

*환경* 은 따로 입력하지 않습니다. 대화상자에 "환경은 데이터 소스의 값 DEV 을 따릅니다." 처럼 안내되며,
고른 데이터 소스의 환경이 그대로 적용됩니다. *추가* 를 누르면 "데이터셋 '<이름>' 을(를) 추가했습니다." 알림과 함께
목록 맨 위에 새 데이터셋이 보입니다. 같은 데이터 소스에 같은 물리명이 이미 있으면 대화상자 안에 오류가 표시되고 만들어지지 않습니다.

NOTE: 데이터 소스 선택지에는 메타데이터 동기화를 지원하는 종류(PostgreSQL · MySQL · Hive · Impala 등)의 데이터 소스만 나옵니다.
태그 · 소유자 · 용어집 · 스키마는 만든 뒤 상세 화면에서 추가합니다.

[[_urn]]
[TIP]
.고급 사용자 — URN
====
데이터셋은 카탈로그 전체에서 URN 으로 식별됩니다. 리니지 · 알림 · 외부 조회 API 가 이 값을 키로 씁니다.

----
{데이터 소스 ID}.{물리명}.dataset
예: sakila-mysql.sakila.film.dataset
----

환경은 URN 에 들어가지 않습니다. 그래서 데이터셋의 환경을 DEV 에서 PROD 로 바꿔도 URN 은 그대로입니다.
예전 형식(`….sakila.film.DEV.dataset`)으로 조회해도 같은 데이터셋을 찾아 줍니다.
====

=== 헤더

헤더에는 논리명과 괄호 안의 물리명(원천의 대소문자 그대로), 한 줄 요약, URN 이 보이고, 오른쪽에 상태 · 환경 배지와
*동기화됨* 배지가 붙습니다. 편집 권한이 있으면 맨 오른쪽에 작업(⋯) 버튼이 나타납니다.

=== 탭 구성

[cols="1,3"]
|===
| 탭 | 내용

| 개요
| 메타데이터 요약 표(분류 체계 · URN · 용어집 · 태그 · 데이터 소스 · 소유자 · 상태 · 환경 · 등급 · 품질 점수 등)와 상세 설명입니다. 분류 · 태그를 누르면 같은 분류 · 태그의 데이터셋 목록, 용어를 누르면 용어집, 이메일이 등록된 소유자를 누르면 메일 쓰기 창이 열립니다.
| 메타데이터
| 소유자 · 태그 · 용어집 연결과 생명주기 · 형식 · 보안 · 비즈니스 메타데이터를 편집합니다.
| DDL
| 원천의 생성 DDL 입니다. DDL 이 수집된 데이터셋에만 보입니다.
| 스키마 (N)
| 컬럼 목록입니다. 괄호 안 숫자는 컬럼 수입니다. 자세한 내용은 xref:catalog/schema.adoc[스키마] 를 참고하세요.
| 표준 용어
| 컬럼을 데이터 표준 사전의 표준 용어와 매핑합니다. xref:governance/standards.adoc[데이터 표준] 을 참고하세요.
| 품질
| 프로파일 · 품질 규칙 · 품질 점수입니다. xref:catalog/quality.adoc[데이터 품질] 을 참고하세요.
| AI-Ready

[TIP]
.고급 사용자 — 적재 코드 (PySpark · Kestra · Airflow)
====
관계형 DB 데이터 소스의 데이터셋은 *더보기* 에서 이 테이블을 데이터레이크로 옮기는 코드 예시를 볼 수 있습니다.
코드는 화면에서 스키마를 바탕으로 바로 만들어지며, 테이블 이름과 컬럼 목록이 채워져 있습니다.

[cols="1,3"]
|===
| 항목 | 하위 탭

| PySpark
| 일단위 증분 · 전체 적재
| Kestra
| Basic · PySpark · Shell + AWS CLI · Hive · Trino
| Airflow
| Basic · PySpark · Incremental · Hive · Trino
|===

* *PySpark* 는 원본을 JDBC 로 읽어 `raw/<데이터 소스>/<이름…>/dt=<적재일>/` 에 Parquet 으로 씁니다. Airflow · Kestra 의
  *PySpark* 하위 탭은 이 스크립트를 파일로 저장해 두고 제출합니다.
* *Hive* 는 PySpark 가 쓴 Parquet 을 Hive 외부 테이블(데이터베이스 `raw_<데이터 소스>`)과 일자 파티션으로 등록합니다. 원본 DB 는 읽지
  않습니다. 컬럼 타입은 원본 타입으로 추정하므로 첫 적재 뒤 파일과 맞는지 확인하세요.
* *Trino* 는 Spark 없이 Trino 가 원본을 읽어 데이터레이크 카탈로그의 일자 파티션 테이블에 넣습니다. 테이블은 원본 타입 그대로 만들고,
  같은 날짜를 다시 돌리면 그 파티션을 지우고 다시 넣습니다. `<SOURCE_CATALOG>` 에는 데이터 소스 *카탈로그 연결* 의 원격 이름을 씁니다.
* 원본에 `dt` 컬럼이 있으면 파티션 이름은 `load_dt` 입니다. `<…>` 자리표시자와 증분 기준 컬럼은 코드 주석을 보고 채웁니다.

image::catalog-datasets/pyspark.png[PySpark 이관 코드, 900]

=== AI 활용 (AI-Ready) 항목 [[help-dataset-ai-ready]]

행정안전부 「공공데이터의 인공지능 친화적 관리 가이드라인」(2026)이 AI 학습 · 분석에 쓰일 공공데이터에 붙이도록 정한 메타데이터입니다.
항목마다 오른쪽 설명에 가이드라인의 속성 이름(예: `dct:license`)과 필수 여부를 적었습니다.

* *기관 기본값* — 제공기관 · 언어 · 라이선스 · 문의 연락처는 기관마다 거의 같으므로 관리자가 *설정 › 데이터 관리 › AI-Ready* 에 한 번 정해 둡니다.
  데이터셋 칸이 비어 있으면 칸 안에 "비우면 기본값: …" 이 보이고, 그 값을 씁니다. 데이터셋에 값을 넣으면 그 값이 우선합니다.
  기본값은 데이터셋에 써 넣지 않으므로 설정을 바꾸면 비어 있는 데이터셋 전체에 바로 반영됩니다.
* *프로파일에서 채우기* — 시간범위와 결측 정보 칸 아래 단추를 누르면 품질 탭에서 수집한 최신 프로파일로 값을 채웁니다.
  시간범위는 날짜 · 시각 컬럼 가운데 최소~최대 기간이 가장 긴 컬럼의 값이고, 결측 정보는 전체 결측률과 결측률이 높은 컬럼 10개입니다.
  채운 값은 저장 전까지 반영되지 않으므로 확인하고 결측 사유 · 처리 방식을 덧붙여 *저장* 하세요. 프로파일이 없으면 먼저 품질 탭에서 수집합니다.
* *허용 이용 유형* — 아무것도 고르지 않았으면 "정하지 않음"입니다. 체크를 모두 해제하면 "모두 허용하지 않음"이 되고,
  *정하지 않음으로 되돌리기* 로 처음 상태로 돌아갑니다. 개요의 *AI 학습 이용* 은 이 값으로 허용 · 허용하지 않음을 보여 줍니다.
* *합성 데이터 · 자동 주석* — 확인하지 않았으면 *미지정* 으로 둡니다. 가이드라인 점검표는 합성 데이터나 기계가 단 주석이 들어 있으면
  반드시 표시하도록 정합니다.
* *AI 초안* — *알려진 편향* · *한계 · 유의사항* · *관련법령* 은 LLM 이 메타데이터와 프로파일 통계로 초안을 쓸 수 있습니다.
  *AI-Ready* 탭의 *AI 초안* 단추나 `⋯` 메뉴로 만들고, 결과는 *AI 제안* 에서 읽고 승인합니다 —
  xref:ai/metadata-generation.adoc#_ai_ready_초안[AI-Ready 초안].
* *버전 이력* [[help-dataset-versions]] — *버전* · *버전 노트* 를 저장할 때마다 이력에 남습니다(버전 · 변경 사항 · 담당자 · 시각).
  가장 최근 이력과 버전이 같으면 새 줄을 만들지 않고 그 줄의 노트를 고칩니다. *버전* 줄 설명 칸의 *이력* 단추로 보고,
  소유자 · 관리자는 잘못 남긴 줄을 지울 수 있습니다(현재 버전 값은 바뀌지 않음). 이력은 데이터 카드의 *버전 이력* 표에도 들어가고,
  체크리스트 C32 의 근거가 됩니다.

== AI-Ready 탭 [[help-dataset-ai-ready-check]]

행정안전부 · NIA 「공공데이터의 인공지능 친화적 관리 가이드라인」 V1.0 부록 4 의 체크리스트(공통 33개 — 필수 15 · 권장 18, 유형별 5개)로
이 데이터셋을 점검합니다. 판정은 가이드라인 표기대로 *적정 · 미흡 · 해당없음* 이고, 카탈로그 정보로 판정할 수 없으면 *판정 필요* 로 둡니다.

* *자동 판정* — 탭을 열 때마다 메타데이터 · 스키마 · 품질 규칙과 결과 · 표준 용어 매핑 · 리니지 · API 카탈로그 연결로 다시 계산합니다.
  항목 아래 회색 글씨가 무엇으로 판정하는지(어디를 채우면 되는지)이고, *근거* 칸이 이번 판정의 이유입니다.
  예를 들어 *C05 필수 메타데이터* 는 비어 있는 항목 이름을 근거에 적고, *C08 데이터 사전* 은 컬럼 설명이 80% 이상이면 적정입니다.
* *담당자 판정* — 온톨로지 정합성 · 정제 코드 공개처럼 카탈로그 밖의 일, 그리고 데이터 배포 · API 제공처럼
  제공 플랫폼(포털)의 일은 담당자가 근거와 함께 판정합니다. 연필 단추를 눌러 판정과 근거(문서 링크 · 메모)를 저장합니다.
* *수동 판정이 우선* — 자동 판정 항목도 수동으로 판정할 수 있습니다(예: 포털이 DCAT 메타데이터를 제공하면 C04 를 적정으로).
  수동 판정이 있으면 근거 칸에 판정자 · 시각과 자동 판정 결과를 함께 보여 줍니다. *자동 판정으로 되돌리기* 로 지웁니다.
  판정은 데이터셋 소유자(생성자)와 관리자만 바꿀 수 있습니다.
* *충족률* — 필수와 권장을 따로 냅니다. 적정 수 ÷ (항목 수 − 해당없음)이고, 판정 필요는 적정이 아니므로 분모에만 들어갑니다.
* *공유 최소 요건* — 가이드라인이 공유 요건의 예로 든 네 가지(결측률 20% 미만, 필수 메타데이터, 갱신 주기 2회 이내, 표준 포맷)를 따로 판정합니다.
  결측률은 최신 프로파일, 갱신 주기는 메타데이터의 갱신주기(시간 · 일 · 주 · 월)와 최종 적재 시각으로 봅니다. 기준값은 관리자가
  xref:ops/settings.adoc#_ai_ready[설정 › AI-Ready] 에서 바꿉니다. 판정할 수 없는 조건(프로파일 없음, 실시간 · 수동 갱신)은 빼고 봅니다.
  요건을 놓치면 알림을 받으려면 xref:governance/alerts.adoc[알림] 규칙의 트리거 *AI-Ready 공유 최소 요건 미충족* 을 씁니다.
* *AI 초안* — 소유자 · 관리자에게는 탭 위쪽에 *AI 초안 (편향 · 한계 · 관련법령)* 단추가 보입니다(LLM 이 켜져 있고 AI 생성 권한이 있을 때).
  비어 있는 항목만 초안을 만들어 *AI 제안* 으로 남깁니다.
* *유형별 항목* — 이미지 · 영상 항목은 데이터 형식이 이미지 · 영상이거나 데이터 유형이 비정형일 때만, 개인정보 항목은 개인정보가 있을 때만
  판정 대상이고 나머지는 해당없음입니다.

=== 배포본 [[help-dataset-distributions]]

체크리스트 아래 *배포본* 카드에 이 데이터를 받는 곳을 적습니다. 공공데이터포털의 파일 · API 주소나 기관 내부 내려받기 주소입니다.

[cols="1,3",options="header"]
|===
| 칸 | 내용

| 접속 URL (필수)
| 데이터를 보거나 신청하는 페이지 또는 API 주소. `http(s)://` 로 시작해야 합니다.
| 내려받기 URL
| 파일을 바로 받는 주소. 있으면 *C27 추가 제공 경로* 가 적정입니다.
| 형식 · MIME 유형
| `CSV` · `PARQUET` · `API` 등. MIME 유형을 비우면 형식에서 추정합니다(CSV → `text/csv`).
| 크기 · 체크섬
| 바이트 수와 16진수 해시(SHA-256 · SHA-512 · SHA-1 · MD5). 체크섬이 있으면 *C33 무결성 정보* 가 적정입니다.
|===

배포본이 하나도 없으면 *C05 필수 메타데이터* 에 '배포본(접속 URL)'이 빠졌다고 나옵니다. 배포본은 소유자(생성자)와 관리자만 고칩니다.

=== 내보내기 [[help-dataset-ai-ready-export]]

*내보내기* 카드에서 카탈로그 메타데이터를 기계가 읽는 형식으로 보고(*보기*) 파일로 받습니다(*내려받기*).
*보기* 는 JSON 을 코드 뷰어로 보여 주고, 데이터 카드는 *미리보기*(문서 모양) 와 *Markdown*(원문) 탭으로 보여 줍니다. *API 주소* 는 다른 시스템이 같은 결과를 받아 갈 주소를 복사합니다.

* *DCAT* — W3C DCAT v3 JSON-LD. 가이드라인 표 9~12 의 속성(제목 · 설명 · 키워드 · 주제 · 제공기관 · 갱신주기 · 언어 · 라이선스 · 연락처 · 버전 · 배포본 · 편향 · 한계 등)을 담습니다.
  이 기능이 있으므로 *C04 표준 스키마 메타데이터* 는 자동으로 적정입니다.
* *Croissant* — MLCommons Croissant 1.0 JSON-LD. 스키마 컬럼을 필드로, 배포본을 파일로 옮기고 책임 있는 AI(RAI) 속성을 붙입니다. AI 학습 도구가 바로 읽습니다.
* *데이터 카드* — 가이드라인 부록 5 양식의 Markdown. 비어 있는 칸은 "작성 필요 — 채울 곳"으로 표시합니다. 설명과 알려진 편향 또는 한계가 있으면 *C21 데이터 카드* 가 적정입니다.
  실데이터가 섞이지 않도록 샘플 레코드는 넣지 않습니다.

내보내기는 저장하지 않고 부를 때마다 지금 메타데이터로 만듭니다. 비어 있는 값은 설정의 기관 기본값(제공기관 · 언어 · 라이선스 · 연락처)으로 채웁니다.
결과에 들어가는 이 서버의 주소(데이터 카드의 *기계 이해 스키마 제공*, DCAT · Croissant 의 URL)는
xref:ops/settings.adoc#_ai_ready[설정 › AI-Ready › 외부 공개 주소] 를 따릅니다.

[TIP]
.고급 사용자 — 외부 연동 API
====
`GET /api/v1/external/datasets/{id}/dcat` · `/croissant` · `/data-card` (URN 으로는 `/api/v1/external/dcat?urn=…` 처럼),
전체 카탈로그는 `GET /api/v1/external/dcat/catalog?page=1&size=100` (`dcat:Catalog`, 다음 쪽 주소는 `argus:next`).
외부 메타데이터 API(`/api/v1/external/metadata`)의 응답에도 `ai_ready` 요약(충족률 · 최소 요건 · 적정이 아닌 필수 항목)이 들어갑니다.
배포본 API 는 `GET · POST /api/v1/catalog/datasets/{id}/distributions`, `PUT · DELETE …/distributions/{배포본 ID}` 입니다.
====

전체 데이터셋의 충족률은 xref:governance/ai-ready.adoc[거버넌스 › AI-Ready 점검] 에서 봅니다.

[[_ddl_탭]]
== DDL 탭 [[help-dataset-ddl]]

원천에서 수집한 DDL 을 읽기 전용으로 보여 줍니다. 오른쪽 위 복사 버튼으로 전체를 복사할 수 있습니다.
DDL 이 없는 데이터셋(직접 추가했거나 데이터 소스가 DDL 수집을 지원하지 않는 경우)에는 탭이 나타나지 않습니다.

카드 제목은 DDL 종류에 맞춰 바뀝니다.

[cols="1,3"]
|===
| 제목 | 언제

| CREATE TABLE DDL
| 일반 테이블
| CREATE VIEW DDL
| 뷰 — `CREATE VIEW`, `CREATE OR REPLACE VIEW` 등으로 시작하는 DDL
| CREATE MATERIALIZED VIEW DDL
| 구체화 뷰
|===

image::catalog-datasets/ddl.png[DDL 탭 — CREATE TABLE DDL, 900]

TIP: 뷰 데이터셋은 DDL 탭에서 뷰 정의(`SELECT …`)를 그대로 확인할 수 있어, 어떤 테이블을 어떻게 조합한 뷰인지 파악할 때 편리합니다.

== 샘플 탭 [[help-dataset-sample]]

실제 데이터가 어떤 모양인지 보여 주는 작은 샘플을 올려 둡니다. 편집 권한이 있는 사람만 올리고 지울 수 있고,
그 밖의 사용자에게는 샘플이 없으면 "샘플 데이터가 없습니다." 만 보입니다.

. *CSV 파일을 업로드하려면 클릭하세요* 를 눌러 파일을 고릅니다(지원 형식 `.csv` · `.tsv`, 최대 100 KB).
+
image::catalog-datasets/sample-upload.png[샘플 업로드 영역, 900]
. 미리보기 위의 *인코딩 · 줄 구분자 · 필드 구분자 · 헤더 · 인용 부호* 를 파일에 맞게 고르고 *새로고침* 을 누릅니다.
  오른쪽에 "3행 · 3컬럼" 처럼 결과가 표시됩니다. 새로고침은 서버에 보내지 않고 화면에서만 다시 읽습니다.
+
image::catalog-datasets/sample-preview.png[구분자를 세미콜론으로 바꾼 미리보기, 900]
. *저장* 을 누르면 구분자 설정대로 Parquet 형식으로 변환되고 "샘플 데이터를 Parquet 형식으로 변환했습니다." 알림이 뜹니다.
+
image::catalog-datasets/sample-parquet.png[Parquet 로 변환된 샘플, 900]
. 필요 없으면 오른쪽 위 *삭제* 로 지웁니다.

NOTE: 샘플은 실제 데이터라 민감할 수 있습니다. 기능 권한 *샘플 데이터 조회* 로 역할별로 탭 자체를 숨길 수 있습니다.

== 댓글 탭 [[help-dataset-comments]]

데이터셋에 대한 질문 · 개선 요청 · 오류 신고를 남기고 답글로 토론합니다. 탭 이름은 수 없이 *댓글* 로만 표시되고,
탭을 열면 위쪽 제목에 최상위 댓글 수가 *댓글 (N)* 으로 표시됩니다(답글은 세지 않으며, 댓글이 없으면 수 없이 *댓글* 입니다).

=== 작성과 답글

편집기에서 굵게 · 목록 · 표 · 코드 블록 · 이모지 등 서식을 넣어 작성하고, 왼쪽 아래에서 분류(*일반* · *개선 요청* · *기능 요청* · *오류 신고*)를
고른 뒤 *등록* 을 누릅니다. 작성자 이름은 로그인한 사용자로 자동 기록됩니다.

image::catalog-datasets/comment-editor.png[댓글 작성 — 서식과 분류, 900]

편집기 안의 표에서 셀을 우클릭하면 표 메뉴가 열립니다. 위 · 아래에 행 추가, 왼쪽 · 오른쪽에 열 추가, 셀 병합 · 분리,
*첫 행을 머리글로* · *첫 열을 머리글로*(지금 켜져 있으면 체크 표시)가 있고, 구분선 아래에 *행 삭제* · *열 삭제* · *표 삭제* 가 빨간 글씨로 있습니다.

댓글 오른쪽의 *댓글* 을 누르면 그 아래에 답글을 달 수 있습니다.

image::catalog-datasets/comment-reply.png[답글, 900]

=== 수정과 삭제

자기 댓글(관리자는 모든 댓글)의 ⋯ 를 누르면 *편집* 과, 구분선 아래 빨간 *삭제* 가 나옵니다. 권한이 없는 댓글에는 ⋯ 가 보이지 않습니다.

image::catalog-datasets/comment-menu.png[댓글 ⋯ 메뉴 — 수정 · 삭제, 900]

*편집* 을 누르면 같은 편집기에 기존 본문과 분류가 채워져 열립니다. 고친 뒤 *저장* 하면 작성 시각 옆에 *(수정됨)* 이 붙고,
*취소* 하면 원래대로 돌아갑니다. 답글이 달리는 것만으로는 원래 댓글에 *(수정됨)* 이 붙지 않습니다.

image::catalog-datasets/comment-edited.png[수정된 댓글 — (수정됨) 표시, 900]

*삭제* 를 누르면 댓글이 지워지고 댓글 수도 함께 갱신됩니다. 답글이 달린 댓글을 지우면 답글은 그대로 남고,
원래 댓글 자리에 "삭제된 댓글입니다." 가 표시됩니다.

=== 오류 신고 · 개선 요청 처리 [[help-dataset-reports]]

분류를 *오류 신고* 나 *개선 요청* 으로 고른 댓글(답글 제외)은 **접수** 되고 처리 기한이 붙습니다. 기한은 접수 시각에
xref:ops/settings.adoc#_ai_ready[설정 › AI-Ready] 의 처리 기한(기본 10일)을 더한 값입니다. 댓글 머리에 상태 배지와
*기한 · D-n* (넘기면 빨간 *n일 넘김*)이 보입니다.

데이터셋 소유자(생성자)와 관리자에게는 처리할 댓글에 *처리* 단추가 보입니다. 누르면 상태를 고릅니다.

[cols="1,3",options="header"]
|===
| 상태 | 뜻

| 접수 | 새로 들어온 신고. *다시 열기* 도 이 상태로 돌립니다.
| 처리 중 | 확인하고 고치는 중입니다.
| 해결 | 데이터를 고쳤습니다. 처리 결과(예: "11월 적재분부터 수정, 버전 v2")를 적어 두면 댓글 아래에 보입니다.
| 소명 | 고치지 않는 이유를 설명합니다(예: 측정 기준 차이). 사유가 있어야 저장됩니다.
|===

해결 · 소명은 처리 시각과 처리자를 남깁니다. 기한을 넘긴 미처리 신고가 있으면 AI-Ready 체크리스트 *C31* 이 미흡입니다.
모든 데이터셋의 신고는 xref:governance/data-reports.adoc[거버넌스 › 오류 신고 처리] 에서 봅니다.

== 변경 요청 [[help-dataset-changes]]

*더보기 → 변경 요청* 은 이 데이터셋을 대상으로 한 변경 요청 목록입니다. *변경 요청 만들기* 를 누르면 대상 데이터셋이
채워진 상태로 작성 화면이 열립니다. 변경 요청의 흐름은 xref:governance/change-management.adoc[변경 관리] 를 참고하세요.

[[_데이터셋_삭제]]
== 데이터셋 삭제

상세 헤더의 ⋯ → *삭제*, 또는 목록 행의 ⋯ → *삭제* 를 누릅니다. 확인 대화상자에서 입력란에 `삭제` 를 정확히
입력해야 *삭제* 버튼이 켜집니다.

image::catalog-datasets/delete-confirm.png[데이터셋 삭제 확인, 700]

삭제하면 "데이터셋 "<이름>" 을 삭제했습니다." 알림과 함께 목록으로 돌아갑니다.

WARNING: 삭제는 되돌릴 수 없습니다. 데이터셋과 함께 스키마 · 속성 · 태그 · 소유자 · 리니지 정보, 댓글,
이 데이터셋을 범위로 한 알림 규칙, 변경 요청이 모두 지워지고 진행 중인 변경 요청의 결재는 취소됩니다.
변경 요청이 있으면 확인 대화상자에 "변경 요청 N건이 함께 삭제됩니다 (진행 중인 결재 N건 취소)" 가 나옵니다.
잠시 쓰지 않게 하려는 것이라면 삭제 대신 상태를 *사용 중단* 이나 *비활성* 으로 바꾸세요.

메타데이터 탭에 *소유자* 로 등록돼 있는데 편집할 수 없습니다.::
  편집 권한은 소유자가 아니라 데이터셋을 만든 사람(생성자)과 관리자에게 있습니다. 동기화로 수집된 데이터셋은 생성자가 없어 관리자만 편집할 수 있으니 관리자에게 요청하세요.

*데이터셋 추가* 버튼이 보이지 않습니다.::
  기본 설정에서는 관리자만 데이터셋을 직접 등록할 수 있습니다. 관리자에게 등록을 요청하거나,
  xref:ops/settings.adoc#_dataset_create[설정 → 데이터셋 등록] 에서 일반 사용자 등록을 허용해 달라고 요청하세요.
  허용돼 있는데도 보이지 않으면 권한 관리에서 내 역할의 *데이터셋 등록* 기능 권한이 해제된 것입니다.

데이터셋 추가 대화상자에 원하는 데이터 소스가 없습니다.::
  메타데이터 동기화를 지원하는 종류의 데이터 소스만 선택지에 나옵니다.

데이터셋을 만들 때 오류가 납니다.::
  같은 데이터 소스에 같은 물리명이 이미 있습니다. 목록에서 기존 데이터셋을 찾아 보세요.

필터를 골랐는데 목록이 그대로입니다.::
  필터 값을 고른 뒤 *검색* 을 눌러야 적용됩니다.

*샘플* · *DDL* 탭이 보이지 않습니다.::
  DDL 이 수집되지 않은 데이터셋에는 DDL 탭이 없습니다. 그 밖에는 관리자가 기능 권한으로 탭을 숨겼을 수 있습니다.
