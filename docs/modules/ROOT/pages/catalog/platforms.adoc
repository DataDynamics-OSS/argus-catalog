= 데이터 소스
:toc: macro
:toclevels: 2

데이터 소스는 데이터가 실제로 저장된 시스템(MySQL · PostgreSQL 같은 DBMS, Hive · Trino 같은 분석 엔진 등)과
그 연결 정보를 카탈로그에 등록한 것입니다. 데이터 소스에서 테이블 · 컬럼 메타데이터를 동기화하면
xref:catalog/datasets.adoc[데이터셋] 이 만들어지고, xref:catalog/quality.adoc[데이터 품질] 의 프로파일링과 품질 배치도
여기 등록한 연결 정보로 원본에 접속합니다.

데이터 소스 화면은 데이터 소스를 *조직 → 시스템 → 데이터 소스* 계층으로 정리해 보여 줍니다. 어느 부서의 어떤 업무 시스템이
어떤 DB 를 쓰는지 한눈에 볼 수 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **구조 정리** — 데이터 소스를 *조직 → 시스템 → 데이터 소스* 트리로 정리합니다.
* **데이터 소스 등록** — DB · 분석 엔진의 연결 정보를 등록하고 *연결 테스트* 로 접속을 확인합니다.
* **연결 정보 관리** — 표시 이름 · 환경 · 소속 시스템 · 연결 설정을 고칩니다. 비밀번호는 안전하게 가려집니다.
* **메타데이터 동기화** — 원본의 테이블 · 컬럼을 읽어 데이터셋을 자동으로 만들고 갱신합니다.
* **ER 다이어그램** — 데이터 소스 전체 테이블의 관계를 한 장의 그림으로 봅니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| 조직
| 부서 같은 최상위 묶음입니다. 하위 조직으로 여러 단계 중첩할 수 있습니다.
| 시스템
| 조직에 속한 업무 시스템입니다. 데이터 소스는 시스템 아래에 놓입니다.
| 데이터 소스
| 실제 DB · 엔진과 그 연결 설정입니다. 환경(DEV · STAGING · PROD)을 하나 가집니다.
| 데이터 소스 ID
| 데이터 소스에 자동으로 붙는 바뀌지 않는 식별자입니다(예: `sakila-mysql`).
| 미분류
| 시스템에 배정되지 않은 데이터 소스가 모이는 곳입니다.
|===

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 데이터 소스* (`/dashboard/datasources`) 로 들어갑니다.

=== 누가 무엇을 할 수 있나요

화면을 쓰려면 로그인해야 하고, xref:ops/permissions.adoc[권한 관리] 의 메뉴 권한에서 이 메뉴가 열려 있어야 합니다.

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 트리 · 상세 · ER 다이어그램 조회
| 로그인한 사용자 누구나
| 조직 · 시스템 · 데이터 소스 추가 · 수정 · 삭제, 연결 설정 저장, 연결 테스트
| 관리자, 그리고 기능 권한 *데이터 소스 관리* (`datasources.manage`)가 허용된 역할
| 연결 설정(호스트 · 계정 등) 보기
| 관리자, 그리고 기능 권한 *연결 설정 조회* (`datasources.connection`)가 허용된 역할
| 메타데이터 동기화 실행
| 관리자, 그리고 기능 권한 *메타데이터 동기화* (`datasources.sync`)가 허용된 역할
|===

세 기능 권한은 *명시 허용형* 입니다. 권한 관리의 *기능 권한* 표에서 아무것도 설정하지 않으면 관리자만 쓸 수 있고,
특정 역할(예: User)에 체크한 경우에만 그 역할에 열립니다.

image::catalog-platforms/feature-matrix.png[권한 관리 — 데이터 소스 그룹의 데이터 소스 관리 · 연결 설정 조회 · 메타데이터 동기화, 900]

[[_조회_전용_모드]]
*조회 전용 모드* — *데이터 소스 관리* 권한이 없는 사용자는 상단 문구가 *(조회 전용)* 으로 바뀌고, 우클릭 메뉴가 열리지 않으며 상세의 입력란이
모두 비활성입니다. *저장* · *연결 테스트* 버튼도 보이지 않습니다. *연결 설정 조회* 권한까지 없으면 연결 설정 자리에
*연결 설정을 볼 수 있는 권한이 없습니다.* 가 표시됩니다. ER 다이어그램은 그대로 볼 수 있습니다.

image::catalog-platforms/read-only.png[조회 전용 모드 — 입력 비활성, 저장 · 연결 테스트 없음, 900]

== 화면 구성

왼쪽은 *조직 · 시스템 · 데이터 소스 구조* 트리, 오른쪽은 트리에서 고른 항목의 상세입니다.

[cols="1,3"]
|===
| 요소 | 설명

| *조직* 루트
| 최상위 조직들이 그 아래에 놓입니다. 조직은 여러 단계로 중첩할 수 있습니다.
| 시스템 행
| 업무 시스템입니다. 오른쪽 배지는 소속 데이터 소스 수입니다.
| 데이터 소스 행
| 앞의 점 색이 환경(DEV 파랑 · STAGING 주황 · PROD 초록)을, 오른쪽 배지가 활성 데이터셋 수를 나타냅니다.
  원본에서 사라져 비활성이 된 데이터셋은 수에서 빠집니다.
| *미분류*
| 시스템에 배정되지 않은 데이터 소스(와 조직이 없는 시스템)가 모입니다. 삭제할 수 없습니다.
| 범례
| 화면 아래에 DEV · STAGING · PROD 색 범례가 있습니다.
|===

트리는 처음에 모두 펼쳐져 있습니다. 행을 *우클릭* 하거나, 마우스를 올리면 나타나는 *…* 버튼을 누르면 그 행에서 할 수 있는
작업 메뉴가 열립니다.

[cols="1,3"]
|===
| 행 | 작업 메뉴

| *조직* 루트 | 조직 추가 · 데이터 소스 추가
| 조직 | 하위 조직 추가 · 시스템 추가 · 이름 변경 · 삭제
| 시스템 | 데이터 소스 추가 · 삭제
| 데이터 소스 | 삭제
| *미분류* | 데이터 소스 추가
|===

== 조직과 시스템 만들기

=== 조직

*조직* 루트를 우클릭해 *조직 추가* 를, 기존 조직을 우클릭해 *하위 조직 추가* 를 고르면 *조직 추가* 대화상자가 열립니다.
*조직 이름* 을 입력하고 *저장* 하면 *조직을 생성했습니다.* 알림이 뜹니다. 이름은 *이름 변경* 으로 바꿉니다.

조직을 지우면 확인 창이 먼저 뜹니다. 하위 조직이나 시스템이 남아 있는 조직은 지울 수 없고,
*조직을 삭제할 수 없습니다: 하위 조직 N개, 시스템 N개가 연결되어 있습니다.* 로 안내됩니다. 하위 항목을 먼저 옮기거나 지우세요.

=== 시스템

조직을 우클릭해 *시스템 추가* 를 고르면 대화상자가 열립니다.

image::catalog-platforms/system-add.png[시스템 추가 — 이름 · 요약 · 설명 · 소속 조직 · 담당자 · 상태, 900]

[cols="1,3"]
|===
| 항목 | 설명

| 시스템 이름 | 필수입니다.
| 요약 · 설명 | 한 줄 요약과 상세 설명입니다.
| 소속 조직 | 우클릭한 조직이 기본으로 들어갑니다. *미분류 (조직 미배정)* 도 고를 수 있습니다.
| 담당자 | 시스템 책임자입니다.
| 상태 | 기본 `ACTIVE` 입니다.
|===

트리에서 시스템을 고르면 오른쪽에 같은 항목의 편집 폼이 열립니다. 값을 바꿔야 *저장* 이 활성화되며,
저장하면 *시스템을 저장했습니다.* 알림이 뜹니다.

시스템을 지울 때 소속 데이터 소스는 함께 지워지지 않고 *미분류* 로 옮겨집니다. 확인 창에 그 수가 표시됩니다.

image::catalog-platforms/system-delete-confirm.png[시스템 삭제 — 소속 데이터 소스는 미분류로 이동, 900]

== 데이터 소스 추가

. 시스템(또는 *조직* 루트 · *미분류*)을 우클릭해 *데이터 소스 추가* 를 고릅니다. 시스템에서 추가하면 그 시스템에 자동으로 배정됩니다.
. *데이터 소스 유형 선택* 에서 유형을 고릅니다. *준비 중* 배지가 붙은 유형은 아직 고를 수 없습니다.
+
image::catalog-platforms/type-select.png[데이터 소스 유형 선택 — 준비 중 유형은 비활성, 900]
. *표시 이름* · *환경* 과 유형별 *연결 설정* 을 입력합니다. 필수 항목(`*`)을 모두 채워야 *생성* 이 활성화됩니다.
. *연결 테스트* 를 지원하는 유형이면 이 버튼으로 접속을 확인합니다. 성공하면 *연결 성공 (N ms)* 알림이 뜹니다.
. *생성* 을 누르면 *데이터 소스 "<이름>" 을(를) 생성했습니다.* 알림과 함께 트리에 나타납니다.

image::catalog-platforms/add-form-test-ok.png[PostgreSQL 추가 — 연결 설정 입력 후 연결 테스트 성공, 900]

[cols="1,3"]
|===
| 항목 | 설명

| 표시 이름
| 화면에 보이는 이름입니다(예: `운영 PostgreSQL`). 나중에 바꿀 수 있습니다.
| 환경
| `DEV` · `STAGING` · `PROD` 중 하나입니다. 이 데이터 소스에서 만들어지는 데이터셋의 환경이 됩니다.
| 연결 설정
| 유형에 따라 항목이 달라집니다. RDBMS 는 *Host* · *Port* · *Database* · *Username* · *Password* · *SSL Enabled*,
  Hive 는 *Metastore Host* · *Metastore Port*, Trino 는 *Catalog* · *Schema* · *Use SSL* 처럼 유형별 폼이 나옵니다.
|===

데이터 소스에는 자동으로 *데이터 소스 ID* (예: `sakila-mysql`, `postgresql-1a1b…`)가 붙습니다. 데이터셋 URN 의 앞부분과
품질 배치의 `--datasource-id` 에 쓰이며 바뀌지 않습니다.

PostgreSQL · MySQL 은 연결 테스트 · 내장 동기화 · 화면 프로파일까지 모두 지원합니다. 그 밖의 유형은 등록은 되지만
일부 기능이 다르니 아래 상자를 확인하세요.

[[_지원_유형]]
[TIP]
.고급 사용자 — 유형별 지원 범위
====
[cols="2,1,1,1,1",options="header"]
|===
| 유형 | 추가 | 연결 테스트 | 내장 동기화 | 화면 프로파일

| PostgreSQL | ✓ | ✓ | ✓ | ✓
| MySQL | ✓ | ✓ | ✓ | ✓
| Greenplum | ✓ | ✓ | — | —
| StarRocks | ✓ | ✓ | — | —
| Apache Hive | ✓ | — | — | —
| Apache Impala | ✓ | — | — | —
| Trino | ✓ | — | — | —
| Apache Kudu | ✓ | — | — | —
| Iceberg REST Catalog | ✓ | — | — | —
| Apache Kafka · Amazon S3 · Snowflake · Google BigQuery · Amazon Redshift · Elasticsearch · MongoDB · Unity Catalog | 준비 중 | — | — | —
|===

* *연결 테스트* — 서버가 직접 접속해 보는 유형입니다(PostgreSQL · MySQL 호환 프로토콜). 그 밖의 유형은 상세 화면에 *연결 테스트* 버튼이 없습니다.
* *내장 동기화* — 카탈로그 서버가 직접 메타데이터를 읽어 오는 유형입니다. 그 밖의 유형(Hive · Impala · Trino · Kudu · StarRocks ·
  Greenplum · Oracle · MSSQL 등)은 xref:extensions/metadata-sync.adoc[Metadata Sync] 서비스로 동기화합니다.
* *화면 프로파일* — 품질 탭의 *프로파일* 버튼이 원본에 직접 접속하는 유형입니다(MariaDB 포함). 그 밖의 유형은
  xref:catalog/quality-batch.adoc[품질 배치] 로 프로파일을 반입합니다.
* HDFS 와 코드 자산용 Java · Python 소스는 추가 대화상자에 나오지 않습니다.
====


== 데이터 소스 편집

트리에서 데이터 소스를 고르면 오른쪽에 상세 편집 폼이 열립니다. 위쪽에 *유형* 과 *데이터 소스 ID* 가 표시되고,
그 아래에서 *표시 이름* · *환경* · *소속 시스템* · *연결 설정* 을 바꿀 수 있습니다.

image::catalog-platforms/datasource-detail.png[데이터 소스 상세 — 유형 · ID · 표시 이름 · 환경 · 소속 시스템 · 연결 설정, 900]

=== 저장 버튼

네 항목 중 하나라도 바뀌어야 *저장* 이 활성화됩니다. 값을 바꿨다가 원래대로 되돌려도 다시 비활성이 됩니다.
저장하면 *데이터 소스를 저장했습니다.* 알림이 뜹니다.

image::catalog-platforms/save-disabled.png[바뀐 값이 없으면 저장 버튼 비활성, 900]

*환경* 을 바꾸면 이 데이터 소스에 속한 모든 데이터셋의 환경도 함께 바뀌므로 *환경 변경* 확인 창이 먼저 뜹니다.
*변경하고 저장* 을 눌러야 저장되고, *취소* 하면 아무것도 바뀌지 않습니다. 데이터셋 URN 은 환경과 무관하게 그대로 유지됩니다.

image::catalog-platforms/origin-confirm.png[환경 변경 확인 — DEV 에서 STAGING 으로, 900]

[[_데이터_소스_비밀값_마스킹]]
=== 비밀값 마스킹

비밀번호 · 액세스 키 같은 비밀값은 암호화해 저장하고, 화면과 API 어디에도 다시 내보내지 않습니다.

* 저장된 비밀값이 있으면 입력란은 비어 있고 *저장됨 — 변경할 때만 입력* 이 표시됩니다.
* 비워 둔 채 저장하면 기존 비밀값이 그대로 유지되고, 비워 둔 채 *연결 테스트* 를 해도 저장된 비밀값으로 접속합니다.
* 새 값을 입력해 저장하면 입력란은 다시 비고 *저장됨* 상태가 됩니다.

image::catalog-platforms/stored-secret-test.png[저장된 비밀번호 — 비운 채 연결 테스트 성공, 900]

*Host* · *Port* 같은 접속 대상을 바꾸면 저장된 비밀값을 새 대상으로 보내지 않습니다. 이때는
*접속 대상이 바뀌어 저장된 비밀값을 쓸 수 없습니다. 비밀번호 등 비밀값을 다시 입력하세요.* 안내가 나오고,
비밀번호를 다시 입력해야 *저장* 이 활성화됩니다. 데이터베이스 이름이나 계정만 바꾸는 경우는 해당하지 않습니다.

image::catalog-platforms/target-changed.png[Host 변경 — 비밀값 재입력 안내, 저장 비활성, 900]

연결 설정을 불러오지 못하면 *연결 설정을 불러오지 못했습니다: … (이름·환경·시스템만 저장됩니다)* 가 표시되고
*연결 테스트* 가 숨겨집니다. 이 상태에서 저장해도 기존 연결 설정은 덮어쓰지 않습니다.

=== 연결 테스트

*연결 테스트* 는 지금 입력된 값(비운 비밀값은 저장된 값)으로 실제 접속해 봅니다. 결과는 알림으로 나오며,
실패 사유는 다음처럼 분류해 안내합니다. 드라이버의 원문 오류(내부 주소 · 경로 등)는 화면에 보여 주지 않고 서버 로그에만 남깁니다.

| 알림 | 확인할 것

| 연결 성공 (N ms) | —

=== ER 다이어그램

RDBMS 유형 데이터 소스는 상세 아래에 *ER 다이어그램 (전체)* 이 표시됩니다. 동기화된 데이터셋의 PK · FK 와 DDL 제약, 리니지로 추정한 관계를
테이블 간 선으로 그리며, 엣지에는 FK 컬럼과 카디널리티(예: `customer_id N:1`)가 붙습니다. *Mermaid 복사* 로 다이어그램 정의를 복사할 수 있습니다.

[[_메타데이터_동기화]]
== 메타데이터 동기화

동기화는 원본의 테이블 · 컬럼 정보를 읽어 카탈로그의 데이터셋을 만들거나 갱신합니다. 테이블과 컬럼을 일일이 손으로 옮길 필요가 없습니다.

.메타데이터 동기화와 데이터셋 갱신
image::diagrams/catalog-platforms-02.png[메타데이터 동기화와 데이터셋 갱신,role="diagram"]

[[_실행_방법]]
=== 실행 방법

데이터 소스 화면에는 동기화 버튼이 없습니다. 다음 두 가지 방법 중 하나로 실행합니다.

* *카탈로그 내장 동기화 (MySQL · PostgreSQL)* — *메타데이터 동기화* 권한이 있는 계정으로 API 를 호출합니다(아래 상자 참고).
* *Metadata Sync 서비스* — 그 밖의 유형과 주기 실행은 xref:extensions/metadata-sync.adoc[Metadata Sync] 확장이 담당합니다.

동기화가 끝나면 *데이터 카탈로그 → 데이터셋* 에서 데이터 소스 필터로 결과를 확인합니다.
새 테이블은 데이터셋으로 등록되고, 이미 있으면 갱신됩니다. 원본에서 사라진 테이블의 데이터셋은 지우지 않고 *비활성* 으로 표시됩니다.

image::catalog-platforms/sync-datasets.png[동기화 후 데이터셋 목록 — 데이터 소스 필터로 확인, 900]

[TIP]
.고급 사용자 — 내장 동기화 API 호출
====
[source,bash]
----
# MySQL: database 를 생략하면 연결 설정의 Database 를 스캔 (그것도 비어 있으면 전체 사용자 DB)
# PostgreSQL: database 값은 스키마 이름으로 해석, 생략하면 접속 DB 의 전체 스키마
curl -X POST "<카탈로그 주소>/api/v1/catalog/datasources/<데이터 소스 번호>/sync?database=shop" \
  -H "Authorization: Bearer <토큰>"
----

성공하면 `databases_scanned` · `tables_total` · `tables_created` · `tables_updated` · `tables_removed` · `samples_uploaded` 를 돌려줍니다.
====

[[_수집_대상과_후처리]]
[TIP]
.고급 사용자 — 수집 대상과 후처리
====
수집 대상::
* 테이블 · 뷰와 각 테이블의 컬럼(이름 · 타입 · NULL 허용 · 기본값 · 설명)
* 키 정보(PK · Unique · FK)와 DDL 원문 — 뷰는 *CREATE VIEW* 정의로 저장됩니다.
* 베이스 테이블의 샘플 데이터(최대 100행, Parquet) — 데이터셋 *샘플* 탭에 보입니다. 뷰와 빈 테이블은 제외됩니다.

후처리::
* 새 테이블은 데이터셋으로 등록하고, 이미 있으면 갱신합니다. 데이터셋의 환경은 데이터 소스 환경을 따릅니다.
* 컬럼 변경은 스키마 변경 이력에 남습니다(데이터셋 상세 *더보기 → 변경 이력*). xref:governance/alerts.adoc[알림] 규칙이 있으면 변경분을 평가합니다.
* 사용자가 입력한 컬럼 설명 · PII 유형은 유지됩니다. 단, 원본에 컬럼 코멘트가 있으면 설명은 원본 값으로 갱신됩니다.
* 원본에서 사라진 테이블의 데이터셋은 지우지 않고 *비활성(removed)* 으로 표시해 목록 · 개수에서 뺍니다. 다시 나타나면 같은 데이터셋이 복원됩니다.
  스캔 결과가 0개면 "전부 삭제" 로 보지 않고 아무것도 비활성화하지 않습니다.
* xref:ai/metadata-generation.adoc[AI 메타데이터 생성] 의 동기화 후 자동 생성이 켜져 있으면 비어 있는 설명을 자동으로 채웁니다.
====

[[_동시_실행과_시간_제한]]
[TIP]
.고급 사용자 — 동시 실행과 시간 제한
====
* 같은 데이터 소스에 동기화가 진행 중이면 새 요청은 거절됩니다(409 *이 데이터 소스는 이미 동기화 중입니다. 완료 후 다시 시도하세요.*).
  다른 데이터 소스의 동기화는 영향을 받지 않습니다.
* 동기화 중인 데이터 소스는 삭제할 수 없습니다(409 *동기화가 진행 중인 데이터 소스는 삭제할 수 없습니다.*).
* 원본 접속은 10초, 메타데이터 조회 쿼리는 120초 제한이 있습니다. 실패하면 400 과 함께
  *원격 DB 메타데이터 조회 실패: 연결 시간 초과 (10초)* 처럼 연결 테스트와 같은 분류로 사유를 알려 줍니다.
* 연결 설정에서 SSL 을 켜 두었다면 동기화도 암호화 접속을 합니다.
====

== 데이터 소스 삭제

데이터 소스를 우클릭해 *삭제* 를 고르면 *데이터 소스 삭제* 대화상자가 열립니다. 대화상자는 먼저 삭제 영향을 조회하며,
조회 중(*삭제 영향 확인 중...*)에는 *삭제* 를 누를 수 없습니다.

image::catalog-platforms/delete-impact.png[데이터 소스 삭제 — 데이터셋 23개 함께 삭제, 확인 문자열 입력, 900]

[cols="1,3"]
|===
| 안내 문구 | 의미

| 이 데이터 소스의 데이터셋 N개 (와 이를 참조하는 타 데이터 소스 리니지 N개) 가 함께 삭제됩니다.
| 활성 데이터셋과 다른 데이터 소스로 이어진 리니지가 함께 지워집니다.
| 원본에서 사라진(비활성) 데이터셋 N개도 함께 정리됩니다.
| 비활성 데이터셋도 함께 지워집니다.
| 이 데이터 소스·데이터셋 대상 알림 규칙 N개가 삭제됩니다.
| 대상이 사라지는 알림 규칙이 지워집니다.
| 데이터셋의 변경 요청 N건이 함께 삭제됩니다.
| 관련 변경 요청이 지워집니다.
| 연결된 모델 · MCP 배포 N개는 데이터 소스 연결만 해제됩니다.
| 모델 · MCP 배포 자체는 남습니다.
|===

삭제를 확정하려면 입력란에 `DELETE <데이터 소스 이름>` 을 정확히 입력해야 *삭제* 가 활성화됩니다. 삭제하면
*데이터 소스 "<이름>" 을 삭제했습니다.* 알림이 뜨고, 데이터셋의 댓글 · 샘플 파일 등 딸린 정보도 함께 정리됩니다.

WARNING: 데이터 소스 삭제는 되돌릴 수 없습니다. 품질 규칙 · 결과, 스키마 이력 등 데이터셋에 쌓인 정보도 모두 사라집니다.

TIP: 페더레이션 노출 허용 목록에 이 데이터 소스 이름이 남아 있으면 대화상자에 경고가 함께 표시됩니다. 같은 이름으로 다시 만들면
자동으로 노출되니 서버 설정에서도 지우세요.

== 자주 묻는 질문

[qanda]
*목록을 불러오지 못했습니다.* 가 나옵니다.::
  일시적인 오류입니다. 함께 나오는 *다시 시도* 버튼을 누르세요.

조직이 지워지지 않습니다.::
  하위 조직이나 시스템이 남아 있는 조직은 지울 수 없습니다. 하위 항목을 먼저 옮기거나 지우세요.

*연결 테스트* 버튼이 없습니다.::
  서버가 직접 접속해 보는 유형(PostgreSQL · MySQL 호환 프로토콜)에만 버튼이 있습니다. *데이터 소스 관리* 권한이 없을 때도 보이지 않습니다.

비밀번호 입력란이 비어 있습니다.::
  저장된 비밀값은 화면에 다시 내보내지 않습니다. *저장됨 — 변경할 때만 입력* 이 보이면 비워 둔 채 저장해도 기존 값이 유지됩니다.

입력란이 모두 비활성이고 *저장* 버튼이 없습니다.::
  *데이터 소스 관리* 권한이 없는 조회 전용 모드입니다. 관리자에게 권한을 요청하세요.

동기화 요청이 409 로 거절됩니다.::
  같은 데이터 소스의 동기화가 이미 진행 중입니다. 끝난 뒤 다시 시도하세요.
