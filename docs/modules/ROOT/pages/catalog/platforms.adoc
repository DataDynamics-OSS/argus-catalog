= 데이터 소스
:toc: macro
:toclevels: 2

데이터 소스는 데이터가 실제로 저장된 시스템(MySQL · PostgreSQL 같은 DBMS, Hive · Trino 같은 분석 엔진 등)과
그 연결 정보를 카탈로그에 등록한 것입니다. 데이터 소스에서 테이블 · 컬럼 메타데이터를 동기화하면
xref:catalog/datasets.adoc[데이터셋] 이 만들어지고, xref:catalog/quality.adoc[데이터 품질] 의 프로파일링과 정밀 진단(원천 직접 경로)도
여기 등록한 연결 정보로 원본에 접속합니다.

데이터 소스 화면은 데이터 소스를 *조직 → 시스템 → 데이터 소스* 계층으로 정리해 보여 줍니다. 어느 부서의 어떤 업무 시스템이
어떤 DB 를 쓰는지 한눈에 볼 수 있습니다.

이 문서는 처음 사용하는 분을 기준으로 화면 순서대로 설명합니다.
**고급 사용자** 상자는 몰라도 사용에 지장이 없는 심화 내용이니 처음에는 건너뛰어도 됩니다.

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **구조 정리** — 데이터 소스를 *조직 → 시스템 → 데이터 소스* 트리로 정리합니다.
* **데이터 소스 등록** — DB · 분석 엔진의 연결 정보를 등록하고 *연결 테스트* 로 접속을 확인합니다.
* **연결 정보 관리** — 표시 이름 · 환경 · 소속 시스템 · 연결 설정을 고칩니다. 비밀번호는 안전하게 가려집니다.
* **메타데이터 동기화(수집)** — 수집할 데이터베이스 · 스키마를 골라 원본의 테이블 · 컬럼을 읽고 데이터셋을 자동으로 만들고 갱신합니다.
  바로 실행하거나 주기를 정해 예약할 수 있고, 관리자와 수집 권한이 있는 사람은 *메타데이터 수집* 화면에서 모든 수집 실행을 한곳에서 봅니다.
* **ER 다이어그램** — 데이터 소스 전체 테이블의 관계를 한 장의 그림으로 봅니다.

=== 먼저 알아 둘 용어

[cols="1,4",options="header"]
|===
| 용어 | 뜻

| 조직
| 부서 같은 최상위 묶음입니다. 하위 조직으로 여러 단계 중첩할 수 있습니다.
| 시스템
| 조직에 속한 업무 시스템입니다. 데이터 소스는 시스템 아래에 놓입니다.
| 데이터 소스
| 실제 DB · 엔진과 그 연결 설정입니다. 환경(DEV · STAGING · PROD)을 하나 가집니다.
| 데이터 소스 ID
| 데이터 소스에 자동으로 붙는 바뀌지 않는 식별자입니다(예: `sakila-mysql`).
| 미분류 · 조직 미지정
| 시스템에 배정되지 않은 데이터 소스를 *미분류*, 조직에 속하지 않은 시스템을 *조직 미지정* 이라 합니다. 둘 다 트리의 *미분류* 에 모입니다.
|===

=== 메뉴 위치

좌측 사이드바의 *데이터 카탈로그 → 데이터 소스* (`/dashboard/datasources`) 로 들어갑니다.
모든 데이터 소스의 수집 실행은 *관리 → 메타데이터 수집* (`/dashboard/sync-runs`)에서 봅니다(<<_메타데이터_수집_화면,메타데이터 수집 화면>>).
관리 메뉴지만 *메타데이터 동기화* 권한을 받은 역할에도 보입니다.

=== 누가 무엇을 할 수 있나요

화면을 쓰려면 로그인해야 하고, xref:ops/permissions.adoc[권한 관리] 의 메뉴 권한에서 이 메뉴가 열려 있어야 합니다.

[cols="1,3"]
|===
| 작업 | 할 수 있는 사람

| 트리 · 상세 · ER 다이어그램 조회, 수집 영역(수집 범위 · 예약 상태 · 최근 실행 · 실행 상세) 조회
| 로그인한 사용자 누구나
| 조직 · 시스템 · 데이터 소스 추가 · 수정 · 삭제, 연결 설정 저장, 연결 테스트
| 관리자, 그리고 기능 권한 *데이터 소스 관리* (`datasources.manage`)가 허용된 역할
| 연결 설정(호스트 · 계정 등) 보기
| 관리자, 그리고 기능 권한 *연결 설정 조회* (`datasources.connection`)가 허용된 역할
| 수집 범위 선택 · 저장, 지금 수집 · 이번 한 번만 수집, 예약 설정, 수집 취소 · 다시 실행
| 관리자, 그리고 기능 권한 *메타데이터 동기화* (`datasources.sync`)가 허용된 역할
| *관리 → 메타데이터 수집* 화면
| 관리자, 그리고 기능 권한 *메타데이터 동기화* (`datasources.sync`)가 허용된 역할(메뉴 권한 표로는 열 수 없습니다)
|===

세 기능 권한은 *명시 허용형* 입니다. 권한 관리의 *기능 권한* 표에서 아무것도 설정하지 않으면 관리자만 쓸 수 있고,
특정 역할(예: User)에 체크한 경우에만 그 역할에 열립니다.

image::catalog-platforms/feature-matrix.png[권한 관리 — 데이터 소스 그룹의 데이터 소스 관리 · 연결 설정 조회 · 메타데이터 동기화, 900]

[[_조회_전용_모드]]
*조회 전용 모드* — *데이터 소스 관리* 권한이 없는 사용자는 상단 문구가 *(조회 전용)* 으로 바뀌고, *조직 추가* · *데이터 소스 추가* 버튼과
우클릭 메뉴가 없습니다. 데이터 소스의 *기본 정보* 탭은 입력란 대신 이름 · 환경 · 소속 시스템과 연결 설정을 표로 보여 주며,
비밀값은 *저장됨 (가려짐)* 으로만 표시됩니다. *연결 테스트* 버튼도 없습니다. *연결 설정 조회* 권한까지 없으면 연결 설정 자리에
*연결 설정을 볼 수 있는 권한이 없습니다.* 가 표시됩니다. ER 다이어그램은 그대로 볼 수 있습니다.

== 화면 구성

왼쪽은 *조직 · 시스템 · 데이터 소스 구조* 트리, 오른쪽은 트리에서 고른 항목의 상세입니다. 트리 위 오른쪽의
*조직 추가* · *데이터 소스 추가* 버튼으로 바로 만들 수 있습니다(관리 권한이 있을 때).

고른 항목과 탭은 주소에 남습니다(예: `?datasource=<데이터 소스 ID>&tab=sync`, `?system=3`, `?org=1`). 새로 고침하거나 주소를
다른 사람에게 보내도 같은 화면이 열립니다.

[cols="1,3"]
|===
| 요소 | 설명

| *조직* 루트
| 최상위 조직들이 그 아래에 놓입니다. 조직은 여러 단계로 중첩할 수 있습니다.
| 시스템 행
| 업무 시스템입니다. 오른쪽 배지는 소속 데이터 소스 수입니다.
| 데이터 소스 행
| 앞의 점 색이 환경(운영 PROD 초록 · 스테이징 STAGING 주황 · 개발 DEV 하늘)을, 오른쪽 배지가 활성 데이터셋 수를 나타냅니다.
  원본에서 사라져 비활성이 된 데이터셋은 수에서 빠집니다.
| *미분류*
| 미분류 데이터 소스와 조직 미지정 시스템이 모입니다. 삭제할 수 없습니다. 고르면 오른쪽에 미분류 상세가 열립니다(<<_미분류_상세,미분류 상세>>).
| 조직 상세
| 머리에 경로와 하위 조직 · 시스템 · 데이터 소스 · 데이터셋 수(하위 조직 포함), 아래에 *기본 정보* 와 하위 조직 · 시스템 표가 있습니다(<<_조직,조직>> 참고).
| 범례
| 화면 아래에 운영 (PROD) · 스테이징 (STAGING) · 개발 (DEV) 색 범례가 있습니다. 대시보드의 환경별 분포도 같은 색을 씁니다.
|===

트리는 처음에 모두 펼쳐져 있습니다. 행을 *우클릭* 하거나, 마우스를 올리면 나타나는 *⋯* 버튼을 누르면 그 행에서 할 수 있는
작업 메뉴가 열립니다. 항목마다 아이콘이 붙고, *삭제* 는 구분선 아래 빨간 글씨로 맨 아래에 있습니다.

[cols="1,3"]
|===
| 행 | 작업 메뉴

| *조직* 루트 | 조직 추가 · 데이터 소스 추가
| 조직 | 하위 조직 추가 · 시스템 추가 · 이름 변경 · 삭제
| 시스템 | 데이터 소스 추가 · 삭제
| 데이터 소스 | 삭제
| *미분류* | 데이터 소스 추가 · 시스템 추가 — 시스템 추가 아래에 "조직 없이 추가합니다" 가 보입니다
|===

== 조직과 시스템 만들기

=== 조직

*조직* 루트를 우클릭해 *조직 추가* 를, 기존 조직을 우클릭해 *하위 조직 추가* 를 고르면 *조직 추가* 대화상자가 열립니다.
*조직 이름* 을 입력하고 *저장* 하면 *조직을 생성했습니다.* 알림이 뜹니다. 같은 상위 아래(최상위끼리 포함)에 같은 이름이 있으면
*최상위에 같은 이름의 조직이(가) 이미 있습니다* 처럼 거부됩니다. 시스템도 같은 조직 안(미분류끼리 포함)에서 이름이 겹칠 수 없습니다.

트리에서 조직을 고르면 오른쪽에 조직 상세가 열립니다.

* 머리 — 이름 · 설명과 경로(상위 › 이 조직), 하위 조직 · 시스템 · 데이터 소스 · 데이터셋 수(하위 조직 포함). 오른쪽 *⋯* 메뉴에
  *하위 조직 추가* · *시스템 추가* · *삭제* 가 있습니다.
* *기본 정보* — 이름 · 상위 조직 · 설명을 바로 고칩니다. 상위 조직을 바꾸면 그 아래 하위 조직 · 시스템 · 데이터 소스가 함께 옮겨 가고,
  자기 자신과 하위 조직은 선택지에 나오지 않습니다. 고친 내용이 있으면 화면 아래에 *저장 안 된 변경이 있습니다* 줄(*취소* · *저장*)이 붙고,
  저장하지 않은 채 다른 항목을 고르면 확인 창이 뜹니다. 관리 권한이 없으면 표로 보입니다.
* *하위 조직 (N)* · *시스템 (N)* — 표로 보입니다(하위 조직은 하위까지 합한 수, 시스템은 상태 · 담당자 · 데이터 소스 · 데이터셋).
  이름을 누르면 그 항목으로 옮겨 가고, 제목 옆 단추로 바로 추가합니다.

하위 조직이나 시스템이 남아 있는 조직은 지울 수 없습니다. 상세의 *⋯* 메뉴에서는 *삭제* 가 비활성이고 그 아래에 남은 수가 안내되며,
트리 메뉴에서 지우면 *조직을 삭제할 수 없습니다: 하위 조직 N개, 시스템 N개가 연결되어 있습니다.* 로 안내됩니다. 하위 항목을 먼저 옮기거나 지우세요.
트리의 *이름 변경* 메뉴로 이름만 빨리 바꿀 수도 있습니다.

=== 시스템

조직을 우클릭해 *시스템 추가* 를 고르면 대화상자가 열립니다.

image::catalog-platforms/system-add.png[시스템 추가 — 이름 · 요약 · 설명 · 소속 조직 · 담당자 · 상태, 900]

[cols="1,3"]
|===
| 항목 | 설명

| 시스템 이름 | 필수입니다.
| 요약 · 설명 | 한 줄 요약과 상세 설명입니다.
| 소속 조직 | 우클릭한 조직이 기본으로 들어갑니다. 선택지는 상위 경로와 함께(예: `경영본부 › 데이터팀`) 보여 이름이 같은 하위 조직도 구별됩니다. *조직 미지정* 도 고를 수 있습니다.
| 담당자 | 시스템 책임자입니다. 이름과 연락처(이메일 · 부서)를 함께 적어 두면 좋습니다.
| 상태 | *운영 중*(기본) · *사용 안 함* · *폐기 예정* 가운데 고릅니다. 운영 중이 아니면 트리의 시스템 이름 옆에 상태 배지가 붙습니다.
|===

트리에서 시스템을 고르면 오른쪽에 시스템 상세가 열립니다. 머리에는 이름 · 상태 · 요약과 소속 조직 경로, 담당자, 데이터 소스 수,
데이터셋 합계가 보이고, 오른쪽 *⋯* 메뉴로 *데이터 소스 추가* · *삭제* 를 할 수 있습니다.

* *기본 정보* — 위 표와 같은 항목의 편집 폼입니다. 값을 바꾸면 화면 아래에 *저장 안 된 변경이 있습니다* 줄과 *취소* · *저장* 이 붙고,
  저장하면 *시스템을 저장했습니다.* 알림이 뜹니다. 저장하지 않은 채 다른 항목을 고르면 확인 창이 뜹니다(데이터 소스 상세와 같음).
  관리 권한이 없으면 같은 항목이 표로 보입니다.
* *데이터 소스 (N)* — 이 시스템의 데이터 소스 표입니다. 이름을 누르면 그 데이터 소스로 옮겨 가고, *데이터 소스 추가* 로 이 시스템에
  바로 추가합니다.

시스템을 지울 때 소속 데이터 소스는 함께 지워지지 않고 *미분류* 로 옮겨집니다. 확인 창에 그 수가 표시됩니다.

[[_미분류_상세]]
=== 미분류 상세

트리에서 *미분류* 를 고르면 머리에 조직 미지정 시스템 수 · 미분류 데이터 소스 수 · 데이터셋 합계가 보이고, 아래에 두 표가 있습니다.

* *조직 미지정 시스템 (N)* — 이름 · 상태 · 담당자 · 데이터 소스 · 데이터셋. 제목 옆 *시스템 추가* 는 조직 없이 시스템을 만듭니다.
* *미분류 데이터 소스 (N)* — 이름 · 유형 · 환경 · 데이터셋. 제목 옆 *데이터 소스 추가* 는 시스템 없이 데이터 소스를 만듭니다.

표 왼쪽 체크박스로 여러 개를 고르면 표 위에 배정 줄이 나옵니다. 시스템은 *배정할 조직*(경로로 표시)을, 데이터 소스는 *배정할 시스템* 을
고르고 *조직에 배정* · *시스템에 배정* 을 누르면 한 번에 옮겨집니다. 일부가 실패하면 실패한 수와 첫 사유가 알림으로 나오고,
성공한 것은 그대로 옮겨집니다. 모두 배정되어 있으면 *모든 데이터 소스와 시스템이 배정되어 있습니다.* 가 보입니다.
관리 권한이 없으면 체크박스와 추가 단추 없이 표만 보입니다.

== 데이터 소스 추가

*데이터 소스 추가* 대화상자는 *유형 선택 → 연결 설정 → 생성* 순서로 진행하고, 유형에 따라 생성 뒤에
*카탈로그 연결* 이나 *수집 범위* 단계가 이어집니다.

. 시스템(또는 *조직* 루트 · *미분류*)을 우클릭해 *데이터 소스 추가* 를 고릅니다. 시스템에서 추가하면 그 시스템에 자동으로 배정됩니다.
. *무엇을 추가하나요?* 화면에서 유형을 고릅니다. 유형은 역할에 따라 세 묶음으로 나뉘어 있고,
  *준비 중* 배지가 붙은 유형은 아직 고를 수 없습니다.
+
[cols="1,2,3",options="header"]
|===
| 묶음 | 뜻 | 고를 수 있는 유형

| 카탈로그
| 테이블 메타데이터를 가진 카탈로그 서비스입니다. 메타데이터를 수집합니다.
| *Apache Iceberg* · Apache Hive · Apache Kudu
| 데이터베이스
| 데이터베이스 자체가 카탈로그입니다. 메타데이터를 수집합니다.
| PostgreSQL · MySQL · Oracle · Microsoft SQL Server · StarRocks · Greenplum
| 쿼리 엔진
| 자체 카탈로그가 없습니다. 등록된 카탈로그에 연결해 쿼리 이력 · 리니지를 수집합니다.
| Apache Impala · Trino
|===
+
*Apache Iceberg* 를 고르면 *Iceberg 카탈로그 선택* 화면이 열리고, 테이블이 등록된 카탈로그를 한 번 더 고릅니다.
*REST Catalog* 는 *Iceberg REST Catalog* 유형으로, *Hive Metastore (HiveCatalog)* 는 *Apache Hive* 유형(기본 표시 이름 `Hive Metastore (Iceberg)`)으로
만들어집니다. *Hadoop Catalog* 는 *Iceberg Hadoop Catalog* 유형으로, 메타스토어 없이 웨어하우스 경로(S3 · HDFS)에 만든 테이블을 수집합니다. *이전* 으로 유형 선택으로 돌아갈 수 있습니다.
+

image::catalog-platforms/type-select.png[데이터 소스 유형 선택 — 준비 중 유형은 비활성, 900]
. *<유형> 추가* 화면(예: *PostgreSQL 추가*)에서 *표시 이름* · *환경* 과 유형별 *연결 설정* 을 입력합니다.
  필수 항목(`+*+`)을 모두 채워야 *추가* 가 활성화됩니다. *이전* 을 누르면 유형 선택으로 돌아갑니다.
. *연결 테스트* 를 지원하는 유형이면 이 버튼으로 접속을 확인합니다(<<_연결_테스트,연결 테스트>> 참고). 성공하면 *연결 성공 (Nms)* 알림이 뜹니다.
. *추가* 를 누르면 *데이터 소스 "<이름>" 을(를) 생성했습니다.* 알림과 함께 트리에 나타납니다.
  시스템 배정만 실패하면 *… 생성했지만 시스템 배정에 실패해 미분류로 두었습니다.* 경고가 뜨고 *미분류* 에 놓입니다.
. 생성 뒤에는 유형에 따라 다음 단계가 이어집니다.
** *쿼리 엔진* (Impala · Trino) — *<이름> — 카탈로그 연결* 단계에서 이 엔진이 조회하는 카탈로그를 연결합니다(아래 상자 참고).
   다 했으면 *완료* 를 누릅니다. 나중에 데이터 소스 상세의 *카탈로그 연결* 영역에서도 바꿀 수 있습니다.
** *화면 수집을 지원하는 그 밖의 유형* — *메타데이터 동기화* 권한이 있으면 *<이름> — 수집 범위* 단계가 나옵니다. *범위 선택…* 을 누르면
   <<_수집_범위_선택,수집 범위 선택>> 대화상자가 열리고, 거기서 *저장하고 지금 수집* 을 누르면 바로 첫 수집이 시작됩니다
   (*수집을 시작했습니다. 오른쪽 "수집"에서 진행을 볼 수 있습니다.*). *나중에* 를 누르면 범위 없이 닫힙니다.
   범위를 정하기 전에는 수집할 수 없습니다. 실수로 원본 전체를 가져오지 않도록 하기 위해서입니다.
** 그 밖의 경우(화면 수집을 지원하지 않는 유형, 수집 권한이 없는 사용자)는 대화상자가 바로 닫힙니다.
. 대화상자가 닫히면 트리에서 새 데이터 소스가 선택되어 오른쪽에 상세가 열립니다. *저장하고 지금 수집* 으로 닫았으면 수집 영역에 진행 상자가 바로 보입니다.

|===
| 항목 | 설명

| 표시 이름
| 화면에 보이는 이름입니다(예: `운영 PostgreSQL`). 나중에 바꿀 수 있습니다.
| 환경
| `DEV` · `STAGING` · `PROD` 중 하나입니다. 이 데이터 소스에서 만들어지는 데이터셋의 환경이 됩니다.
| 연결 설정
| 유형에 따라 항목이 달라집니다. RDBMS 는 *Host* · *Port* · *Database* · *Username* · *Password* · *SSL Enabled*,
  Hive 는 *Metastore Host* · *Metastore Port*, Trino 는 *Catalog* · *Schema* · *Use SSL* 처럼 유형별 폼이 나옵니다.
|===

생성 뒤 연결 설정 저장 같은 다음 단계가 실패하면 *데이터 소스는 추가했지만 다음 단계를 마치지 못했습니다. 다시 "추가"를 누르면 이어서 저장합니다.*
가 표시됩니다. 이때 *추가* 를 다시 누르면 데이터 소스를 새로 만들지 않고 남은 단계만 이어서 저장합니다.

데이터 소스에는 자동으로 *데이터 소스 ID* (예: `sakila-mysql`, `postgresql-1a1b…`)가 붙습니다. 데이터셋 URN 의 앞부분에
쓰이며 바뀌지 않습니다.

[TIP]
.고급 사용자 — 쿼리 엔진의 카탈로그 연결
====
쿼리 엔진(Impala · Trino)은 자기 카탈로그가 없으므로, 이미 등록된 카탈로그(예: Hive 데이터 소스가 만든 카탈로그)에 연결해 씁니다.
생성 직후 단계와 데이터 소스 상세의 *카탈로그 연결* 영역에서 같은 방법으로 연결합니다.

* *카탈로그 연결 추가* 에서 카탈로그와 연결 방식(*조회* · *수집*)을 고르고, 엔진 쪽 카탈로그 이름(Trino 예: `hive`, `iceberg`)을 적은 뒤 *연결* 을 누릅니다.
** *조회* — 이 엔진의 쿼리 리니지를 그 카탈로그의 데이터셋으로 잇습니다.
** *수집* — 엔진으로만 닿는 카탈로그의 메타데이터를 이 엔진을 통해 수집합니다. Trino 를 화면에서 수집하려면 이 연결이 있어야 하며,
   없으면 *쿼리 엔진은 카탈로그에 {apos}수집{apos}으로 연결해야 엔진을 통해 수집할 수 있습니다.* 로 거절됩니다.
* Trino 는 *Trino 에서 카탈로그 불러오기* 로 엔진에 있는 카탈로그 목록을 읽어 와 하나씩 연결할 수 있습니다.
* 카탈로그 · 데이터베이스 유형은 데이터 소스를 만들 때 수집용 카탈로그가 자동으로 만들어져 *카탈로그 연결* 영역에 *수집* 으로 표시됩니다.
====

PostgreSQL · MySQL 은 연결 테스트 · 내장 수집 · 화면 프로파일까지 모두 지원합니다. 그 밖의 유형은 등록은 되지만
일부 기능이 다르니 아래 상자를 확인하세요.

====
[cols="2,1,2,2,1",options="header"]
|===
| 유형 | 추가 | 연결 테스트 | 화면 수집 | 화면 프로파일

| PostgreSQL | ✓ | ✓ (서버 직접) | ✓ 내장 | ✓
| MySQL | ✓ | ✓ (서버 직접) | ✓ 내장 | ✓
| Greenplum | ✓ | ✓ (서버 직접) | ✓ Metadata Sync | —
| StarRocks | ✓ | ✓ (서버 직접) | ✓ Metadata Sync | —
| Oracle | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync | ✓
| Microsoft SQL Server | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync | ✓
| Apache Hive | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync | —
| Iceberg REST Catalog | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync | —
| Iceberg Hadoop Catalog | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync | —
| Apache Kudu | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync (전체 수집만) | —
| Trino | ✓ | ✓ (Metadata Sync) | ✓ Metadata Sync (카탈로그에 *수집* 으로 연결해야 함) | —
| Apache Impala | ✓ | — | — | —
| Apache Kafka · Snowflake · Amazon Redshift · Elasticsearch · Unity Catalog | 준비 중 | — | — | —
|===

* *연결 테스트* — *서버 직접* 은 카탈로그 서버가 드라이버로 직접 접속해 보는 유형(PostgreSQL · MySQL 호환 프로토콜)이고,
  *Metadata Sync* 는 xref:extensions/metadata-sync.adoc[Metadata Sync] 서비스에 시험 접속을 맡기는 유형입니다. 표시가 없는 유형은 *연결 테스트* 버튼이 없습니다.
* *화면 수집* — 데이터 소스 상세의 <<_메타데이터_동기화,수집>> 영역에서 범위 선택 · 지금 수집 · 예약을 쓸 수 있는 유형입니다.
  *내장* 은 카탈로그 서버가 직접 메타데이터를 읽고, *Metadata Sync* 는 카탈로그 서버가 Metadata Sync 서비스에 수집 작업을 보냅니다.
  표시가 없는 유형(Impala)은 수집 영역에 *이 유형은 아직 화면에서 수집을 지원하지 않습니다.* 만 보입니다.
* *화면 프로파일* — Trino 카탈로그 연결 없이도 품질 워커가 원본에 직접 접속해 프로파일 · 정밀 진단하는 유형입니다(MariaDB 포함, *원천 직접* 경로). Oracle · SQL Server 는 품질 워커에 드라이버를 더 설치하고, SSL 접속은 지원하지 않습니다.
  그 밖의 유형은 Trino 에 카탈로그로 등록하고 *카탈로그 연결* 로 이으면 Trino 경로로 진단합니다.
* HDFS 와 코드 자산용 Java · Python 소스, 지원 계획이 없는 Amazon S3 · Google BigQuery · MongoDB 는 추가 대화상자에 나오지 않습니다.

== 데이터 소스 편집

트리에서 데이터 소스를 고르면 오른쪽에 상세가 열립니다. 맨 위 머리에는 이름 · 유형 · 환경과 함께 소속(조직 › 시스템),
데이터 소스 ID, 데이터셋 수(누르면 이 데이터 소스로 거른 데이터셋 목록), 마지막 수집 결과 · 시각, 연결된 카탈로그가 한 줄로 보입니다.
관리 권한이 있으면 이름 오른쪽 *⋯* 메뉴에 *삭제* 가 있습니다(트리 행 메뉴의 *삭제* 와 같은 확인 창이 열립니다).

그 아래는 탭입니다 — *기본 정보* · *카탈로그 연결* · <<_메타데이터_동기화,수집>> · (RDBMS 유형이면) <<_er_다이어그램,ER 다이어그램>>.
*기본 정보* 탭에서 *표시 이름* · *환경* · *소속 시스템* · *연결 설정* 을 바꿀 수 있습니다.

=== 저장 버튼

네 항목 중 하나라도 바꾸면 화면 아래에 *저장 안 된 변경이 있습니다* 줄과 *취소* · *저장* 버튼이 붙습니다(스크롤해도 따라옵니다).
값을 원래대로 되돌리면 줄이 사라지고, *취소* 는 고친 내용을 모두 처음 값으로 돌립니다. 저장하면 *데이터 소스를 저장했습니다.* 알림이 뜹니다.

저장하지 않은 채 트리에서 다른 항목을 고르면 *저장 안 된 변경* 확인 창이 뜹니다(*버리고 이동* 해야 옮겨 갑니다).
창을 닫거나 다른 주소로 갈 때는 브라우저가 확인합니다. 다른 탭을 보고 와도 고치던 내용은 남아 있습니다.

// TODO: screenshot - 화면 아래 "저장 안 된 변경이 있습니다" 줄(취소 · 저장)

*환경* 을 바꾸면 이 데이터 소스에 속한 모든 데이터셋의 환경도 함께 바뀌므로 *환경 변경* 확인 창이 먼저 뜹니다.
*변경하고 저장* 을 눌러야 저장되고, *취소* 하면 아무것도 바뀌지 않습니다. 데이터셋 URN 은 환경과 무관하게 그대로 유지됩니다.

=== 비밀값 마스킹

비밀번호 · 액세스 키 같은 비밀값은 암호화해 저장하고, 화면과 API 어디에도 다시 내보내지 않습니다.

* 저장된 비밀값이 있으면 입력란은 비어 있고 *저장됨 — 변경할 때만 입력* 이 표시됩니다.
* 비워 둔 채 저장하면 기존 비밀값이 그대로 유지되고, 비워 둔 채 *연결 테스트* 를 해도 저장된 비밀값으로 접속합니다.
* 새 값을 입력해 저장하면 입력란은 다시 비고 *저장됨* 상태가 됩니다.

image::catalog-platforms/stored-secret-test.png[저장된 비밀번호 — 비운 채 연결 테스트 성공, 900]

*Host* · *Port* 같은 접속 대상을 바꾸면 저장된 비밀값을 새 대상으로 보내지 않습니다. 이때는
*접속 대상이 바뀌어 저장된 비밀값을 쓸 수 없습니다. 비밀번호 등 비밀값을 다시 입력하세요.* 안내가 나오고,
비밀번호를 다시 입력해야 *저장* 이 활성화됩니다. 데이터베이스 이름이나 계정만 바꾸는 경우는 해당하지 않습니다.

image::catalog-platforms/target-changed.png[Host 변경 — 비밀값 재입력 안내, 저장 비활성, 900]

연결 설정을 불러오지 못하면 *연결 설정을 불러오지 못했습니다: … (이름·환경·시스템만 저장됩니다)* 가 표시되고
*연결 테스트* 가 숨겨집니다. 이 상태에서 저장해도 기존 연결 설정은 덮어쓰지 않습니다.

=== 연결 테스트

*연결 테스트* 는 지금 입력된 값(비운 비밀값은 저장된 값)으로 실제 접속해 봅니다. 결과는 알림으로 나오고, *연결 설정* 제목 아래에도
마지막 결과와 테스트 시각이 남습니다. 테스트한 뒤 설정을 고치면 *(그 뒤에 설정을 고침)* 이 붙습니다.
버튼은 연결 테스트를 지원하는 유형에만 있고, 상세 화면에서는 *데이터 소스 관리* 와 *연결 설정 조회* 권한이 모두 있어야 보입니다.

* *서버가 직접 접속하는 유형* — PostgreSQL · MySQL · Greenplum · StarRocks. 시간 제한은 8초이며, 실패 사유는 아래 표처럼 분류해 안내합니다.
  드라이버의 원문 오류(내부 주소 · 경로 등)는 화면에 보여 주지 않고 서버 로그에만 남깁니다.
* *Metadata Sync 에 맡기는 유형* — Oracle · Microsoft SQL Server · Apache Hive · Trino · Apache Kudu · Iceberg REST Catalog.
  xref:extensions/metadata-sync.adoc[Metadata Sync] 서비스가 시험 접속하고, 실패 사유도 그 서비스가 돌려준 문구로 표시됩니다.
  서비스에 닿지 않으면 *연결 실패: 수집 서비스(metadata-sync)에 연결할 수 없습니다.* 가 뜹니다.
* Apache Impala 처럼 지원하지 않는 유형은 버튼이 없습니다(<<_지원_유형,유형별 지원 범위>> 참고).

=== ER 다이어그램

RDBMS 유형 데이터 소스는 상세에 *ER 다이어그램* 탭이 있습니다. 탭을 열 때 불러옵니다. 동기화된 데이터셋의 PK · FK 와 DDL 제약, 리니지로 추정한 관계를
테이블 간 선으로 그리며, 엣지에는 FK 컬럼과 카디널리티(예: `customer_id N:1`)가 붙습니다. *Mermaid 복사* 로 다이어그램 정의를 복사할 수 있습니다.

[[_메타데이터_동기화]]
== 메타데이터 동기화 [[help-sync-runs]]

동기화는 원본의 테이블 · 컬럼 정보를 읽어 카탈로그의 데이터셋을 만들거나 갱신합니다. 테이블과 컬럼을 일일이 손으로 옮길 필요가 없습니다.
화면에서는 이 작업을 *수집* 이라고 부릅니다. 데이터 소스 상세의 *수집* 영역에서 범위를 정해 실행 · 예약하고,
관리자는 *관리 → 메타데이터 수집* 화면에서 모든 데이터 소스의 수집을 한곳에서 봅니다.

.메타데이터 동기화와 데이터셋 갱신
image::diagrams/catalog-platforms-02.png[메타데이터 동기화와 데이터셋 갱신,role="diagram"]

=== 수집 영역

트리에서 데이터 소스를 고르고 *수집* 탭을 엽니다.

|===
| 요소 | 설명

  아직 정하지 않았으면 *범위를 먼저 선택하세요* 가 표시됩니다.
| *범위 선택…*

| 저장된 범위는 그대로 두고 다른 범위로 한 번만 수집합니다(<<_이번_한_번만_수집,이번 한 번만 수집>>).
| *예약*
| 예약 수집 스위치와 주기입니다(<<_예약_수집,예약 수집>>).
| 진행 상자
| 수집 중일 때만 보입니다. 상태 · 단계 · 진행 막대와 *상세* · *중지* 버튼이 있습니다(<<_진행_취소_다시_실행,진행 · 중지 · 다시 실행>>).
| *최근 실행*
| 이 데이터 소스의 최근 실행 5건을 표(실행 번호 · 상태 · 시각 · 생성 · 갱신 · 제거 · 실패 · 요청자)로 보여 줍니다. 오른쪽 위의 *이 데이터 소스의 데이터셋 보기* 는 이 데이터 소스로 거른 데이터셋 목록을,
*전체 수집 이력* 은 이 데이터 소스로 거른 <<_메타데이터_수집_화면,메타데이터 수집 화면>> 을 엽니다(메타데이터 수집 화면을 볼 수 있는 사람에게만 보입니다).
| *새로고침*
| 수집 설정과 최근 실행을 다시 읽습니다. 수집 중에는 3초마다 저절로 갱신됩니다.
|===

* 화면 수집을 지원하지 않는 유형(Impala 등)은 영역에 *이 유형은 아직 화면에서 수집을 지원하지 않습니다.* 만 표시됩니다(<<_지원_유형,유형별 지원 범위>> 참고).
* *메타데이터 동기화* 권한이 없는 사용자도 수집 범위 · 예약 상태 · 최근 실행은 볼 수 있습니다. 다만 *범위 선택…* · *지금 수집* · *이번 한 번만…* ·
  *중지* · *다시 실행* 버튼이 보이지 않고 예약 스위치와 주기는 비활성입니다.

[[_실행_방법]]
=== 실행 방법

처음 수집하는 순서는 다음과 같습니다.

. 데이터 소스를 고르고 *수집* 영역의 *범위 선택…* 을 누릅니다.
. 수집할 데이터베이스 · 스키마(유형에 따라 네임스페이스 · 카탈로그)를 체크합니다(<<_수집_범위_선택,수집 범위 선택>>).
. *저장하고 지금 수집* 을 누릅니다. 범위가 저장되고 수집이 시작됩니다. 범위만 저장하려면 *저장* 을 누르고, 나중에 *지금 수집* 을 누릅니다.
. 진행 상자에서 진행을 지켜봅니다. 수집 영역을 연 채로 두면 끝났을 때 결과 알림이 뜹니다.
+
[cols="1,2",options="header"]
|===
| 알림 | 의미

| 수집 완료 — 생성 N · 갱신 N · 제거 N | 모두 성공했습니다.
| 수집 일부 실패 — 생성 N · 갱신 N · 제거 N · 실패 N | 일부 대상만 실패했습니다. *실패 항목 N* 을 눌러 사유를 봅니다.
| 수집 실패 — <사유> | 수집하지 못했습니다. 사유를 확인하고 *다시 실행* 합니다.
|===
. 결과는 *데이터 카탈로그 → 데이터셋* 에서 데이터 소스 필터로 확인합니다.

새 테이블은 데이터셋으로 등록되고, 이미 있으면 갱신됩니다. 원본에서 사라진 테이블의 데이터셋은 지우지 않고 *비활성* 으로 표시됩니다.

[[_수집_범위_선택]]
=== 수집 범위 선택

*범위 선택…* 을 누르면 *수집 범위 선택 — <데이터 소스 이름>* 대화상자가 열립니다. 대화상자는 원본에 접속해 목록을 보여 주므로
*메타데이터 동기화* 권한이 있어야 열 수 있습니다.

// TODO: screenshot - 수집 범위 선택 대화상자(선택한 데이터베이스만 · 트리 · 제외 패턴 · 저장하고 지금 수집)

범위를 고르는 단위는 유형마다 다릅니다. 화면 문구의 *<단위>* 자리에 이 이름이 들어갑니다.

[cols="1,3",options="header"]
|===
| 단위 | 유형

| 데이터베이스 | MySQL · Microsoft SQL Server · Apache Hive · StarRocks
| 스키마 | PostgreSQL · Greenplum · Oracle
| 네임스페이스 | Iceberg REST Catalog
| 카탈로그 | Trino
| 대상 | Apache Kudu — 단위를 고를 수 없고 전체 수집만 됩니다(*이 유형은 아직 전체 수집만 지원합니다.*).
|===

. 위쪽에서 방식을 고릅니다.
** *선택한 <단위>만* — 아래 목록에서 고른 것만 수집합니다(기본).
** *전체 (새로 생기는 <단위> 포함)* — 원본 전체를 수집합니다. 나중에 생기는 데이터베이스 · 스키마도 다음 수집부터 들어갑니다.
. *선택한 <단위>만* 이면 목록에서 고릅니다.
** 데이터베이스 · 스키마를 *체크* 하면 그 안의 테이블 전체를 수집합니다. 나중에 생기는 테이블도 포함됩니다.
** 왼쪽 화살표로 *펼쳐서* 테이블을 체크하면 그 테이블만 수집합니다. 상위 항목에 *일부 N* 배지가 붙습니다.
** 오른쪽에는 이미 수집된 데이터셋 수(*수집됨 N*)와 원본에서 사라져 제거된 수(*제거됨 N*)가 보입니다. 시스템 데이터베이스에는 *시스템* 배지가 붙습니다.
** 이름 검색칸에 입력하고 Enter(또는 돋보기)를 누르면 목록을 좁힙니다. 항목이 많으면 *더 보기 (N / 전체)* 로 이어서 불러옵니다.
** Iceberg REST 는 네임스페이스를 펼쳐 하위 네임스페이스를 따로 고릅니다. 상위를 골라도 하위 네임스페이스는 포함되지 않습니다.
** 검색으로 가려졌거나 원본에서 사라져 목록에 없는 선택은 *목록에 안 보이는 선택:* · *일부 테이블:* 배지로 아래에 모여 표시되며, × 로 뺄 수 있습니다.
. 필요하면 *제외 패턴* 을 적습니다. 하나씩 적고 Enter 를 누르면 배지가 되며(× 로 뺌), `+*+` · `+?+` 를 쓸 수 있습니다(예: `+tmp_*+` · `+*_bak+`).
  특정 데이터베이스 · 스키마에서만 빼려면 `+sales:tmp_*+` 처럼 앞에 이름과 콜론을 붙입니다. 패턴에 걸린 테이블에는 *제외* 배지가 붙습니다.
. 아래쪽 요약(예: *선택: 데이터베이스 2개 전체 + 테이블 3개 · 제외 패턴 1개*)을 확인하고 *저장* 또는 *저장하고 지금 수집* 을 누릅니다.
  하나도 고르지 않으면 두 버튼이 비활성입니다. 200개 이상 고르면 수집이 오래 걸릴 수 있다는 안내가 뜹니다.

원본에 접속하지 못하면 목록 자리에 오류가 표시됩니다. 이때 *이름을 직접 입력하기* 를 눌러 수집할 이름을 한 줄에 하나씩
(하위 네임스페이스는 `sales.emea` 처럼 점으로) 적을 수 있고, *원본에서 고르기* 로 목록 화면으로 돌아갑니다.

==== 범위 밖에 남는 데이터셋

범위를 좁혀서 이미 수집된 데이터셋이 새 범위 밖에 남게 되면, 저장 전에
*새 범위 밖에 이미 수집된 데이터셋 N개가 남습니다 (…). 어떻게 할까요?* 확인이 나옵니다.

* *그대로 둠 (기본 — 더 이상 갱신되지 않음)* — 데이터셋은 남지만 이후 수집에서 갱신되지 않습니다.
* *제거로 표시* — 범위 밖 데이터셋을 *비활성(removed)* 으로 바꿉니다. 알림에 *… 범위 밖 데이터셋 N개를 제거로 표시했습니다.* 가 붙습니다.

*뒤로* 를 누르면 범위 선택으로 돌아가고, *저장* (또는 *저장하고 지금 수집*)으로 확정합니다. 저장하면 *수집 범위를 저장했습니다.* 알림이 뜹니다.

[[_이번_한_번만_수집]]
=== 이번 한 번만 수집

*이번 한 번만…* 은 같은 모양의 *이번 한 번만 수집 — <이름>* 대화상자를 엽니다. 범위를 고르고 *이 범위로 한 번 수집* 을 누르면
그 범위로 한 번만 수집하고(*이번 한 번만 수집을 시작했습니다.*), 저장된 범위와 예약은 바뀌지 않습니다.
특정 스키마만 급히 다시 가져올 때 씁니다. 저장된 범위가 없어도 쓸 수 있으며, 범위 밖 데이터셋 확인은 나오지 않습니다.

[[_예약_수집]]
=== 예약 수집

*예약* 스위치를 켜면 저장된 범위로 정해진 주기마다 자동으로 수집합니다. 범위를 저장해야 켤 수 있습니다.

. 주기를 고릅니다. *15분* · *30분* · *1시간* · *3시간* · *6시간* · *12시간* · *1일* · *7일* 마다 중에서 고르며, 기본은 *1일마다* 입니다.
. *예약* 스위치를 켭니다. *예약 수집: 1일마다* 처럼 알림이 뜹니다. 켜 둔 상태에서 주기를 바꾸면 바로 저장됩니다.
. 끄면 *예약 수집을 껐습니다.* 가 뜨고 수동으로만 수집합니다.

스위치 옆 문구는 상태에 따라 다음과 같이 바뀝니다.

[cols="2,3",options="header"]
|===
| 문구 | 의미

| 다음 예정 <시각> (마지막 실행 기준, 수동 실행 포함) | 예약이 켜져 있습니다.
| 꺼짐 — 수동으로만 수집 | 예약이 꺼져 있습니다.
| 범위를 먼저 선택하세요 | 저장된 범위가 없어 켤 수 없습니다.
|===

* 다음 예정 시각은 *마지막 실행 접수 시각 + 주기* 입니다. 수동으로 *지금 수집* 하면 예약도 그만큼 뒤로 밀립니다.
* 서버가 1분마다 예정 시각이 된 데이터 소스를 확인해 수집을 시작합니다. 그때 이미 수집 중이면 다음 확인으로 미룹니다.
* 예약으로 시작한 실행은 최근 실행에 *예약* 배지가 붙고, 메타데이터 수집 화면의 *시작* 열에 *예약* 으로 표시됩니다.
* 수집 실패나 오랫동안 성공한 수집이 없는 것을 알림으로 받으려면 xref:governance/alerts.adoc[알림] 에서 *수집 실패* · *수집 지연* 조건의 규칙을 만듭니다.

[[_진행_취소_다시_실행]]
=== 진행 · 중지 · 다시 실행

수집이 진행 중이면 수집 영역에 진행 상자가 나타납니다.

* 상태 배지(*대기* · *수집 중*)와 단계(*접속 중* · *대상 조회* · *테이블 수집* · *제거 반영*)가 표시됩니다.
* 진행 막대 아래에 처리한 수 / 전체 수(%), *남은 시간 약 …*, *생성 · 갱신 · 실패* 수, *현재:* 처리 중인 대상이 보입니다.
  남은 시간은 테이블을 10개 이상 처리한 뒤부터 처리 속도로 추정합니다.
* 2분 넘게 진행 보고가 없으면 *응답 없음 N분* 배지가 붙고, 5분이 지나면 실패로 처리됩니다
  (*수집 서비스 응답 없음으로 중단되었습니다(5분 넘게 진행 보고 없음). 다시 실행하세요.*).
* *중지* 를 누르면 *중지를 요청했습니다.* 가 뜨고 *중지 요청됨* 으로 바뀝니다. 내장 수집(MySQL · PostgreSQL)은 지금 처리 중인
  데이터베이스 · 스키마를 마친 뒤 멈춥니다. 끝난 실행은 *중지됨* 이 됩니다.
* *상세* 를 누르면 <<_실행_상세,실행 상세>> 가 열립니다.

*최근 실행* 의 각 줄에는 실행 번호(누르면 실행 상세), 상태 배지, 시각, *생성 · 갱신 · 제거 · 실패* 수, 실행한 사용자(*by …*)가 보이고,
실패한 실행은 오류 문구가 함께 표시됩니다. 실패 · 경고 항목이 있으면 *실패 항목 N* 버튼이 생깁니다.
가장 최근 실행이 *실패* · *일부 실패* · *중지됨* 이면 그 줄에 *다시 실행* 이 나타나며, 그 실행과 같은 범위로 다시 수집합니다(*다시 실행했습니다.*).

[cols="1,3",options="header"]
|===
| 상태 | 의미

| 대기 | 접수되어 시작을 기다립니다.
| 수집 중 | 원본에서 메타데이터를 읽고 있습니다.
| 성공 | 모두 수집했습니다.
| 일부 실패 | 일부 대상만 실패했습니다. 성공한 대상은 반영되었습니다.
| 실패 | 수집하지 못했습니다.
| 중지됨 | 사용자가 중지했습니다.
|===

[[_실행_상세]]
=== 실행 상세

실행 번호나 *상세* · *실패 항목 N* 을 누르면 *수집 실행 #N — <데이터 소스 이름>* 대화상자가 열립니다. 제목 아래에는 유형과
실행 방식(*내장 수집* 또는 *metadata-sync*)이 표시되고, 진행 중이면 저절로 갱신됩니다.
그 아래 링크로 결과를 바로 확인합니다 — *이 데이터 소스의 데이터셋 보기*, *전체 수집 이력*(이 데이터 소스로 거른 메타데이터 수집 화면),
메타데이터 수집 화면에서 연 경우에는 *데이터 소스 열기* 도 있습니다.

// TODO: screenshot - 수집 실행 상세 대화상자(상태 · 범위 · 시작 · 소요 · 처리 · 실패·경고 항목 · 이전 실행)

[cols="1,3"]
|===
| 항목 | 내용

| 상태 | 상태 배지와 단계, 진행 중이면 현재 대상
| 범위 | 이 실행에 쓴 수집 범위
| 시작 | *수동* · *예약*, 실행한 사용자, 접수 시각
| 소요 | 걸린 시간, 초당 처리 수, 남은 시간, 종료 시각
| 처리 | 처리 수 / 전체, 생성 · 갱신 · 제거 · 실패 수
| 중지 요청 · 오류 | 중지를 요청한 사용자, 실패 사유(있을 때만)

*실패·경고 항목 (N)* 표에서는 수준(*전체* · *오류* · *경고*)으로 거르고, *대상·사유 검색* 으로 찾고, *CSV 내려받기* 로 내려받을 수 있습니다.
항목은 실행마다 1,000건까지만 저장하며, 넘으면 *1,000건까지만 저장합니다 — 외 N건* 이 표시됩니다.
아래 *이전 실행* 표에는 같은 데이터 소스의 이전 실행 결과가 나옵니다.

[[_메타데이터_수집_화면]]
=== 메타데이터 수집 화면

*관리 → 메타데이터 수집* (`/dashboard/sync-runs`)은 모든 데이터 소스의 수집 실행을 한곳에서 보는 화면입니다. 관리자와
기능 권한 *메타데이터 동기화* (`datasources.sync`)를 허용받은 역할이 봅니다.
xref:catalog/dashboard.adoc[대시보드] 의 *수집 실패 (24시간)* 카드를 눌러도 실패 · 일부 실패, 최근 24시간 조건으로 이 화면이 열립니다.

// TODO: screenshot - 메타데이터 수집 화면(metadata-sync 상태 · 필터 · 실행 표)

맨 위에는 Metadata Sync 서비스 상태가 표시됩니다. 정상이면 *metadata-sync 정상 · 워커 N/N 사용 · 대기 N · v버전*,
닿지 않으면 *metadata-sync 연결 안 됨 — <사유>* 입니다. 오른쪽의 *자동 새로고침* 을 켜 두면 실행 중 · 대기 실행이 있을 때 5초마다 갱신되고,
새로고침 버튼으로 바로 다시 읽을 수도 있습니다.

필터는 세 가지입니다.

[cols="1,3",options="header"]
|===
| 필터 | 선택지

| 상태 | *실행 중·대기* · *실패·일부 실패* · *성공* · *중지됨* · *전체 상태* (기본)
| 데이터 소스 | *전체 데이터 소스* 또는 데이터 소스 하나
| 기간 | *최근 24시간* (기본) · *최근 7일* · *최근 30일* · *전체 기간*
|===

기본 조건이 *전체 상태 + 최근 24시간* 이라, 지켜보던 실행이 끝나도 목록에서 사라지지 않고 결과 상태로 바뀝니다.
고른 조건은 주소(`?status=` · `?datasource=` · `?period=`)에 남습니다.

[cols="1,3",options="header"]
|===
| 열 | 내용

| 데이터 소스 | 데이터 소스 이름(누르면 데이터 소스 화면에서 그 데이터 소스를 엽니다), 아래에 실행 번호와 유형
| 시작 | 수동이면 실행한 사용자, 예약이면 *예약*. 아래에 시작 시각
| 진행 | 대기 중이면 *대기 (앞에 N개)*, 수집 중이면 진행 막대와 단계(보고가 2분 넘게 없으면 *응답 없음 N분 ⚠*), 끝났으면 상태 배지와 *실패 N건*
| 경과 · 남은 시간 | 걸린 시간과, 진행 중이면 남은 시간 추정
| 생성/갱신/실패 | 처리 결과 수
| (버튼) | 진행 중이면 *중지*, 성공 외로 끝났으면(*실패* · *일부 실패* · *중지됨*) *다시 실행*
|===

행을 누르면 <<_실행_상세,실행 상세>> 가 열립니다. 한 번에 50건씩 보이며 더 있으면 *더 보기* 를 누릅니다.
조건에 맞는 실행이 없으면 *조건에 맞는 수집 실행이 없습니다.* 가 표시됩니다.

끝난 실행 기록은 90일이 지나면 자동으로 지워집니다(서버 설정 `metadata_sync.run_retention_days`).

[TIP]
.고급 사용자 — Metadata Sync 서비스
====
MySQL · PostgreSQL 이외 유형의 수집과 연결 테스트는 카탈로그 서버가 xref:extensions/metadata-sync.adoc[Metadata Sync] 서비스에 맡깁니다.
서버 설정의 `metadata_sync.base_url` (기본 `http://localhost:4610`)과 `metadata_sync.api_token` 으로 서비스에 접속하며,
수집 진행은 서비스가 카탈로그 서버로 보고합니다.

* 서비스에 닿지 않으면 수집이 바로 *실패* 로 끝나고 *수집 서비스(metadata-sync)에 연결할 수 없습니다.* 가 표시됩니다.
* 토큰이 맞지 않으면 *수집 서비스 인증에 실패했습니다(metadata_sync.api_token 설정 확인).* 가 표시됩니다.
* 메타데이터 수집 화면 맨 위의 상태 표시로 서비스가 살아 있는지 확인할 수 있습니다.
====

[TIP]
.고급 사용자 — API 로 수집하기
====
화면의 동작은 다음 API 로도 할 수 있습니다(기본 경로 `/api/v1/catalog`, 범위 저장 · 실행 · 취소 · 다시 실행은 *메타데이터 동기화* 권한 필요).

[cols="2,3",options="header"]
|===
| 엔드포인트 | 설명

| `GET · PUT /datasources/{id}/sync-scope` | 수집 설정(범위 · 예약) 조회 · 범위 저장
| `POST /datasources/{id}/sync-scope/preview` | 새 범위 밖에 남는 데이터셋 수 확인
| `PUT /datasources/{id}/sync-schedule` | 예약 켜기 · 끄기 · 주기(분, 15 ~ 10080)
| `POST /datasources/{id}/sync-runs` | 수집 시작(본문 없으면 저장된 범위, `{"scope": …}` 면 이번 한 번만)
| `GET /datasources/{id}/sync-runs` · `GET /sync-runs` | 실행 목록(`status` 에 `ACTIVE` · `PROBLEM` 사용 가능)
| `GET /sync-runs/{run_id}` · `GET /sync-runs/{run_id}/items` | 실행 상세 · 실패 · 경고 항목
| `POST /sync-runs/{run_id}/cancel` · `POST /sync-runs/{run_id}/retry` | 취소 · 같은 범위로 다시 실행
|===

예전부터 있던 *동기 실행 API* 도 남아 있습니다. MySQL · PostgreSQL 만 지원하고, 요청 안에서 끝까지 수집한 뒤 결과를 돌려줍니다.
저장된 수집 범위를 쓰지 않고, 실행 기록을 남기지 않아 수집 영역 · 메타데이터 수집 화면에 나타나지 않습니다. 새로 쓰는 경우에는 위의 `sync-runs` API 를 쓰세요.

[source,bash]
----
# MySQL: database 를 생략하면 연결 설정의 Database 를 스캔 (그것도 비어 있으면 전체 사용자 DB)
# PostgreSQL: database 값은 스키마 이름으로 해석, 생략하면 접속 DB 의 전체 스키마
curl -X POST "<카탈로그 주소>/api/v1/catalog/datasources/<데이터 소스 번호>/sync?database=shop" \
  -H "Authorization: Bearer <토큰>"
----

성공하면 `databases_scanned` · `tables_total` · `tables_created` · `tables_updated` · `tables_removed` · `samples_uploaded` 를 돌려줍니다.
====

[[_수집_대상과_후처리]]
[TIP]
.고급 사용자 — 수집 대상과 후처리 (내장 수집)
====
MySQL · PostgreSQL 의 내장 수집 기준입니다. Metadata Sync 로 수집하는 유형의 수집 항목은
xref:extensions/metadata-sync-sources.adoc[Metadata Sync — 데이터 소스별 설정] 을 보세요.

수집 대상::
* 테이블 · 뷰와 각 테이블의 컬럼(이름 · 타입 · NULL 허용 · 기본값 · 설명)
* 키 정보(PK · Unique · FK)와 DDL 원문 — 뷰는 *CREATE VIEW* 정의로 저장됩니다.
* 베이스 테이블의 샘플 데이터(최대 100행, Parquet) — 데이터셋 *샘플* 탭에 보입니다. 뷰와 빈 테이블은 제외됩니다.

후처리::
* 새 테이블은 데이터셋으로 등록하고, 이미 있으면 갱신합니다. 데이터셋의 환경은 데이터 소스 환경을 따릅니다.
* 컬럼 변경은 스키마 변경 이력에 남습니다(데이터셋 상세 *더보기 → 변경 이력*). xref:governance/alerts.adoc[알림] 규칙이 있으면 변경분을 평가합니다.
* 사용자가 입력한 컬럼 설명 · PII 유형은 유지됩니다. 단, 원본에 컬럼 코멘트가 있으면 설명은 원본 값으로 갱신됩니다.
* 원본에서 사라진 테이블의 데이터셋은 지우지 않고 *비활성(removed)* 으로 표시해 목록 · 개수에서 뺍니다. 다시 나타나면 같은 데이터셋이 복원됩니다.
  스캔 결과가 0개면 "전부 삭제" 로 보지 않고 아무것도 비활성화하지 않습니다.
* 데이터셋을 새로 만들거나 갱신했으면 쿼리 리니지 중 아직 데이터셋과 이어지지 않은 항목을 다시 연결합니다.
* xref:ai/metadata-generation.adoc[AI 메타데이터 생성] 의 동기화 후 자동 생성이 켜져 있으면 비어 있는 설명을 자동으로 채웁니다.
====

[[_동시_실행과_시간_제한]]
[TIP]
.고급 사용자 — 동시 실행과 시간 제한
====
* 같은 데이터 소스에 수집이 대기 · 진행 중이면 새 수집은 거절됩니다(409 *이 데이터 소스는 이미 수집 중입니다(실행 #N).*).
  화면에서는 이때 *지금 수집* · *이번 한 번만…* 이 비활성입니다. 다른 데이터 소스의 수집은 영향을 받지 않습니다.
  예전 동기 실행 API 끼리는 *이 데이터 소스는 이미 동기화 중입니다. 완료 후 다시 시도하세요.* 로 거절됩니다.
* 동기화나 수집(지금 수집 · 예약 수집)이 진행 중인 데이터 소스는 삭제할 수 없습니다(409 *수집이 진행 중인 데이터 소스는 삭제할 수 없습니다(실행 #N).*). 삭제하면 수집 범위 · 예약 설정과 수집 이력도 함께 지워지며, 삭제 대화상자가 그 건수를 보여 줍니다.
* 내장 수집은 원본 접속 10초, 메타데이터 조회 쿼리 120초 제한이 있습니다. 실패하면 실행이 *실패* (여러 데이터베이스 · 스키마 중 일부만 실패하면 *일부 실패*)로 끝나고,
  *원격 DB 메타데이터 조회 실패: 연결 시간 초과 (10초)* 처럼 연결 테스트와 같은 분류로 사유를 알려 줍니다.
* 연결 설정에서 SSL 을 켜 두었다면 수집도 암호화 접속을 합니다.
====

== 데이터 소스 삭제

데이터 소스를 우클릭해 *삭제* 를 고르면 *데이터 소스 삭제* 대화상자가 열립니다. 대화상자는 먼저 삭제 영향을 조회하며,
조회 중(*삭제 영향 확인 중…*)에는 *삭제* 를 누를 수 없습니다.

image::catalog-platforms/delete-impact.png[데이터 소스 삭제 — 데이터셋 23개 함께 삭제, 확인 문자열 입력, 900]

[cols="1,3"]
|===
| 안내 문구 | 의미

| 이 데이터 소스의 데이터셋 N개 (와 이를 참조하는 타 데이터 소스 리니지 N개) 가 함께 삭제됩니다.
| 활성 데이터셋과 다른 데이터 소스로 이어진 리니지가 함께 지워집니다.
| 원본에서 사라진(비활성) 데이터셋 N개도 함께 정리됩니다.
| 비활성 데이터셋도 함께 지워집니다.
| 이 데이터 소스·데이터셋 대상 알림 규칙 N개가 삭제됩니다.
| 대상이 사라지는 알림 규칙이 지워집니다.
| 데이터셋의 변경 요청 N건이 함께 삭제됩니다.
| 관련 변경 요청이 지워집니다.
| 연결된 모델 · MCP 배포 N개는 데이터 소스 연결만 해제됩니다.
| 모델 · MCP 배포 자체는 남습니다.
|===

삭제를 확정하려면 입력란에 `DELETE <데이터 소스 이름>` 을 정확히 입력해야 *삭제* 가 활성화됩니다. 삭제하면
*데이터 소스 "<이름>" 을 삭제했습니다.* 알림이 뜨고, 데이터셋의 댓글 · 샘플 파일 등 딸린 정보도 함께 정리됩니다.

WARNING: 데이터 소스 삭제는 되돌릴 수 없습니다. 품질 규칙 · 결과, 스키마 이력 등 데이터셋에 쌓인 정보도 모두 사라집니다.

TIP: 페더레이션 노출 허용 목록에 이 데이터 소스 이름이 남아 있으면 대화상자에 경고가 함께 표시됩니다. 같은 이름으로 다시 만들면
자동으로 노출되니 서버 설정에서도 지우세요.

== 자주 묻는 질문

[qanda]
*목록을 불러오지 못했습니다.* 가 나옵니다.::
  일시적인 오류입니다. 함께 나오는 *다시 시도* 버튼을 누르세요.

조직이 지워지지 않습니다.::
  하위 조직이나 시스템이 남아 있는 조직은 지울 수 없습니다. 하위 항목을 먼저 옮기거나 지우세요.

*연결 테스트* 버튼이 없습니다.::
  연결 테스트를 지원하지 않는 유형(Apache Impala 등)입니다(<<_지원_유형,유형별 지원 범위>> 참고). 상세 화면에서는 *데이터 소스 관리* 와
  *연결 설정 조회* 권한 중 하나라도 없거나 연결 설정을 불러오지 못했을 때도 보이지 않습니다.

연결 테스트가 *수집 서비스(metadata-sync)에 연결할 수 없습니다.* 로 실패합니다.::
  Oracle · MS-SQL · Hive · Trino · Kudu · Iceberg REST 는 Metadata Sync 서비스가 시험 접속합니다. 서비스가 떠 있는지 관리자에게 확인을 요청하세요.
  관리자는 *관리 → 메타데이터 수집* 맨 위의 상태 표시로 확인할 수 있습니다.

비밀번호 입력란이 비어 있습니다.::
  저장된 비밀값은 화면에 다시 내보내지 않습니다. *저장됨 — 변경할 때만 입력* 이 보이면 비워 둔 채 저장해도 기존 값이 유지됩니다.

입력란이 모두 비활성이고 *저장* 버튼이 없습니다.::
  *데이터 소스 관리* 권한이 없는 조회 전용 모드입니다. 관리자에게 권한을 요청하세요.

*지금 수집* 이 눌리지 않습니다.::
  수집 범위를 아직 저장하지 않았거나(*범위를 먼저 선택하세요*), 이미 수집이 대기 · 진행 중입니다. *범위 선택…* 으로 범위를 저장하거나 진행 중인 수집이 끝나기를 기다리세요.

수집 영역에 *범위 선택…* · *지금 수집* 버튼이 없습니다.::
  *메타데이터 동기화* (`datasources.sync`) 권한이 없습니다. 수집 현황은 볼 수 있지만 실행 · 예약은 할 수 없습니다. 관리자에게 권한을 요청하세요.
  수집 영역에 *이 유형은 아직 화면에서 수집을 지원하지 않습니다.* 만 보이면 화면 수집을 지원하지 않는 유형입니다.

Trino 수집이 *쿼리 엔진은 카탈로그에 {apos}수집{apos}으로 연결해야 …* 로 거절됩니다.::
  Trino 는 *카탈로그 연결* 영역에서 카탈로그를 *수집* 방식으로 연결해야 수집할 수 있습니다(<<_데이터_소스_추가,데이터 소스 추가>> 의 쿼리 엔진 상자 참고).

수집 요청이 409 로 거절됩니다.::
  같은 데이터 소스의 수집이 이미 대기 · 진행 중입니다(*이 데이터 소스는 이미 수집 중입니다(실행 #N).*). 끝난 뒤 다시 시도하세요.

예약을 켰는데 수집이 돌지 않습니다.::
  스위치 옆의 *다음 예정* 시각을 확인하세요. 예정 시각은 마지막 실행 접수 시각 + 주기라서, 그 사이 수동으로 수집했으면 그만큼 뒤로 밀립니다.

사이드바에 *메타데이터 수집* 메뉴가 없습니다.::
  관리자와 기능 권한 *메타데이터 동기화* 를 허용받은 역할에게만 보입니다. 그 밖의 사용자는 데이터 소스 상세의 수집 영역에서 데이터 소스별 수집 현황을 봅니다.
