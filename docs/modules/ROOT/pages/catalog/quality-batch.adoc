= 품질 배치 — 원본 전체 데이터 검증
:toc: macro
:toclevels: 2

품질 배치는 원본 DB 의 *전체 데이터* 를 읽어 품질 규칙을 평가하고, 그 결과를 카탈로그로 반입하는 명령줄 스크립트입니다.
품질 탭의 *검증 실행* 이 판정하지 못하는 규칙(허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python)까지 모두 판정합니다.
품질 탭 사용법은 xref:catalog/quality.adoc[데이터 품질] 을 먼저 읽어 두세요.

toc::[]

== 시작하기 전에

=== 이런 일을 할 수 있습니다

* **전체 데이터 검증** — 스냅숏 통계가 아니라 원본 전체 데이터로 규칙을 판정합니다.
* **화면이 못 하는 규칙 평가** — 허용 값 · 정규식 · 커스텀 SQL · 커스텀 Python 규칙을 평가하고 위반 샘플을 남깁니다.
* **더 많은 원본 지원** — 화면 프로파일이 지원하지 않는 유형(Oracle · Trino · Hive 등)의 프로파일과 행 수를 반입합니다.
* **주기 실행** — cron · Airflow · Kestra 에 등록해 야간에 자동으로 돌립니다.

=== 개요

품질 배치는 저장소의 `quality/` 디렉터리에 있는 명령줄 스크립트입니다. 카탈로그에서 데이터셋과 활성 규칙을 가져와
원본 DB 를 *전체* 읽은 뒤, 프로파일 · 행 수(row_count) · 규칙 결과를 다시 카탈로그로 반입합니다. 반입한 결과는 품질 탭에
서버 검증 결과와 똑같이 표시됩니다.

[cols="1,1,2",options="header"]
|===
| 스크립트 | 엔진 | 용도

| `python-quality.py` | pandas | 테이블이 메모리에 올라가는 크기(수백만 행 이하)
| `dataset-quality.py` | PySpark | 대용량 — Spark 클러스터로 분산 처리
|===

두 스크립트는 같은 인자 · 흐름 · 판정 기준을 공유합니다. 판정 기준은 서버 검증과 같아서, 같은 데이터라면 두 쪽 점수가 어긋나지 않습니다.

=== 누가 무엇을 할 수 있나요

[cols="1,3"]
|===
| 작업 | 필요한 권한

| 결과 반입(프로파일 · row_count · 규칙 결과)
| 관리자 계정
| 카탈로그에 저장된 원본 연결 설정 조회
| *연결 설정 조회* (`datasources.connection`)
| 반입 없이 결과만 확인(`--dry-run`)
| 일반 계정도 가능 — 원본 접속을 `--db-host` · `--db-user` 로 직접 지정
| 서버의 원천 데이터 시간대 변경
| 관리자만 (<<_원천_데이터_시간대,원천 데이터 시간대>> 참고)
|===

[[_서버_검증과의_차이]]
== 서버 검증과의 차이

[cols="1,2,2",options="header"]
|===
| | 품질 탭 *검증 실행* (서버) | 품질 배치

| 평가 기준 | 최신 프로파일 스냅숏 통계 | *원본 전체 데이터*
| 허용 값 · 정규식 | 판정하지 않음 — 배치 결과 이어받기, 없으면 미평가 | 위반 행 수 실제 계산 + 위반 샘플
| 커스텀 SQL · 커스텀 Python | 실행하지 않음(보안) — 위와 같음 | 원본 DB 에서 실행
| FRESHNESS(컬럼 미지정) | 마지막 프로파일 이후 경과 시간 | 0시간(통과)
| 지원 원본 | MySQL · MariaDB · PostgreSQL | MySQL · MariaDB · StarRocks · PostgreSQL · Greenplum · Redshift · Oracle · Tibero · MSSQL · Trino · Hive · Impala · Snowflake
| 행 수 갱신 | 안 함 | 데이터셋 row_count 갱신
|===

배치를 돌리고 나면 서버가 평가하지 못하던 규칙까지 모두 판정되어 점수에 들어갑니다.

배치가 반입한 프로파일은 pandas · Spark 의 타입 이름(`INT64`, `STR`, `OBJECT` 등)으로 표시됩니다.

[[_실행해_보기]]
== 실행해 보기

[source,bash]
----
# 설치 — pandas 버전 (드라이버는 쓰는 것만 있어도 동작)
python3 -m venv .venv-quality && . .venv-quality/bin/activate
pip install -r quality/requirements.txt

# 비밀번호는 명령행이 아니라 환경변수(또는 파일)로 넘깁니다
export ARGUS_PASSWORD='<관리자 비밀번호>'
export ARGUS_SOURCE_DB_PASSWORD='<원본 DB 비밀번호>'

# 데이터셋 하나
python quality/python-quality.py --urn <데이터셋 URN> \
    --api-url <카탈로그 주소> --username <관리자 계정>

# 데이터 소스에 속한 데이터셋 전체
python quality/python-quality.py --datasource-id <데이터 소스 ID> \
    --api-url <카탈로그 주소> --username <관리자 계정>

# 반입 없이 결과만 확인
python quality/python-quality.py --datasource-id <데이터 소스 ID> \
    --api-url <카탈로그 주소> --username <관리자 계정> --dry-run
----

`--datasource-id` 에는 xref:catalog/platforms.adoc[데이터 소스] 상세의 *데이터 소스 ID* (예: `sakila-mysql`)를 씁니다.
`--api-url` 의 기본값은 `http://localhost:4600` 이므로, 운영 환경에서는 대상 카탈로그 주소를 반드시 명시하세요.

배치는 다음 순서로 진행되고, 끝나면 데이터셋별 요약표를 출력합니다.

----
로그인 → 대상 데이터셋 조회 → 원본 접속 결정(데이터 소스당 1회)
→ (데이터셋마다) 활성 규칙 조회 → 원본 읽기 → 프로파일 계산 → 규칙 평가
→ 프로파일 반입 → row_count 갱신 → 결과 반입(점수 산출)
----

* 활성 규칙이 없는 데이터셋은 프로파일과 row_count 만 반입합니다.
* 반입 점수는 반입한 규칙만이 아니라 데이터셋의 *활성 규칙 전체* 기준입니다.
* 종료 코드: 모두 처리되면 `0`, 데이터셋 단위 실패가 하나라도 있으면 `1` 입니다. 로그인 · 대상 조회 · 원본 접속 결정처럼
  전체에 영향을 주는 오류는 즉시 종료(`1`)합니다. 스케줄러에서 실패를 감지할 수 있습니다.

[[_주요_인자]]
== 주요 인자

[cols="2,3",options="header"]
|===
| 인자 | 설명

| `--urn` / `--datasource-id` | 둘 중 하나 필수 — 단일 데이터셋 / 데이터 소스 일괄
| `--api-url` | 카탈로그 API 주소 (기본 `http://localhost:4600`)
| `--api-timeout` | API 요청 타임아웃(초, 기본 60)
| `--username` | 카탈로그 계정 (필수). 반입은 관리자만 할 수 있습니다.
| `--password-file` / env `ARGUS_PASSWORD` / `--password` | 카탈로그 계정 비밀번호 (셋 중 하나)
| `--dry-run` | 반입 없이 프로파일 · 검증 결과만 출력
| `--checks-dir` | `CUSTOM_PYTHON` 모듈 디렉터리 (기본: 스크립트 위치의 `custom_checks`)
| `--source-timezone` / env `ARGUS_SOURCE_TIMEZONE` | 원천 데이터 시간대 (기본 `Asia/Seoul`) — <<_원천_데이터_시간대,원천 데이터 시간대>> 참고
| `--db-password-file` / env `ARGUS_SOURCE_DB_PASSWORD` / `--db-password` | (pandas) 원본 DB 비밀번호
| `--db-host` · `--db-port` · `--db-name` · `--db-user` · `--db-ssl` | (pandas) 원본 접속 직접 지정
| `--jdbc-url` · `--jdbc-user` · `--jdbc-driver` · `--jdbc-password-file` | (PySpark) 원본 접속 직접 지정
| `--partition-column` / `--num-partitions` | (PySpark) 병렬 JDBC 읽기 (파티션 수 기본 8)
| `--fetchsize` | (PySpark) JDBC fetchsize (기본 10000)
| `--approx-distinct` | (PySpark) 고유 값 수를 근사 계산(UNIQUE 규칙 컬럼은 정확히 다시 셈)
|===

비밀번호 우선순위는 *명령행 값 > 파일 > 환경변수* 입니다. 명령행 인자는 프로세스 목록에 노출되므로 권장하지 않습니다.

[[_원본_접속과_권한]]
== 원본 접속과 권한

* 기본적으로 xref:catalog/platforms.adoc[데이터 소스] 에 등록한 연결 설정(호스트 · 포트 · DB · 계정 · SSL)을 읽어 접속합니다.
* *원본 DB 비밀번호는 배치에 직접 넘겨야 합니다.* 카탈로그는 저장된 비밀번호를 화면 · API 어디에도 내보내지 않습니다.
  비밀번호가 저장된 데이터 소스인데 배치에 주지 않으면 전달 방법(`ARGUS_SOURCE_DB_PASSWORD` 또는 `--db-password-file`)을 안내하고 종료합니다.
* 연결 설정 조회에는 *연결 설정 조회* (`datasources.connection`) 권한이, 결과 반입에는 관리자 계정이 필요합니다.
  일반 계정은 `--db-host` · `--db-user` 로 원본 접속을 직접 지정하고 `--dry-run` 으로 결과만 확인합니다.
* `--db-host` 를 주면 카탈로그 연결 설정을 조회하지 않습니다. `--db-host` 없이 `--db-port` · `--db-name` · `--db-user` 를 주면 그 항목만 덮어씁니다.
* 연결 설정에서 SSL 을 켜 두었다면 배치도 암호화 접속을 합니다(서버 인증서는 검증하지 않습니다).
* 테이블 · 컬럼 이름은 DB 방언에 맞게 인용하므로 대소문자 혼용 · 예약어 · 공백이 든 이름도 읽을 수 있습니다.

[[_커스텀_sql_커스텀_python]]
== 커스텀 SQL · 커스텀 Python

`CUSTOM_SQL` 은 결과의 *첫 행 첫 컬럼이 위반 건수* 여야 하며, 0 이면 통과입니다.

[source,sql]
----
SELECT count(*)
FROM rental r
LEFT JOIN inventory i ON i.inventory_id = r.inventory_id
WHERE i.inventory_id IS NULL          -- 고아 대여 건
----

* SELECT / WITH 로 시작하는 단일 조회문만 실행하고, 데이터를 바꾸는 키워드가 들어 있으면 실행을 거부합니다.
  원본 접속에는 조회 전용 계정을 쓰기를 권장합니다.

`CUSTOM_PYTHON` 은 `quality/custom_checks/` 의 함수를 기대값 JSON 으로 연결합니다.

[source,json]
----
{"module": "rental_checks", "fn": "rental_duration_outlier", "params": {"max_outlier_pct": 1.0}}
----

* 함수 규약은 `fn(df, params) -> (passed, actual, detail)` 입니다. 예시 모듈 `rental_checks.py` 와 품질 탭 *도움말* 을 참고하세요.
* 플러그인은 코드 리뷰를 거친 신뢰 코드라는 전제입니다. 모듈 · 함수 이름은 식별자만 허용하고 `--checks-dir` 안에서만 불러옵니다.

규칙 하나의 평가 오류(잘못된 정규식, SQL 실행 오류, 플러그인 오류, 없는 컬럼 등)는 배치를 멈추지 않고 그 규칙의
*실패 결과* (`actual_value: N/A`, 상세에 사유)로 기록됩니다.

[[_원천_데이터_시간대]]
== 원천 데이터 시간대

`FRESHNESS` 에서 시간대 정보가 없는 시각 값(MySQL `DATETIME`, PostgreSQL `timestamp` 등)을 어느 시간대로 해석할지 정하는 설정입니다.
서버와 배치가 같은 값을 써야 두 쪽의 경과 시간이 일치합니다. 시간대가 있는 값(PostgreSQL `timestamptz` 등)은 자기 시간대를 그대로 씁니다.

[cols="1,3"]
|===
| 대상 | 설정 방법

| 서버 검증
| 카탈로그 설정 `quality_source_timezone` (기본 `Asia/Seoul`). 화면 메뉴는 없고 API 로 조회 · 변경합니다.
  조회는 `GET /api/v1/quality/settings`, 변경은 관리자만 `PUT /api/v1/quality/settings` 로 하며 변경 내역은 감사 로그에 남습니다.
| 품질 배치
| `--source-timezone` 또는 환경변수 `ARGUS_SOURCE_TIMEZONE` (기본 `Asia/Seoul`). 배치 호스트의 시간대와는 무관합니다.
|===

[TIP]
.고급 사용자 — 서버 시간대를 API 로 바꾸기
====
[source,bash]
----
curl -X PUT <카탈로그 주소>/api/v1/quality/settings \
  -H "Authorization: Bearer <관리자 토큰>" -H "Content-Type: application/json" \
  -d '{"source_timezone": "UTC"}'
----
====

값은 IANA 이름(`Asia/Seoul`, `UTC`) 또는 `+09:00` 형식입니다. 알 수 없는 시간대는 서버가 거부(422)하고,
배치는 `--source-timezone: 알 수 없는 시간대: ... (예: Asia/Seoul, UTC, +09:00)` 를 출력하고 시작 전에 종료합니다.

[[_운영_시_알아_둘_점]]
== 운영 시 알아 둘 점

* 일괄 실행은 한 데이터셋이 실패해도(원본 읽기 오류, 규칙 조회 · 반입 API 오류 포함) 나머지를 계속 처리합니다.
* 반입 순서는 프로파일 → row_count → 결과입니다. 결과 반입이 실패해도 앞 단계는 이미 저장돼 있습니다.
* 긴 배치 중 로그인 토큰이 만료되면 한 번 자동으로 재발급하고 요청을 재시도합니다.
* pandas 버전은 테이블 전체를 메모리에 올립니다. 수백만 행을 넘으면 PySpark 버전을 쓰세요.
  PySpark 는 공통 모듈을 함께 배포해야 합니다 — `spark-submit --py-files quality/quality_common.py quality/dataset-quality.py ...`
* cron · Airflow · Kestra 등에 등록해 야간에 주기 실행하는 것을 권장합니다.

TIP: 인자 전체, 유형별 접속 키와 SSL 매핑, PySpark 파티션 분할 등 자세한 내용은 저장소의 `quality/README.md` 에 정리돼 있습니다.

== 자주 묻는 질문

[qanda]
원본 DB 비밀번호를 안내하는 메시지와 함께 배치가 끝납니다.::
  카탈로그는 저장된 원본 비밀번호를 내보내지 않습니다. `ARGUS_SOURCE_DB_PASSWORD` 또는 `--db-password-file` 로 직접 넘기세요.

`--source-timezone: 알 수 없는 시간대` 가 나옵니다.::
  IANA 이름(`Asia/Seoul`, `UTC`) 또는 `+09:00` 형식으로 지정하세요.

규칙 하나가 `N/A` 로 실패 처리됐습니다.::
  잘못된 정규식, SQL 실행 오류, 플러그인 오류, 없는 컬럼 같은 평가 오류입니다. 결과 상세에 사유가 적혀 있습니다.

스케줄러에서 실패를 어떻게 감지하나요?::
  종료 코드를 보세요. 모두 처리되면 `0`, 하나라도 실패하면 `1` 입니다.

일반 계정으로는 결과가 반입되지 않습니다.::
  반입은 관리자 계정만 할 수 있습니다. 일반 계정은 `--dry-run` 으로 결과만 확인하세요.
